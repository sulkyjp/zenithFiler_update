## Latest Changes — [1.10.6] - 2026-08-01 : Major terminal upgrade (persistent command history with Ctrl+R search, syntax-colored input, jumping between commands, Ctrl+C/V copy & paste, panes following cd, inline suggestions), middle-click tab closing, and fixes including the Favorites crash

### Added
- **Tabs can now be closed by middle-clicking (wheel-clicking) them (Issue #204).** Closing a tab used to mean aiming at the small "×" button or pressing `Ctrl + W`. Now, just as in a browser, a middle-click anywhere on the tab closes it. It works on the nav pane's terminal tabs too. Locked tabs and the last remaining tab still stay open, as before.
- **The rest of a command you have typed before is now suggested as you type.** Start typing a command you have run before and the remainder appears dimmed ahead of the cursor; press End (or → when the cursor is at the end of the line) to accept it, so long commands no longer have to be retyped in full. Suggestions stay out of the way where they would be a nuisance — during IME composition, while text is selected, and so on — and can be turned off.
- **Pasting text that contains line breaks now asks for confirmation.** Command Prompt executes each pasted line break, so pasting several lines by accident sets off a run of unintended commands. You now see the line count and the first three lines before anything runs, with a "Don't ask again" option.
- **Terminal command history now survives a restart.** Until now the only history was the one Command Prompt keeps for itself, so closing the app threw away everything you had typed and the next day you were retyping the same long commands. Commands you run are now recorded and saved by the app, so you can recall them after a restart — and from any other tab or pane, since the history is shared. Press **Ctrl+R** to open the history list: type to filter, use ↑↓ to pick, and press Enter to run it (or Shift+Enter to drop it into the prompt without running, so you can tweak it first). The "History" button in the action bar opens the same list. Recording can be turned off in the settings, and a "Clear history" button wipes it at any time.
- **Commands are now colored by syntax as you type.** Terminal text used to be a single flat color, which made long commands hard to read at a glance. The colorization you see in the VS Code terminal is a PowerShell feature and is not normally available under Command Prompt — but now that the app works with the shell to know exactly where your typing begins, it can apply the colors itself. The prompt's current path is bright blue, built-in commands (`cd`, `dir`, …) are bright yellow, external commands (`git`, `dotnet`, …) bright green, subcommands such as `status` in `git status` bright cyan, separators like `&`, `|` and `>` bright magenta, `"..."` cyan, `%PATH%` magenta, options such as `/w` gray, paths bright blue, and numbers yellow; other arguments keep the foreground color you configured. The coloring follows your keystrokes and stays in place after you press Enter (and can be turned off). **Output lines that look like errors are now shown in red** as well: a mistyped command name is detected reliably, while messages such as "Access is denied" are matched against a list of known error phrasings.
- **You can now move through long output one command at a time.** After a few hundred lines of build log have scrolled past, finding "which command did I run back there" meant hunting with the scrollbar. **Ctrl+↑ / Ctrl+↓** now jump between the positions where you typed each command, and a thin bar marks the left edge of each of those lines with a matching tick in the scrollbar (can be turned off). A mistyped command is marked in red. Turning on **"Pin the command to the top while scrolling"** keeps the command that produced the output you are looking at pinned at the top, so you never lose track of what you are reading.
- **Ctrl+C and Ctrl+V now work as copy and paste in the terminal.** Previously you had to press Ctrl+Shift+C / Ctrl+Shift+V, which is out of step with every other app. Ctrl+C copies when text is selected and still sends the interrupt (^C) when nothing is selected, so interrupting a running command keeps working. Ctrl+Shift+C / Ctrl+Shift+V remain available, and the new behavior can be turned off in the settings.
- **Where you `cd` to in the terminal can now be reflected in the file list pane.** The "A cd" / "B cd" buttons could already point the terminal at a pane's folder, but going the other way — reopening the terminal's current location in a pane — meant copying and pasting the path. The action bar now has **"→A" and "→B" buttons** that open the terminal's current location in that pane. Picking A or B under the **"Follow target for cd"** setting makes that pane follow every `cd` without pressing anything (the default is "Don't follow"). The target is shared by all terminals rather than set per terminal, so you can work in a terminal in pane A and have pane B follow along, keeping the moves visible. Whenever a pane moves, a line such as `Moved to "C:\..." in pane B` appears right below the command you typed, so you can tell on the spot that it followed.
- **Added a setting to draw the backslash using the yen sign (￥) glyph (off by default).** Many people working in Japanese would rather see a path as `C:￥work`, but the terminal's monospaced font renders it as `C:\work`. With the setting on, the font is left alone and only the backslash is drawn with the ￥ glyph. **Only the appearance changes, not the character itself** — copy that line and paste it elsewhere and you get a normal `\` back.

### Changed
- **The terminal now tracks command boundaries exactly.** It receives markers from Command Prompt telling it where the prompt ends and the typed command begins. As a result, recalling an earlier command with ↑ and editing part of it, or completing a path with Tab, records exactly what you actually ran.
- **Changing a terminal setting no longer forces a redraw for options unrelated to the font.** Previously any settings change triggered a font recalculation.

### Fixed
- **Fixed the app crashing when you add a folder to Favorites (Issue #205).** Right after a folder was added, the app crashed as it began the flourish that lights up the newly registered row. That flourish animates the row's background color directly, but the color set on the background had been created as a fixed, unchangeable one, so the animation could not start. Each row now gets its own changeable background color. Registering an index search target used the same flourish and was crashing in exactly the same way, so that path is fixed as well.
- **Fixed CLI tools sometimes losing their colors in the terminal.** Tools with colored output, such as Claude Code, could render in a single flat color inside the ZenithFiler terminal. The cause was that a "do not emit color" preference set by whatever launched the app — an editor or an automation tool, say — was being inherited all the way down into the terminal's shell and the tools started from it. The terminal is a real terminal, so whether to use color is now left to each tool to decide for itself.
- **Fixed Ctrl+R and F5 breaking the terminal display.** The terminal's view was being reloaded as a web page, wiping the contents of every open terminal. Those keys now reach the shell as intended.
- **Addressed the items of the OS-standard right-click menu (shown with Shift+right-click, for example) occasionally collapsing into an unreadable strip (Issue #173).** When Windows' automatic per-monitor menu scaling disagrees with the item sizes that shell extensions such as 7-Zip calculate for the entries they draw themselves, the items can come out squashed. This can happen when the system's scale factor and the monitor's current one drift apart — right after changing the display scale, or when docking or using remote desktop. The menu is now excluded from that automatic scaling so the entries are drawn at exactly the size the shell extensions calculated.

## 最新の変更履歴 — [1.10.6] - 2026-08-01 : ターミナルを大幅強化（コマンド履歴の永続化とCtrl+R検索・入力コマンドの色分け・コマンド単位の移動・Ctrl+C/Vコピー貼り付け・cdのペイン追従・入力予測）、タブの中ボタンクローズ、お気に入り追加時のクラッシュ等を修正

### Added
- **タブをマウスの中ボタン（ホイールクリック）で閉じられるようにした（Issue #204）:** これまでタブを閉じるには小さな「×」ボタンを狙うか `Ctrl + W` を押す必要があった。ブラウザと同じように、タブのどこでも中ボタンで押せば閉じられる。ナビペインのターミナルのタブでも同じように使える。ロック中のタブと最後の1枚が閉じない点は従来どおり
- **打ちかけのコマンドの続きを先読みして表示するようにした:** 一度打ったことのあるコマンドを、打ち始めた時点で薄字の続きとして表示する。End キー（またはカーソルが行末にあるときの → キー）を押すとその場で確定するので、長いコマンドを最後まで打ち直さなくてよい。日本語入力の変換中や文字を選択しているときなど、邪魔になる場面では表示しない（設定でオフにできる）
- **改行を含むテキストを貼り付けるときに確認するようにした:** コマンドプロンプトでは貼り付けた改行がそのまま実行になるため、複数行をうっかり貼ると意図しないコマンドが次々に走ってしまう。貼り付ける行数と先頭3行を確認してから実行できるようにした。「次回から確認しない」で以後スキップもできる
- **ターミナルのコマンド履歴が、アプリを再起動しても残るようになった:** これまで履歴はコマンドプロンプト自身が持つものだけだったため、アプリを閉じると打ったコマンドはすべて消え、翌日にはまた同じ長いコマンドを打ち直すことになっていた。実行したコマンドをアプリ側で記録して保存するようにしたので、再起動後も、また別のタブやペインのターミナルからも、過去に打ったコマンドを呼び出せる。**Ctrl+R** を押すと履歴の一覧が開き、文字を入れて絞り込み、↑↓ で選んで Enter で実行できる（Shift+Enter なら実行せず入力欄に入るので、少し直してから実行できる）。操作バーの「History」ボタンからも開ける。履歴の記録は設定でオフにでき、「履歴を消去」ボタンでいつでも消せる
- **入力中のコマンドを色分けして表示するようにした:** これまでターミナルの文字はすべて同じ色で、長いコマンドを打つとどこがコマンド名でどこが引数なのか目で追うのが大変だった。VS Code のターミナルで見られる色分けは PowerShell の機能なので、コマンドプロンプトでは本来使えないが、シェルと連携して「どこからがユーザーの打った文字か」を正確に把握できるようになったため、アプリ側で色を付けられるようになった。プロンプトのカレントパスは明るい青、組み込みコマンド（`cd` `dir` 等）は明るい黄、外部コマンド（`git` `dotnet` 等）は明るい緑、`git status` の `status` のようなサブコマンドは明るいシアン、`&` `|` `>` などの区切りは明るいマゼンタ、`"..."` はシアン、`%PATH%` はマゼンタ、`/w` などのオプションは灰色、パスは明るい青、数値は黄で表示する。その他の引数は設定した文字色のまま残る。打鍵に追従して色が付き、Enter を押した後もそのまま履歴として残る（設定でオフにできる）。あわせて**エラーらしい出力行を赤で表示**するようにした。コマンド名の打ち間違いは確実に検出し、「アクセスが拒否されました」などは既知のエラー文言との照合で判定する
- **長い出力の中を、コマンド単位で行き来できるようにした:** ビルドログのように何百行も流れた後で「さっきどのコマンドを打ったか」を探すには、これまでスクロールバーを目で追うしかなかった。**Ctrl+↑ / Ctrl+↓** でコマンドを打った位置へ順に飛べるようにし、あわせて各コマンドの行の左端に細いバー、スクロールバーにも同じ位置の目盛りを表示するようにした（設定でオフにできる）。打ち間違いのときだけ印が赤くなる。さらに設定で **「スクロール中もコマンドを上端に固定」**をオンにすると、出力の途中を見ているときに、その出力を出したコマンドが上端に残るので、何の出力を見ているのかを見失わない
- **ターミナルで Ctrl+C / Ctrl+V がそのままコピー・貼り付けとして使えるようになった:** これまでは Ctrl+Shift+C / Ctrl+Shift+V を押す必要があり、他のアプリと操作が違って戸惑いやすかった。文字を選択しているときの Ctrl+C はコピー、選択していないときは従来どおり実行中のコマンドの中断（^C）になるので、中断が使えなくなることはない。従来の Ctrl+Shift+C / Ctrl+Shift+V も引き続き使える。設定でオフにもできる
- **ターミナルで `cd` した場所を、ファイル一覧のペインにも反映できるようにした:** これまでは「A cd / B cd」ボタンでペインの場所へターミナルを合わせることはできたが、その逆——ターミナルで移動した先をペインで開き直すには、パスをコピーして貼り付ける必要があった。操作バーに **「→A」「→B」ボタン**を追加し、押すとそのときのターミナルの場所をペインで開くようにした。あわせて設定の **「cd の追従先」**で A か B を選ぶと、ボタンを押さなくても `cd` するたびにそのペインが追従する（既定は「追従しない」）。追従先はターミナルごとではなく全ターミナル共通で、たとえば A ペインのターミナルで作業しながら B ペインを追従させると、移動の様子が常に目に見える。ペインが移動したときは、打ったコマンドのすぐ下に「B ペインにて「C:\...」に移動しました」と表示されるので、追従したかどうかがその場で分かる
- **バックスラッシュを「￥」の字形で表示する設定を追加した（既定はオフ）:** 日本語環境ではパスの区切りを `C:￥work` のように見たい人が多いが、ターミナルの等幅フォントでは `C:\work` と表示されていた。設定をオンにすると、フォントはそのままにバックスラッシュだけを ￥ の字形で描く。**見た目が変わるだけで文字そのものは変わらない**ので、その行をコピーして他のアプリに貼り付ければ通常どおり `\` に戻る

### Changed
- **ターミナルがコマンドの区切りを正確に把握できるようになった:** コマンドプロンプトと連携して「どこまでがプロンプトで、どこからが打ったコマンドか」を受け取るようにした。これにより、↑ キーで前のコマンドを呼び出して一部を書き換えた場合や、Tab キーでパスを補完した場合でも、実際に実行した内容がそのまま履歴に残る
- **ターミナルの設定を変更したとき、フォントに関係のない項目では画面の再描画が走らないようにした:** 以前はどの設定を変えてもフォントの再計算が走っていた

### Fixed
- **お気に入りに追加するとアプリが強制終了する問題を修正（Issue #205）:** フォルダをお気に入りに追加した直後、登録した行を光らせる演出を始めるところでクラッシュしていた。この演出は行の背景色を直接アニメーションさせるのだが、背景に設定していた色が「変更できない色」として作られていたため、アニメーションを開始できずに落ちていた。行ごとに変更可能な背景色を持たせるようにして解消した。同じ演出を使っているインデックス検索対象の登録でも同様に落ちる状態だったので、あわせて修正している
- **ターミナルで CLI ツールの表示が色付きにならないことがあった問題を修正:** Claude Code のようなカラー表示を持つツールが、ZenithFiler のターミナルでは白一色で表示されることがあった。アプリを起動した親（エディタや自動化ツールなど）が「色を出力しない」指定をしていると、その指定がターミナル内のシェルおよびそこから起動したツールにまで引き継がれていたのが原因。ターミナルは本物の端末なので、色を出すかどうかは各ツール自身の判断に委ねるようにした
- **ターミナルで Ctrl+R や F5 を押すと表示が壊れることがあった問題を修正:** ターミナルの表示部分がブラウザとして再読み込みされてしまい、開いていたターミナルの内容がすべて消えていた。これらのキーがシェル側へ正しく届くようにした
- **OS標準の右クリックメニュー（Shift+右クリックなどで表示）の項目が、まれに潰れて読めなくなる問題への対策（Issue #173）:** Windows がモニタごとの拡大率に合わせてメニューを自動で拡大縮小する仕組みと、7-Zip などのシェル拡張が自前で描くメニュー項目の寸法計算が食い違うと、項目が潰れて表示されることがある。画面の拡大率を変更した直後やドック接続・リモートデスクトップなど、システムの拡大率と表示先モニタの拡大率がずれた状況で起きうるもので、このメニューの表示だけ自動拡大縮小の対象から外し、シェル拡張が計算したとおりの寸法で描画されるようにした
