**[2.1.0] - 2026-11-07 : Working sets now keep tab names, notes and colors, and tab colors were rebuilt as an easy-to-tell-apart palette; macros get a "Create file" step; right-dragging from File Explorer, dropping onto the nav tree and restarting for an update now behave as expected; and "Bridge", a screen made for Claude Code, arrives as a draft**

### Added

- **Working sets now save tab names, notes and colors, and bring them back (#461)** [Preview 2.0.0.1 → 2.0.0.8] — A tab's name, note and color used to disappear when you closed the tab or quit the app, and opening a working set did not bring them back. Now **saving or overwriting a working set, and the history kept before switching, include each tab's name, note and color**, for folder tabs and terminal tabs alike. Opening the set puts them back on each tab. In the tab list shown when you hover over a set, named tabs show their name. Sets saved by earlier versions come back as before, with no labels. In preview 2.0.0.7, opening a set while a Bridge tab was open in a pane left that pane's tabs without their names, notes and colors (#480). Bridge tabs are kept out of sets and left open, so the pane had one more tab than the set and the labels were skipped because they could not be matched to tabs. Bridge tabs are now skipped and the other tabs get their labels back

- **Right-click a tab to give it a random color (#465)** [Preview 2.0.0.3] — For when you just want a color to tell tabs apart and don't care which, without picking from the 30-color window. Right-click a tab → "**Random color**" colors it on the spot, without opening any window. It works for tabs in panes A/B and for terminal tabs in the nav pane. Since a color shared with the next tab doesn't help tell them apart, it picks **from colors the other tabs in the same row aren't using yet**, and never the current color (each click gives a different one). The "Name, note and color…" window also gets a dice button at the end of the swatches. Each click picks a color by the same rule, and you save it when you like it

- **Macros get a "Create file" part (#469)** [Preview 2.0.0.3] — Until now macros could only create folders, so a routine that prepares a note or minutes file under a set name could not be built. "📄 New file" creates an empty file inside the current folder. Write the name with its extension; tokens such as `note_{date}.txt` work too. It can also create the file in a subfolder, such as `minutes\today.md`, and creates that subfolder if it is missing. **If a file or folder with the same name already exists, it stops instead of overwriting**. As with creating folders, it cannot create anything outside the current folder, and a single undo (`Ctrl+Z`) after the run removes what it made. The input box's common values offer a dated note, minutes and a to-do list (TODO.md). Creating a new text file while recording a macro is also saved as this part

- **Bridge, a dedicated view for Claude Code, can now be opened as a pane tab, as a draft (#478)** [Preview 2.0.0.6] — Separately from the terminal, Bridge lets you use Claude Code with an input box that works like a text editor. Open it as a tab in a pane with the ✦ button to the right of the terminal button at the top right of the pane. In the input box you can cut from the middle of a line or move lines with `Alt+Up/Down`, and pasted images go in where you put them. The bottom row switches the model, effort and permission mode, and shows context, 5-hour and 7-day usage. Type `/` at the start for command suggestions; `/btw` asks a side question without adding it to the conversation. If you quit the app, open Bridge tabs come back in the same place on the next start. Choosing a folder from Favorites or the nav pane's tree while a Bridge tab is selected switches to the folder tab you were viewing just before and opens it there (or opens a new tab if there is no folder tab); this does not change Bridge's working folder. To change the working folder, pick it again from the folder name below the input box (this starts a new conversation; the previous one can be continued from past conversations). It is still an in-development draft and its screen text is Japanese only. It runs the same Claude Code you use in the terminal, with the same sign-in and pricing

### Changed

- **Tab colors went from 7 to 30 (#461)** [Preview 2.0.0.1] — The swatches under right-click on a tab → "Name, note and color…" are now None plus 30 colors. The previous seven (red, orange, yellow, green, blue, purple, gray) stay as they were, and 23 more such as salmon, mint, turquoise, lavender and pink are lined up in hue order. Colors are brought to the same brightness against the theme background so they stay readable, which means colors that differ only in brightness would look the same. The set was chosen so any two colors can be told apart on every one of the 57 bundled themes. Hover over a swatch to see the color's name. Favorites color tags stay at seven colors

- **The working set list now remembers how you sorted it (#466)** [Preview 2.0.0.3] — After sorting by a column heading (name, date, A/B), the nav pane list went back to your own order on the next launch, and the status bar quick access went back every time you opened it. Now the column and direction are remembered, so the list opens sorted the same way. The nav pane and the quick access are still sorted separately, and each remembers its own sort. Sorting only changes what you see; the stored order and the quick access numbers 1 to 9 stay the same

- **Tab colors are rebuilt as an easy-to-tell-apart color chart painted as is, and can also be picked in the Windows color dialog (#470)** [Preview 2.0.0.3] — The 30 tab colors looked alike side by side and did little to tell tabs apart. Every color had its brightness evened out for the theme, and the tab showed it only as a light tint and a thin band, so only the hue was left to differ. Now **the whole tab is filled with the chosen color itself**, and the text and icons turn white or black automatically, whichever reads better on it (a selected colored tab also gets a line in the text color along its bottom edge). You choose from a chart of 10 hues (red, orange, yellow, yellow green, green, teal, sky blue, blue, purple, magenta) in **vivid, bright, pale and deep** tones, plus white, light gray, dark gray and black: 44 colors. **"More colors…" opens the Windows color dialog for any color you like**. Colors set in earlier versions keep their color. "Random color" on the right-click menu and the dice also pick from these 44 colors. If you prefer the earlier look that blends with the theme (a light tint adjusted to the theme, with a band on the left), turn on the new **"Tone tab colors to match the theme"** under Tabs in Settings (off by default; switching it repaints open tabs on the spot). **It can also be set per tab**: "Tone this tab's color to match the theme" in the name, note and color window lets you turn it off for particular tabs even when the default is on (and the other way round). The choice is kept in working sets too

- **Right-dragging files from File Explorer now brings up the "Copy here / Move here" menu when you drop (#473)** [Preview 2.0.0.4] — Until now the menu appeared only for right drags started inside the app. Right-dragging from File Explorer or the desktop and dropping copied or moved the files silently by the same rules as a left drag. File Explorer always shows a menu when you drop with the right button, so the app behaving differently was confusing. Now a right-drag from outside brings up the same menu as a right drag inside the app (Copy here, Move here, Create shortcut here, Cancel), wherever you drop: the file list, the breadcrumb or the nav pane tree. With the right-click menu set to "Explorer-compatible menu", items from apps such as 7-Zip appear too. The app carries out the operation you choose, so the same-name prompt, the progress window and undo with `Ctrl + Z` all work. Clicking outside the menu does nothing. Dropping with the left button works as before

- **Dropping on the nav pane's tree now puts items into the folder wherever you drop on its row; placing them alongside on the edges is now a setting (#471)** [Preview 2.0.0.4] — Until now, dropping on the top or bottom edge of a folder row in the tree (a quarter of its height each) put the items alongside that folder (in its parent) instead of inside it. With half of each row meaning "into the parent", it was hard to hit the middle on a high-resolution screen with small text and icons, and while dragging files the row stayed highlighted even over the edges, so you could not tell where they would go. Now, as in File Explorer, **dropping anywhere on a row puts the items into that folder**. To place them alongside on the edges, turn on "**Drop on a tree row's edge to place alongside it**" in Settings → General → Navigation pane (off by default). When it is on, a line appears above or below the row over the edges, and the row is highlighted when the items will go inside. Dragging a folder within the tree works the same way

- **Pressing the update "Restart" while copying or moving now waits for the work to finish before restarting, and you come back to the tabs you had open (#476)** [Preview 2.0.0.5] — Until now, pressing "Restart" by mistake while files were being moved closed the app straight away, stopping the move partway and possibly leaving files half-finished. Now, if you press it while copying, moving or deleting, or while extracting an archive, exporting, transferring to a remote server or doing anything else that shows progress, the app first tells you that some work is still in progress. Press **OK** and it waits for the work to finish, then restarts on its own (you can keep working meanwhile, and if you cancel the work it restarts once nothing is running). Press **Cancel** and it does not restart. This works the same from "Restart and apply" on the About page and from the "Restart" button on the update-ready notice. Your settings are still saved before the restart, and when the app starts again it reopens the tabs you had open — even if "Restore previous tabs on startup" is off in General, but only for restarts made to apply an update

### Fixed

- **What's new no longer folds the later part of the v2.0.0 changes into "N more" (#464)** [Preview 2.0.0.1] — What's new lists every change in a version, one per line. To avoid building thousands of lines from a broken file, it had a cap of 60 entries per version, so v2.0.0, with 143 entries, showed 83 of its changes, fixes and removals only as a count. The cap is now 300, so a version with many changes is no longer cut short

- **Box "Copy share link with path" no longer fails from the second use until you wait a while (#463)** [Preview 2.0.0.1 → 2.0.0.3] — After getting the link, Zenith Filer closes Box's share window. It was closing not only the share window itself but also **the helper windows Box uses behind the scenes to draw the window's content**. Box keeps running for a while without recreating them, so the next share window could not show its content and stopped before creating a link. It kept failing until Box restarted those parts on its own, which took a while. Now Zenith Filer **tells the share window itself apart and closes only that, leaving Box's helper windows alone**, so the link comes through every time, however often you use it in a row. Preview 2.0.0.1 still stopped at a second place on the second use: when Box's menu, rebuilt just before running "Copy link", came back completely empty, Zenith Filer treated it like a changed menu and gave up right away. Now it waits briefly and rebuilds the menu, and if it is still empty, it looks the command up in the menu of the folder itself (when the menu has items but no "Copy link", it still stops as before, so it never runs the wrong command)

- **Feedback "It's fixed" and "Still happening" no longer make you wait a minute between reports (#462)** [Preview 2.0.0.1] — Replies from the reply box and the "It's fixed" / "Still happening" buttons shared the same 60-second anti-spam wait. Checking several fixed reports in a row showed "Please wait N more seconds before replying again" from the second one on. These buttons appear only once per fix and disappear when pressed, so there is nothing to spam. **You can now press them on as many reports as you like without waiting**, and writing a reply right afterwards does not make you wait either. Replies from the reply box still need 60 seconds between one and the next

- **Stickman's speech bubble no longer hides behind the terminal, so you can talk to it again (#467)** [Preview 2.0.0.3] — When a pane showed a terminal under Stickman, the bubble (the greeting and the input box) went behind the terminal and could be neither seen nor typed into. That is because, by the way Windows works, the terminal always draws in front of everything else inside the app's window. The bubble now opens in a small window that follows the main window, the same approach used for the toasts with buttons (#403). When you open the input box you can type into the bubble's window, and closing it returns focus to where it was. Switching to another app still closes it as before

- **Asking "Create with AI" for a macro that makes a folder named with today's date no longer answers that there is no such feature (#469)** [Preview 2.0.0.3] — Macros have both a create-folder part and a date token (`{date}`), but the description given to the AI listed only the parts, with no example of combining them. Depending on the AI in use, it returned a macro that only said it could not be done. The AI is now shown common requests (a folder named with today's date, creating it somewhere else such as the Desktop, asking for a name, a dated note) with how to build each, and told these are supported. Also, the macro "Navigate" and "New tab" parts did not resolve environment variables such as `%USERPROFILE%\Desktop` or `..`, so an AI-made "create on the Desktop" macro could not reach the Desktop. They now resolve them the same way as typing in the address bar

- **On a preview build, "About this app" now shows the same changes as the update notice (#468)** [Preview 2.0.0.3] — On a preview build (for example 2.0.0.1), the update notice listed the changes delivered in the preview, while "About this app" in the Control Deck listed the changes of the previous release (2.0.0). Only "About this app" cut the version down to three parts when reading, and it also showed the preview marks ([Preview …]) as they were. It now goes through the same reading as the update notice, so both screens list the same changes. On a release build it shows that version's changes, as before

- **Hovering a cut-off date modified, type or other column in the list now shows the full text (#475)** [Preview 2.0.0.4] — In File Explorer, when a column is too narrow and its text is cut off, hovering it shows the full text. Zenith Filer's details view did not, so hovering out of Explorer habit showed nothing. Now, **only when the text is cut off**, the full text appears below it after a short wait (nothing appears when the whole text is visible). This covers name, date modified, type, date created, extension, attributes, the columns added from the header's right-click menu, and the name, date modified and match in search results. Long names wrap. Shortcut names still show their link target, as before. The date modified column also used to be cut mid-number without notice when narrowed; it now ends with "…" like the other columns

- **Fixed a crash with the error "A drag operation is already in progress" while dragging files (#474)** [Preview 2.0.0.4] — Windows lets an app run only one drag at a time. A pane's list remembers where a mouse button was pressed and starts a drag once the mouse moves a little. If it missed the button being released (for example, when an app opened by double-click came to the front), it kept treating the button as held. When you later started a drag somewhere else and passed over that list, the list also tried to start a second drag from the old starting point, and the app crashed. Now the stale state is dropped whenever the mouse passes over the list with the buttons released. During a drag, other lists and panes do not start a new drag and do not change the selection of the list you pass over. All drags inside the app — pane lists, tabs, the navigation pane's tree, favorites, drives, macro steps and more — now start through the same gate, so they never overlap, and the app does not crash even if one does. Pressing `Esc` during a drag also sometimes failed to cancel it: Windows notices `Esc` only when keyboard input reaches the app, which it does not when the terminal or a similar view has focus. The app now checks the `Esc` key itself and cancels the drag wherever focus is, moving nothing, as in File Explorer

- **Fixed right-click menus showing a vertical scroll bar even when there was room on screen (#472)** [Preview 2.0.0.4] — The right-click menu and the submenus that open beside it (the OS standard menu ▶, Send to and so on) had fixed height limits (600 for the menu, 500 for submenus). The menu was resized to the screen when it opened, but submenus were not, so a submenu with many items appeared with a scroll bar even on a tall screen. Both now fit the height of the screen they open on, every time they open. As long as a menu fits on screen there is no scroll bar; it scrolls only when it is taller than the screen

- **Fixed themes applied from the Theme Store reverting when you left the store page; a downloaded theme now stays applied when you click its card (#477)** [Preview 2.0.0.5] — After a download, answering yes to "Switch to it now?" could still put your previous theme back once you left the Theme Store page. On the free edition, switching themes is a trial until you confirm it with "Switch", and that confirmation bar existed only on the Theme page, so leaving the store cancelled the trial. And if you had clicked a card to try a theme before downloading it, the app still remembered the theme from before the trial and returned to it when you left. Answering yes now counts as the confirmation, and the theme stays when you leave. **Clicking the card of a theme you have already downloaded, or of a built-in theme, now applies it just as choosing it on the Theme page does.** Until now even themes you owned were only tried on and reverted when you left the store. Themes you do not have can still be tried without downloading, and revert when you leave. On the free edition, the "Switch" bar now also appears on the store page, and moving between the Theme page and the store no longer cancels a theme you are trying

- **Choosing a folder from Favorites or the nav pane's tree while a terminal tab is selected no longer seems to do nothing (#478)** [Preview 2.0.0.6] — Choosing a folder moved the tab selected in the pane to that folder. When that tab was a terminal tab, only its hidden folder list moved and nothing on screen changed. Now the app switches to the folder tab you were viewing just before and opens the folder there, or opens a new tab if the pane has no folder tab. The Home button works the same way. The terminal's working folder does not change

- **Pasting files copied inside a Remote Desktop session no longer leaves you guessing about progress, and no longer lands in a folder you moved to while waiting (#479)** [Preview 2.0.0.6] — Files copied inside a Remote Desktop (RDP) session reach the clipboard as their contents rather than their locations. That is the same form as Outlook attachments, so the app used to read everything before writing any of it, and showed nothing in the meantime. With large files it looked as if nothing was happening, and you could not tell when it had finished. And because the destination was decided only after reading finished, moving to another folder while waiting pasted the files there. Pasting is now handed to Windows, as File Explorer does, so the same Windows progress window as an ordinary copy appears (time remaining, cancel, and the prompt for files with the same name). The destination is the folder that was open when you pasted, and it stays so even if you move to another folder afterwards. Contents copied from inside a zip in File Explorer are now pasted with the same window too, keeping their folder structure. Pasting Outlook attachments and messages works as before

The theme you pick there is now also remembered as the theme to apply at startup. Existing settings are not affected

- **エクスプローラーから右ボタンでドラッグして落としたときも、「ここにコピー／ここに移動」のメニューを出すようにしました (#473)** 〔先行版 2.0.0.4〕 — これまでメニューが出るのはアプリの中で始めた右ドラッグのときだけで、エクスプローラーやデスクトップから右ボタンでドラッグして落とすと、左ドラッグと同じ決まりで黙ってコピー・移動していました。エクスプローラーでは右ボタンで落とすと必ずメニューが出るので、このアプリだけ違って戸惑わせていました。いまは外から右ボタンで落としても、アプリの中の右ドラッグと同じメニュー（ここにコピー・ここに移動・ここにショートカットを作成・キャンセル）が出ます。ファイル一覧・パンくず・ナビペインのツリーのどこへ落としても同じです。右クリックを「エクスプローラー互換メニュー」にしていれば、7-Zip などのアプリの項目も並びます。選んだ操作はこのアプリが行うので、同じ名前の確認・進み具合の窓・`Ctrl + Z` での取り消しが効きます。メニューの外をクリックすると何もしません。左ボタンで落としたときは、今までどおりです

- **ナビペインのツリーへ落とすとき、行のどこに落としてもそのフォルダの中へ運ぶようにしました。端で同じ階層へ運ぶ動きは設定でオンにできます (#471)** 〔先行版 2.0.0.4〕 — これまでツリーのフォルダの行の上端・下端（それぞれ高さの 4 分の 1）に落とすと、そのフォルダの中ではなく同じ階層（親フォルダ）へ運んでいました。行の半分が「親へ」になるため、高い解像度で文字やアイコンが小さいと中心を狙うのが難しく、しかもファイルを運んでいる最中は端でも行が強調されたままで、どこへ運ばれるのか見分けられませんでした。いまはエクスプローラーと同じく、**行のどこに落としてもそのフォルダの中**へ運びます。端で同じ階層へ運びたいときは、設定 → 基本設定 → ナビペインの「**ツリーの端に落としたら同じ階層へ運ぶ**」をオンにしてください（既定はオフ）。オンのときは、端の上では行の上か下に線が出て、中へ運ぶときは行が強調されます。ツリーの中でフォルダをドラッグしたときも同じです

- **コピーや移動の途中で更新の「再起動」を押しても、処理が終わるのを待ってから再起動するようにしました。再起動のあとは押す前のタブに戻ります (#476)** 〔先行版 2.0.0.5〕 — これまでは、ファイルを移動している途中でうっかり「再起動」を押すと、そのままアプリが終わって移動が途中で止まり、ファイルが中途半端に残ることがありました。いまは、コピー・移動・削除や、書庫の展開・書き出し・リモートの転送など進捗が出ている処理の途中で押すと、「まだ終わっていない処理があります」と確かめます。**OK** を押すと処理が終わるのを待ち、終わったら自動で再起動します（待っている間も操作を続けられ、処理を中止したときも手が空いたところで再起動します）。**キャンセル**なら再起動しません。製品情報の「再起動して適用」と、更新の準備ができたときのお知らせの「再起動」のどちらから押しても同じです。再起動の前には今までどおり設定を保存し、立ち上がったら押す前に開いていたタブへ戻します。基本設定の「起動時に前回のタブを復元する」をオフにしていても、更新のための再起動のときだけは戻します

### Fixed

- **更新のお知らせで、v2.0.0 の変更の後ろのほうが「ほか N 件」にまとめられ、読めなかったのを直しました (#464)** 〔先行版 2.0.0.1〕 — 更新のお知らせは、その版の変更を 1 件ずつ全部並べます。ただ、壊れた資料で何千行も組み立てないよう 1 版 60 件までの上限があり、143 件あった v2.0.0 では変更・修正・削除の 83 件が件数だけになっていました。上限を 300 件に上げました。これからの版でも、変更が多い版のお知らせが途中で畳まれることはありません

- **Box の「リンク連携コピー」が 2 回目から必ず失敗し、しばらく時間を空けないと成功しなかったのを直しました (#463)** 〔先行版 2.0.0.1 → 2.0.0.3〕 — リンクが取れたあと、Zenith Filer は Box の共有ウィンドウを閉じています。このとき、共有ウィンドウの本体だけでなく、**Box が画面の中身を出すために裏で使っている部品の窓まで一緒に閉じていました**。Box はその部品を作り直さないまましばらく動き続けるので、次に開いた共有ウィンドウは中身を出せず、リンクが作られないまま止まっていました。Box が裏で入れ替わるまで（しばらく時間が空くまで）は、何度やっても失敗していました。いまは**共有ウィンドウの本体だけを見分けて閉じ、Box の部品には触りません**。続けて何度使っても、毎回リンクが取れます。先行版 2.0.0.1 では、2 回目に別の場所でも止まっていました。「リンクをコピー」を実行する直前に作り直した Box のメニューが丸ごと空で返ってきたときに、メニューの構成が変わったときと同じ扱いで、すぐにあきらめていました。いまは空のときは少し待って作り直し、それでも空ならフォルダそのもののメニューから引き直します（項目が並んでいるのに「リンクをコピー」だけが無いときは、別の操作を誤って実行しないよう今までどおり中止します）

- **フィードバックの「直った」「まだ直っていない」を続けて押すと、2 件目から 1 分ずつ待たされていたのを直しました (#462)** 〔先行版 2.0.0.1〕 — 返信欄からの返信と、「直った」「まだ直っていない」のボタンが、連投を防ぐ 60 秒の待ち時間を共有していました。そのため、直った報告をいくつか続けて確かめると、2 件目からは「続けて返信するには あと N 秒お待ちください」と出て押せませんでした。このボタンは 1 つの修正について 1 回しか出ず、押すと消えるので、連投のおそれがありません。いまは**待ち時間なしで何件でも続けて押せます**。押したあとに返信欄から書いて送るときも待たされません。返信欄からの返信どうしは、これまでどおり 60 秒あけて送ります

- **Stickman の吹き出しがターミナルの後ろに隠れて、話しかけられなかったのを直しました (#467)** 〔先行版 2.0.0.3〕 — Stickman の下にペインのターミナルがあると、吹き出し（一言と入力欄）がターミナルの後ろに回り、見えず打てませんでした。ターミナルは Windows の仕組み上、アプリの画面の中のほかの表示より必ず手前に出るためです。吹き出しを、本体に付いて動く小さな窓に出すようにしました。ボタン付きのお知らせを直したとき (#403) と同じやり方です。入力欄を開くと吹き出しの窓に打てるようになり、閉じると元の場所へフォーカスが戻ります。ほかのアプリへ切り替えると、今までどおり閉じます

- **マクロの「AI で作る」で「本日の日付のフォルダを作るマクロ」を頼むと、「そんな機能はない」と返ることがあったのを直しました (#469)** 〔先行版 2.0.0.3〕 — マクロにはフォルダ作成の部品も日付のトークン（`{date}`）もありますが、AI への説明には部品の一覧しか無く、組み合わせ方の例がありませんでした。使う AI によっては「できない」と知らせるだけのマクロを返していました。いまは、よくある頼み方（本日の日付のフォルダ・デスクトップなど別の場所に作る・名前を聞いて作る・日付のメモを作る）とその組み方を AI に見せ、「これらはできる」と伝えています。あわせて、マクロの「フォルダ移動」と「新規タブ」が `%USERPROFILE%\Desktop` のような環境変数や `..` を解かず、AI が作った「デスクトップに作る」マクロがデスクトップへ移れなかったのも直しました。アドレスバーに打ったときと同じように解きます

- **先行版で、「このアプリについて」の更新内容が更新のお知らせと違っていたのを直しました (#468)** 〔先行版 2.0.0.3〕 — 先行版（例: 2.0.0.1）を使っていると、更新のお知らせには先行版で届いた変更が出るのに、Control Deck の「このアプリについて」には一つ前の製品版（2.0.0）の変更が出ていました。「このアプリについて」だけが版を 3 桁に切り詰めて読んでいたためで、先行版の印（〔先行版 …〕）もそのまま出ていました。いまは更新のお知らせと同じ読み取りを通すので、どちらの画面でも同じ変更が並びます。製品版では、今までどおりその版の変更が出ます

- **一覧で省略されている更新日時や種類などに、マウスを乗せても全文が出なかったのを直しました (#475)** 〔先行版 2.0.0.4〕 — エクスプローラーでは、列が狭くて文字が省略されているとき、マウスを乗せると全文が出ます。Zenith Filer の詳細表示では出なかったので、エクスプローラーと同じつもりで乗せても読めませんでした。いまは**文字が切れているときだけ**、少し待つとその下に全文が出ます（全部見えているときは出ません）。名前・更新日時・種類・作成日時・拡張子・属性と、見出しの右クリックで足した列、検索結果の名前・更新日時・一致した行が対象です。長い名前は折り返して出します。ショートカットの名前は、今までどおりリンク先を出します。あわせて、更新日時の列を狭めると数字の途中で黙って切れていたのを、ほかの列と同じく「…」で切れたと分かるようにしました

- **ファイルをドラッグしている途中で「ドラッグ操作は既に実行中です」のエラーが出て落ちることがあったのを直しました (#474)** 〔先行版 2.0.0.4〕 — Windows では、1 つのアプリで同時に始められるドラッグは 1 つだけです。ペインの一覧は、マウスのボタンを押した場所を覚えておき、少し動いたらドラッグを始めます。ボタンを離したことを取りこぼすと（ダブルクリックで開いたアプリが前に出たときなど）、押したままの状態を覚え続けていました。そのあと別の場所からドラッグを始めてその一覧の上を通ると、一覧も古い起点からもう 1 つドラッグを始めようとしてエラーになっていました。いまは、ボタンを離した状態でマウスが通ったときに古い状態を捨てます。ドラッグの最中は、ほかの一覧やペインが新しいドラッグを始めず、通った一覧の選択も変えません。ペインの一覧のほか、タブ・ナビペインのツリー・お気に入り・ドライブ・マクロの部品など、アプリの中のドラッグをすべて同じ窓口から始めるようにしたので、どこから始めても重ならず、万一重なっても落ちません。あわせて、ドラッグの途中で `Esc` を押してもキャンセルできないことがあったのを直しました。Windows は、キーボードの入力がこのアプリに届いたときにしか `Esc` に気づかず、ターミナルなどにフォーカスがあると届かないためです。いまは `Esc` キーそのものを見て、どこにフォーカスがあってもキャンセルします（エクスプローラーと同じく、何も運ばれません）

- **画面に余裕があるのに、右クリックのメニューに縦のスクロールバーが出ていたのを直しました (#472)** 〔先行版 2.0.0.4〕 — 右クリックのメニューと、その中で横に開くサブメニュー（OS標準メニュー ▶・送る など）は、高さの上限が決め打ちでした（メニューは 600、サブメニューは 500）。メニューのほうは開くときに画面の高さへ合わせ直していましたが、サブメニューはそのままで、項目の多いサブメニューは画面に十分な高さがあってもスクロールバー付きで出ていました。いまはどちらも、開くたびにそのメニューを出す画面の高さに合わせます。画面に収まるうちはスクロールバーが出ず、画面より長いときだけスクロールします

- **テーマストアで当てたテーマが、ストアのページを離れると元に戻っていたのを直しました。ダウンロード済みのテーマは、カードを押すとそのまま当たります (#477)** 〔先行版 2.0.0.5〕 — ダウンロードが済んだあとの「今すぐこのテーマに切り替えますか？」で「はい」を選んでも、ストアのページを離れると元のテーマに戻ることがありました。無料版では、テーマを切り替えると「切り替える」で確かめるまでお試しの扱いになります。その確かめるバーがテーマのページにしか無く、ストアを離れるとお試しのまま取り消されていました。また、先にカードを押して試してからダウンロードすると、試す前のテーマを覚えたままで、ストアを離れたときにそこへ戻していました。いまは「はい」がそのまま確定の返事になり、ストアを離れても戻りません。あわせて、**ダウンロード済みのテーマと同梱のテーマは、カードを押すとテーマのページで選んだのと同じように当たる**ようにしました。これまでは持っているテーマでも「試しに当てる」扱いで、ストアを離れると戻っていました。持っていないテーマは、今までどおりダウンロードせずに試せて、ストアを離れると元に戻ります。無料版では、ストアのページにも「切り替える」のバーが出ます。テーマのページとストアの間を行き来しても、お試しのテーマは取り消されません

- **ターミナルのタブを選んだままお気に入りやナビペインのツリーでフォルダを選んでも、何も起きないように見えていたのを直しました (#478)** 〔先行版 2.0.0.6〕 — フォルダを選ぶと、ペインで選んでいるタブをそのフォルダへ移していました。選んでいるのがターミナルのタブだと、表には出ていないフォルダの一覧だけが移り、画面は何も変わりませんでした。いまは、直前まで見ていたフォルダのタブへ切り替えてそこで開きます。フォルダのタブが 1 つも無ければ、新しいタブで開きます。ホームへ戻るボタンも同じです。ターミナルの作業フォルダは変わりません

- **リモートデスクトップの向こうでコピーしたファイルを貼り付けると、進み具合が分からず、待っている間に別のフォルダへ移るとそちらへ貼り付けられていたのを直しました (#479)** 〔先行版 2.0.0.6〕 — リモートデスクトップ（RDP）の向こうでコピーしたファイルは、クリップボードに場所ではなく中身で届きます。Outlook の添付と同じ形なので、これまでは全部を読み込み終えてから書き出しており、その間は何も表示しませんでした。大きいファイルでは長く何も起きないように見え、終わったかどうかも分かりませんでした。また、貼り付け先を読み込みが終わってから決めていたため、待っている間に別のフォルダへ移ると、移った先へ貼り付けられていました。いまはエクスプローラーと同じく Windows に貼り付けを任せるので、ふつうのコピーと同じ Windows の進捗の画面（残り時間・中止・同じ名前の確認）が出ます。貼り付け先は押したときに開いていたフォルダに決まり、そのあと別のフォルダへ移っても変わりません。エクスプローラーで zip の中身をコピーして貼り付けたときも同じ画面で運び、フォルダの階層もそのまま保ちます。Outlook の添付・メールの貼り付けは今までどおりです

- **初回起動の案内で選んだテーマが、次に起動すると標準のテーマに戻っていたのを直しました (#477)** 〔先行版 2.0.0.6〕 — 初めて起動したときの案内（言語・テーマ・キー操作を選ぶ画面）で選んだテーマは、その日のあいだは当たっていても、アプリを閉じて起動し直すと標準のテーマに戻っていました。案内で選んだテーマを、起動のときに当てるテーマとしても覚えるようにしました。すでに使っている人の設定には関係しません
