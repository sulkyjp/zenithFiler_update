## Latest changes

<details>
<summary><b>Show the notes for the latest release</b></summary>

<!-- latest-changes-en:begin -->
**[2.4.0] - 2026-11-21 : Adds a switch that turns off all network access other than files, and an option to show the description and version of programs on hover; moves the Microsoft Store version's settings and data into its package folder; fixes item info in Details view appearing only over the name text, and scroll bars appearing in right-click menus after they open**

### Added

- **Added a switch that turns off all network access other than files, such as update checks, the stores, feedback and AI (#544)** [Preview 2.3.0.1] — A user suggested a way to cut off everything that goes online but isn't about managing files. Until now you could only turn off the update check, the XP leaderboard and reply checks one by one, and there was no way to stop features like the stores or AI that go online when you use them. Turn on "Turn off network access other than files" under Control Deck → General → Network, and update checks and downloads, the XP leaderboard, feedback, the theme and Stickman stores, online AI services, and Ollama and FFmpeg downloads no longer go online. Files on network drives, NAS, FTP and Box, and Ollama running on this PC, keep working. The stores, the feedback page and the update check show the reason in one line at the top and disable their buttons, and trying an online AI feature from anywhere else tells you it isn't available and sends nothing. While it's on you won't be told about new versions, so check for updates yourself (off by default)
- **The hover info can now also show the description and version of programs such as .exe and .dll files (#545)** — A user asked to see the version of an .exe or .dll before opening it, even as an opt-in feature. File Explorer shows a program's file description, company and file version when you point at it, but Zenith Filer's hover info never reads the disk, so it left them out. Turn on "Also show program description and version" under Control Deck → Display → File list, and pointing at a program (.exe, .dll, .sys, .ocx, .cpl, .scr, .drv, .ax, .mui) adds its file description, company and file version below the usual type, size and date modified (and the product version when it differs from the file version). This is the only part that reads inside the file, so it's off by default, and it only reads files that are on this PC's drives with their contents on this PC. Network drives, online-only cloud files and drives already known to be slow are skipped. The file is read in the background: the pop-up opens with the usual lines first and the program details are added below when ready. Each file is read only once


### Changed

- **The Microsoft Store version now keeps its settings and data in its own package folder (#521)** — Microsoft Store review did not approve the special permission (`unvirtualizedResources`) that exempts an app's AppData writes from Windows' tracking. Without it, settings and data kept in `%LocalAppData%\ZenithFiler\data` would live only inside the Microsoft Store version, so Explorer couldn't see them and you couldn't copy them over from the GitHub version. They now live in `%LocalAppData%\Packages\ZenithFiler.ZenithFiler_qvnemebdepqqe\LocalState\data`, the folder Windows sets aside for each Microsoft Store app. It looks the same from inside and outside the app, and it is removed when you uninstall. One more difference: files and folders that the Microsoft Store version newly creates directly in `%LocalAppData%` or `%AppData%` (by copying, creating, or installing from the built-in terminal) are visible in Zenith Filer but not in other apps. Anything created inside a folder that already exists, and editing or deleting existing files, works normally (checked on a test install). If you often create new folders directly in AppData, use the GitHub version. The GitHub version is unchanged. The differences are in the manual under "Installation and Folder Structure"


### Fixed

- **In Details view, item info now appears anywhere in the Name column, not only over the name itself (#543)** [Preview 2.3.0.1] — Version 2.3.0 brought the hover pop-up with type, size and dates to Details view and search results, but it only appeared while the pointer was right on the text of the name. Pointing at the icon or at the empty space after the name showed nothing, so with short file names it looked as if some files had no info at all. As in File Explorer, it now appears wherever you point in the Name column. The full name is still shown at the top when it is cut off by the column width, and shortcuts still show their target. While you are renaming an item, the pop-up stays hidden so it does not cover the text box
- **When a vertical scroll bar appears in a right-click menu after it opens, the menu is now repositioned (#472)** — After 2.3.0 fixed menus being cut to half the screen when opened near the vertical middle, a report said scroll bars still appeared quite often. On the reporting PC, the log showed that no menu ever had a scroll bar right when it opened; it appeared afterwards. The previous version only checked once, right after opening, so it missed these. Menus and submenus are now watched for a scroll bar the whole time they're open. If the contents would fit on the screen but the menu's window is still too small and cuts them off, the menu is repositioned on the spot. The size and screen position at the moment a scroll bar appears, and whether repositioning removed it, are now logged and included with feedback. Menus that are taller than the screen still scroll as before

## 最新の変更履歴

<details>
<summary><b>最新リリースの内容を表示</b></summary>

**[2.4.0] - 2026-11-21 : ファイル以外の通信をまとめて止める設定と、マウスを乗せたときにプログラムの説明とバージョンを出す設定を足し、Microsoft Store 版の設定の置き場をパッケージ専用のフォルダに移し、詳細表示の項目の情報が名前の文字の上でしか出なかったのと、右クリックのメニューに開いたあとでスクロールバーが出るのを直した**

### Added

- **更新の確認・ストア・フィードバック・AI など、ファイル以外の通信をまとめて止める設定を足しました (#544)** 〔先行版 2.3.0.1〕 — 海外の利用者から「メッセージなど、ファイルの操作に関わらない通信を全部切れるようにしてほしい」と提案がありました。これまでは、更新の確認・経験値のランキング・返信の確認をそれぞれの設定で止めるしかなく、ストアや AI のように押せば外へ出る機能を一度に止める手段はありませんでした。Control Deck →「基本設定」→「通信」の「ファイル以外の通信を止める」をオンにすると、更新の確認と更新のダウンロード、経験値のランキング、フィードバック、テーマと Stickman のストア、外の AI のサービス、Ollama と FFmpeg の取得が、外へ通信しなくなります。ネットワークドライブ・NAS・FTP・Box のファイルと、この PC で動かす Ollama はそのまま使えます。ストア・フィードバック・更新の確認の画面は頭に理由を 1 行出してボタンを押せなくし、ほかの画面から外の AI を使おうとしたときも「使えません」と知らせて何も送りません。オンのあいだは新しい版の知らせも届かないので、更新はご自分で確かめてください（既定オフ）
- **マウスを乗せたときの情報に、.exe や .dll などのプログラムの説明とバージョンも出せるようにしました (#545)** — 海外の利用者から「exe や dll のバージョンを、開く前に見られるとうれしい。オプトインでもよい」と要望がありました。エクスプローラーはプログラムに乗せるとファイルの説明・会社・ファイル バージョンを出しますが、Zenith Filer の情報ヒントは乗せたときにディスクを読まない作りなので、これまで出していませんでした。Control Deck →「表示」→「ファイル一覧」の「プログラムの説明とバージョンも出す」をオンにすると、プログラム（.exe・.dll・.sys・.ocx・.cpl・.scr・.drv・.ax・.mui）に乗せたとき、いつもの種類・サイズ・更新日時の下に、ファイルの説明・会社・ファイル バージョンを足します（製品バージョンはファイル バージョンと違うときだけ）。これだけはファイルの中を読むので既定はオフで、読むのはこの PC のドライブにあって中身もこの PC にあるファイルだけです。ネットワークドライブ・オンラインのみのクラウドのファイル・遅いと分かっているドライブは読みません。読むのは裏で行い、ヒントは先にいつもの行で開いて、読めたら下に足します。同じファイルは 1 回だけ読みます


### Changed

- **Microsoft Store 版の設定とデータの置き場を、パッケージ専用のフォルダに移しました (#521)** — Microsoft Store の審査で、AppData への書き込みを Windows の見張りから外す特別な権限（`unvirtualizedResources`）が認められませんでした。この権限が無いと、`%LocalAppData%\ZenithFiler\data` に置いた設定やデータが Microsoft Store 版の中にだけ置かれ、エクスプローラーからは見えなくなります（コピーで GitHub 版から移ることもできません）。そこで置き場を、Windows が Microsoft Store のアプリごとに用意する `%LocalAppData%\Packages\ZenithFiler.ZenithFiler_qvnemebdepqqe\LocalState\data` に変えました。ここはアプリの中からも外からも同じに見え、アンインストールすると一緒に消えます。もう一つの違いとして、Microsoft Store 版で `%LocalAppData%` や `%AppData%` のすぐ下に新しく作ったファイルやフォルダー（コピー・新規作成・内蔵ターミナルで入れたもの）は、Zenith Filer からは見えますが、ほかのアプリからは見えません。すでにあるフォルダーの中に作ったものと、もとからあるファイルの編集・削除はふつうに効きます（手元で確かめました）。AppData のすぐ下に新しいフォルダーをよく作るときは GitHub 版を使ってください。GitHub 版は何も変わりません。違いはマニュアルの「インストールとフォルダ構成」にあります


### Fixed

- **詳細表示で、名前の文字の上に乗せたときにしか項目の情報が出なかったのを、名前の列のどこに乗せても出るようにしました (#543)** 〔先行版 2.3.0.1〕 — 2.3.0 で詳細表示と検索結果にも、マウスを乗せると種類・サイズ・日時を出すようにしましたが、出るのは名前の文字そのものの上だけでした。アイコンの上や、名前の右の空いた所に乗せても何も出ず、名前の短いファイルでは「このファイルだけ出ない」ように見えていました。エクスプローラーと同じく、名前の列のどこに乗せても出るようにしました。名前が列の幅で切れているときに先頭に全文を出すこと、ショートカットではリンク先を出すことは変わりません。名前を変えている最中は、入力欄に重ならないよう出しません
- **右クリックのメニューに、開いたあとで縦のスクロールバーが出ることがあったのを、出たときに置き直すようにしました (#472)** — 2.3.0 で「画面の真ん中で開くとメニューが画面の半分で切られる」問題を直したあとも、「割と多くの場面でスクロールバーが出る」と報告がありました。報告をくださった環境の記録では、メニューを開いた直後にスクロールバーが出ていたことは一度もなく、出るのは開いたあとでした。前の版の記録は開いた直後に 1 回だけ見ていたので、これを捉えられていませんでした。メニューとサブメニューを開いているあいだ、スクロールバーが出ないかを見張るようにしました。中身が画面に収まる長さなのにメニューの窓が小さいまま切られていたら、その場でメニューを置き直させます。あわせて、スクロールバーが出たときの寸法と画面の上の位置、置き直して消えたかどうかを記録に残し、フィードバックの添付にも載るようにしました。中身が画面より長いメニューは、これまでどおりスクロールします

> 過去の変更履歴は [Releases](https://github.com/sulkyjp/zenithFiler_update/releases) を参照してください。
