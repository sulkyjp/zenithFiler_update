**[1.17.3] - 2026-10-13 : Effects that move the screen along with what you do, middle-click to open in a new tab from the nav pane and the breadcrumb, Snap Layouts on the maximize button, and stepping through images in Photos with the arrow keys**

### Added

- **You can now open the Pro purchase page from inside the app (#386)** [Preview 1.17.2.2] — Until now the app only had a field for entering your key, so you had to read instructions outside the app to find out where to buy one. The notice shown when you used up a free allowance also just said the limit was reached. The page in the Control Deck where you register your key now has a "Buy Pro" section whose button opens the store page in your browser. With the Japanese UI, Vector (¥2,000, tax included) is shown first; with any other language, Polar ($15, tax included) is shown first, and the other store is listed below it. The notice for a used-up free allowance now has a "How to buy" button that opens that page. The button appears only once per feature each time you start the app, and disappears after 10 seconds. The app never suggests buying at startup or on a timer. Nothing changes for people who have already purchased.

- **Added five effects that move the screen along with what you do (#392)** [Preview 1.17.2.3] — Until now most effects told you what had changed with a fade or a glow, and almost none actually moved anything. Now the screen moves in the direction of your action. When you move the selection to the next row with the arrow keys and similar keys, the selection frame slides from the previous row to the new one (it does not slide when you select with Shift or Ctrl held down, with the mouse, or when the move jumps off screen, as with PageDown). Going into a folder slides the new list in slightly from the right, going back slides it in from the left, and going up a level slides it in from the top; when you go into a folder, the new crumb in the breadcrumb also slides in from the right. Switching tabs slides the contents in from the right if the new tab is to the right, and from the left if it is to the left. When you drag files inside the app and drop them on a folder, a snapshot of the rows you were holding shrinks into that folder. Switching between one pane and two side-by-side panes, and opening or closing the nav pane in docked mode, now animate the width. All of these are visual only: the selection, the focus, and copying or moving are settled the instant you press the key or drop, and never wait for an effect to finish. Slide-ins travel no more than 12px, and pane widths never animate at startup. Each effect can be turned off from its category in Control Deck > Effects (the selection frame under I. File List, the suck-in under L. Drag & Drop, folder moves under Feedback on actions, tabs under D. Tab Operations, and widths under E. Pane Transitions) or with Turn off all effects. The tab switch effect also now stops when "Show animations" is turned off in Windows; it used to keep playing.

- **Hovering over the maximize button now shows Windows 11 Snap Layouts (#394)** [Preview 1.17.2.6] — The main window's maximize button is drawn by the app itself, and Windows did not see it as a maximize button, so hovering over it never brought up the layout picker (Snap Layouts). The app now tells Windows that this is the maximize button, so hovering over it shows the layout choices just like in other apps, and picking one places the window there. The button looks the same, and clicking it still maximizes or restores the window. To turn the picker off, use Windows Settings > System > Multitasking > Snap windows. Windows 10 does not have this feature, so nothing appears there. The window layout buttons on the status bar work as before.

- **You can now middle-click items in Favorites, History and other nav pane lists, and folders in the breadcrumb, to open them in a new tab (#398)** — Double-clicking an entry in History and similar lists replaced what the current tab was showing, so the folder you had been looking at disappeared from the screen. Only folders in the file list and favorites could be opened in a new tab with a middle-click. Now, middle-clicking an item in History, Frequently Used, the folder tree, Drives, Recent Files, Remote or Box in the nav pane, or a folder in the breadcrumb, opens it in a new tab in the active pane and switches to that tab. For Recent Files, the folder containing the file opens. Middle-clicking an entry in Search History or Saved Searches opens the current folder in a new tab and runs the search in that tab. The current tab's list stays as it was. Middle-clicking a folder in the file list still opens it in a background tab without switching. All of these can be turned off together with General > Open folders in a new tab with middle-click in Settings. Middle-clicking a favorite used to work regardless of that setting; it now follows the setting like the others.

### Changed

- **Folders added automatically to "Frequently Used" now get a description made of keywords about what they hold (#389)** [Preview 1.17.2.3] — Favorites added by "Add frequently used folders automatically" were described only as having been opened twice and added automatically, so every one of them had the same text and the description told you nothing. The description now lists keywords taken from the parts of the folder name (a date-style name is shown as a date), the names of its parent and grandparent folders, words that recur in the names of the files and folders inside it, and the most common file types inside (such as "xlsx×4"), followed by the date it was added and how many times it was opened. AI is not used. The folder is still added to your favorites right away; its contents are read in the background and the description is filled in afterwards, so nothing you are doing is held up. If reading takes more than 5 seconds, the description is built from the folder name and its parents only. Folders already added automatically whose description is still the original text are rebuilt the same way shortly after the app starts. Descriptions you have edited are left alone.
- **Clicking a path in the terminal now opens the pane chosen by the "cd follow target" setting (#390)** [Preview 1.17.2.3] — A click used to open pane A and Ctrl+click pane B, always. Clicking from a terminal opened as a tab in pane A only moved the folder tab behind it, so the terminal stayed on screen and nothing seemed to happen. Now, when the cd follow target is A or B, a click opens that pane and Ctrl+click opens the other one. When it is "Don't follow" (the default), a click opens the pane next to the terminal (pane B for a terminal tab in pane A, pane A for one in pane B, and pane A for the nav pane terminal), and Ctrl+click opens the terminal's own pane. What you open always ends up on screen: a pane hidden in single-pane view makes the view switch to two panes, a pane showing a terminal tab switches to the folder tab it opened, and a pane with no folder tab opens the path in a new tab. The hint shown when hovering a path now reads "Click: open the folder / Ctrl+click: open in the other pane".
- **Characters that can't be used in a file name are now left out as you type, as in File Explorer (#397)** — When renaming, typing `\ / : * ? " < > |`, or pasting text that contains them, used to put them in the box as they were. The rename dialog then showed a warning and would not let you press OK, and renaming in place in the file list failed when you confirmed. Now, as in File Explorer, typing these characters enters nothing, and when you paste text they are removed and only the rest is entered. When characters are removed, "A file name can't contain any of the following characters" appears below the box with the list of characters for a few seconds. This applies to the rename dialog (both the name and the extension boxes) and to renaming in place in the file list. Full-width characters such as `？` and `：` can still be used. Reserved names (such as `CON`) and names ending with a dot or a space are still reported with a warning.

### Fixed

- **The ring launcher could stay partly cut off after switching displays (#385)** [Preview 1.17.2.1] — To open quickly, the ring launcher does not close its window but hides it and reuses it the next time. When the display layout changed, for example by connecting or disconnecting an external monitor or switching the projection mode, the hidden window's size no longer matched the display's scaling, and the right or bottom part of the ring could be cut off. Because the window kept being reused, it stayed that way until the app was restarted. The window is now created again the next time you open the ring after the display layout changes. If an opened window's size does not match the display's scaling, it is also created again before it is shown.
- **With wrapped tabs, the tab strip could stay several rows tall after starting in single-pane view (#387)** [Preview 1.17.2.3] — If tabs were set to wrap onto several rows and the two panes' tab strips were set to match heights, starting the app in single-pane view without maximizing could leave the tab strip several rows tall, with empty space above and below, even when there was only one row of tabs. Startup briefly goes through the two-pane layout, and the strip kept matching the hidden pane's height from when it was wrapped at half width. Switching to two panes and back fixed it. Heights are now matched only between panes that are on screen, and nothing is matched while one pane is hidden. Heights are also matched again when you go from a top-and-bottom split back to a single pane.
- **Batch files and scripts opened from the app could not read files in their own folder by relative path (#388)** [Preview 1.17.2.3] — When you opened a file from Zenith Filer, the app that opened it kept Zenith Filer's own folder as its working folder. A batch file that runs PowerShell, for example, failed with "path does not exist" when it read a file in the same folder by name only, as in `Get-Content list.txt`. Files now open with their own folder as the working folder, just like in File Explorer. This applies to double-clicking or pressing Enter in the file list, favorites, recent files, Open and Edit in the right-click menu, and opening with your chosen text editor.
- **Paths in the terminal prompt and in Claude Code's output did not become clickable links (#390)** [Preview 1.17.2.3] — Paths printed in the terminal were supposed to be underlined and open their folder on click, but the most common one, the command prompt `C:\work\proj>`, was not treated as a path because of the trailing `>`. Claude Code's `Read(Views/Foo.cs)` and `Update(src/a.cs:12)` did not become links either, because the word before the bracket was checked as part of the path. The prompt now links up to the `>`, even with a command typed after it, and Claude Code's form links just the path inside the brackets. A long path broken across two lines at the edge of the screen is still not treated as one path.
- **Recalling a working set could turn Box, SharePoint and similar folders into Desktop (#391)** [Preview 1.17.2.3] — If a registered folder could not be found at the moment you recalled a working set, its tab was replaced with Desktop (or Downloads for the first tab in pane B). Box Drive and OneDrive hide their folders entirely until syncing is ready, so recalling a set right after startup or while syncing resumed turned folders you had registered into Desktop. Using Overwrite then wrote Desktop into the set. Folders that can't be found are no longer replaced: the tab keeps the registered path, shows "This location is not available yet. Waiting for it to come online…", and opens the folder as soon as it appears (checked every 2 seconds; it stops waiting after 2 minutes, but the tab still keeps the registered path). The same applies to an external drive you plug in later and to a registered drive root such as `D:\`. The notification says how many folders are not found yet and will open when they appear. Restoring tabs at startup works as before.

- **Fixed Shift+Enter not opening files (#393)** [Preview 1.17.2.4] — An Access database (.mdb / .accdb) can be opened with its automatic macros and startup settings skipped by holding Shift while opening it. In Zenith Filer that worked with a double-click, but pressing Enter while holding Shift did nothing, because Open was assigned only to Enter without modifiers and Shift+Enter matched no action at all. Now, as in Explorer, Shift+Enter opens the file too. Shift is passed straight on to the app that opens it, so Access skips its automatic startup. If you have reassigned Open to another key in the key settings, that key with Shift added opens in the same way. If you have assigned that keystroke to another action, that action takes priority.

- **Fixed the app not starting through a symbolic link (#381)** [Preview 1.17.2.5] — `ZenithFiler.exe` is a small launcher that starts the main program in `data\bin` next to it. When you made a symbolic link to it somewhere else and started the app from that link, the launcher looked for `data\bin` next to the link, showed an error saying the main program could not be found, and did not start. It now follows the link and looks next to the real file. Starting from a shortcut (.lnk) was never affected.

" < > |` を打ったり、これらを含む文字列を貼り付けたりすると、これまではそのまま入り、名前の変更ダイアログでは警告が出て OK を押せなくなり、一覧の上でその場で書き換えたときは確定した時点で失敗していました。いまはエクスプローラーと同じく、これらの文字は打っても入らず、貼り付けた文字列からは取り除いて残りだけを入れます。取り除いたときは、入力欄の下に「ファイル名には次の文字は使えません」と使えない文字の一覧を数秒間出します。名前の変更ダイアログ（名前の欄・拡張子の欄）と、一覧の上でのその場の書き換えの両方が対象です。全角の `？` や `：` はこれまでどおり使えます。予約名（`CON` など）や末尾のドット・空白は、これまでどおり警告で知らせます。

### Fixed

- **画面を切り替えたあと、リングランチャーの一部が欠けたままになることがあったのを直しました (#385)** 〔先行版 1.17.2.1〕 — リングランチャーは速く出すために、閉じた窓を捨てずに隠しておき、次に開くときに使い回しています。外部モニタの抜き差しや投影の切り替えで画面の構成が変わると、隠していた窓の大きさが画面の拡大率と合わなくなり、輪の右や下が欠けて出ることがありました。窓を使い回しているかぎり直らないので、アプリを再起動するまで欠けたままでした。いまは画面の構成が変わったら、次に開くときに窓を作り直します。開いた窓の大きさが画面の拡大率と合わないときも、その場で作り直してから表示します。

- **バッチファイルやスクリプトを開いたとき、同じフォルダのファイルを相対パスで読めなかったのを直しました (#388)** 〔先行版 1.17.2.3〕 — Zenith Filer からファイルを開くと、開いたアプリの作業フォルダが Zenith Filer の置き場所のままになっていました。そのため、PowerShell を呼ぶバッチファイルなどで `Get-Content list.txt` のように同じフォルダのファイルを名前だけで読もうとすると、「パスが存在しない」と言われて失敗していました。いまはエクスプローラーと同じく、開くファイルのあるフォルダを作業フォルダにします。ファイル一覧のダブルクリックと Enter・お気に入り・最近使ったファイル・右クリックの「開く」「編集」・指定したテキストエディターで開くとき、どれも同じです。
- **ターミナルのプロンプトや Claude Code の出力に出たパスが、クリックできるリンクにならなかったのを直しました (#390)** 〔先行版 1.17.2.3〕 — 画面に出たパスに下線が付き、クリックでフォルダを開ける機能がありましたが、いちばんよく目にするコマンドプロンプトの `C:\work\proj>` は、末尾の `>` のせいでパスと見なされず、下線が付きませんでした。Claude Code が出す `Read(Views/Foo.cs)` や `Update(src/a.cs:12)` の形も、括弧の前の語ごとパスとして調べてしまい、リンクになりませんでした。いまはプロンプトは `>` の手前（後ろに打ったコマンドが続いていても同じ）、Claude Code の形は括弧の中のパスだけをリンクにします。長いパスが画面の幅で 2 行に折り返されている場合は、これまでどおりつながったパスとしては扱えません。
- **ワーキングセットを呼び出したとき、Box や SharePoint などのフォルダがデスクトップに化けることがあったのを直しました (#391)** 〔先行版 1.17.2.3〕 — 呼び出した瞬間に登録したフォルダが見つからないと、そのタブをデスクトップ（B ペインの 1 枚目はダウンロード）に差し替えていました。Box Drive や OneDrive は同期の準備ができるまでフォルダ自体が見えないため、起動した直後や同期の再開中に呼び出すと、ちゃんと登録したはずのフォルダがデスクトップになっていました。そのまま「上書き」すると、登録までデスクトップに書き換わっていました。いまは見つからないフォルダも差し替えず、登録したパスのタブに「この場所はまだ利用できません。接続を待っています…」と出し、フォルダが現れたらそのまま開きます（2 秒ごとに確かめ、2 分で待つのをやめます。やめたあともタブは登録したパスのままです）。外付けドライブをあとからつないだ場合や、登録したドライブの直下（`D:\` など）も同じです。通知には「まだ見つからないフォルダ N 件は、現れたら開きます」と出ます。起動したときのタブの復元の扱いは変えていません。

- **Shift を押しながら Enter でファイルを開けなかったのを直しました (#393)** 〔先行版 1.17.2.4〕 — Access のデータベース（.mdb / .accdb）は、Shift を押しながら開くと自動実行や起動時の設定を飛ばして開けます。Zenith Filer でもダブルクリックならそれができましたが、Enter で開くときは Shift を押していると何も起きませんでした。「開く」が修飾キーなしの Enter にだけ割り当たっていて、Shift+Enter はどの操作にも当たっていなかったためです。いまはエクスプローラーと同じく、Shift を押しながら Enter でも開きます。Shift はそのまま開いた先のアプリに伝わるので、Access なら自動実行を飛ばして開きます。キーの設定で「開く」を別のキーに変えている場合は、そのキーに Shift を足した打鍵で同じように開きます。その打鍵をほかの操作に割り当てているときは、そちらが優先されます。

- **シンボリックリンクから起動すると「本体が見つかりません」になったのを直しました (#381)** 〔先行版 1.17.2.5〕 — Zenith Filer の `ZenithFiler.exe` は、同じフォルダの `data\bin` にある本体を起動する小さな起動用の EXE です。この EXE を指すシンボリックリンクを別の場所に作ってそこから起動すると、リンクを置いた場所に `data\bin` を探しに行ってしまい、「本体が見つかりません」と出て起動できませんでした。いまはリンクから起動されたときも、リンクの先の実体があるフォルダから本体を探します。ショートカット（.lnk）からの起動は、これまでどおり問題ありません。

- **Zenith Filer から開いた画像を、フォトで左右キーで送れなかったのを直しました (#396)** 〔先行版 1.17.2.7〕 — 画像を開くと、Windows のフォトなどで ← → を押しても同じフォルダの次の画像へ進めませんでした。エクスプローラーから開いた場合は進めます。エクスプローラーはファイルと一緒に「同じフォルダの、表示中の並び順の一覧」もアプリに渡していますが、Zenith Filer はファイル 1 つだけを渡していたためです。いまは画像と動画を開くとき、同じフォルダの画像と動画の一覧をタブの並び順（名前・更新日時・サイズ・種類と、昇順／降順）で渡すので、Zenith Filer で見ている順番どおりに送れます。名前の並びは 2 の次に 10 が来る数字の順です。動画を送れるかは、開くアプリによります。Shift を押しながら開いたとき、複数のファイルをまとめて開いたとき、Box やネットワークの場所で一覧の用意に時間がかかったときは、これまでどおりファイルだけを渡して開きます。

> 過去の変更履歴は [Releases](https://github.com/sulkyjp/zenithFiler_update/releases) を参照してください。
