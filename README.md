## Latest Changes — [1.11.1] - 2026-08-19 : Moved to .NET 10, with hash verification, batch timestamp changes and Claude hand-off

### Added

- **Added a way to confirm that a downloaded file is identical to the one the publisher released.** Select a file and choose **Compute and verify hash** from **More ▶** in the context menu: a dedicated window opens and starts calculating straight away. **SHA-256 (default), SHA-1, MD5 and CRC-32** are supported. The main way to use it is to **paste the hash published on the download page** into the field at the top — the verdict appears immediately, and **the algorithm is detected from the length of what you pasted**, so there is nothing to select by hand. Case and surrounding whitespace are ignored, and values followed by a file name (`sha256sum` output), values with a `SHA256:` label, values split into groups by spaces, and values separated by `-` or `:` can all be pasted as they are — a mismatch caused by formatting looks exactly like a corrupted download, so none of those are turned away. **Select exactly two files and it reports whether their contents are identical**, which holds even when their names or timestamps differ. Any number of files can be processed at once, and **Copy** puts the results on the clipboard as `file name <TAB> hash`, ready to paste into a spreadsheet. A multi-gigabyte file is never loaded into memory in full; a progress bar is shown while the work runs and **Stop** ends it at any point. If a file cannot be read, only that row shows the reason and the remaining files are still processed. Free to use.

- **Added a way to change file timestamps and attributes in bulk.** Select files or folders and choose **Batch timestamp and attributes** from the context menu (next to batch rename); the **pen icon that appears when you hover over the modified, created or attributes row** in the properties pane opens it too. You can change the **created, modified and accessed** timestamps (each selectable on its own) and the **read-only, hidden and archive** attributes (each set, cleared or left alone). The value can be decided in four ways: **current time, a specific date and time, match the creation time, or match the modification time.** Matching the creation time is aimed at photos and downloads that ended up with the download moment as their modification time. Dates accept `20260819`, `0819` or `2026/8/19` and times accept `0930`, `09:30` or `9:30:45` — the same flexible formats as the search date filter — and **the time is optional, defaulting to midnight**. The heart of it is that **you can check the resulting values in the list before applying**: only the entries that actually change are highlighted in colour and bold, and the footer reads "M of N items will change", so **a setting that changes nothing is visible right away**. Items already holding the target value are not counted. A fifth option, **match the date taken**, applies the date recorded in a photo's EXIF data to the modification time and friends — for photos whose modification time became the moment they were downloaded or copied. **Files without a date taken are left untouched**, so mixing photos and other files in one selection is safe; the EXIF data itself is never rewritten, since that risks damaging the image. Afterwards **`Ctrl+Z` restores the previous values** — only what this operation actually changed. Timestamps cannot be written while the read-only attribute is set, so the app clears it temporarily and restores it behind the scenes. The free version allows 3 uses.

- **Added a way to hand the selected file paths straight to the built-in terminal or Claude Code.** **Send selection to Claude** and **Insert selection paths into the terminal** were added under **More ▶** in the context menu. The first inserts the selected paths into the input field of Claude Code running in the built-in terminal, written **relative to the working directory, one per line** (anything outside it falls back to an absolute path). The second inserts them into a plain terminal prompt as **absolute paths separated by spaces**, quoting only those that contain spaces. Until now this took two steps — `Ctrl+Shift+C` and then a paste. **It only inserts; it never runs anything.** Adding instructions and pressing Enter is your own action, and because **file changes Claude makes cannot be undone with `Ctrl+Z`** (they fall outside the app's undo history), a notification says so each time. The terminal in the pane you are working in is preferred, falling back to the navigation pane's terminal; if neither is open the app **does not open one on its own**, it just tells you to. Beyond 100 items the path list is written to a file and only that file's path is inserted, so the input field does not become unmanageable.

### Changed

- **Updated the bundled .NET runtime from 8 to 10.** Zenith Filer ships the .NET runtime inside the app, so runtime updates can only reach you through a rebuild and a new release — Windows Update cannot change it. The .NET 8 runtime it used to bundle **reaches end of support on 10 November 2026**, after which it stops receiving security fixes. The .NET 10 runtime it now bundles is a long-term support release with fixes provided **through November 2028**. Everything needed to run the app is still bundled, so you do not need to install .NET yourself. The download grows by a few MB. The database component the app relies on was also swapped for a build in which a known vulnerability is fixed.

### Fixed

- **Fixed some settings reverting to their defaults every time the app was closed.** The bulk save that runs on exit rebuilt the settings from an empty object and then listed the values to carry over one by one, so **anything missing from that list was reset on every exit**. 16 of 205 settings were affected: **the automatic day/night theme switch (both themes and both times), the navigation pane layout presets and the preset applied at startup, which entries the tab management menu shows (close / lock / related / working set), the challenge and level banners and the badge dots, which tips you had dismissed, and the automatic restore of per-folder tab display settings** — all silently lost ever since they were added in March 2026 (the remaining one is a legacy field no longer in use). The exit save now **starts from the values currently on disk** and overwrites only what the main window owns, so those 16 are restored and **no setting added in the future can be dropped on exit**.

## 最新の変更履歴 — [1.11.1] - 2026-08-19 : .NET 10 へ移行し、ハッシュ照合・タイムスタンプ一括変更・Claude 連携を追加

### Added

- **ダウンロードしたファイルが配布元のものと同じか確かめられるようにした:** ファイルを選び、独自コンテキストメニューの「その他の操作 ▶」から**「ハッシュを計算・照合」**を実行すると、専用のウィンドウが開いてその場で計算が始まる。**SHA-256（既定）／SHA-1／MD5／CRC-32** に対応する。配布元サイトに載っているハッシュ値を上部の欄に**貼り付けるだけで一致・不一致が出る**のが主な使い方で、**アルゴリズムは貼り付けた値の桁数から自動的に判別する**ので選び直す必要はない。大文字小文字と前後の空白は無視するほか、ファイル名が後ろに続く形式（`sha256sum` の出力）・`SHA256:` のようなラベル付き・4 桁ごとに空白で区切った形式・`-` や `:` 区切りも、そのまま貼り付けられる（書式の違いで「不一致」と出ると、壊れたファイルを掴んだようにしか見えないため）。**ファイルを 2 つ選ぶと、その 2 つが同じ内容かを判定する**（名前や更新日時が違っていても中身で確かめられる）。何件でも同時に計算でき、結果は「コピー」で `ファイル名 <タブ> ハッシュ値` の形式でクリップボードに入るので表計算ソフトにそのまま貼れる。数 GB のファイルでも全体をメモリに載せず、計算中は進捗バーが出て「中止」でいつでも止められる。読み取れないファイルが混ざっていても、その行に理由が出るだけで残りは計算を続ける。無料で使える

- **ファイルの日時と属性をまとめて変更できるようにした:** ファイルやフォルダを選び、独自コンテキストメニューの**「タイムスタンプ・属性の一括変更」**（一括リネームの隣）から開く。プロパティペインの**更新日時・作成日時・属性の各行にマウスを乗せると出るペンアイコン**からも開ける。変更できるのは**作成日時 / 更新日時 / アクセス日時**（個別に選択可）と、**読み取り専用 / 隠しファイル / アーカイブ**の属性（それぞれ「変更しない」「付ける」「外す」）。日時の決め方は**現在時刻 / 指定した日時 / 作成日時に合わせる / 更新日時に合わせる**の 4 つ。「作成日時に合わせる」は、写真やダウンロードしたファイルの更新日時が取得時刻になってしまったときに元へ揃える用途を想定している。日付は `20260819` / `0819` / `2026/8/19`、時刻は `0930` / `09:30` / `9:30:45` のいずれの形式でも入力でき（検索の日付フィルタと同じ）、**時刻は省略でき 0 時 0 分**になる。**実行前に一覧で変更後の値を確認できる**のが要で、実際に変わる項目だけを色と太字で示し、フッターに「N 件中 M 件が変更されます」と出す（**何も変わらない指定になっていればその場で分かる**）。既に同じ値の項目は変更対象に数えない。決め方にはもう 1 つ**「撮影日時に合わせる」**があり、写真の EXIF に記録された撮影日時を更新日時などへ反映できる（ダウンロードやコピーで更新日時が取得時刻になってしまった写真を撮影順に並べ直す用途）。**撮影日時を持たないファイルは変更しない**ので、写真とそれ以外を一度に選んでも安全。EXIF そのものの書き換えは画像を壊す危険があるため行わない。実行後は **`Ctrl+Z` で元に戻せる**（戻るのはこの操作で実際に変更した項目だけ）。読み取り専用のままでは日時を書き込めないため、一時的に属性を外して書き込み元に戻す処理を内部で行う。無料版では 3 回まで

- **選択したファイルのパスを、内蔵ターミナルや Claude Code へその場で渡せるようにした:** 独自コンテキストメニューの「その他の操作 ▶」に**「選択項目を Claude に渡す」**と**「選択項目のパスをターミナルに挿入」**を追加した。前者は内蔵ターミナルで動いている Claude Code の入力欄へ、選んだアイテムのパスを**作業フォルダからの相対パス・改行区切り**で差し込む（作業フォルダの外は絶対パス）。後者は素のターミナル入力欄へ**絶対パス・空白区切り**で差し込み、空白を含むパスだけ二重引用符で囲む。これまでは `Ctrl+Shift+C` でコピーしてから貼り付ける 2 手が必要だった。**差し込むだけで実行はしない。** 指示を書き足して Enter を押すのはご自身の操作で、**Claude が行ったファイル操作は `Ctrl+Z` で戻せない**（アプリの取り消し履歴の管理外）ため、差し込んだ時点でその旨を通知する。渡し先は操作しているペインのターミナルが優先で、閉じていればナビペインのターミナルへ回る。どちらも開いていなければ**勝手に開かず**、開くようお知らせするだけにしている。100 件を超える選択ではパス一覧をファイルへ書き出し、そのファイルのパスだけを差し込む（入力欄が長大になるのを避けるため）

### Changed

- **アプリが同梱する .NET ランタイムを 8 から 10 に更新した:** Zenith Filer は .NET ランタイムを丸ごと同梱して配布しているため、ランタイムの更新は**再ビルドと再配布でしか届かない**（お使いの Windows Update では変わらない）。同梱していた .NET 8 は **2026 年 11 月 10 日でサポートが終了**し、以降はセキュリティ修正が出なくなる。新しく同梱する .NET 10 は長期サポート版で、**2028 年 11 月まで**修正が提供される。動作に必要なものはこれまでどおりすべて同梱しているので、お使いの環境に .NET を入れる必要はない。配布物の容量は数 MB 増える。あわせて、データベースまわりで使っている外部部品を、既知の脆弱性が修正されたものへ入れ替えた

### Fixed

- **一部の設定が、変更してもアプリを終了すると既定値に戻ってしまう問題を修正:** 終了時の一括保存は「空の設定を組み立て直し、引き継ぐ項目を 1 つずつ書き並べる」方式だったため、**書き並べ忘れた項目は終了のたびに既定値へ戻っていた**。実測で 205 項目中 16 項目が該当し、**昼夜でテーマを自動で切り替える設定（切替先のテーマ 2 つと時刻 2 つ）／ナビペインのレイアウトプリセットと起動時に適用するプリセット／タブ管理メニューに出す項目（閉じる・ロック・関連・ワーキングセット）／チャレンジとレベルのバナー表示とバッジの点／「今後表示しない」にしたヒントの記憶／フォルダ別のタブ表示設定の自動復元** が、2026 年 3 月に追加されて以来ずっと消え続けていた（残り 1 つは現在は使われていない旧形式の項目）。**保存の基点をディスク上の現在値に反転**し、メインウィンドウが持っている項目だけを上書きする形に変えたので、16 項目が元に戻ると同時に、**今後どこに設定を足しても終了時に消えることは構造的に起こり得なくなった**
