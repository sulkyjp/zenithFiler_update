## Zenith Filer in 4 Lines / 4 行でわかる Zenith Filer

- ⚡ **Fast** — starts in about 1 second, every operation runs asynchronously. Optimized on real measurements to stay snappy even on antivirus-laden corporate PCs<br>**速い** — 起動約 1 秒・全操作を非同期化。ウイルス対策ソフトで重い社用 PC でも軽快に動くよう実測ベースで最適化

## Latest Changes — [1.16.2] - 2026-09-21 : Nav panes can be detached into their own windows and snapped together, and lingering theme previews along with several click and search problems are fixed

### Added

- **Nav panes can now be detached into their own windows (#342)** — Keeping a nav pane open has always cost you width in the A and B panes, so you were stuck choosing between the two. The detach button at the top right of the nav pane (left of the ∨) turns it into a standalone window. While it is detached, the main window folds away the space it used, so **the A and B panes get that width back** — move the window to a second display and you can keep the nav pane in view without giving up any of the file list. **The left and right nav panes detach independently**, and a terminal keeps its session across the move. Shortcuts from the main window still work inside the detached window, except while you are typing into the terminal or into a text field, where the keys are left alone. To bring a pane back, press the button in the same spot in the detached window — its icon changes to a pane shape — or simply close the window. Position and size are remembered, so **quitting with a pane detached brings it back detached next time**. While a pane is detached, the key that shows and hides it shows and hides that window instead.
- **Windows placed side by side now stick together and move as one (#342)** — A detached nav pane would not snap to the screen edges at all; the maximize you get at the top edge is Windows' own doing. It now settles into edges and corners the same way the main window does. Windows also snap to **each other**: line up the left nav pane, the main window and the right nav pane with no gaps between them, and **dragging any one of them brings the whole set along**. To pull a single window out of a set, **hold Alt while dragging** — a reminder appears when you start moving one, so there is nothing to memorise. Snapping works for stacked layouts too, and joining an edge lines up the **top or bottom edges** at the same time. So that windows do not grab each other in passing, a join needs at least **24 px of overlap** along the shared edge. All of it is tied to Settings → General → "Snap window to screen edges", which now covers both screen edges and other windows. Note that **crossing between displays with different scaling can leave a gap**, since the windows change size and sizes are not matched up.

### Fixed

- **Colours you were only trying out could stay applied (#325)** — "Customise colours" and "Adjust with AI" both **paint the app as you go**, so you can see what you are doing. Reverting, however, **only hung off the Cancel and × buttons**. Close the window any other way — `Alt+F4`, `Esc`, the taskbar, the system menu — and **whatever you were trying out stayed on screen**. It then sat there until a theme was applied in full again, which in normal use means **until the next restart**. That is what was behind reports of a theme looking right except for one thing, such as address bar text too dark to read. Reverting now happens in **one place on the way out**, so an unsaved window **always reverts however you close it**. In the AI window, closing without saving also deleted the preview file while leaving its theme applied, leaving **a theme with a name but nothing behind it**; that is fixed too.
- **A per-pane theme could come back after you turned it off (#325)** — Switching Settings → Theme away from "Per pane" was meant to drop the colours applied to each pane. The clearing step, though, **never reached the container the theme itself sits in**. Switch back to "Per pane" and **the old theme returned to that pane alone**, out of step with the rest of the app. Clearing now empties the pane completely.
- **Every theme change piled up another set of colours (#325)** — When swapping in a new set of colours, the app **only remembered one previous set**. There are **five places to paint** — the app plus four panes — so once a pane had been painted, changing the overall theme left the previous set behind instead of removing it. The newest set wins, so nothing looks wrong, but **the pile grows with every change and only clears on restart**. In the theme modes that **switch on their own** — "Pick automatically" and "Switch by time" — it grows for as long as the app is open. Each place now remembers its own previous set, so a swap **always replaces it**. Applying a single changed colour was landing in the wrong place for the same reason when a pane had just been painted; that is fixed as well.
- **The first click after switching back to the app did nothing (#341)** — Coming back from another app, clicking **an item in the navigation pane** or the **Restart button** in the update notice did nothing, and **you had to click a second time**. The app was **pulling keyboard input back to the file list the instant the window came to the front**. When you click an inactive window, Windows **sends a wake-up message first and only then delivers the button press**. Moving keyboard input at that first moment makes the button you are pressing **let go of its pressed state**, so releasing the mouse never completes the click. The toolbar, tabs, search box and terminal were unaffected because they sit **inside the very pane** the input was being pulled to. When the window is woken by a click, input is **no longer moved straight away** — it is restored only if the click landed nowhere. Coming back with `Alt+Tab`, from the taskbar or with the hotkey still returns input to the file list as before.
- **Clicking directly on a folder's name in the tree raised an internal error (#343)** — In the nav pane's tree, clicking **the text of a folder name** — as opposed to its icon or the empty part of the row — raised an error inside the app, and that click's drag detection was lost with it. The code that walks up from the spot you clicked did not allow for **text being a different kind of element** from everything around it: it belongs to the document, not to the on-screen parts the walk expected. The same walk was used elsewhere, so the **tab list, tab reordering and the theme colour list** — all of which could have hit this — are fixed along with it.
- **In a narrow pane, the × in the search history was cut off and could not be clicked (#337)** — The history suggestions open at **the same width as the search box**, so in a narrow pane the × at the right end of each row fell outside the frame and could not be reached (reported from a Full HD screen split in two). Rows carrying conditions — preset, size, date — put even more in the line, which pushes the × further out. The search bar now **drops to a second row automatically whenever a single row cannot fit it**. On its own row it gets the full width of the pane, so the × is always in reach. If you have Settings → Display → "Search Bar Second Row" switched on yourself, nothing changes for you.
- **Popups left open were stranded when the window was moved (#337)** — A popup such as the search history **does not follow the window**. Move the window by its title bar with one open and it stays behind at the old spot — and the filter popups (scope, size and so on) do not close when you click outside them, leaving you stuck. They now **close when the window moves**. This covers the search history, scope, size, date and preset popups, the address bar suggestions and the breadcrumb's subfolder list.

## 最新の変更履歴 — [1.16.2] - 2026-09-21 : ナビペインを別ウィンドウへ切り離して並べられるようにし、テーマのプレビューが残る問題とクリック・検索まわりの不具合を直した

### Added

- **ナビペインを別のウィンドウに切り離せるようにしました (#342)** — ナビペインは**出しておきたいのに、出すと A ペイン・B ペインが狭くなる**という板挟みがありました。ナビペイン右上の切り離しボタン（∨ の左）を押すと、ナビペインが**独立したウィンドウ**になります。切り離している間は本体側の枠が畳まれるので、**A ペイン・B ペインがそのぶん広がります**。拡張ディスプレイへ移してしまえば、ナビペインを出したままファイル一覧を最大限に使えます。**左と右はそれぞれ独立して切り離せ**、ターミナルを開いたままでも移せます（セッションは切れません）。切り離した窓の中でも**本体のショートカットはそのまま効きます** —— ただしターミナルに打ち込んでいるときと、検索欄などで文字を入力しているときは、キーを横取りしません。本体へ戻すには、切り離した窓の**同じ位置にあるボタン**（アイコンが枠の形に変わります）を押すか、窓を閉じます。窓の位置と大きさは覚えているので、**切り離したまま終了すれば、次に起動したときも切り離した状態**で出てきます。切り離している間にナビペインの表示キーを押すと、その窓の**表示・非表示**が切り替わります。
- **並べたウィンドウが吸い付いて、まとめて動くようになりました (#342)** — 切り離したナビペインは**画面の端に吸い付きませんでした**（上端まで持っていくと最大化されるのは Windows 側の動きです）。本体と同じように、端や四隅へ近づけるとぴたりと収まります。あわせて**ウィンドウ同士も吸い付く**ようにしました。ナビ左・本体・ナビ右を隙間なく並べられ、**くっついた一式は、どれを動かしても全部が付いてきます**。1 枚だけ引き離したいときは **Alt を押しながらドラッグ**します（くっついた窓を動かし始めると画面にも出るので、覚えておく必要はありません）。吸着は上下の並びでも働き、辺がくっつくと同時に**上端どうし・下端どうしも揃います**。通りすがりに吸い付いてしまわないよう、並んでいると認めるには**接する辺に 24px 以上の重なり**が要ります。入／切は設定 →「一般」→「ウィンドウを画面端にスナップする」で、端への吸着とウィンドウ同士の吸着をまとめて切り替えます。なお**表示倍率の違うディスプレイをまたぐと、窓の大きさが変わるぶん並びに隙間が空くことがあります**（大きさまでは合わせません）。

### Fixed

- **色を試しただけのつもりが、その色が当たったまま残る問題を修正しました (#325)** — テーマの「色をカスタマイズ」と「AI で調整」は、いじっている間ずっと**画面に当てて見せる**つくりです。ところが元へ戻す処理が**「キャンセル」と「×」のボタンにしか付いていません**でした。どちらも押さずに `Alt+F4`・`Esc`・タスクバー・システムメニューから閉じると、**試していた色がそのまま残ります**。残った色は次にテーマを丸ごと当て直すまで居座るので、ふつうに使っているぶんには**再起動するまで直りません**。アドレスバーの文字だけが暗くて読めない、といった「テーマは変えていないのに一部だけおかしい」状態は、これで起きていました。元へ戻す処理を**閉じる経路の 1 か所**にまとめ、保存していなければ**どんな閉じ方でも必ず戻る**ようにしました。AI の調整画面では、戻さずに閉じると仮試着用のファイルだけが消えて**名前だけ残って中身の無いテーマ**になっていたのも直しています。
- **ペインごとのテーマをやめても、前のテーマが戻ってくる問題を修正しました (#325)** — 設定 →「テーマ」で「ペインごと」から他のモードへ切り替えると、ペインに当てた色は消えるはずでした。ところが**中身を空にする処理が、テーマ本体の入っている入れ物には届いていません**でした。そのままもう一度「ペインごと」に戻すと、**外したはずの古いテーマがそのペインだけに甦り**、全体のテーマと食い違ったままになります。空にする範囲を直し、外したら**中身ごと消える**ようにしました。
- **テーマを替えるたびに、内部の色の置き場が積み上がる問題を修正しました (#325)** — 色の置き場を差し替えるとき、**前回のぶんを 1 つしか覚えていません**でした。全体用とペイン 4 枚ぶんで**置き場が 5 つある**ため、ペインに色を当てたあとに全体のテーマを替えると、前回のぶんが外れずに残ります。見た目は新しいほうが勝つので気づきませんが、**替えるたびに増え続け、再起動するまで減りません**。テーマの「自動選択」「時刻で切り替え」のように**勝手に替わるモード**では、使っているあいだずっと積み上がります。置き場ごとに覚えるようにして、**必ず前回のぶんと入れ替わる**ようにしました。あわせて、色を 1 つだけ変える差分の反映が、**直前にペインを塗っていると別の置き場へ書き込まれていた**のも直しています。
- **アプリが後ろに回っているとき、1 回目のクリックが効かない問題を修正しました (#341)** — 他のアプリを使ったあとに戻ってきて、**ナビペインの項目**や、更新のお知らせの**【再起動】ボタン**を押しても反応せず、**もう一度押さないと効きません**でした。ウィンドウが手前に出た瞬間に、**キーボードの入力先をファイル一覧へ引き戻していた**のが原因です。Windows はクリックで後ろのウィンドウを起こすとき、**先に「起きろ」の合図を送り、そのあとでボタンの押下を届けます**。その合図の時点で入力先を動かすと、押している最中のボタンが**押されている状態を手放してしまい**、指を離してもクリックが成立しません。ツールバー・タブ・検索欄・ターミナルが平気だったのは、引き戻す先とクリック先が**同じペインの中**だったためです。クリックで起こされたときは**入力先をすぐに動かさず**、クリックがどこにも届かなかったときだけ戻すようにしました。`Alt+Tab` やタスクバー、呼び出しキーで戻ったときにファイル一覧へ入力先が戻る動きは、これまでどおりです。
- **ツリーでフォルダ名の文字の上をクリックすると、内部でエラーが出ていた問題を修正しました (#343)** — ナビペインのツリーで、**フォルダ名の文字そのもの**を左クリックしたときだけ内部でエラーが起き、そのクリックのドラッグ判定が失われていました。アイコンや行の余白を押したときは起きず、**文字の上だけ**です。押した場所から要素をたどっていく処理が、**文字を描く部品は他の部品と種類が違う**（画面上の部品ではなく文章の部品として扱われる）ことを見ていなかったのが原因でした。同じたどり方をしている場所を全部洗い、**タブ一覧・タブの並べ替え・テーマの色一覧**でも同じことが起こりうる状態だったので、まとめて直しています。
- **ペインが狭いと、検索履歴の × が見切れて押せなかったのを直しました (#337)** — 検索履歴の候補は**検索ボックスと同じ幅**で出るため、ペインが狭いと行の右端にある × が枠からはみ出して押せませんでした（フル HD を 2 分割した環境からの報告です）。条件（プリセット・サイズ・日付）の付いた履歴があると横に並ぶものが増えるぶん、いっそう届かなくなります。**1 段では収まらない幅のときは、検索バーを自動で 2 段目へ下ろす**ようにしました。2 段目ならペインの幅をいっぱいに使えるので、× まで届きます。設定 →「表示」→「検索バー 2段目表示」を自分で入れている場合の動きはこれまでどおりです。
- **ポップアップを開いたままウィンドウを動かすと、その枠だけ取り残されたのを直しました (#337)** — 検索履歴などの小窓は**ウィンドウの移動に付いてきません**。開いたままタイトルバーで動かすと元の場所に浮いたまま残り、しかもスコープやサイズなどの絞り込みの小窓は**外側を押しても閉じない**ため、そのまま操作できなくなっていました。**ウィンドウを動かしたら閉じる**ようにしています。対象は検索履歴・スコープ・サイズ・日付・プリセット・アドレスバーの候補・パンくずの下階層です。

## Feedback & bug reports / フィードバック・不具合報告

Please send requests and bug reports from **inside the app**: **Settings → Feedback**.

要望・不具合は、**アプリ内の「設定 → フィードバック」**からお送りください。

| Why from inside the app / アプリから送っていただきたい理由 |
|---|
| Replies come back to you in the app's **Feedback history**, so you actually get an answer<br>作者からの回答が**アプリ内の「フィードバック履歴」に届きます** |
| When a fix ships, the app asks whether it is fixed — a report is followed through to the end<br>修正版が出ると「直った／まだ直っていない」を知らせるボタンが出るので、**最後まで追えます** |
| It reaches me directly. This repository only hosts the release files and is not a support channel<br>確実に届きます。このリポジトリは配布物を置くためだけのもので、問い合わせ窓口ではありません |
