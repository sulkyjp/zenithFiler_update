## Latest Changes — [1.10.2] - 2026-07-28 : Fixed UI hangs, thread leaks, and shutdown failures on corporate PCs (Box Drive + EDR environments); fixed content clipping while maximized and Theme Store re-rating/upload notification issues

### Fixed
- **Fixed the app becoming unresponsive for seconds to tens of seconds when clicking folders on corporate PCs (Box Drive + EDR environments).** Analysis of on-device logs showed that the "open in Explorer" / "open file" commands' enabled-state check and execution both ran a cloud-sync path existence check and app launch synchronously on the UI thread; the enabled-state check was especially costly since it re-evaluates on every keystroke and click. All of this was moved to background threads so the UI thread is never blocked by it.
- **Fixed the app's internal thread count growing without bound while navigating cloud-synced folders on corporate PCs (Box Drive + EDR environments).** The component that reads cloud storage's right-click menu items spawned a dedicated thread on every folder navigation; when the shell extension stopped responding, that thread could never be reclaimed, so the count kept climbing the longer the app was used. Added a cap on the number of threads that can be in flight at once, silently skipping new ones once the cap is reached.
- **Fixed the selected item disappearing — making the list look like the cursor had jumped back to the top — while browsing a Box or other cloud-synced folder.** When a cloud-sync change notification triggered an automatic list reload, a combination of "was something selected before the reload" and "did the user interact during the reload" logic ended up skipping the restore even though the selection had, in fact, already been lost. The list now restores the previous selection whenever the current selection is empty, regardless of intervening input, and the auto-reload interval for cloud-synced folders was also widened to reduce how often this churn happens in the first place.
- **Fixed the app becoming unresponsive after closing on corporate PCs (Box Drive + EDR environments), with the next launch reporting that the previous session did not exit cleanly.** Analysis of on-device logs showed that the window-close handler (which saves settings) could run multiple times for a single close action; the second and later runs then blocked the UI thread waiting for the first run's save to finish, sometimes for a very long time. Users who ran out of patience and force-closed the app via Task Manager then saw a crash reported on the next launch. Added a re-entrancy guard to the close handler so the save logic runs exactly once per close action, and consolidated a duplicate debounced-save flush call into one.
- **Fixed the terminal tabs' (A/B pane) embedded browser component not being disposed on app exit.** The exit handler already disposed the other preview browser component but skipped the terminal one, contributing to a slower shutdown. Added the missing disposal call to the exit handler.
- **Fixed the v1.10.1 fix for the spurious gray band around the app while maximized causing the opposite problem on some monitor setups and maximize paths (such as maximizing across a monitor move): the window edge could now spill off-screen, clipping a few pixels off the title bar, the outer border, and the bottom status bar.** The previous fix always treated the "overhang" — the amount a maximized window extends past the monitor's work area — as zero. On some paths, such as maximizing while moving across monitors, the underlying overhang was never actually eliminated, so forcing the compensation to zero anyway just pushed that amount off-screen, clipping the content. The app now measures the actual window position against the work area every time it maximizes, and compensates edge by edge with the real overhang amount — zero when there is none, the exact difference when there is — so no monitor or maximize path produces either a spurious band or clipped edges anymore.
- **Fixed being unable to change a Theme Store rating once you'd rated it once — pressing the stars again had no visible effect.** Re-rating did submit to the server, but the average-rating value driving the star display was only recomputed the first time you rated a theme, so from the second rating onward the stars stayed put until the next list refresh, making it look like the rating couldn't be changed. Re-rating now subtracts your previous score and adds the new one, recalculating the displayed average immediately.
- **Fixed the completion toast sometimes not appearing after uploading a custom theme to the Theme Store, leaving no way to tell whether the upload actually succeeded.** The upload progress bar (GlowBar) occupied the same screen area as the completion toast, so the toast's display timer could run out while the progress bar was still covering it, making the notification disappear before — or without ever — becoming visible. The success/failure toast is now shown only after the progress bar has fully closed.

## 最新の変更履歴 — [1.10.2] - 2026-07-28 : 社用PC（Box Drive + EDR環境）でのUIハング・スレッドリーク・終了失敗を修正、最大化時の外周欠け・テーマストアの★再評価とアップロード完了通知を修正

### Fixed
- **社用PC（Box Drive + EDR環境）でフォルダをクリックしても反応がなくなる・数秒〜数十秒固まる問題を修正:** 実機ログを解析した結果、エクスプローラーで開く／ファイルを開くボタンの有効・無効判定と実行処理が、クラウド同期パスに数秒かかることのある「フォルダの存在確認」と「アプリ起動」を UI スレッド上で同期実行しており、キー入力やクリックのたびに繰り返し評価される判定処理が特に影響していた。これらをすべてバックグラウンドスレッドへ退避し、UI スレッドを一切ブロックしないようにした
- **社用PC（Box Drive + EDR環境）でクラウド同期フォルダを行き来しているうちに、アプリ内部のスレッドが際限なく増え続ける問題を修正:** クラウドストレージの右クリックメニュー項目を読み取る内部処理が、フォルダ移動のたびに専用スレッドを生成しており、シェル拡張が応答しなくなった場合にそのスレッドを回収できず、使い続けるほど増え続けていたことが判明した。同時に動けるスレッド数に上限を設け、上限に達した場合は新規生成を見送るようにした
- **Box 等のクラウド同期フォルダで一覧を操作している最中に、選択中の項目が消えてカーソルが一覧の先頭に戻ったように見える問題を修正:** クラウド同期の更新通知を受けて一覧が自動的に再読込されると、直前まで選択されていた項目や操作中だったという判定が働いてしまい、実際には選択が失われているにもかかわらず元の選択を復元しない、という組み合わせが起きていた。選択が既に失われている場合は、直前の操作の有無にかかわらず選択を復元するよう修正し、あわせてクラウド同期フォルダでの自動再読込の間隔を広げて頻度そのものも抑えた
- **社用PC（Box Drive + EDR環境）で終了操作後にアプリが応答しなくなり、翌起動時に前回セッションが正常終了しなかったと表示される問題を修正:** 実機ログを解析した結果、ウィンドウを閉じる際の終了処理（設定保存）が1回の終了操作で複数回実行されてしまい、2回目以降の処理が1回目の保存完了を待ち続けることで UI スレッドが長時間ブロックし、待ちきれずタスクマネージャー等で強制終了した結果、翌起動時にクラッシュとして検知されていたことが判明した。終了処理に再入防止のガードを追加し、1回の終了操作につき保存処理が1回だけ実行されるようにした。あわせて、重複していたデバウンス保存のフラッシュ呼び出しを1回に整理した
- **アプリ終了時にターミナルタブ（A/Bペイン）の内部ブラウザーコンポーネントが破棄されずに残っていた問題を修正:** 終了処理で他のプレビュー用ブラウザーコンポーネントは破棄していたが、ターミナル機能のものは対象外になっていたため、プロセスの終了処理を遅らせる一因になっていた。終了処理に破棄呼び出しを追加した
- **v1.10.1 で対処した「最大化時にアプリ外周へ出るグレーの帯」の修正が、一部のモニタ環境・最大化経路（モニタ間移動を伴う最大化等）では逆にウィンドウの端が画面からはみ出し、タイトルバーや外周線・下部のステータスバーが数ピクセル見切れてしまう問題を修正:** 前回の修正は、最大化時にウィンドウが画面の作業領域からはみ出すぶんの補正を常にゼロとして扱う実装だったが、モニタをまたいだ最大化などの一部の経路ではそもそものはみ出し自体が解消されておらず、補正がゼロのままだとその分がそのまま画面外に押し出されてコンテンツの欠けとして現れていた。最大化のたびに実際のウィンドウ位置と作業領域を都度比較し、はみ出しがあればその分だけを、なければゼロを、辺ごとに正確に補正するように改めた。これによりプライマリ・セカンダリを問わずどのモニタで最大化しても外周の欠けや余計な帯が出なくなる
- **テーマストアで一度★評価すると、再度★を押しても評価を変更できなかった問題を修正:** 星を押し直すとサーバーへの送信自体は行われていたが、画面上の星の表示に使う平均評価の値が初回評価時にしか再計算されておらず、2回目以降は星の見た目が変わらないままだった（次回の一覧更新まで反映されず、事実上「変更できない」ように見えていた）。再評価時も直前の自分の点数を差し引いてから新しい点数を加算し、その場で平均評価を正しく再計算するようにした
- **自作テーマをテーマストアへアップロードした際、完了を知らせる通知が表示されないことがあった問題を修正:** アップロード中に表示される進捗バー（GlowBar）が、完了通知の表示エリアと同じ場所を使っていたため、進捗バーが閉じきる前に通知の表示タイマーが進んでしまい、実際に画面に見える前後で通知が消えてしまっていた。進捗バーが完全に閉じてから完了・失敗の通知を表示するよう順序を修正した
