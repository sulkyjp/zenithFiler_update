## Latest Changes — [1.12.0] - 2026-08-20 : Added FTP / SFTP support, folder compare & sync, archives, and a command palette

### Added

- **Added a way to match up the folders open in pane A and pane B and list where they differ.** Open it from the compare button on the action bar. **The comparison itself is read-only and never modifies a file** — nothing is written unless you explicitly run the sync described below. You can compare by **size only, size and modification time (default), or contents (hash)**. Each row is marked as identical, only-on-the-left, only-on-the-right, contents-differ, or case-differs, and **the markers differ in shape so you never have to rely on colour alone**. **Identical items are hidden by default** — you came to look at the differences, and showing everything buries them — but they are always included in the counts along the bottom. The matching itself carries the fixes that long-standing sync tools learned the hard way. **Modification times within 2 seconds are treated as identical**, because USB drives and NAS store timestamps at a coarser resolution and a strict comparison marks every file as different. **An exact one-hour gap is flagged as a likely daylight-saving artefact** rather than a content difference. **Names differing only in letter case are not silently treated as identical**, since some environments handle them as two separate files. File names coming from macOS are matched correctly too. Folders that tend to flood the result, such as `node_modules` and `.git`, are excluded by default and the pattern list is fully editable. **A folder blocked by permissions does not stop the comparison, and is not silently reported as zero either** — it says "N folders could not be read" so you know the result is incomplete. Shortcuts (junctions and symbolic links) are not followed by default, since following them can count the same file twice or loop forever.

- **Added a way to bring pane B into line with pane A, straight from the comparison result.** Run it with **Sync A → B** in the comparison window. **It is one-way only, and the pane A side is never modified** — two-way syncing needs conflict resolution and makes the shape of a mistake impossible to predict, so it is deliberately left out. **Before anything happens you are shown the breakdown — N to copy, M to overwrite, K to delete — and asked to confirm.** **Items that exist only on the right are not deleted by default**: deletion is the mistake the word "sync" invites most easily, so removing them requires **ticking a checkbox on purpose**. **Overwriting and deleting cannot be taken back on their own**, so the original files are moved to a backup folder first, and **a single `Ctrl+Z` reverts the whole run** (copied files disappear again, and overwritten or deleted files come back with their contents). Five generations of backups are kept under the app's data folder. Progress is shown while it runs, and a file that cannot be read or written **does not stop the rest** — the number of failures is reported at the end. Comparing is free; the sync is limited to 3 uses in the free version.

- **Archive extraction and compression are now built into the app.** An **Archive ▶** submenu was added to the **top level** of the right-click menu, gathering extraction, compression and verification in one place. **Its contents swap depending on what you selected.** With only archives selected you get **extraction commands alone** (*Extract...*, *Extract here*, *Extract to "(name)\"*, *Extract to pane (A/B)*, *Test archive*); with anything else selected you get **compression commands alone** (*Compress...*, *Compress to "(name).zip"*, *Compress each to its own ZIP*, *Create ZIP in pane (A/B)*). Showing both at all times would mean reading the list every time to work out which half currently applies. **Where the destination is already decided, the resulting folder or file name is shown in the command itself**, so you can read what will happen before pressing — folders carry a trailing `\` so they are distinguishable from files. **Being able to target the other pane** is something only a two-pane file manager can offer — no extracting and then copying. **Test archive writes nothing at all**: it reads the archive through to the end so you can tell whether a download was truncated before you extract it. Until now this meant Shift-right-clicking to reach the OS menu and calling 7-Zip from there — and on a machine without 7-Zip installed, there was nothing to call. **ZIP, TAR and TAR.GZ (.tgz)** can be extracted; **ZIP** can be created. 7z and rar are **deliberately not built in**: the components that read them are large and complex, and serious vulnerabilities are found in them nearly every year. Bundling one would make its vulnerabilities Zenith Filer's vulnerabilities, so 7z and rar are left to Explorer's own support (Windows 11 24H2 and later) or to your installed copy of 7-Zip. **What is built in uses only components that ship with Windows — no external component was added.** **Extracting means opening contents you did not write**, so the following protections are in place. (1) **Nothing is ever written outside the destination** — the classic trick of a crafted name containing `..\` to write into a parent or system folder is blocked by resolving each real path and checking it stays inside. (2) **Shortcut (symbolic link) entries are discarded unconditionally** — harmless-looking in themselves, they become the foothold that lets later files be written outside the destination. (3) **An archive whose contents expand abnormally is cut off part-way**, so a small file cannot keep expanding until it fills the disk; extraction stops the moment more data arrives than the archive declared. (4) **Windows reserved names** such as `CON` and `NUL`, and **alternate data streams** hidden in a file name (`readme.txt:other content`), are rejected. (5) **The total extracted size is checked against the free space before anything is written.** (6) **Contents are checked against the checksum recorded in the archive** — structure surviving intact does not mean the data did, and a corrupted file extracted under a healthy-looking name is the worst outcome; files that fail the check are removed rather than left behind, and the summary says what went wrong. **Existing files are not overwritten by default** — they are saved under a new name. When a name collides you get the same confirmation used for copying, offering overwrite, skip or rename. **Garbled names in older ZIPs are handled too**: a ZIP without the UTF-8 marker is read using your system's code page, the same way Explorer and 7-Zip do it. Both extraction and compression show progress, and **`Ctrl+Z` puts things back afterwards** — only what the operation created is removed, leaving what was already there and anything you added yourself after extracting. **Extracting is free to use**, since gating it would break the daily routine of anyone moving over from another file manager. Creating a ZIP is limited to 3 uses in the free version.

- **Added key map presets, so another file manager's key layout can be applied in one go.** A preset switcher now sits at the top of **Shortcut Keys** in settings, with two presets included: **Total Commander style** (`F5` copy, `F6` move, `F7` new folder, `F8` delete, `Shift+F6` rename, `F3` quick preview, `Ctrl+R` refresh) and **Explorer style** (`Backspace` goes back, `Alt+Up` goes to the parent). The Explorer preset looks like a small change, but it closes the divergence people trip over first: **`Backspace` means "up" in Zenith and "back" in Windows Explorer.** For someone moving over, **an app whose every feature is present but whose keys their fingers do not know is closed within minutes** — this exists to close that gap. **The breakdown is always shown before you press**: how many assignments will change, how many of those replace assignments you changed yourself, and — if any key would end up shared by two actions after applying — which combinations those are (a setting disappearing quietly is the worst outcome). **Anything the preset does not mention is left completely alone.** Other file managers have no keys corresponding to Zenith's own features (AI, macros, themes), so those keep their current assignment, and your own individual customizations survive there too. **"Zenith standard" puts everything back at any time**, so trying a preset costs nothing. Presets are JSON in the data folder, like themes and language files, so dropping one file into `data\keymaps\` adds a preset of your own.

- **Copy to the other pane, move to the other pane, and open in a text editor can now be bound to keys.** These are the staple two-pane operations, corresponding to Total Commander's `F5`, `F6` and `F4`. The transfer runs through exactly the same path as drag and drop, so the name-collision prompt, the progress display and `Ctrl+Z` all work as usual. **None of them are bound to a key by default** — `F5` currently means Refresh, and taking it would betray the fingers of anyone coming from Explorer. Apply the Total Commander preset above, or assign whatever keys you like in settings.
- **The shortcut settings page gained a pinned search bar and jump links to each group.** With over 50 bindable actions across five groups, **finding a particular key meant scrolling**. A bar that stays in place while you scroll now sits at the top of the page, holding a filter and links to each group (built the same way as the ones on the achievements page). **The filter works in both directions**: type "copy" and you get `Ctrl+C`, and conversely **type `Ctrl+D` and you can see what that key is currently used for** — the direction you need when hunting for a free key. Omitting the `+`, as in `ctrlc`, still finds `Ctrl+C`. Separating words with a space narrows to entries containing all of them (full-width spaces work too), and descriptions and group names are searched as well. **While filtering, the remaining count is shown as "3 of 52"**, so when nothing matches you can tell "there is none" apart from "the filter is wrong". The group links in the bar are likewise reduced to the groups that survived the filter.
- **Added a command palette for finding and running any action by name.** Open it with `Ctrl+Shift+P` or the **≡** button at the right of the title bar. **Every action is reachable by name, whether or not it has a key bound to it.** Shortcuts mean "the common actions have keys", not "every action can be reached from the keyboard" — so anything without a key had to be hunted down with the mouse. It serves the purpose of the menu bar found at the top of a conventional file manager, but **occupies no screen space at all** (the top already carries five rows — title bar, tabs, toolbar, search bar, breadcrumb — and permanently claiming a sixth sits badly with speed being the app's identity). **Everything is listed under group headings**, and the filter works from the action name, its description, or the key. **The current binding is shown at the right of each row**, so using the palette teaches you the shortcuts. `Up` / `Down` selects, `Enter` runs, `Esc` closes. Pane-dependent actions apply to **whichever pane was active when the palette opened.**

- **The navigation pane layout preset shortcut moved from `Ctrl+Shift+P` to `Ctrl+Shift+J`**, freeing `Ctrl+Shift+P` for the command palette above. `Ctrl+Shift+P` is the command palette key across VS Code, Sublime Text, Windows Terminal and others, and letting fingers trained elsewhere work here is worth more. If you have customized this shortcut yourself, your setting is left untouched.

- **You can now register SFTP, FTP, and FTPS servers and verify that they connect.** A **Sites view** has been added to the nav pane. Register a server's name, host, port, user name, authentication method (password or private key), and initial folder, then use the **Test connection** button to confirm it actually connects (double-clicking a row does the same). The icon at the start of each row **distinguishes encrypted connections (SFTP / FTPS) from plain FTP**. **Passwords and passphrases are stored so that only this Windows user can decrypt them** — settings carried over to another PC or account cannot be decrypted, so they have to be re-entered there. **Private keys are never copied; only the file location is remembered**, because every extra copy of a key is one more thing to hunt down and delete later. Leaving the port empty uses the standard port for the protocol (22 for SFTP, 21 for FTP, 990 for FTPS), and leaving the display name empty uses the host name. Leaving the user name empty connects as anonymous FTP. **For SFTP, the host key fingerprint is shown for approval on the first connection and then recorded.** If a different key ever appears, **the connection is stopped** — the server may simply have been rebuilt, but the connection may also have been redirected elsewhere, and only you can tell those apart, so the app will not quietly reconnect. FTPS certificates are validated by default, and there is no setting to accept them unconditionally. **Connections are opened only when you use them and dropped automatically once they sit idle** (nothing happens at startup, and a connection in the middle of a transfer is never dropped).

- **You can now open a registered server's folders in pane A or B.** Double-click a row in the Sites view, or use the open button, and the server's folder appears in the pane you are working in. Entering folders, going up a level, and jumping to a level from the breadcrumb all work as they do locally. Because **the files have no local counterpart on this PC**, icons come from the name and extension rather than the file itself, and thumbnails are never fetched (each one would trigger a download). For the same reason the folder is not watched for outside changes. **A folder that could not be reached is never shown as an empty one** — the reason is reported instead. Double-clicking a remote file does not open it; it has to be brought to your PC first.

- **You can now bring files from a server to your PC.** Drag from a pane showing a remote folder onto a pane showing a local one. Choosing a folder brings its whole contents. Progress is measured in **bytes rather than file count**, so a single large file does not look stuck. **When a file of the same name already exists you can overwrite, keep both, or skip** — the same confirmation used for local copies. **Timestamps are taken from the server**, so the files sort in their original order rather than by when you fetched them. **A file that failed or was cancelled part-way is deleted** — a half-sized file left behind as if it had arrived is the worst outcome. Once finished, `Ctrl+Z` undoes the transfer. If a name the server returned cannot be used as a Windows file name (contains `..`, uses forbidden characters, and so on), **that item alone is skipped and the count is reported**. **Local-to-local copies still take exactly the same path as before** — only transfers involving a remote side take the separate route.

- **You can now act on files on the server: upload, delete, rename, and create folders.** Dragging from a local pane onto a pane showing a remote folder **uploads**. Choosing a folder sends the whole tree, creating intermediate folders as needed. The same-name confirmation (overwrite / keep both / skip), the byte-level progress, and the clean-up of partly written files all work as they do for downloads. **Deleting does not go through a Recycle Bin and cannot be undone** — servers have no Windows Recycle Bin, so the confirmation says so plainly. **Renaming can be undone with `Ctrl+Z`** (it runs over the network, so it is not waited on at the moment you press it). **Creating a folder asks for the name first** — locally the app creates a default-named folder and then renames it, but doing that remotely costs two round trips (three if you cancel and it has to be deleted), and on a slow link that difference is pure waiting. **Server-to-server transfers are not supported**; bring the files to your PC first, then send them.

- **A pane showing a remote folder is now recognizable at a glance.** Deleting on a server **does not go through a Recycle Bin and cannot be undone**, so treating a remote pane as if it were your PC turns straight into an accident. Three signals now make it obvious before you act: the **tab icon becomes a server icon** (so you can tell which of several tabs is remote), a **`SFTP` / `FTP` / `FTPS` badge appears at the start of the address bar** (so you know what you are connected over without reading the path), and the **pane gets an accent-colored outline** (so you can tell which pane is the server from across the screen). **Plain FTP alone is shown in a warning color** — it sends passwords and file contents in the clear, so it does not get to look like SFTP or FTPS. Panes showing local folders are unchanged.

- **The Sites view now has a right-click menu.** Right-clicking a row offers: open in the pane, open in pane A, open in pane B, edit, test connection, and delete. **The row you right-clicked becomes the selected one**, so the row you are looking at is always the row being acted on. Right-clicking empty space offers adding a site and refreshing the list.

- **A brief network drop no longer restarts a transfer from the beginning.** If the connection breaks mid-transfer, the app resumes **from what was already received (or sent)**. It retries up to three times per file, with a growing pause between attempts. **Only connection-side failures are retried** — no permission, no such path, or a failed login are given up on immediately, since repeating them only spends the wait. When resuming an upload, the app **asks the server how much actually landed** rather than trusting its own count. The progress bar never moves backwards across a retry.

- **You can now change permissions on files on the server.** Select remote items, right-click, and choose "Change permissions". Read / write / execute for owner, group, and others are toggled in a grid. The dialog shows **both the numeric form (`644`) and the symbolic form (`rw-r--r--`) at once** — administrators quote either one, and showing only one means converting in your head to check. It can be applied to a multi-item selection. The current value is re-read from the server each time the dialog opens, so a value changed elsewhere is never shown as the starting point.

- **You can now set the file name encoding for FTP.** A "File name encoding" setting has been added to each site (Automatic / UTF-8 / Shift_JIS). **Automatic is correct for most servers**, but servers that do not advertise UTF-8 can garble non-ASCII file names, and this is where you fix that. The setting does not apply to SFTP, where names are always UTF-8.

- **Fixed being unable to reach FTP servers that sit behind NAT.** Such servers can answer a passive-mode request with **a private address that is unreachable from outside**, which showed up as a puzzling failure: the login succeeds, but listings and transfers hang and then time out. When the address the server hands back turns out to be unreachable, the app now **connects to the same host as the control connection instead**. The switch happens once per connection and is kept across reconnects. In addition, operations that are **safe to repeat** — such as fetching a listing — are now retried a few times when a data connection cannot be established, which does happen intermittently on busy public servers. Deleting and renaming are not retried automatically, because the first attempt may already have done something.

### Fixed

- **Fixed two shortcuts that were each bound to two different actions.** `Ctrl+Shift+E` was assigned to both "focus the active pane" and "open in Explorer", and `Ctrl+Shift+W` to both "switch to two panes" and "working set quick access". **When two actions share a key, only whichever is evaluated first ever runs** — pressing the key did nothing for the other one. For E, the Explorer association was kept and "focus the active pane" moved to `Ctrl+Shift+H`; for W, the one-pane (`Ctrl+Shift+Q`) / two-pane pairing was kept and "working set quick access" moved to `Ctrl+Shift+S`. If you have customized these shortcuts yourself, your settings are left untouched.
- **Fixed instability when running PC-folder features while a cloud listing (Box) was open.** A Zenith Filer pane can show things that have no counterpart on your PC — most notably **Box opened directly inside the app**. Running features that read and write local files in that state — **Grep search, CSV / Excel export, batch timestamp changes, handing the selection to the terminal** — could **fail with an error or stop responding** (and sometimes did nothing at all, silently). A check for whether the target really exists now sits at the entrance to each such feature, and where the feature cannot work it **stops and says why**. When a selection mixes real and non-existent items, the feature **continues with the real ones** rather than refusing outright (having one stray item disable the whole feature is worse). Existing features that already made the same check were routed through the same gate, so **no future feature can quietly miss it**.

### Added

- **A ペインと B ペインのフォルダを突き合わせて、違いを一覧で見られるようにした:** 上部のアクションバーの比較ボタンから開く。**比較そのものは読み取り専用で、ファイルを変更することはない**（書き込むのは、下記の「揃える」を明示的に実行したときだけ）。比較の方法は**サイズのみ／サイズと更新日時（既定）／内容（ハッシュ）**の 3 つ。結果は行頭のしるしで「同じ・左にしかない・右にしかない・中身が違う・名前の大小だけ違う」を示し、**色だけに頼らずしるしの形でも区別できる**ようにしている。**一致した項目は既定で隠す**（差を見に来ているので、全部出すと目的の行が埋もれるため）が、画面下部の件数には必ず含めるので隠れていても数は分かる。判定には、長年使われている同期ツールが踏んできた落とし穴への対策を入れた。**更新日時の 2 秒以内のずれは同一として扱う**（USB メモリや NAS は時刻の刻みが粗く、そのまま比べると毎回全ファイルが「違う」と出てしまう）。**ちょうど 1 時間のずれは「夏時間の可能性」として区別**する（中身が違うわけではないと分かるように）。**名前の大文字小文字だけが違う場合も黙って同一にしない**（環境によっては 2 つの別ファイルとして扱われるため）。macOS 由来のファイル名も同じ名前として扱う。`node_modules` や `.git` のように差分を埋め尽くしがちなフォルダは既定で対象から外し、除外パターンは自由に足し引きできる。**権限で読めないフォルダがあっても止まらず、かつ黙って 0 件にもしない** —「N 個のフォルダを読み取れませんでした」と出して結果が不完全であることを伝える。ショートカット（ジャンクション・シンボリックリンク）は既定で辿らない（二重に数えたり循環したりするため）

- **比較した結果を見ながら、A ペインの内容に合わせて B ペインを揃えられるようにした:** 比較結果の画面の**「A → B へ揃える」**から実行する。**片方向のみで、A ペイン側は決して書き換わらない**（双方向の同期は競合の解決が要り、事故の形が読めなくなるため入れていない）。**押す前に「コピー N 件・上書き M 件・削除 K 件」の内訳を出し、確認してから実行する。** **右にしかない項目は既定では消さない** —「揃える」の語感で消えるのが最も事故になりやすいため、消す場合は**チェックボックスで明示的に指定**する必要がある。**上書きと削除は、それ自体では取り返しがつかない操作**なので、実行前に元のファイルの実体を退避フォルダへ移しておき、**`Ctrl+Z` 1 回で今回揃えた分を全部元に戻せる**ようにした（コピーしたものは消え、上書き・削除したものは中身ごと戻る）。退避はアプリのデータフォルダ配下に 5 世代残す。実行中は進捗が出て、途中で読めない・書けないファイルがあっても**そこで止まらず残りを続け**、終わったあとに何件失敗したかを伝える。比較は無料で使えるが、揃える操作は無料版では 3 回まで

- **アーカイブの展開・圧縮をアプリに内蔵した:** ファイルを右クリックして出る独自メニューの**第一階層**に **「アーカイブ ▶」** を追加し、展開・圧縮・テストの操作をここにまとめた。**中身は選んだものによって入れ替わる。** アーカイブだけを選んでいるときは**展開の項目だけ**（「展開...」「ここに展開」「『（名前）\』に展開」「（もう一方の）ペインに展開」「アーカイブをテスト」）、それ以外を選んでいるときは**圧縮の項目だけ**（「圧縮...」「『（名前）.zip』に圧縮」「個別に ZIP へ」「（もう一方の）ペインに ZIP を作成」）が並ぶ。両方を常に並べると、いま押せるのがどちらなのかを毎回読んで判断することになるためで、**行き先が決まっている項目は、できるフォルダ名・ファイル名をそのまま見出しに出す**（押す前に何ができるのかが読めるように。フォルダになるものは末尾に `\` を付けてファイルと区別できるようにしている）。**もう一方のペインを行き先にできる**のは 2 画面のファイラーならではで、いちいち展開してからコピーする手間が要らない。**「アーカイブをテスト」は 1 バイトも書かずに**中身を最後まで読み切り、ダウンロードが途中で切れていないかを展開前に確かめる。これまでは Shift を押しながら右クリックして OS 標準メニューを出し、そこから 7-Zip などを呼ぶ必要があり、**7-Zip を入れていない環境では何もできなかった**。展開できるのは **ZIP / TAR / TAR.GZ（.tgz）**、作れるのは **ZIP**。7z や rar は**あえて内蔵していない** — それらを読み書きする部品は仕組みが大きく、毎年のように深刻な脆弱性が見つかっている。同梱すればその脆弱性がそのまま Zenith Filer の脆弱性になるため、7z / rar は Windows 11 24H2 以降の Explorer 標準機能か、お使いの 7-Zip に任せる方針にした（**内蔵分は Windows に元から入っている部品だけで書いており、外部の部品は 1 つも増やしていない**）。**展開は、送られてきた中身を信用せずに開く操作**なので、次の対策を入れてある。①**展開先の外へは 1 バイトも書かない**（`..\` を含む細工されたファイル名で親フォルダやシステムフォルダへ書き込ませる古典的な手口を、展開先の内側かどうかの実パス照合で塞ぐ）②**ショートカット（シンボリックリンク）の項目は無条件で捨てる**（それ自体は無害に見えて、後続のファイルを展開先の外へ書き込ませる足場になる）③**中身が異常に膨らむアーカイブは途中で打ち切る**（小さな圧縮ファイルがディスクを埋め尽くすまで展開され続けるのを防ぐ。宣言されたサイズより多く出てきた時点で止める）④`CON` や `NUL` のような**Windows の予約名**、ファイル名に紛れ込ませた**代替データストリーム**（`readme.txt:別の中身`）を弾く ⑤**展開後の合計サイズが入るかを、書き始める前に空き容量と突き合わせる** ⑥**中身が化けていないかを、アーカイブに記録された検査値と突き合わせる**（構造が無事なら中身が壊れていても展開自体は通ってしまうため。合わないファイルは置かずに消し、何が駄目だったかを伝える）。**既存ファイルは既定で上書きしない**（別名で保存する）。同じ名前のものがあるときは、コピー時と同じ確認画面が出て「上書き・スキップ・別名」を選べる。**日本語 Windows で作られた古い ZIP の文字化けにも対応**した（UTF-8 の目印が無い ZIP はお使いの環境の文字コードで読む。Explorer や 7-Zip と同じ挙動）。展開・圧縮とも進捗が出て、**終わったあとは `Ctrl+Z` で元に戻せる**（この操作で作られたものだけが消え、元からあったものや、展開後にご自身で置いたものは残る）。**展開は無料でお使いいただける**（他のファイラーから移ってこられた方の日常が回らなくなるため）。ZIP を作る操作は無料版では 3 回まで

- **他のファイラーの操作体系をまとめて当てられる「キーマッププリセット」を追加した:** 設定の**「ショートカットキー」**の先頭にプリセットの切り替えを置き、**Total Commander 風**（`F5` でコピー、`F6` で移動、`F7` でフォルダ作成、`F8` で削除、`Shift+F6` で名前の変更、`F3` でクイックプレビュー、`Ctrl+R` で更新）と**エクスプローラー風**（`Backspace` で「戻る」、`Alt+↑` で「上へ」）の 2 つを同梱した。エクスプローラー風は既定との差が小さく見えますが、**Zenith では `Backspace` が「上へ」なのに対し Windows のエクスプローラーでは「戻る」**という、移ってきた方がいちばん最初につまずく食い違いを埋めます。移ってきた方にとって**機能がすべて揃っていても、指が動かないアプリは数分で閉じられる**ので、そこを埋めるための機能です。**押す前に必ず内訳が出ます** —「何件の割り当てが変わるか」「そのうち何件がご自身で変更した割り当てを置き換えるか」を確認画面に出し、当てたあとに同じキーが重なる場合はその組み合わせも一緒に示す（設定が黙って消えるのが一番の事故のため）。**プリセットが指定していない操作には一切手を出しません。** 他のファイラーには Zenith 固有の機能（AI・マクロ・テーマ）に当たるキーが無いので、そこは今の割り当てがそのまま残り、ご自身で個別に変更した割り当ても生き残ります。**「Zenith 標準」を押せばいつでも元に戻せる**ので、気軽に試せます。プリセットはテーマや言語ファイルと同じくデータフォルダの JSON なので、`data\keymaps\` に 1 ファイル置くだけで独自のプリセットを増やせます

- **「反対ペインへコピー」「反対ペインへ移動」「テキストエディタで開く」をショートカットに割り当てられるようにした:** 2 画面ファイラーの定番操作で、Total Commander の `F5` / `F6` / `F4` に当たります。転送はドラッグ＆ドロップとまったく同じ経路を通るので、同じ名前のファイルがあるときの確認画面・進捗・`Ctrl+Z` での取り消しもそのまま使えます。**既定ではどのキーにも割り当てていません** — `F5` は現在「更新」で、Explorer から来た方の指を裏切ってしまうためです。上記の Total Commander 風プリセットを当てるか、設定画面で好きなキーを割り当ててください
- **ショートカット設定に、上部固定の検索バーとグループへのジャンプを追加した:** 割り当てられる操作は 50 を超え 5 グループに分かれているため、**目的のキーを探すのにスクロールが必要**でした。ページ上部にスクロールしても消えないバーを新設し、そこに絞り込みとグループへのリンク（実績ページのものと同じ作り）を置きました。絞り込みは**名前からでもキーからでも引けます** —「コピー」と打てば `Ctrl+C` が出ますし、逆に **`Ctrl+D` と打てばそのキーが今どの操作に使われているかが分かります**（空いているキーを探すときに要る方向です）。`ctrlc` のように `+` を省いても、`Ctrl+C` に当たります。空白で区切ると複数の語すべてを含むものだけに絞られ（全角空白でも同じ）、説明文やグループ名でも引けます。**絞り込み中は残った件数を「3 / 52 件」の形で出す**ので、0 件になったときに「無い」のか「絞り込めていない」のかが分かります。バーに並ぶグループのリンクも、絞り込みで残っているグループだけになります
- **すべての操作を名前で探して実行できる「コマンドパレット」を追加した:** `Ctrl+Shift+P` か、タイトルバー右の **≡** ボタンで開きます。**割り当てられたキーがあるかどうかに関係なく、すべての操作へ名前で辿り着けます。** ショートカットは「よく使う操作にキーが割り当ててある」であって「全部の操作がキーで届く」ではないため、キーの無い操作はマウスで探すしかありませんでした。一般的なファイラーの上部メニューバーに当たる導線ですが、**画面を 1px も常時占有しません**（上部はすでにタイトルバー / タブ / ツールバー / 検索バー / パンくずで 5 段あり、6 段目を常時使うのは「速さがアイデンティティ」という方針と噛み合わないため）。**グループ見出し付きで全操作が一覧され**、絞り込みは操作名・説明・キーのどれからでも効きます。**各行の右端に現在の割り当てが出る**ので、パレットを使っているうちにショートカットを覚えられます。`↑` `↓` で選び `Enter` で実行、`Esc` で閉じます。ペインに関わる操作は、**パレットを開いた時点でアクティブだったペイン**に効きます

- **ナビペインのレイアウトプリセットのショートカットを `Ctrl+Shift+P` から `Ctrl+Shift+J` に変更した:** `Ctrl+Shift+P` を上記のコマンドパレットに譲るためです。`Ctrl+Shift+P` は VS Code・Sublime Text・Windows ターミナルなど多くのアプリで**コマンドパレットのキー**として共通していて、他所で覚えた指がそのまま動く価値のほうが大きいと判断しました。ショートカットをご自身で変更されている場合、その設定はそのまま残ります

- **SFTP・FTP・FTPS のサーバーを登録し、接続を確かめられるようにした:** ナビペインに**接続先ビュー**を追加した。サーバー名・ホスト・ポート・ユーザー名・認証方式（パスワード／秘密鍵）・初期フォルダを登録でき、下部のボタンから**接続テスト**を実行して、実際につながるかをその場で確かめられる（行のダブルクリックでも走る）。一覧の行頭アイコンで**通信が暗号化される接続（SFTP / FTPS）と平文の FTP を見分けられる**ようにした。**パスワードとパスフレーズは、この Windows ユーザーだけが復号できる形で保存する**（別の PC やユーザーへ設定を持ち込むと復号できないため、その場合は入力し直しになる）。**秘密鍵は複製せず、ファイルの場所だけを覚える** — 鍵の実体を増やすと、あとで消して回る対象が増えるため。ポートを空欄にすると選んだプロトコルの標準の番号（SFTP は 22、FTP は 21、FTPS は 990）を使い、表示名を空欄にするとホスト名がそのまま名前になる。ユーザー名を空欄にすると FTP では匿名接続になる。**SFTP のホスト鍵は初回に指紋を見せて承認を求め、承認した指紋を記録する。** 次回以降に違う鍵が出てきたときは**接続を止める** — サーバーを作り直しただけのこともあるが、接続先がすり替えられている可能性もあり、その区別は利用者にしか付けられないため、黙ってつなぎ直すことはしない。FTPS の証明書も既定で検証し、無条件に受け入れる設定は用意していない。**接続は使うときに初めて張り、しばらく使わなければ自動で切る**（起動時には何もしない。転送中の接続は切らない）。

- **登録したサーバーのフォルダを A / B ペインで開けるようにした:** 接続先ビューの行をダブルクリックするか、フォルダを開くボタンで、操作中のペインにサーバーのフォルダが出る。フォルダを開く・上の階層へ戻る・パンくずで途中の階層へ飛ぶ、といったローカルと同じ操作ができる。**リモート側にはファイルの実体がこの PC に無い**ため、アイコンは名前と拡張子から決まる標準のものになり、サムネイルは取りに行かない（1 件ごとにダウンロードが走ってしまうため）。同じ理由で、フォルダの監視（ほかのアプリによる変更の自動反映）も行わない。**繋がらなかったときに空のフォルダとして見せない** — 理由を出す。リモートのファイルをダブルクリックしても開かない（先にパソコンへ取り込む必要がある）

- **サーバーのファイルをパソコンへ取り込めるようにした:** リモートを開いたペインから、パソコン側のペインへドラッグ＆ドロップする。フォルダを選べば中身ごと取り込む。進捗はファイル数ではなく**バイト単位**で出す（1 件が巨大なときに止まって見えないため）。**同名のファイルがあるときは、上書き・別名で残す・飛ばすを選べる**（ローカル同士のコピーと同じ確認画面）。取り込んだファイルの**更新日時はサーバー側に合わせる**ので、取り込んだ順ではなく元の順で並べ替えられる。**途中で失敗・中止したファイルは消す** — 中途半端な大きさのファイルが取り込めたものとして残るのが最も困るため。取り込んだあとは `Ctrl+Z` で取り消せる。サーバーが返した名前がそのままでは Windows のファイル名にできない場合（`..` を含む、使えない文字がある等）は**その項目だけ飛ばして件数を伝える**。**ローカル同士のコピーはこれまでどおりの経路**で、リモートが絡む転送だけが別の道を通る

- **サーバー側のファイルを操作できるようにした（送信・削除・名前の変更・フォルダの作成）:** パソコン側のペインからリモートを開いたペインへドラッグ＆ドロップすると**送信**します。フォルダを選べば階層ごと送り、途中の階層は自動で作ります。同名があるときの確認（上書き・別名で残す・飛ばす）と、バイト単位の進捗、失敗時の書きかけの後始末は取り込みと同じです。**削除はごみ箱を経由せず、元にも戻せません** — Windows のごみ箱はサーバー側には無いため、確認の文言でその旨をはっきり伝えます。**名前の変更は `Ctrl+Z` で戻せます**（ネットワーク越しの処理なので、押した時点では待たずに走ります）。**フォルダの作成は先に名前を尋ねます** — ローカルは「既定の名前で作ってから変える」流れですが、リモートで同じことをすると往復が 2 回（取り消すとさらに削除で 3 回）になり、遅い回線ではその差がそのまま待ち時間になるためです。**サーバー間の直接転送には対応していません**（いったんパソコンへ取り込んでから送ってください）

- **リモートを開いているペインが、ひと目で分かるようにした:** リモートの削除は**ごみ箱を経由せず元に戻せない**ため、「パソコンのつもりで操作した」がそのまま事故になる。押す前に分かるよう、3 つの合図を出す。**タブのアイコンがサーバー型**になり（複数タブを並べたときにどれがサーバーか分かる）、**アドレスバーの先頭に `SFTP` / `FTP` / `FTPS` のバッジ**が出て（何で繋いでいるかがパスの文字列を読まなくても分かる）、**ペインの外周にアクセント色の縁**が付く（離れて見てもどちらのペインがサーバーか分かる）。**平文の FTP だけは警告色**にしている — FTP はパスワードもファイルの中身もそのまま流れるので、SFTP / FTPS と同じ見た目にはしない。パソコン側のペインの見た目はこれまでどおり変わらない

- **接続先ビューを右クリックでも操作できるようにした:** 行を右クリックすると、ペインで開く / A ペインで開く / B ペインで開く / 接続先を編集 / 接続テスト / 削除が出る。**右クリックした行がその場で選択される**ので、見ている行と操作される行が食い違わない。何も無い場所を右クリックすると、接続先を追加 / 一覧を更新が出る

- **転送が回線の瞬断で最初からやり直しにならないようにした:** 転送の途中で接続が切れた場合、**受け取った（または送れた）ところから続き**を試みます。同じファイルにつき最大 3 回まで、待ち時間を刻んで伸ばしながら試します。**やり直すのは回線側の失敗だけ**で、権限が無い・パスが無い・認証に失敗したといった「いつやっても同じ結果になるもの」は即座に諦めます（同じ失敗を待ち時間ぶん繰り返しても意味が無いため）。送信をやり直すときは、**こちらが送ったつもりの量ではなくサーバーに実際に届いている量を聞き直して**から続きを送ります。進捗のバーは、やり直しの前後で戻らないようにしてあります

- **サーバー上のファイルのアクセス権を変更できるようにした:** リモートの項目を選んで右クリック →「アクセス権を変更」。所有者・グループ・その他の読み取り／書き込み／実行を格子で切り替えます。**数字（`644`）と記号（`rw-r--r--`）の両方を同時に表示**します — 管理者から指示される形はどちらもありうるので、片方だけだと突き合わせに変換が必要になるためです。複数選択にまとめて適用できます。現在の値は開くたびにサーバーへ聞き直すので、ほかから変更されていても古い値が初期表示になることはありません

- **FTP のファイル名の文字コードを指定できるようにした:** 接続先の設定に「ファイル名の文字コード」を追加した（自動 / UTF-8 / Shift_JIS）。**自動のままで大半のサーバーは正しく読めます**が、UTF-8 を名乗らない国内のサーバーでは日本語のファイル名が化けることがあり、その場合に指定します。SFTP には無い設定です（SFTP の名前は UTF-8 と決まっているため）

- **NAT の内側に置かれた FTP サーバーに繋がらない問題を修正:** 自身が NAT の内側にある FTP サーバーは、受動モードの応答に**外から到達できない私設アドレス**を書いて返すことがあります。この場合、ログインはできているのに一覧も転送も待たされた末にタイムアウトする、という理由の分かりにくい失敗になっていました。サーバーが返した接続先へ到達できないと分かった時点で、**制御接続と同じ相手へ繋ぎ直す**ようにしました。切り替えは 1 接続につき一度だけ行い、以降は繋ぎ直しても同じ方式を使います。あわせて、一覧の取得のように**やり直しても副作用が無い操作**は、データ接続が張れなかったときに数回まで自動でやり直すようにしました（利用者の多い公開サーバーでは、受動接続が間欠的に張れないことが実際にあります）。削除や名前の変更は、1 回目で何かが起きたかもしれないため自動ではやり直しません

### Fixed

- **同じショートカットキーが 2 つの操作に割り当てられていた問題を修正:** `Ctrl+Shift+E` が「アクティブペインへフォーカス」と「エクスプローラーで開く」の両方に、`Ctrl+Shift+W` が「2 画面に切り替え」と「ワーキングセットのクイックアクセス」の両方に割り当てられていました。**同じキーに 2 つ載っていると、先に判定された側しか動きません**（もう一方は押しても何も起きない状態でした）。E は「エクスプローラー」の連想が強い側を残して「アクティブペインへフォーカス」を `Ctrl+Shift+H` へ、W は 1 画面（`Ctrl+Shift+Q`）と 2 画面の対を崩さないよう「ワーキングセットのクイックアクセス」を `Ctrl+Shift+S` へ移しました。ショートカットをご自身で変更されている場合、その設定はそのまま残ります
- **クラウド表示（Box）を開いているときに、パソコン上のフォルダ向けの機能を実行すると不安定になる問題を修正:** Zenith Filer のペインには、パソコン上のフォルダだけでなく **Box をアプリ内で直接開いた表示**のように、パソコン上に実体が無いものも表示されます。この状態で **Grep 検索・CSV / Excel の書き出し・一括タイムスタンプ変更・選択項目をターミナルへ渡す**といった、パソコン上のファイルを直接読み書きする機能を実行すると、**エラーになったり応答が返らなくなったり**することがありました（何も起きずに黙って終わることもありました）。実体があるかどうかを確かめる関門を機能の入口に置き、使えない場所では**理由を出して止める**ようにしました。実体のあるものと無いものが混ざって選択されている場合は、**実体のあるものだけを対象に実行を続けます**（1 つ混ざっただけで機能全体が使えなくなるほうが不便なため）。あわせて、同じ確認をしていた既存の機能もすべてこの関門を通るよう揃えたので、**今後どの機能を足しても同じ抜けが起きない**ようにしました
