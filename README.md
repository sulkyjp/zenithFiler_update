## Latest changes

<details>
<summary><b>Show the notes for the latest release</b></summary>

<!-- latest-changes-en:begin -->
**[1.17.2] - 2026-10-05 : Effects that make everyday actions feel smoother, tried out in preview builds, come to release builds; Shift+Delete and Alt+drag work as in File Explorer, AI can write descriptions for favorites, column width becomes one setting, file conflicts can be decided one by one, and a privacy policy is added**

### Added

- **Effects that make everyday actions feel smoother, and an option to turn off all effects on the Effects page (#364)** [Preview 1.17.0.2] — Row hover in the list, moving between folders and switching the pane you are working in all changed in an instant, which sometimes made it hard to see what had just changed. The hover fill on rows and the highlight on the drop target folder now fade in and out. After pasting, moving, creating or renaming, the affected rows glow briefly, and a folder that receives a drop glows too. When you move to another folder, the list fades in. If loading the destination takes 0.15 seconds or longer, a thin line runs along the top of the list, so you can tell it is loading while the old list is still showing. The colour of the pane you are working in also changes with a fade, and dialogs such as confirmations that used to appear without any effect now have one. None of these effects get in your way: the selection, the focus and the contents of the list are settled immediately regardless of any effect, and keys and clicks keep working while an effect is playing. On-screen elements themselves are never moved, so where you click never shifts. Every effect can be turned off under Control Deck > Effects. Turning on **Turn off all effects (instant display)** at the top stops them and switches the display instantly. A new category, **Feedback on actions**, covers moving between folders, switching panes, buttons and dialogs; button hover and the glow on pane dividers, which used to play regardless of the settings, can now be turned off with it as well. For new users, Feedback on actions is off by default.

- **A detached nav pane window can now be always on top, in front of the main window, or a normal window (#374)** [Preview 1.17.1.3] — A detached window always stayed in front of the main window. It got in the way when you wanted to see more of the file list, yet it still disappeared behind other apps. Now, while a pane is detached, a stacking button appears next to the detach button. Click it to choose "Always on top (above other apps)", "In front of the main window" or "Normal window (can go behind the main window)". A normal window also appears on the taskbar so you can find it when it is behind the main window. The choice is shared by the left and right nav panes and is kept the next time you start the app. The default is "In front of the main window", the same as before.
- **AI can now write the description when you add a favorite (#377)** [Preview 1.17.1.3] — The Add to favorites window has a new "Write the description with AI: On / Off" choice. When it is on, AI writes one description and puts it in the description box as soon as the window opens. Switching from Off to On writes it right away as well. The description is based on the folder's name, parent folders, neighboring folders and contents, and on the way you have written favorite descriptions before. You can edit the result, and if you start typing while it is being written, what you typed wins. The same setting is in the list of automatic AI functions on the Overview tab of Control Deck > AI ("Descriptions when adding favorites"); whichever you choose is used the next time you add a favorite. It is off by default. If the neighboring folders are on Box or a network share and take a long time to read, it gives up after 5 seconds and writes the description from the name and location only. There is no usage limit.
- **The manual has a new Privacy Policy page (#381)** [Preview 1.17.1.5] — It explains on one page what Zenith Filer sends over the internet, when, and how to turn it off. For the update check, the XP leaderboard, the theme and Stickman stores, feedback and the AI features, it lists what is sent, where it goes, whether it is stored, and how to stop it. You can find it under Settings & Data in the manual, and in the online manual.
- **As in File Explorer, Shift+Delete deletes permanently and Alt+drag creates a shortcut (#382)** [Preview 1.17.1.5] — `Shift+Delete` deletes the selected files or folders without moving them to the Recycle Bin. Since this cannot be undone, you are always asked first, even with "Confirm before deleting" turned off. In the keymap presets it is `Shift+Delete` for Explorer style and `Shift+F8` for Total Commander style. When dragging and dropping, holding `Alt` (or `Ctrl+Shift`) as you drop creates a shortcut to the original where you drop it. `Ctrl+Shift` used to copy; it now creates a shortcut, as in File Explorer. The cursor changes to the shortcut shape when you press the key before dropping. When a server file or folder is involved a shortcut cannot be made, so it copies instead.


### Changed

- **Use the ← and → keys to choose between Yes and No in confirmation dialogs (#367)** [Preview 1.17.1.1] — In dialogs such as the delete confirmation, Enter pressed Yes, but the buttons never took focus and ignored the arrow keys, so choosing No meant reaching for the mouse. Now the default button (Yes, for the delete confirmation) is selected when the dialog opens, and ← and → move to the neighbouring button. Pressing past the last button wraps around to the first, so with two buttons a single key press switches between them; Tab works as well. The selected button is outlined, and Enter presses it, so selecting No and pressing Enter leaves your files alone. Esc still cancels. This applies to every confirmation dialog the app shows (OK / Cancel and the like), not just the delete confirmation.
- **The File Conflict dialog now says Keep both instead of Rename, lets you edit the new name, and can ask about each file in turn (#366)** [Preview 1.17.1.1] — When a file with the same name already existed, "Rename" never asked for a name: it kept both files by giving the copy another name automatically, so the button did not match what it did. The "Apply to all" checkbox made no difference either (every file got the same action even with it cleared), which made it hard to tell what would happen when several files clashed. The button is now called Keep both, and the dialog shows the name the copy will get (for example "a - Copy.txt"). The checkbox now reads "Do the same for the remaining N", and **clearing it makes the dialog ask about each file in turn**: the heading shows which one you are on (for example "2 of 5"), and you can choose Replace, Skip or Keep both per file. Ticking it again partway through settles the rest with that answer. While you decide one file at a time (including when only one file clashes), you can edit the name in "Name for the copy when keeping both" and press Keep both to use it; Enter in that box also presses Keep both rather than the default Replace. The dialog also no longer stays on top of other apps while it waits: it stays in front only while Zenith Filer is active, so you can switch to Explorer to compare the files. The buttons can be chosen with ← and →. By default one answer still covers every file, and Replace is selected when the dialog opens.
- **The copy progress window now has "Close when done" (#370)** [Preview 1.17.1.1] — Even when everything succeeded, the window waited 1.5 seconds before closing, so it got in the way when you wanted to move straight on. The window now closes 1 second after everything succeeds, and ticking "Close when done" in its footer (off by default) makes it close the moment everything succeeds. The choice is remembered for next time. As before, the window stays open either way when something was stopped or failed, and the results also appear as a notification.
- **Extracting archives and transferring to or from a server (FTP/SFTP and so on) can now also ask about each clashing file (#368)** [Preview 1.17.1.1] — Deciding one file at a time and editing the name for Keep both used to work only for local copies and moves; extracting and remote downloads and uploads applied one answer to every file. They now all behave the same: clear "Do the same for the remaining N" to be asked about each file. Uploads to a server also name the kept copy the same way as local copies, "name - Copy", "name - Copy (2)" and so on (it used to be "name (2)").
- **Effects are now clearly noticeable, and moving between folders, tabs, right-click menus and helper windows have effects too (#364)** [Preview 1.17.1.2] — People trying the preview effects told us they were hard to notice and too weak: they were short, and in the default Plain theme the glow was almost the same colour as the list. Row hover and drop target fades are now longer, and when you move to another folder the list fades in from half strength. The glow after pasting or renaming now fades in softly and melts away, with a faint outline in the focus ring colour, so it can be told apart in every theme. When you switch to the other pane, its edge glows softly. New: a tab you open fades in, and a tab you close leaves a fading afterimage. Tab hover, expanding folder trees, the breadcrumb when you move, right-click menus, the key guide, and opening Quick Jump, the command palette and Quick Preview also fade in. Rows you add to Favorites or index search glow softly in the same way. Every effect is visual only: selection, focus and clicks work immediately, and a closed tab disappears without waiting. All of them can be turned off under Control Deck > Effects (tab effects under D. Tabs, right-click menus and the key guide under I. File list, and the rest under Feedback on actions).
- **Card effects in the Control Deck now stop in lightweight mode and when Windows is set not to show animations (#364)** [Preview 1.17.1.2] — The lift and glow when you point at theme, store and stickman cards only checked "E. Pane transitions" and ignored lightweight mode and the Windows setting. The brief glow on the row selected after deleting and on the current folder in the tree now also follow the Windows "Show animations" setting.
- **The kind of place you are in (local, network, Box, cloud, remote) is now shown by an icon at the left end of the address bar instead of a column in the list (#375)** [Preview 1.17.1.3] — It used to appear in the Location column on every row, but everything in a folder is in the same place, so the column was just the same icon repeated down the list, taking up width. Now it appears once at the left end of the address bar, and hovering over it shows the name of the place, such as "Local" or "Network". The Location column is gone from normal lists and from the column header's right-click menu. The Name column gets the extra width, and as the window narrows, columns now disappear in the order Type, Size, Date Modified. Search results mix files from different places, so they still have a Location column.
- **The address bar's text box no longer switches back when the mouse leaves the bar (#375)** [Preview 1.17.1.3] — After switching to the text box with the pencil button, moving the mouse off the address bar took you back to the breadcrumb, so you could not, say, copy a file name from the list and come back to paste it. Switching between the text box and the breadcrumb is now a toggle: each click on the location icon at the left end (which takes over the pencil button's job) switches it, and the icon looks pressed in while the text box is on. Pressing Esc in the text box also goes back. If you go back without pressing Enter, whatever you had typed is dropped and the bar shows the current location again. Clicking an empty part of the bar or pressing Ctrl+L still switches to the text box as before.
- **The theme on first launch is back to the original standard instead of Plain (#380)** [Preview 1.17.1.4] — Since v1.17.0 new users started with Plain, a theme close to File Explorer. They now start with standard, Zenith Filer's own calm beige theme. standard is also the theme selected first in the first-run setup and the first theme in the Standard category of the theme list, with Plain right after it. If you already use Zenith Filer, your theme does not change.
- **The error log attached to feedback no longer contains your Windows user name (#381)** [Preview 1.17.1.5] — Log lines were copied as they were, so paths such as `C:\Users\(name)\…` sent your user name to the developer. The user name in those paths is now replaced with `<user>` before the preview is shown, and the preview is what gets sent. This also works when your profile folder is outside `C:\Users`. Other folder and file names stay as they are, so check the preview before sending.
- **Backup AI Summary is now off on new installations (#381)** [Preview 1.17.1.5] — With AI set up, every start-up sent the changed settings (which can include folder paths such as your favorites) to your AI service. On new installations it runs only after you turn it on in the list of automatic features on Control Deck › AI. Existing settings are not changed.
- **The XP ranking description in Challenges now matches what is actually sent, and when (#381)** [Preview 1.17.1.5] — It said data was sent on level-up and that only your display name, title, XP and level were sent. In fact it is also sent when the app starts (at most once every 20 hours), together with a random ID that keeps your entry linked to you. Only the description changed; what is sent is the same.
- **On a preview build, the changelog now lists the changes of each preview build (#384)** [Preview 1.17.1.5] — Preview changes appeared only on the update card, so once you closed it you could not read them again until the next release. The changelog now lists them at the top, under versions such as "1.17.1.4 : Preview build". An item that a later preview build changed again is listed under the later one. When the next release comes out, the preview versions disappear and their changes are listed under the release. The changelog is unchanged on release builds.
- **Column width is now one setting with three modes, and the icon at the left end of the column headers shows which one is in use (#378)** [Preview 1.17.1.5] — Column widths used to be decided by three separate features: "Auto-fit columns" on the toolbar, and "Size this column to fit" and "Size all columns to fit" in the header's right-click menu. It was hard to tell which one was in effect. They are three answers to one question — what the columns should fit — so they are now one setting: "Fit to window", "Fit to text" or "Set by hand". Unlike the old "Size all columns to fit", Fit to text refits every time you open a folder, and includes long names further down the list. The icon at the left end of the column headers always shows the current mode, and each click moves to the next one. Right-click it for a menu with all three (the header right-click menu and the "Column width" toolbar button show the same menu). Dragging a column border switches to Set by hand, and the widths you set are remembered across restarts. The mode applies to every pane and tab. New users start with Fit to text; if you used Zenith Filer before, the old "Auto-fit columns" on/off setting carries over.
- **The readme in the download is now in English and Japanese, and its outdated parts are fixed (#381)** — `ZenithFiler_Readme.txt`, the first file you see after extracting, was Japanese only, and what it said about the free version's daily limits, the bundled runtime and where to buy was out of date. It now has an English section first and a Japanese section after it, both matching the current app, including where to buy from outside Japan (Polar) and where the privacy policy is. The list of open-source components the app uses, with the full terms for each, is now included as `data\apps\THIRD_PARTY_NOTICES.txt`.

### Fixed

- **"Copy share link with path" for Box often failed, although it sometimes worked (#371)** [Preview 1.17.1.2] — Box's sharing window can only write the link to the clipboard while it is in front and has focus. Zenith Filer brought the window forward, but Windows sometimes refused, and after a refusal it never tried again, waited 8 seconds, and left the sharing window open. Whether Windows refused depended on the moment. Box is now allowed to come to the front on its own before its menu command runs, and if the window still is not in front, Zenith Filer tries again a few times at short intervals. If you switch to another window after the sharing window has come to the front, it does not take the focus back.
- **Quickly double-clicking a shortcut to a folder sometimes opened File Explorer (#372)** [Preview 1.17.1.2] — Reading a shortcut's target also checked the target folder itself, with a 0.3-second limit. Right after a folder opens, reading the targets of all shortcuts in the list and the hover display run at the same time, and a double-click on top of that could hit the limit. The target was then treated as unknown and the shortcut was handed to Windows as is, which is why File Explorer opened. It was more likely when the target was on a network. The target is now taken from the shortcut file alone, so it is never lost this way and the folder opens in a new Zenith Filer tab.
- **Four places that should change color or text with their state never did (#373)** [Preview 1.17.1.2] — In the Ollama steps under AI in the Control Deck, the step 2 circle stayed gray after installation instead of highlighting the next step. In addition, your own bar in the leaderboard was not highlighted, completed challenges did not show a full progress bar, and the title bar tooltip for a title without a backstory showed no description. All of them now follow their state. The number in the step 3 circle, which was hard to read in light themes, is fixed too.
- **Emoji icons set on favorites could not be seen in themes such as Plain (#373)** [Preview 1.17.1.2] — A favorite's icon is drawn as lines on a small square filled with the accent color. The line color did not match the accent color, and in the default Plain theme two nearly identical grays overlapped, so the lines disappeared. 21 of the bundled themes were hard to read. The lines are now drawn in whichever of white or black reads better on the fill, so the icon is visible in every theme, and it follows theme changes. The icons in the Set Emoji picker are fixed the same way. Other labels and buttons filled with the accent color were hard to read in some themes for the same reason and now choose their text color the same way (the "FTP"/"SFTP" tag on remote locations, selected chips, the unread count, "FEEDBACK" and "FULL LICENSE" tags, reward and stickman badges, store page numbers and the theme assignment hint in the Control Deck, the selected tab and filter in the challenge history, your own messages in AI chat, "Recommended" in the macro studio, the selected algorithm in the hash window, and check marks in the index search scope list). The "Favorites" tag next to Quick Jump results was also faint in light themes and is now darker.
- **Copies kept under another name were called "a -  - Copy.txt" (#366)** [Preview 1.17.1.1] — The separator in the automatic name was added twice, both for Keep both in the File Conflict dialog and for copying into the same folder. Copies are now named "a - Copy.txt", or "a - Copy (2).txt" if that is taken.
- **Shortcuts such as Ctrl+Shift+Space did nothing after you pressed a button on the "First 5 steps" card (#354)** [Preview 1.17.1.1] — Pressing How to (or any other button on the card) made the card's window active, so keys no longer reached the main window. Pressing Ctrl+Shift+Space for the Ring Launcher then pressed the same button again with Space, and the card just expanded and collapsed. The main window now stays active when you press the card's buttons, so your shortcuts keep working. The same fix applies to What's New and to the copy progress window (Pause, Cancel and so on), and the progress window no longer takes the keyboard away from the main window when it comes to the front as you start another copy or move.
- **After a stopped or failed operation, the progress window no longer closed by itself (#370)** [Preview 1.17.1.1] — Finished rows were only cleared when the window closed on its own, so a stopped or failed row left behind (after closing the window by hand, or from a small transfer that never showed the window) kept the window open even when every later copy succeeded. Pressing × in the file conflict dialog was enough to leave such a row. Starting a new copy or move now clears the finished rows from earlier operations.
- **After you clicked a button on the toolbar or status bar, Space or Enter pressed that button again (#369)** [Preview 1.17.1.1] — Buttons on the title bar, status bar, toolbar, the top of the navigation pane and the tab strip kept the keyboard focus after you clicked them, so the next Space or Enter went to the button instead of the file list, and the status bar toggles (sidebar, macro recording, AI, always on top and so on) flipped back. Clicking these buttons no longer moves the keyboard focus, so your next key goes where you were working.
- **Back, Forward or double-clicking a folder could open it at the previous folder's scroll position (#364)** [Preview 1.17.1.2] — Only one scroll position was kept, and it was applied to whichever folder you moved to. After scrolling to the bottom of a long folder and moving elsewhere, the new folder could open part way down. Scroll positions are now kept per folder: going back to a folder with Back, Forward or Refresh (F5) returns to where you were, and a folder you open for the first time starts at the top. As before, going back selects the folder you came from.
- **Faint text such as counts and descriptions, in the "What's new" card, Control Deck and elsewhere, was hard to read in some themes (#376)** [Preview 1.17.1.3] — The count for each category (such as "2 items"), the "Earlier updates" heading, the version numbers and the "N more versions" text used the already subdued secondary text color and then faded it further. In Espresso this made them almost indistinguishable from the background. They now use the secondary text color as is, so they are readable in every theme. The same extra fading was found in 48 more places across the app, and all of them now work the same way. Most are descriptions and notes on Control Deck pages (Theme, Store, Challenges, Feedback, AI, Stickman, License, About and others), the item count, open count, path and description in Favorites, the file name and hint in the copy progress window, descriptions in theme customization, Quick Jump, and the Index Search hint.
- **Copying onto folders that already existed copied nothing when you chose Keep newer or Keep larger (#379)** [Preview 1.17.1.4] — When two folders had the same name, the folders themselves were compared by date and size. A destination folder just created by a sync looked newer, and both folders counted as size 0, so the whole folder was skipped. Folders are now compared file by file: files missing in the destination are copied, and only files that exist on both sides are decided by date or size, in subfolders as well. Overwrite still merges the contents into the existing folder without deleting it.
- **Column borders in the file list (between Name, Date modified and so on) were hard to grab (#378)** [Preview 1.17.1.4] — The area you could grab to resize a column was only 1 pixel on each side of the border line. It is now 5 pixels on each side. The lists in the navigation pane (Recent files, Frequent folders), the Working Sets list and others use the same width.
- **Opening a file or folder right after renaming it could fail with "not found" (#383)** [Preview 1.17.1.5] — After a rename, the row kept pointing to the old name until the list finished reloading. On a file server the reload takes a few seconds, and opening during that time tried to open the old name, which no longer existed. The reload itself could also bring back the old name, because file servers keep folder listings for a short while. The row now takes the new name the moment you rename it, and is corrected if the reload returns the old name. If you still open it from an old row, Zenith Filer follows the rename you just made and opens the file under its new name.
- **Turning off "Auto-fit columns" left columns that had been hidden for lack of space stuck at zero width, impossible to grab (#378)** [Preview 1.17.1.5] — Leaving "Fit to window" for another mode now brings those columns back at their usual width. In addition, path shortening in search results now follows the column width when auto-fit is off, and you can scroll to the right-hand columns when the columns are wider than the window.
- **The status bar showed "N items" and "N items selected" in Japanese whatever the display language (#381)** — The item count and the selection count were not translated, so they stayed in Japanese while other messages on the same bar, such as "Copied 19 item(s)", were. They now follow the display language.
- **In the ring launcher, the names of the items at 3 and 9 o'clock overlapped their icons (#381)** — Names sit outside their icons, but at 3 and 9 o'clock that puts them at the same height as the icon, right on top of it. At those positions the name now goes below the icon and wraps onto up to two lines that fit inside the ring. It was most noticeable with long names such as in English. Other positions look the same as before.
- **The note at the bottom of the copy window ("Closing does not stop the transfer…") was cut off (#381)** — It sat between "Close when done" and the buttons, where there was not enough room in any language. It now has its own full-width line below the buttons, so it can be read in full.

### Added

- **操作の手触りを上げる演出を加え、演出ページで「演出をすべてオフ」にもできるようにしました (#364)** 〔先行版 1.17.0.2〕 — これまで一覧の行のホバーやフォルダの移動、操作中のペインの切り替えは、どれも一瞬で切り替わるだけで、何が変わったのかを目で追いにくいことがありました。行のホバーの塗りと、ドロップ先のフォルダの強調がフェードで出入りします。貼り付け・移動・新規作成・名前の変更のあとは、対象の行が一瞬光ります。ドロップを受け取ったフォルダも光ります。フォルダを移ると、一覧がフェードで出ます。移動先の読み込みに 0.15 秒以上かかるときは、一覧の上端に細い線が流れ、古い一覧のまま待たされている間も読み込み中だと分かります。操作中のペインの色も、フェードで切り替わります。登場の演出が無かった確認画面などのダイアログにも、演出が付きました。どの演出も操作の妨げにならないように作ってあります。選択・フォーカス・一覧の中身は演出と関係なくすぐに決まり、演出の途中でもキーとクリックはそのまま効きます。クリックの位置がずれないよう、画面の部品そのものは動かしません。演出はすべて Control Deck ＞ 演出 で切れます。先頭の「演出をすべてオフ（即時表示）」をオンにすると、演出を止めて表示を即時に切り替えます。カテゴリ別の設定には「操作の手応え」を足しました（フォルダ移動・ペインの切り替え・ボタン・ダイアログ）。これまで設定と関係なく動いていたボタンのホバーやペインの境目の光も、このカテゴリで切れます。はじめて使う方の既定では「操作の手応え」はオフです。

- **お気に入りに追加するときの概要説明を、AI に作らせられるようにしました (#377)** 〔先行版 1.17.1.3〕 — お気に入り追加ウィンドウに「AI で説明を作る: する／しない」を足しました。「する」にしておくと、ウィンドウを開いたときに AI が説明を 1 つ作って説明欄に入れます。「しない」から「する」に切り替えたときも、その場で作ります。説明は、追加するフォルダの名前・親の階層・同じ階層のフォルダ・中身の名前と、これまでにお気に入りへ書いた説明の書き方を参考にします。入った説明は書き換えられ、作っている途中で説明欄に打ち始めたら打った文を優先します。同じ設定は Control Deck ＞ 生成AI の概要タブの自動機能の一覧（「お気に入り追加時の概要説明」）にもあり、どちらで選んでも次に追加するときはそれを使います。はじめは「しない」です。周りのフォルダが Box やネットワーク上で読むのに時間がかかるときは、5 秒で見切って名前と場所だけで作ります。回数制限はありません。
- **マニュアルに「プライバシーポリシー」を足しました (#381)** 〔先行版 1.17.1.5〕 — Zenith Filer がインターネットに何を、いつ送るのかと、その止め方を 1 ページにまとめました。更新の確認・経験値のランキング・テーマとスティックマンのストア・フィードバック・AI の機能それぞれについて、送るもの・送り先・保存の有無・止め方を書いています。マニュアルの「設定とデータ」にあり、Web 版のマニュアルでも読めます。

- **戻る・進むやフォルダのダブルクリックで、前のフォルダのスクロール位置のまま開くことがあったのを直しました (#364)** 〔先行版 1.17.1.2〕 — スクロール位置を 1 つしか覚えておらず、フォルダを移ると前のフォルダの位置を新しいフォルダにそのまま当てていました。そのため、長いフォルダを下までスクロールしてから別のフォルダへ移ると、途中から表示されることがありました。いまはフォルダごとに位置を覚えていて、戻る・進む・更新（F5）でそのフォルダに戻ったときだけ前の位置に戻り、初めて開くフォルダは先頭から出ます。戻ったときに、入っていたフォルダが選ばれるのはこれまでどおりです。
- **「更新のお知らせ」や Control Deck などで、件数や説明などの淡い文字が、テーマによって読みにくかったのを直しました (#376)** 〔先行版 1.17.1.3〕 — 分類ごとの件数（「2 件」など）、「これまでの更新」の見出し、版の番号、「ほか N 件のバージョン」の文字は、もともと淡い補助の文字色を、さらに薄めて表示していました。そのため Espresso では地の色とほとんど見分けられませんでした。いまは薄める指定をやめて補助の文字色のまま表示するので、どのテーマでも読めます。同じように補助の文字をさらに薄めていたところがアプリ全体で 48 か所あったので、すべて同じように直しました。主なものは、Control Deck の各ページの説明や注意書き（テーマ・ストア・チャレンジ・フィードバック・AI・棒人間・ライセンス・バージョン情報など）、お気に入りの件数・参照回数・パス・説明、コピー中の窓のファイル名と案内、テーマのカスタマイズの説明、クイックジャンプ、インデックス検索の案内です。
- **フォルダが既にあるところへのコピーで「新しい方を残す」「大きい方を残す」を選ぶと、中身が 1 件もコピーされなかったのを直しました (#379)** 〔先行版 1.17.1.4〕 — 同じ名前のフォルダがぶつかったとき、フォルダそのものの日時と大きさで比べていました。移行先のフォルダが同期で作られたばかりだと「移行先のほうが新しい」、大きさはどちらも 0 で「移行元のほうが大きくない」と判定され、フォルダごとスキップしていました。いまはフォルダ同士なら中へ入り、ファイルごとに比べます。移行先に無いファイルはそのままコピーし、両方にあるファイルだけ日時や大きさで決めます。サブフォルダの中も同じです。「上書き」を選んだときはこれまでどおり、移行先のフォルダを消さずに中身を合わせます。
- **一覧の列の境目（名前・更新日時などの間）が掴みにくかったのを直しました (#378)** 〔先行版 1.17.1.4〕 — 列の幅を変えるときに掴める範囲が、境目の線の左右 1 ピクセルずつしかありませんでした。いまは線を中心に左右 5 ピクセルずつ掴めます。ナビペインの「最近使ったファイル」「よく使うフォルダ」、ワーキングセットの一覧なども同じ幅にそろえました。
- **名前を変えた直後にファイルやフォルダを開くと「見つかりません」になることがあったのを直しました (#383)** 〔先行版 1.17.1.5〕 — 名前を変えたあと、一覧を読み直し終わるまで、行は古い名前のパスを指したままでした。ファイルサーバーでは読み直しに数秒かかり、その間に開くと、もう無い古い名前のファイルを開こうとしていました。読み直しても、ファイルサーバーが一覧を少しの間覚えているため、古い名前が返ってくることもありました。いまは名前を変えた瞬間に行を新しい名前にし、読み直しが古い名前を返したときも直します。それでも古い行から開いたときは、直前に変えた名前を辿って新しいファイルを開きます。
- **「列を自動補正」をオフにすると、狭さで隠れていた列が幅 0 のまま戻らず、掴めなくなっていたのを直しました (#378)** 〔先行版 1.17.1.5〕 — いまは「画面の幅に合わせる」から別のモードへ移ると、隠れていた列が元の幅で戻ります。あわせて、自動補正がオフのときに検索結果のパスの省略が列の幅に追従しなかったのと、列の合計が画面より広くなると右の列へスクロールで届かなかったのも直しました。
- **英語などの表示でも、ステータスバーの「N 個の項目」「N 個の項目を選択中」が日本語のままでした (#381)** — 一覧の項目数と選んでいる数は訳さずに出していたため、同じバーの「19 件コピーしました」は訳されているのに、こちらだけ日本語が残っていました。いまは表示言語に合わせて出します。
- **リングランチャーで、真横の項目の名前がアイコンに重なっていました (#381)** — 名前はアイコンの外側に置いていますが、3 時と 9 時の位置ではアイコンと同じ高さに来るため、名前がアイコンの上に重なっていました。いまはその位置だけ名前をアイコンの下へ移し、輪の内側に収まる幅で 2 行まで折り返します。英語のように名前が長いときに特に目立っていました。ほかの位置の見た目は変わりません。
- **コピー中の窓の下の「閉じても転送は続きます…」が途中で切れていました (#381)** — 「終わったらすぐ閉じる」とボタンの間に置いていたため、日本語でも英語でも幅が足りませんでした。いまはボタンの列の下に窓の幅いっぱいで置き、全文が読めます。
