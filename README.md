**[1.17.4] - 2026-10-17 : Basic operations and drag and drop now match File Explorer, folder sizes appear just by opening a folder, and moving onto a same-name folder with overwrite no longer deletes what was only in the destination**

### Added

- **Folder sizes now appear just by opening a folder (#404)** [Preview 1.17.3.2] — Until now, folder sizes were shown only in indexed locations; everywhere else the Size column was blank. Now, when you open a folder, the sizes of the folders inside it are counted in the background and shown in the Size column. While counting, a small spinning mark appears in the Size column for folders that don't have a size yet. Counted sizes are remembered (even after you close the app) and shown right away the next time. A folder's modified date doesn't change when files deep inside it are added or changed, so whether it has changed can't be told from dates. Instead, until the interval you set (10 minutes by default) has passed since the last count, the remembered size is simply shown; after that, the remembered size stays on screen while the folder is recounted in the background and replaced if it differs. Places you move, copy, delete or rename in Zenith Filer drop their remembered sizes on the spot and are recounted. Counting runs as a single low-priority background task that doesn't get in the way of other disk activity, and it stops as soon as you move to another folder. Network drives (slow, and the counting puts load on the server) and cloud-synced folders (Box Drive, OneDrive, SharePoint, where the sync app has to respond for every folder, which tends to be slow) aren't counted by default. Indexed locations keep showing the sizes from the index. If only part of a folder could be counted because some folders inside couldn't be opened, the size is shown like "≥ 12.3 GB". Under Control Deck → 1. Basic Settings → Display, "Folder sizes", you can choose whether to count automatically, the recount interval (every time / 10 minutes / 1 hour / 1 day), whether to also count on network drives, and whether to also count in cloud folders, each on its own.

- **Hovering over a folder while dragging now opens it (#401)** [Preview 1.17.3.3] — This is the same spring-loading behavior as File Explorer. Hold the cursor over a folder in the file list for about a second and the list moves into it; hold it over a branch in the nav pane tree and the branch expands; hold it over a tab header and that tab comes to the front. Until now the row was only highlighted, so you couldn't drop into a deep folder that wasn't visible. The nav pane tree now also scrolls automatically when you drag to its top or bottom edge. Once a folder opens, it won't open again until you move away and come back.

- **Dropping files on a tab header now copies or moves them into that tab's folder (#401)** [Preview 1.17.3.3] — Until now dropping a folder only opened it in a new tab, and dropping files did nothing. Now, when what you drop includes files, they go to the folder open in that tab. Whether it moves or copies follows the same rules as dropping on the file list (same drive moves, another drive copies, Ctrl copies, Shift moves, Alt makes a shortcut). Dropping only folders still opens them in a new tab.

- **Pressing Tab while renaming in place now commits the name and starts renaming the next row (#400)** [Preview 1.17.3.3] — As in File Explorer, Shift+Tab goes to the previous row. You can name a series of items without clicking each row again. Until now Tab switched panes and simply ended the edit. It stops at the first and last rows.

- **An action can now have a second key, and File Explorer's basic keys were added (#400)** [Preview 1.17.3.3] — Until now an action could have only one key, so choosing Backspace for Back in the Explorer-style key set took Alt+Left away. Now a second key is possible, and in the Explorer-style set both Backspace and Alt+Left go back. The standard key set also gained File Explorer's second keys: Alt+Up in addition to Backspace to go up, Alt+D in addition to Ctrl+L for the address bar, Ctrl+E in addition to Ctrl+F for search, Ctrl+R in addition to F5 to refresh, and Alt+P in addition to Space for Quick Preview. The key list shows both, such as "Ctrl+L / Alt+D". In the Explorer-style set, Ctrl+1 to Ctrl+8 switch to the tab in that position and Ctrl+9 to the last tab (so Ctrl+3 for the top/bottom split is removed in that set). If you chose the Explorer-style set before, choose it again to get Alt+Left and the rest. The second key can't yet be changed on screen ("Reset to default" restores the default second key).

- **Added Invert selection, Select none, and switching tabs by number (#400)** [Preview 1.17.3.3] — Invert selection swaps selected and unselected items, and Select none clears the selection in the list. "Switch to tab 1–8" and "Switch to last tab" open the tab in that position from the left, or the rightmost tab, in the active pane. None of them has a key in the standard key set, so assign one in the key settings or use them from the Command Palette.

### Changed

- **In the Favorites pane, the favorite for where you are now stands out from the related ones (#406)** [Preview 1.17.3.3] — Favorites that are the same as, above or below the open folder get an accent bar at the left and a faint background. Until now they all got the same mark, so if you had registered both `C:\Program Files (x86)\Realtek` and `C:\Program Files (x86)\Realtek\Realtek PC Camera`, opening one made both look open. Now only the one favorite for where you are gets the faint background, and the other parents and children get the bar alone. Where you are is the favorite that matches the open folder; if none matches, it is the closest parent that contains it.

- **Dropping on the nav pane tree now follows the same rules as dropping on the file list (#401)** [Preview 1.17.3.3] — Until now a drop on the tree always moved, even with Ctrl held or from another drive, so the original moved when you meant to copy. Right-dragging showed no menu, and name clashes got a new name without asking. Now, as on the file list, the same drive moves, another drive copies, Ctrl copies, Shift moves, and Alt makes a shortcut. Right-dragging shows the "Copy here / Move here / Create shortcut here" menu. A name clash asks you what to do, Ctrl+Z undoes it, and the items you brought are selected. Dragging a folder within the tree works the same way.

- **The cursor now shows that you can't drop while it is over the folder you're dragging or a folder inside it (#401)** [Preview 1.17.3.3] — This matches File Explorer. Until now the move cursor stayed on and you could drop, and only afterwards were you told the folder can't go inside itself.

- **Copying the full path (Ctrl+Shift+C or right-click "Copy full path") now wraps each path in double quotes (#400)** [Preview 1.17.3.3] — This matches File Explorer's "Copy as path". A path with spaces stays one path when pasted into Command Prompt or a file name box. With several items selected, each is quoted on its own line. Copying the current folder's path when nothing is selected, and "Copy file name", still copy without quotes.

- **Type-to-select now works with symbols and Japanese, and remembers what you typed for about a second (#400)** [Preview 1.17.3.3] — Typing in the file list jumps to the item that starts with what you typed. Until now only letters and digits worked, and what you typed was forgotten after half a second, so you couldn't jump to names starting with `_` or `~`, and typing slowly jumped somewhere else on the second letter. Text typed with an IME also works once you confirm it.

Restart to apply it" appears at the bottom center of the window with a Restart button. It was drawn inside the Zenith Filer window, so when a terminal tab such as Command Prompt was open underneath, the terminal was drawn on top and the message was hidden behind it. Switching to a file tab made it clickable again, but you had no way to tell it was there. The message now appears in a small window attached to Zenith Filer, so it stays in front and can be clicked even with a terminal open. It appears in the same place as before, follows the window when you move or resize it, and doesn't take keyboard input when it appears. The See how to buy message shown when you reach a free-plan limit uses the same kind of message, so it is fixed too.

- **Fixed files dropped from Outlook not being selected, so you couldn't rename them with F2 right away (#402)** [Preview 1.17.3.2] — When you drop files from File Explorer, the files you moved are selected and the list gets the focus, so you can press F2 to rename them or Enter to open them. When you dropped an email or an attachment from Outlook, the list was only reloaded after saving: nothing was selected and the focus didn't move anywhere. You couldn't tell which file had been added, and pressing F2 did nothing. Now the saved files are selected and the list gets the focus. If a file was saved under a new name such as "(2)" because the name was taken, the file with the new name is selected. Pasting Outlook data with Ctrl+V and dropping a URL from a browser to create a shortcut are fixed the same way. When you drop onto a folder row, that folder is selected, just as with a drop from File Explorer.

- **Fixed working sets showing "Waiting for it to come online…" for folders that can't be found, leaving the tab unusable (#391)** [Preview 1.17.3.1] — When you recalled a working set and a registered folder couldn't be found, the tab always showed "This location is not available yet. Waiting for it to come online…" and waited for 2 minutes, whatever the reason. Waiting makes sense for Box Drive before syncing starts or for an external drive you haven't plugged in yet, but a folder that was deleted, moved or renamed never comes back. The waiting message stayed anyway, and after 2 minutes the list simply turned empty without a word. Now, when the drive or share is there but the folder itself is gone, the tab doesn't wait: it shows "This folder can't be found" right away and suggests opening the right location and using Overwrite to register it again. The notification also says how many folders can't be found. For Box Drive and SharePoint folders, or when the whole drive or share can't be found, the tab waits for it to appear as before, and switches to "This folder can't be found" if it still hasn't appeared after 2 minutes. The check made while waiting now also matches the check used when the wait starts; it used to be lighter, so some network folders couldn't be opened even after they appeared. In every case the tab keeps the registered path and is never replaced with Desktop or anything else.

- **Fixed the Pro price shown in the app not matching the price on the Vector page (#405)** [Preview 1.17.3.3] — The buy button on the License page said "Buy on Vector (¥2,000, tax included)". The Vector page lists ¥2,310 (tax and fees included), which is what you actually pay. ¥2,000 was the price before tax and fees. The button now says "¥2,310, tax and fees included", and the bundled Readme and the manual show the same price.

- **Fixed moving a folder onto a folder with the same name with "Overwrite" deleting files that were only in the destination (#399)** [Preview 1.17.3.3] — When you moved a folder onto one with the same name and chose "Overwrite", the destination folder was swapped out as a whole. Files and folders that existed only in the destination were deleted without going to the Recycle Bin. Now, as in File Explorer, folders are merged and what was already in the destination stays. Only files with the same name are asked about, one at a time, and the dialog shows where they are inside the folder (such as "Photos > 2024 > a.jpg"). Copying onto a folder with the same name merged the contents but overwrote files with the same name without asking, so it now asks too. When a file and a folder share a name, neither is overwritten and both are kept. Source folders left empty after the move are removed, and folders that still hold skipped items stay. A merged move can be undone with Ctrl+Z.

- **Fixed right-click "Create shortcut" naming the shortcut like "report -  - Shortcut.lnk" (#399)** [Preview 1.17.3.3] — The " - " separator was added twice, the extension was dropped, and duplicates were numbered from "(1)". The name is now "report.xlsx - Shortcut.lnk", as in File Explorer, with duplicates numbered from "(2)". This is the same naming as shortcuts made by dragging. The new shortcut is selected, so you can rename it right away with F2.

- **Fixed Ctrl+Z not undoing a delete to the Recycle Bin (#399)** [Preview 1.17.3.3] — Copy, move, and rename could be undone with Ctrl+Z, but delete could not. Now a delete to the Recycle Bin can be undone, restoring the items from the Recycle Bin to where they were. If something with the same name went into the Recycle Bin several times, the one from that delete is restored. - **タブでターミナルを開いていると、アップデート完了のお知らせがその後ろに隠れて［再起動］を押せなかったのを直しました (#403)** 〔先行版 1.17.3.2〕 — アップデートの準備ができると、画面の下の中央に「アップデート完了。再起動して適用してください」と［再起動］ボタンが出ます。この表示は Zenith Filer の画面の中に描いていたため、下にコマンドプロンプトなどのターミナルのタブがあると、ターミナルのほうが手前に出て、お知らせがその後ろに隠れていました。ファイルのタブへ切り替えれば押せましたが、隠れていること自体に気づけません。いまはお知らせを Zenith Filer に付いて動く小さな窓に出すので、ターミナルを開いていても手前に出て押せます。置く場所はこれまでと同じで、窓を動かしたり大きさを変えたりすると付いてきます。出たときにキーボードの入力を奪うこともありません。無料版の上限に達したときの［購入方法を見る］も同じお知らせなので、あわせて直っています。

- **Outlook からメールや添付をドロップしたあと、保存したファイルが選ばれず、そのまま F2 で名前を変えられなかったのを直しました (#402)** 〔先行版 1.17.3.2〕 — エクスプローラーからファイルをドロップしたときは、運んだファイルが選ばれて一覧にフォーカスが移るので、続けて F2 で名前を変えたり Enter で開いたりできます。Outlook からメールや添付ファイルをドロップしたときは、保存したあと一覧を読み直すだけで何も選ばず、フォーカスもどこにも移りませんでした。どのファイルが増えたのかが分からず、F2 を押しても何も起きません。いまは保存したファイルを選び、一覧にフォーカスを渡します。名前が重なって「(2)」などを付けて保存したときは、付け直した名前のファイルを選びます。Outlook のデータを Ctrl+V で貼り付けたときと、ブラウザから URL をドロップしてショートカットを作ったときも同じように直しました。フォルダの行の上に落としたときは、エクスプローラーからのドロップと同じく、そのフォルダを選びます。

- **ワーキングセットで見つからないフォルダに「接続を待っています…」が出続け、何もできなくなっていたのを直しました (#391)** 〔先行版 1.17.3.1〕 — ワーキングセットを呼び出したとき、登録したフォルダが見つからないと、どんな理由でも「この場所はまだ利用できません。接続を待っています…」と出して 2 分待っていました。Box Drive の同期やつなぐ前の外付けドライブなら待てば現れますが、フォルダを削除・移動・名前の変更していた場合は待っても現れません。それでも待つ表示が出続け、2 分たつと何も言わずに空の一覧になっていました。いまは、ドライブや共有はあるのにフォルダだけが無いときは待たず、すぐに「このフォルダは見つかりません」と出して、正しい場所を開いて「上書き保存」すれば登録し直せることを案内します。通知にも見つからないフォルダの件数が出ます。Box Drive・SharePoint のフォルダや、ドライブ・共有ごと見つからないときは、これまでどおり現れるのを待ちます。2 分待っても現れなかったときも「このフォルダは見つかりません」に切り替わります。あわせて、待っている間の見張りを、待ちに入ったときと同じ確かめ方にしました。これまでは見張りの確認が軽く、ネットワーク上の一部のフォルダでは現れても開けないことがありました。どの場合もタブは登録したパスのままで、デスクトップなどには差し替えません。

- **アプリに出る Pro の値段が、Vector のページの値段と違っていたのを直しました (#405)** 〔先行版 1.17.3.3〕 — ライセンスのページの購入ボタンには「Vector で購入する（¥2,000・税込み）」と出ていました。Vector のページの値段は 2,310 円（税額表示・手数料込み）で、買うときに実際に払う額と合っていませんでした。2,000 円は消費税と手数料を足す前の額でした。いまは「¥2,310・税と手数料込み」と出します。同梱の Readme とマニュアルの値段も同じ額に直しました。

- **同じ名前のフォルダへ「上書き」で移動すると、移動先にだけあったファイルが消えていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — 同じ名前のフォルダへ移動して競合の確認で「上書き」を選ぶと、移動先のフォルダを丸ごと入れ替えていました。移動先にだけあったファイルやフォルダは、ごみ箱を通らずに消えていました。いまはエクスプローラーと同じく、フォルダ同士は中身を統合し、移動先にあったものは残します。同じ名前のファイルだけを競合の確認で 1 件ずつ尋ね、「Photos > 2024 > a.jpg」のようにフォルダの中の場所も出します。コピーも、同じ名前のフォルダへは中身を統合したうえで、同じ名前のファイルを尋ねずに上書きしていたので、同じように尋ねるようにしました。ファイルとフォルダで種類が違うときは上書きせず、両方残します。運び終えて空になった元のフォルダは消し、スキップしたものが残ったフォルダは残します。統合した移動も Ctrl+Z で戻せます。

- **右クリックの「ショートカットの作成」で、名前が「report -  - ショートカット.lnk」のようになっていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — 区切りの「 - 」を二重に付け、拡張子も落とし、同じ名前のときの番号も「(1)」から始めていました。いまはエクスプローラーと同じ「report.xlsx - ショートカット.lnk」で、重なったら「(2)」から付けます。ドラッグで作るショートカットと同じ名前の付け方です。作ったショートカットは選ばれた状態になり、そのまま F2 で名前を変えられます。

- **ごみ箱へ入れた削除を、Ctrl+Z で元に戻せなかったのを直しました (#399)** 〔先行版 1.17.3.3〕 — コピー・移動・名前の変更は Ctrl+Z で戻せましたが、削除だけは戻せませんでした。いまはごみ箱へ入れた削除を、ごみ箱から元の場所へ戻せます。同じ名前のものが何度もごみ箱に入っていても、その削除で入ったものを戻します。元の場所に同じ名前のものが既にあるときは上書きせず、戻せなかったことを知らせます。完全に削除（Shift+Delete）したものと、ごみ箱の無いネットワークの場所で消したものは戻せません。

- **名前の変更で大文字と小文字だけを変えると、「同じ名前が既にあります」と出ていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — `a.txt` を `A.txt` にするだけで、自分自身を見つけて警告が出ていました（OK は押せました）。

- **移動の進み具合の画面で、「一時停止」が効かなかったのを直しました (#399)** 〔先行版 1.17.3.3〕 — コピーは止まりましたが、移動は押しても止まりませんでした。いまは移動も、次の 1 件へ進む前で止まります。

- **一覧の何もない場所から Shift を押しながらドラッグすると、選択が消えていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — マニュアルには「Shift + ドラッグで範囲を広げて選ぶ」とありましたが、Shift は効かず、それまでの選択が消えていました。いまはエクスプローラーと同じく、Shift+ドラッグはそれまでの選択を残したまま、囲んだものを足します。Ctrl+ドラッグは、これまでどおり囲んだものの選択を反転します。

- **アドレスバーに `..` と打つと、今のフォルダの親ではない場所へ移っていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — `..` や `.\sub`、フォルダ名だけの相対の書き方を、今のフォルダではなくアプリを起動した場所から解いていました。いまはエクスプローラーと同じく、今のフォルダを基準にします。`%USERPROFILE%` のような環境変数も展開します。

- **開くアプリが決まっていないファイルを開くと、英語の「Error:」だけのダイアログが出ていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — いまはエクスプローラーと同じく、Windows の「このファイルを開く方法を選んでください」が出ます。そのほかの理由で開けなかったときも、英語ではなく「ファイルを開けませんでした」と理由を出します。

- **アクセス権の無いフォルダを開くと、何の案内もなく空の一覧になっていたのを直しました (#399)** 〔先行版 1.17.3.3〕 — いまは「アクセス権限が不足しています」とフォルダの場所を知らせます。フォルダの中の入れない場所は、これまでどおり飛ばして表示します。

- **その場の名前の編集で → を押すと、文字の間を動かずに隣のペインへ移ってしまうのを直しました (#407)** — 一覧で名前を変えている最中に → を押すと、カーソルが右へ動かずに B ペインへ移っていました。B ペインで名前を変えているときの ← も、同じく A ペインへ移っていました。← → でのペインの移動が、入力欄よりも先にキーを取っていたためです。いまは入力欄にカーソルがあるあいだは、← → を文字の間の移動に譲ります。アドレスバーと検索欄でも同じことが起きていたので、あわせて直しました。一覧にフォーカスがあるときは、これまでどおり ← → でペインを移れます。

### Removed

- **フォルダを移るたびに一覧とパンくずが動く演出をやめました (#392)** 〔先行版 1.17.3.4〕 — フォルダを移ると、一覧とパンくずを薄い状態から出し、移った向きから一覧を少し滑り込ませていました（パンくずの新しい段も右から入っていました）。移るたびに毎回動くので、目障りになっていました。いまは一覧とパンくずがそのまま切り替わります。読み込みに時間がかかるときに一覧の上端に流れる細い線は、待っている合図なので残しました。タブを切り替えたときの動きは変わりません。
