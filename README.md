## Latest Changes — [1.11.0] - 2026-08-18 : A tidier distribution folder, replies to your feedback in the app, and batch renaming

### Added

- **You can now see the status of the feedback you sent, and read the developer's replies, inside the app.** Until now there was **no mechanism for a reply to reach you** — feedback went out and nothing came back. **Your submissions** now appear as a table at the bottom of the Feedback page, listing status, reference number, type, subject, date sent and reply count. Status is one of **In progress / Done / Not planned / Not checked**, shown with **both an icon and a text label** (never colour alone). Clicking a row expands it to show **the developer's replies and your own, in chronological order** (theirs aligned left, yours right). Reply text is **rendered with its emphasis, headings, bullets and code formatting applied**, so the markup characters are never left showing. **You can reply on the spot**, so it becomes a conversation rather than a one-way report. When a reply is unread, a **count badge** appears on "Feedback" in the left menu and an accent bar appears at the left edge of the row; opening the row marks it read. **The app only contacts the network when you open the Feedback page** — never at startup. Offline, whatever is stored locally is still readable. Only replies to reports **you sent yourself** are shown; there is no way to read someone else's report by entering its number.

- **Conversations you have with Claude Code in the terminal are now saved automatically, in a form you can read back later.** The screen-buffer log added previously **cannot capture a full-screen app like Claude Code even in principle** — its display lives in a region that only ever holds "the current screen", not the scrollable history the log reads from. In practice, a session log from a Claude Code run was mostly blank; not a word of the conversation survived. Conversations are now built instead from **the record Claude Code itself writes (its transcript)**, converted straight into Markdown. Your messages and Claude's response text are kept in full; actions such as running a command or editing a file are summarised in **one line**, like `> Bash: git status` (the results of those actions are not included). Each of your messages gets its own heading, so it's easy to scan later and **searchable with Grep from inside the app**. Files are saved alongside the screen log in the same `data\logs\terminal\` folder, distinguished only by the `.md` extension (cleaned up automatically after 30 days, just like the screen log). This works whether or not the usage meter is displayed — all it needs is Claude Code's usage hook to be registered.

On a gauge of over a hundred cells this is a difference of one or two cells, so the length looks unchanged.

- **Fixed the terminal screen log filling up with nothing but Claude Code's launch command, over and over.** The fix just before this one made the bookmark that remembers "how far we've already written" refresh only while the regular, visible screen region is active — but a session that **moves into the hidden full-screen region right after starting, as `cd ... && claude` does, never gets a bookmark at all**. The fallback position for that case (the number of lines already handed over) was being recorded, yet **only ever read when a bookmark existed**, so each 15-second append started over from the top. The result was **the single launch-command line piled up indefinitely** (in a real log, the same line 97 times over a 24-minute session, with nothing else recorded at all). That line count is now used as the starting point directly while no bookmark exists. A session that only ran Claude Code therefore keeps **just one copy** of the launch command, and shell activity after you leave Claude Code is recorded on from there.

- **Fixed closing a terminal tab splitting one session's log across two files.** The final chunk was landing in **a separate file with a new timestamped name and its own header** (in practice, a single session split into a 160-byte file and a 95-byte one). Closing a tab **asks the screen side to write out its contents and then waits for the reply**, but the mapping of "which file to append to" was being discarded immediately after the request went out — so by the time the reply arrived, the tab **looked like one being recorded for the first time, and a new file was created**. The mapping is now discarded **only after the final append has been written**. Two related hazards were addressed at the same time: closing a tab while a 15-second append is already in flight leaves two requests running at once, and concurrent appends can complete out of order. The mapping is now **kept for as long as any request is still unanswered**, and **appends to the same tab always wait for the previous one to finish**. One session therefore stays in one file.

- **Fixed the app being able to crash when another application held the clipboard at the moment you pasted.** The previous update protected the copy (write) side, but **the paste (read) side was left unguarded**. Reading the clipboard involves opening it internally, so pasting during the instant a browser, an IME, a third-party clipboard manager or monitoring software (EDR/DLP) holds it would fail — and **take the app down with it**. Reads now run on a dedicated thread and retry automatically at 50, 100 and 200 millisecond intervals. If the clipboard still cannot be read, the app no longer crashes: it reports **"Clipboard is busy. Could not paste."** and stops there. Pasting from Outlook (dropping files attached to a mail straight into a folder) keeps working as before — the attachment extraction is completed inside that same thread.

- **Hovering a theme card now animates instead of snapping.** The border colour and thickness used to **switch instantly**, which felt abrupt. The border now **fades up and the card lifts slightly** (0.18s on entry, 0.28s on exit). Only **opacity and position** are animated — both handled on the graphics side — so 50 cards on screen cost nothing extra. The border thickness **no longer changes at all**: altering it forces a layout pass every time, which would undo the scrolling work above. With effects turned off, the same appearance appears instantly (the response itself is never removed). **Theme store cards now respond the same way** — until now they alone had no border glow, and lifted differently from the rest. Store cards also **show a border on the theme you are currently using**, which previously could not be told apart on the store side. **Achievement and reward cards respond at the same speed**, but there the card only **lifts** — with around 300 of them on screen, layering a glow onto each would add drawing work and undo the earlier effort to make that list scroll smoothly. The gold borders and completed-state highlights are unchanged.

- **Scrolling the theme list is now lighter.** The icons on each card were drawn as shapes that get **redrawn from scratch every time**, so every scroll recalculated the outlines of everything on screen. With 50 themes and up to 6 icons per card, that calculation alone accounted for most of the work done during a scroll. The icons are now **pre-drawn and frozen into images**, reducing the outline calculation to a simple rectangle (they look exactly the same). Measured, the share of frames that could not be drawn smoothly went from **47% to 4%**, and time lost to late drawing from **322ms to 37ms per second** — 9 out of 10 frames now land within the display's refresh interval. **The theme store shares the same card layout**, so it gets lighter too. The same treatment was applied to the **rewards collection** cards (around 300 of them). The achievements page received this in the previous update; this is the second round.

- **Fixed records of the screen freezing carrying no indication of what had been running.** When the screen stops responding, the app records the duration alongside what it was doing at the time — but it **wrote the record only after recovery**, by which point the operation had finished, so **almost every entry said "nothing in progress"** (in practice, a 0.78-second freeze from an Outlook drop was recorded that way). The app now picks up the operation that was running during the frozen window, so the next freeze can be traced to a named cause.

- **Fixed the same warning flooding the log on machines that cannot read the stored AI API key.** The API key is saved using Windows encryption, which **can only be decrypted by the PC and user account that encrypted it**. Carrying settings over from another PC therefore makes decryption fail no matter how many times it is tried — yet the app **recorded the same warning on every startup and on every settings change**. Since the "recent error log" attached to feedback submissions holds only a limited number of entries, **that one line was pushing out the errors actually worth seeing**. The warning is now recorded only once per distinct value. **The stored key is not discarded** — it decrypts again on the original PC, so removing it would force a needless re-entry.

- **Fixed the settings pages stalling every time they were reopened (third round of the scrolling work).** The previous update replaced the icons on each card with images that are **drawn once and frozen**, but the shelf holding those images had a **cap of 500 entries, which was below what is actually needed**. One image is required per combination of icon shape and color, and the colors differ per theme, so **the themes alone need 50 cards × 5 icons = 250** — with the store, achievements and rewards on top of that, and more colors added every time a theme is switched, the cap was within reach. Anything past the cap never makes it onto the shelf, so **every reopen redraws it**. The cap has been raised so everything needed fits, and the **theme-list icons are now prepared in the background the moment the settings window opens** (nothing runs at all unless the settings window is opened, so startup stays as fast as before). In addition, each card **used to walk far up the screen hierarchy on its own to read a setting**; that walk is now done once per list and shared by every card (50 walks → 1 for themes and the store, roughly 300 → 15 for achievements and rewards). Nothing changes visually.
- **The warning shown when Box API credentials are missing now matches every other input error.** Pressing "Save and continue" with Client ID, Client Secret or the redirect URI left empty raised a **modal dialog** on this screen alone, blocking everything else until it was dismissed. The same "input required" warning in AI theme generation and stickman generation appears as a **status bar notification**, so the two behaved inconsistently. It is now a notification as well, so you can read it without your work being interrupted.

- **ターミナルを表示している間だけ、ステータスバーの相棒をめんだこ（Claude Code のマスコット）に変えるようにした:** ステータスバー上辺を歩き回る相棒は、これまでテーマの区分に応じて犬・猫・小型ロボット・大型犬・ドット風ロボットの 5 種類に変わる仕組みで、**ターミナルで Claude Code を動かしていても見た目は何も変わらなかった**。ターミナルが画面に見えている間は、相棒を**めんだこ**（Claude Code のマスコット）に差し替えるようにした。A/B ペインのターミナルタブ・ナビペインに埋め込んだターミナルのどちらでも切り替わり、**閉じるとテーマ由来の元の種類に戻る**（左右に 2 つ開いて片方だけ閉じた場合はめんだこのまま）。テーマの色には追従せず**常に Claude のサーモン色で描く**ので、いま Claude と作業していることが目の端で分かる。足を着けずにふわふわ浮きながら、5 本の触手と耳ヒレをゆっくり動かす（寝るときは沈み込んで目を閉じる）。設定画面の「Stickman」にある**「ターミナル中はめんだこ」**で切り替えられる（既定は ON。OFF にすると従来どおりテーマ連動の相棒のまま）。「犬のコンパニオンを表示」を OFF にしている場合は、めんだこも出ない

- **ターミナルのログを「履歴」ボタンから直接開けるようにした:** ログは `data\logs\terminal\` に自動で溜まるのに、**アプリ内からそこへ辿る導線が無かった**。ターミナルの反対側のペインでログフォルダを表示しておき、毎回自分でパスを手繰る必要があった。「履歴」ボタンのメニューに**セッションログ**の区画を設け、3 つの項目を足した。**「ログフォルダを開く」**はサブメニューで開き先を選べる — **反対側のペイン**（ターミナルが A ペインにあれば B ペインへ。**どちらのペインで作業していても、いま見ているターミナルを潰さずにログが並ぶ**）・A ペイン・B ペイン・エクスプローラ。1 画面表示のときに B ペインを選ぶと**2 画面に広げてから**開き、フォルダタブが無いペインでは**新しいタブとして**開くので、押しても何も起きない状態にはならない。**「現在のターミナルログを開く」「現在の Claude Code ログを開く」**は、いま動いているセッションの `.log` / `.md` を関連付けられたアプリで直接開く。まだ記録が無いあいだ（起動直後、または Claude Code の最初の応答前）は**押せない状態にして理由をツールチップで示す**ので、空振りしない。ナビペインのターミナルには自分のペインが無いため「反対側のペイン」は出ない

- **ファイル I/O が遅いドライブを実測で見つけて、重い読み込みを自動で控えるようにした:** クラウド同期ドライブ（Box・OneDrive 等）や監視ソフトが入った環境では、フォルダを開く・ファイルを選んでいくといった操作が引っ掛かることがあった。実測したところ、クラウド同期ドライブはローカルの SSD に比べ **1 ファイルあたり約 40 倍**（読み書きの速度では約 160 倍）遅く、**この差はアプリ側の並列処理をどう調整しても縮まらない**ことが分かった。そこで、**普段の操作で既に発生している問い合わせの所要時間をそのまま観測**し、遅いドライブを見つけたら**「無くても操作そのものは成り立つ読み込み」を自動的に控える**ようにした ── 具体的にはサムネイルの作成、大きな画像のプレビュー、フォルダツリーでアイコンを取る前に行っていた先回りの一覧取得（Box Drive の暖気）である。アイコンの取得そのものは従来どおり行うので、**アイコンが出なくなることはない**。判定は**ドライブごと**に持つので、片側にクラウド同期フォルダ・もう片側にローカルを並べていても、**速い側の操作は一切影響を受けない**。遅い状態が続かなくなれば自動で元に戻る。**判定のために新しい問い合わせは一切足していない**（速さを測るために遅くなる、という本末転倒を避けている）。小さい画像は遅いドライブでも実害が無いためそのまま表示するので、プレビュー機能自体が失われることはない。**あわせて、クラウド同期ドライブ（Box）では画像のサムネイルを一律で出さない仕様をやめた** — 従来はパスの形だけで判断して**ドライブが十分速くてもサムネイルが永久に出なかった**が、実測して遅いときだけ控えるようにしたため、速い環境では通常どおりサムネイルが並ぶ（同期が済んでいないファイルは従来どおり対象外）。判断には**処理したデータ量あたりの時間**も使うので、「大きな画像だから時間がかかった」ケースを「ドライブが遅い」と取り違えない。設定画面の「Effects」にある **「I/O の自動間引き」**で切り替えられる（既定は ON）。従来の「自動軽量モード」とは**別の設定**で、あちらは画面の描画が重い環境で演出を控えるもの、こちらはドライブが遅い環境で読み込みを控えるもの

- **選択したファイル・フォルダの名前をまとめて変更できるようにした（一括リネーム）:** これまで名前の変更は **1 件ずつ**しかできず、10 件処理するにはダイアログを 10 回開く必要があった。選択したアイテムを右クリックして**一括リネーム**を選ぶと、専用のウィンドウが開く（`Shift+F2`、ペイン上部のアイコンバーからも開ける）。ウィンドウは **3 段構成**で、上段の**リネームマスク**に `$N`（元の名前）・`$E`（拡張子）・`$P`（親フォルダ名）・`$G`（その上のフォルダ名）・`${}`（連番）・`$YYYY$MM$DD`（日付）といった変数を書くと新しい名前を組み立てられる。変数はボタンからも挿し込める。中段の**検索／置換**は正規表現に対応し、`(\d{4})(\d{2})(\d{2})` → `$1-$2-$3` のような書き換えができる。記法は Windows 標準の PowerToys PowerRename に合わせてあるので、**すでに知っている書き方がそのまま通る**。記号を覚えていなくても組めるよう、**変数ボタンの下に凡例と、いま選んでいるファイルでの変換例**（`例: report.txt → report_20260813.txt`）を常時表示している。正規表現にチェックを入れると `\d+` `\s+` `.*` `( )` `$1` などの**挿入ボタンと凡例**が現れ、さらに**プレビューの「変更前」列で、検索がマッチした部分が色付きで示される**ので、思ったとおりに動かないときも原因を目で追える。下段には**変更前 → 変更後の 2 列プレビュー**が並び、**実行する前に 1 行ずつ結果を確認**できる。気に入らない行は**チェックを外して個別に除外**でき、「変更されるものだけ表示」で絞り込める。名前が**重複する行・使えない文字を含む行**は赤く表示され、**問題が残っているあいだは実行ボタンが押せない**ので、気づかないまま壊すことがない。適用範囲（名前部のみ／拡張子のみ／両方）・文字種変換（小文字・大文字・文の先頭・各単語の先頭）・ファイルとフォルダの対象切り替え・日付の参照元（更新日時／作成日時）も選べる。`a → b, b → a` のように**名前が入れ替わる指定でも壊れない**（内部で一時的な名前を経由する）。実行後は **`Ctrl+Z` の 1 回ですべて元に戻る**。組んだルールは**プリセットとして名前を付けて保存**でき、次回から呼び出せる。プレビューの再計算は入力のたびに裏側で行うので、**何件選んでも操作が止まらない**

### Changed

- **アプリが作るファイルを、EXE と同じ場所の `data` フォルダにまとめた:** これまで設定・テーマ・ログ・検索インデックスなどが EXE の隣に直接並んでいたため、実行に必要な数百個の DLL と混ざってフォルダが乱雑になっていた。**アプリ由来のファイルはすべて `data` フォルダ配下**に置くようにした。既存の環境では**更新後の初回起動時に一度だけ自動で移動**されるので、設定・テーマ・インデックスはそのまま引き継がれる。全データを EXE と同じ場所に保持するポータブル設計は変わらない

- **展開したフォルダに見えるものを、起動用のアプリと `data` フォルダだけにした:** 上記の整理をしてもなお、実行に必要な DLL が数百個そのまま並んでいたため、初めて開いたときにどれを起動すればよいか分かりにくかった。**プログラム本体一式を `data` フォルダの中（`data\bin`）へ移し、展開直後に見えるのは `ZenithFiler.exe`・`data` フォルダ・説明書の 3 つだけ**にした。既存の環境から更新した場合も、**初回起動時に古いファイルが自動で片付けられる**（自分で置いたファイルには手を触れない）。なお**この更新のダウンロードは完全版になる** — ファイルの置き場所そのものが変わるため、変更分だけを当てても必要なファイルが揃わない。次回以降は、前のバージョンから続けて更新した場合は**変更分のみ（差分版）**、バージョンを飛ばした場合は**完全版**が自動で選ばれる

- **アプリ独自の右クリックメニューを、よく使う操作が拾いやすい構成にした:** 機能が増えるにつれて項目が一列に並び続け、フォルダを右クリックすると **23 項目**（うち 9 項目が区切りなしの連続）になっていたため、目的の項目を目で追うのに時間がかかっていた。**利用頻度の低い操作を「その他の操作」サブメニューへまとめ**、よく使う操作は第一階層に残した（フォルダの場合 23 → 15 項目）。第一階層に残したのは、開く・コピー／切り取り／貼り付け・削除・名前の変更・**ファイル名をコピー・フルパスをコピー**・リンク連携コピー・プロパティ・クイックジャンプなど。「その他の操作」に移したのは、お気に入りへの追加・ショートカットの作成・インデックス検索・CSV／Excel 出力・ホームフォルダへの設定・PDF 変換・連携用 BOX パスのコピー。背景（空きスペース）・ファイル・複数選択の各メニューも同じ方針で揃えている

- **Windows の右クリックメニューにあるアプリの項目を、アプリ独自メニューから直接使えるようにした:** これまで Visual Studio・VS Code・Git・7-Zip・SAKURA Editor・Everything・Microsoft Defender などの項目を使うには、**いったんエクスプローラ互換メニューに切り替える必要**があった。独自メニューに **「OS標準メニュー」サブメニュー**を追加し、Windows に登録されているアプリの項目を**アイコン付きでそのまま**呼び出せるようにした（7-Zip のような入れ子のメニューもそのまま展開される）。開く・コピー・削除・名前の変更・プロパティのように**独自メニューに同じ機能があるものは重複表示しない**。Box や OneDrive の項目は従来どおり「クラウドメニュー」側に出る

- **右クリックメニューの項目ごとの利用回数を記録するようにした:** これまでは「メニューを開いた回数」しか記録しておらず、**どの項目がよく使われているかを実データで確認できなかった**（そのため配置の判断が推測になっていた）。項目ごとに回数を記録するようにしたので、今後の並べ替えは実際の使用状況に基づいて判断できる。記録は端末内のデータベースに保存されるだけで、外部へ送信されることはない。設定画面の「使用統計」の表示内容は従来どおり変わらない

- **ターミナルのボタンを 5 つのグループにまとめ、Claude Code を意図しないフォルダで起動しないようにした:** ボタンが 1 機能につき 1 個ずつ増え続け、下部のバーに **17 個**が横一列に並んで画面幅を食っていた。とくに「Claude 起動」の右には**過去のフォルダを選ぶドロップダウンが幅 11 ピクセルで隙間なく密着**しており、履歴を出すつもりで押し損ねると**そのまま今いるフォルダで Claude Code が立ち上がってしまう**状態だった。ボタンを**「フォルダ」「Claude」「Skip」「履歴」「実行」「オプション」の 6 個**に畳み、**どのボタンも押すとメニューが開くだけ**にした。起動コマンドは必ずメニューの項目を選んでから走るので、隣のボタンを取り違えても起動には至らない

- **ターミナルのフォルダ選択を、名前だけでなくフルパスで見て選べるようにした:** 過去に Claude Code を起動したフォルダの一覧は**末尾のフォルダ名だけ**を高さ 24 ピクセルの行で並べていたため、`ZenithFiler` のように似た名前が続くと**どれがどれか区別できず、確かめるにはマウスを乗せて待つ**しかなかった。各行を**フォルダ名（太字）＋フルパスの 2 段組**にして行の高さを広げ、**今いるフォルダには「現在地」バッジ**を付けた。先頭 9 件は**数字キー 1〜9 でも選べる**ので、狙いを定めずに指定できる。A/B ペインのフォルダへ移動するメニューも同じ作りに揃えている

- **フィードバックを送ると受付番号が出るようにし、送信の控えを手元に残すようにした:** これまでは送信しても「送信しました」以外に何も残らず、**あとから「あの報告はどうなったか」を照合する手段がなかった**。送信に成功すると **受付番号**（例: `受付番号 #220`）を表示し、番号・表題・分類・送信日時を `data\feedback_history.json` に控えとして保存する（最新 50 件、古いものから順に消える）。再起動しても残る。**送信内容に送信者を特定する情報は一切足していない** — 番号と送信者の対応付けは、この手元の控えだけで完結する。番号が取れなかった場合も送信は成功として扱い、従来どおりのメッセージを出す

- **フィードバック送信まわりの内部セキュリティを強化した:** 送信に使う内部の資格情報を、フィードバックの受付に必要な最小限の範囲だけに作り直した。送信の動作・手順・送る内容はこれまでと変わらない

- **Outlook からドラッグ＆ドロップしたときに画面が一瞬止まる時間を短くした:** 実測で **0.6 秒** 止まっていた（添付 1 件・300KB）。添付そのものの取り出しは「**その場で終わらせないと元のデータが無効になる**」という Windows 側の決まりがあるため画面を止めて行うしかないが、**その後の処理まで画面を止めたまま**続けていた。具体的には保存先フォルダの実体解決・存在確認・同名ファイルの重複チェックで、いずれもディスクへの問い合わせを伴う。とくに重複チェックは**添付 1 件ごとに毎回**画面側で行っていたため、添付が多いほど積み上がっていた。クラウド同期フォルダ（Box・OneDrive 等）や監視ソフトが入った環境では、この問い合わせだけで数百ミリ秒かかることがある。**取り出し以外のすべてを裏側の処理に移した**ので、止まる時間は取り出しの分だけになった。あわせて、添付の受け取り方を **1 回分の無駄な問い合わせを省く**ようにした ── Outlook は 3 通りある受け取り方のうち 1 番目を拒否して 2 番目で返すため、**添付 1 件ごとに必ず 1 往復を捨てて**いた。前回うまくいった方法を覚えておき、次はそれから試すようにしている（相手のアプリによって当たりが違うため、固定の並べ替えではなく学習方式にした）。取り出し・コピー・空振りにそれぞれ何ミリ秒かかったかも記録するようにしたので、今後は推測せずに切り分けられる

### Fixed

- **フォルダを 1 階層上へ切り貼りすると、エラーになったうえで中身ごと消えてしまう問題を修正:** 圧縮ファイルを展開したときによくできる `hoge\hoge\aaa.abc` のような二重フォルダを `hoge\aaa.abc` に直そうとして、内側のフォルダを切り取り、**外側と同じ場所へ貼り付けて上書きした場合**に起きていた。上書きは「先に既存を削除してから移動する」順で動いていたため、**削除の対象（外側のフォルダ）が移動元（内側のフォルダ）を含んでいる**この状況では、削除の時点で移動するはずの中身まで一緒に消え、続く移動が失敗して**ファイルが完全に失われる**状態だった。**移動元と移動先が入れ子になる転送は実行前に見送り**、その旨を通知するようにした（エクスプローラと同じ扱い。移動元・移動先はどちらも無傷のまま残る）。あわせて上書きの手順自体も見直し、**ファイルは削除せずそのまま上書き**、**フォルダは「新しい方を先に移してから古い方を破棄」**する順序に変更した。これにより、途中で失敗しても移動先を失わない
- **Box の「リンク連携コピー」が「共有に失敗しました」となり、リンクを取得できない問題を修正:** 前回の更新で「リンクをコピーすると同時に開く共有ウィンドウを自動的に閉じる」ようにしたが、**この共有ウィンドウこそがリンクを作っている実体**で、開いた直後（実測 0.9〜1.2 秒後）に閉じていたためリンクの生成そのものが中断されていた。実機ログでは、この機能が入って以降の「リンク連携コピー」が **4 回中 4 回すべて失敗**していた。**リンクがクリップボードに入ったことを確認してから閉じる**ように変更し、1 回押すだけで手に入る使い勝手はそのまま、生成を中断しないようにした。リンクを取得できなかった場合は共有ウィンドウを閉じずに残すので、そのまま共有ウィンドウ側で操作を続けられる

- **「リンク連携コピー」を押しても何も起きず、20 秒待たされることがある問題を修正:** 実行の直前にメニューを引き直して照合する際、表示名が完全に一致しない場合は誤操作を防ぐために中止していたが、Box は同じ操作を「共有リンクをコピー」「リンクをコピー」と表記し分けることがあり、**構成が変わっていないのに中止**していた。加えて中止しても通知が出ず、進捗表示が 20 秒回り続けるだけだった。表記の揺れを吸収して引き直すようにし、それでも実行できなかった場合は**待たせずにその場で結果を通知**するようにした（誤操作防止のため、「共有」のようにウィンドウを開くだけの項目は従来どおり実行しない）

- **ステータスバー中央で、進捗中のメッセージと完了メッセージが重なって滲むことがある問題を修正:** ステータスバー中央には「操作中のメッセージ（アクセント色）」と「完了メッセージ（通常色）」が**同じ位置に重ねて**置かれており、切り替えは「操作中の文字を消してから完了メッセージを出す」というタイミング頼みの作りだった。ところが進捗表示は 0.03 秒ごとに文字を書き込み続けるため、消した直後に書き戻されて**両方に文字が入った瞬間**が生まれ、そこで 2 文が重なって表示されていた（例:「[Box共有] クリップボードに書き込み中」と「Box共有情報をコピーしました」）。操作中の文字が残っている間は完了メッセージを出さないよう表示条件そのものを変更し、あわせて進捗表示側が**操作終了後は文字を書き込まない**ようにした。リンク連携コピーだけでなく、コピー／移動・検索・エクスポート・お気に入り整理・アップデートの各進捗表示にも同じ対策を入れている

- **「リンク連携コピー」の進捗表示が、ほとんど動かないまま終わっていた問題を修正:** 進捗の更新点が完了直前の 1 箇所しかなく、実際には 3〜4 秒かかる処理の間ずっと 2% のまま止まって見えていた。メニュー取得・実行・リンク取得の各段階に応じて進み、段階の合間もゆっくり伸び続けるようにした

- **「リンク連携コピー」の記録を増やした:** これまで失敗したときしか記録が残らず、再発時に「そもそも実行されたのか」すら追えなかった。実行した項目名・リンク取得までの所要時間・共有ウィンドウを閉じた結果を記録するようにした

- **同じフォルダから 2 つ起動したときに、検索インデックスの作成済み情報が失われることがある問題を修正:** 一方が作成済み情報を保存している最中にもう一方が読み込むと、ごく短い時間だけファイルを開けないことがある。これを「ファイルが壊れている」と誤って判断していたため、正常なファイルを退避したうえで**すべてのフォルダが未インデックス扱いに戻り、大量の再インデックスが走る**ことがあった。読み込みを短時間リトライするようにし、あわせて「壊れている」と「今は読めない」を区別して、後者では元のファイルに一切手を加えないようにした

- **`data` フォルダへの移動が、正常に終わってもログ上は「致命的なエラー」として記録されていた問題を修正:** 更新後の初回起動で一度だけ走る移動処理について、成功した記録まで最も重大なレベルで書き出していた。この移動は全員の環境で必ず一度は走るため、不具合を調べるときに**本当に確認すべき致命的な記録が埋もれてしまう**。完了は通常の記録として残し、失敗したときだけ警告として記録するようにした

- **お気に入りの参照回数とピン留めの並び順が更新されなくなることがある問題を修正:** フォルダの参照履歴に `C:\` と `c:\` のように大文字小文字だけが異なる記録が混ざっていると、集計時にエラーとなり、**参照回数と「よく使う順」の並びが一切更新されない**状態のままになっていた。大文字小文字の違いは同じフォルダとみなして合算するようにした

- **「リンク連携コピー」で共有ウィンドウが一瞬見えてしまう問題を修正:** 共有ウィンドウは表示された瞬間に伏せていたが、**表示されてから伏せるまでに 1 コマ（実測 15〜16 ミリ秒）かかる**ため、その 1 コマが見えていた。Windows はウィンドウを表示する「前」には知らせてくれないので、この方式では原理的に消せない。さらに **Box は伏せたウィンドウを毎回出し直しており**（実測 1〜3 回）、そのたびにまた 1 コマ見えていた。**ウィンドウが作られた時点（まだ表示される前）で画面の外へ退避させる**方式に変え、Box が画面内へ置き直した場合も即座に退避し直すようにした。ウィンドウ自体は生かしたままなので、リンクの生成は従来どおり中断されない。リンクを取得できなかった場合は元の位置へ戻して表示するので、そのまま共有ウィンドウ側で操作を続けられる

- **「リンク連携コピー」の完了メッセージが、進捗メッセージと重なって表示される問題を修正:** ステータスバー中央には「操作中のメッセージ（アクセント色）」と「完了メッセージ（通常色）」が同じ位置に重ねて置かれており、**完了メッセージはリンクを取得した直後（進捗表示が消える約 0.7 秒前）に出していた**ため、両方に中身がある時間が生まれていた。**進捗メッセージが消えるまで完了メッセージを出さず、消えた瞬間に出す**ようにした。これにより、これまで重なっていた時間ぶん**完了メッセージの表示時間（3 秒）が削られていた**問題も同時に解消している。判定条件を 1 箇所にまとめたので、表示側と通知側で条件がずれることもなくなった

- **同じフォルダなのに、参照回数が分かれて数えられていた問題を修正:** フォルダの参照履歴は**パスの文字列そのもの**で 1 件を見分けていたため、`C:\Work` と `c:\work` のように大文字小文字が違うだけの表記が別のフォルダとして記録されていた（アドレス欄への入力・ショートカット・他アプリからのドラッグなど、開き方によって表記が変わる）。そのため**参照回数が分散し、お気に入りの「よく使う順」やホームの「よく使うフォルダ」が実際の使用状況とズレる**ことがあり、履歴の一覧にも同じフォルダが二重に並んでいた。大文字小文字の違いは同じフォルダとして記録するようにし、**更新後の初回起動で既存の記録も自動的に 1 件へまとめる**（参照回数は合計し、最終アクセス日時は新しい方を残す）。あわせて記録するパスのドライブレターを大文字に揃えた。前回の更新で入れた対応は集計時に合算する応急処置だったので、記録する側から直した

- **ターミナルのタブ名をフォルダ名だけにし、ターミナルのタブに色を付けた:** これまでは「Terminal: 」を頭に付けていたため、その分だけ幅を取られて**肝心のフォルダ名が省略されて**いた（`Terminal: myfol...`）。フォルダ名だけを出すようにし、代わりに**タブ自体をテーマのアクセント色で薄く塗って**一目でターミナルと分かるようにした。色はテーマの色を使うので、50 種類のどのテーマでも馴染む

- **ターミナルの内容を、セッション終了時に自動でログとして残すようにした:** これまでターミナルの出力は閉じた時点で消えており、「さっきのコマンドの結果をもう一度見たい」というときに手段がなかった。タブを閉じたときに、**その時点で画面に残っている内容をテキストとして `data\logs\terminal\` に保存**する。ファイル名は日時とフォルダ名なので、後から探しやすい（30 日を過ぎたものは自動で片付ける）。**表示中は一切書き込まない**ので、ターミナルの速度には影響しない。スクロールバックの上限（既定 5000 行）を超えて古い出力が失われている場合は、その旨をログの先頭に記載する

- **Claude の起動メニューを作り直した:** 履歴 1 件が 2 段（名前とパス）で表示されていたため、件数が増えるとメニューが画面の高さいっぱいまで伸び、**いちばん使う「今のフォルダで起動」が上端で見切れて**いた。1 件を **1 行**（名前の右にパスを薄く添える）にして高さを半分にし、画面の上端を越える場合はメニュー内でスクロールさせて**先頭の項目が必ず見えるように**した。あわせて、`C:\work\mywork` と `c:\work\mywork` のように**大文字小文字だけが違う重複**を 1 件にまとめた（重複が限られた表示枠を食い潰していた）

- **ターミナルの操作バーのボタンが、入力中の文字に続けて実行されてしまう問題を修正:** 何か打ちかけの状態で「Claude」「Skip」などのボタンを押すと、打ちかけの文字にコマンドが連結されて別物のコマンドが走っていた。**押した時点で入力中の文字を捨ててから**実行するようにした

- **使用量メータが 2 行に折り返すことがある問題を修正:** 幅が足りないとき、残り時間が次の行へ落ちて操作バーの上を 2 行占有していた。幅に応じてゲージを縮め、それでも入らない場合はゲージを省いて、**必ず 1 行に収まる**ようにした（％と残り時間は常に残す）

- **アプリとターミナルで使用量メータが二重に表示される問題を修正し、空いた行を「累計作業量」メータにした:** アプリ側のメータを表示していると、Claude Code 側の表示と合わせて**同じ数字が上下に並んで**いた。かといって Claude Code 側の行を空にしても、**Claude Code は statusLine を設定している限りその行を必ず確保する**ため、入力欄の下に**空行が居座る**（出力を空にしても詰まらない）。そこで、アプリ側のメータを表示している間は、Claude Code 側の行を**アプリのメータが持っていない情報**へ差し替えるようにした。出すのは **そのセッションを開始してから今までに使ったトークンの累計** で、`作業量 ■■■■■□□□□□ 2.5M tok` のように 1 本のゲージで表す。使用率（ctx / 5h / 7d）と違って減らずに増え続けるので、作業が積み上がっていく様子が分かる。ゲージの満杯は 100k → 250k → 500k → 1M → 2.5M … と、超えるたびに天井が上がるので張り付かない。メータは**ターミナルの横幅いっぱい**まで伸び、ゲージの色は左から右へ**グラデーション**で流れる（色そのものが目盛りになるので、長さと色の両方でどこまで来たかが読める）。幅は折り返さないように計算しており、**文字が見切れることはない** ── 全角のラベルは 1 文字で 2 桁を占めることまで数えているほか、幅が足りない場合は「桁揃え → ラベル → 単位」の順に削って数値だけは必ず残す。累計には**同じ内容を読み直した分（キャッシュ読み込み）は含めない** ── 含めると会話が伸びるほど読み直しの量が膨らみ、新しく積み上がった作業量が読み取れなくなるため。独自の statusLine を設定している場合、アプリ内ではその中継も止まる（中継先が使用率の表示だと、結局同じ数字が並ぶため）。この差し替えが働くのは **Zenith Filer のターミナルの中だけ**で、VS Code など**アプリの外で使っている Claude Code の表示は従来どおり**になる。アプリ内でも Claude Code 側の表示に戻したいときは、使用率メータの表示を切ってください

- **別フォルダの Zenith Filer から使用率メータを有効にすると、元から使っていた statusLine の表示が失われる問題を修正:** アプリを複数の場所に置いている場合（インストール版とポータブル版、更新前後のフォルダなど）、**ユーザーが元から使っていた statusLine の退避先はフォルダごとに別のファイル**になっている。にもかかわらず、別フォルダのフックが登録済みの状態から登録し直すと退避を引き継いでいなかったため、**元の表示が中継されなくなり**（VS Code など、アプリの外で使っている Claude Code でも消えた）、しかも**「フックを解除」しても書き戻せない**状態になっていた。登録し直すときに、別フォルダ側へ退避されている内容を**引き継ぐ**ようにした（相手のファイルは読むだけで書き換えないので、そちらから解除した場合も元に戻せる）

- **ターミナルの Claude Code 上で右クリックすると、同じ内容が 2 回貼り付けられる問題を修正:** ターミナルは右クリックを「選択中ならコピー / 未選択ならペースト」に割り当てているが、**その右クリック自体を、実行中のアプリにもマウス操作として通知していた**。Claude Code は右クリックを「クリップボードから貼り付け」として自前で処理するため、こちらの貼り付けと合わさって同じ文字列が 2 回入っていた（実測でも、送っていたのは 1 回分だけだった）。右クリックはターミナル側で使い切り、**アプリへは通知しない**ようにした。マウス操作を受け取るアプリ（Claude Code 等）を使っているときだけ起きる現象で、コマンドプロンプトでは元から 1 回だった。左ボタン（範囲選択・選択と同時にコピー）と中ボタンの動作は変更していない。あわせて、貼り付けの内部処理にも「1 回の操作につき 1 回だけ貼る」照合を入れ、経路のどこかで二重になっても貼り付けが増えないようにした

- **設定画面（オプション）を開くとしばらく操作できなくなる問題を修正:** 設定画面を独立したウィンドウにした際、**閉じるたびにウィンドウを捨てて、開くたびに作り直す**作りになっていた。設定画面の中身は 8000 行を超える大きな画面で、作り直すたびに画面全体の再計算と、200 項目以上の設定と画面の結び付けをやり直していたため、ボタンを押してから表示されるまで**画面が固まっていた**（実測 2.0 秒）。**セッション中はウィンドウを捨てずに隠すだけ**にして、次に開くときはそのまま出すようにした。あわせて、初回だけ必要な画面の組み立ては**ウィンドウを表示してから**行うようにしたので、押した瞬間にウィンドウが出る（実測 0.07 秒。組み立て中は「読み込み中...」と表示する）。さらに、開くたびに設定ファイル（160KB 超）を読み直す処理と、初回に全フォントを調べる処理を裏側に回し、画面が固まらないようにした。メモリの増加は無い（大きな画面自体は元から保持していたため） ターミナルは右クリックを「選択中ならコピー / 未選択ならペースト」に割り当てているが、**その右クリック自体を、実行中のアプリにもマウス操作として通知していた**。Claude Code は右クリックを「クリップボードから貼り付け」として自前で処理するため、こちらの貼り付けと合わさって同じ文字列が 2 回入っていた（実測でも、送っていたのは 1 回分だけだった）。右クリックはターミナル側で使い切り、**アプリへは通知しない**ようにした。マウス操作を受け取るアプリ（Claude Code 等）を使っているときだけ起きる現象で、コマンドプロンプトでは元から 1 回だった。左ボタン（範囲選択・選択と同時にコピー）と中ボタンの動作は変更していない。あわせて、貼り付けの内部処理にも「1 回の操作につき 1 回だけ貼る」照合を入れ、経路のどこかで二重になっても貼り付けが増えないようにした

- **使用量メータの中継プログラムが、ターミナルを閉じた後も残り続けることがある問題を修正:** Claude Code が使用量を渡すために起動する中継プログラムには、万一応答しなくなっても Claude Code を待たせないよう 10 秒で自ら終了する仕掛けを入れてあった。ところがこの終了処理は**後片付けの完了を待つ**ため、別の処理が解けない待ちに入っていると**その終了処理自体が固まる**。そのため、**Claude Code を終了した後も中継プログラムが残り続ける**ことがあった（実際に 30 分以上生き残っている例を確認）。残ったプログラムはファイルを掴んだままなので、**アプリの更新が「ファイルが使用中です」で失敗する**という実害もあった。10 秒経過時は後片付けを待たず**無条件に終了する**ようにした

- **ゲージのグラデーションをテーマ連動にし、累計作業量メータの天井を実使用から決めるようにした:** グラデーション配色は左から右へ緑→黄→赤の固定色だったため、暖色系のテーマでは浮いて見えていた。**テーマのアクセント色から作った 2 色の間を流す**ようにしたので、50 種類のどのテーマでも馴染む（色相を ±14 度だけずらして明度に幅を付ける方式で、テーマ外の色にはならない）。ターミナル内の statusLine に出る累計作業量メータも**同じ色**を使うので、上下の 2 本が揃う。

  累計作業量メータの目盛りは 100k → 250k → 500k … と天井を機械的に上げる方式だったが、**5 時間枠を使い切った量がちょうど 75% を指す**ように置き換えた。ただし単純な比例では 5 時間枠が大きすぎて**序盤は何時間働いてもほぼ 0% のまま**動かず、かといって天井を段階的に上げる方式では上げた瞬間にゲージが必ず後戻りする（75% → 30% のように落ちる）。そこで**対数で伸ばす**ことにした ── 序盤ほど 1 トークンの重みが大きいので**1 万トークン台から動き始め**、しかも**一度も後戻りしない**。実測では 1.7 万で 9%、100 万で 47%、420 万で 66%、5 時間枠 1 本ぶんで 75%、2 本ぶんで 82% と伸びる。「いま 5 時間枠の何割ぶんの仕事をしたか」として読めて、枠を超えて働いた日も 25% の余白があるので針が振り切らない。5 時間枠 100% が何トークンに相当するかは**実際の使い方から学習する** ── 使用率の伸びとトークンの伸びを突き合わせて割り出すので、モデル（Opus / Sonnet）によって 1% あたりのトークン数が大きく違っても自動で合う。学習が済むまでは実測から求めた暫定値（5 時間枠 ≈ 12.9M トークン）で描く

- **ターミナルのセッションログ（画面バッファの記録）が、空白だらけで実用にならなかった問題を修正:** 前回追加したこの機能は、実際のログを見ると **9 割以上が空白行**で埋まっており、まともに使える状態ではなかった。原因は 2 つ。1 つ目は、画面消去を Windows 側（ConPTY）が**実際にスペース文字で塗りつぶす**方式で行っていたため、行末の空白を取り除く処理が効かず、幅いっぱいのスペース行がそのまま残っていたこと。2 つ目は、「前回どこまで書いたか」を覚えておく仕組みが、**Claude Code のような全画面表示のアプリが使っている裏側の画面領域**に紐付いてしまい、そちら側は履歴を持たない一時的な領域のため、**再描画のたびに位置を見失って画面全体を何度も再取得**していたこと（「スクロールバックの上限に達した」という偽の警告も、実際には何も失われていないのに繰り返し出ていた）。行末の空白を確実に取り除くようにし、位置を覚える仕組みも表側の画面領域に限定して安定させた。これにより、コマンドプロンプトなど**通常のシェルの操作記録として実用できる**ようになった（Claude Code 自身の会話は上記のとおり別の仕組みで残す）

- **使用量メータの右端の文字（週次枠の残り時間）が省略されることがある問題を修正:** ゲージの長さは「行の幅から固定文字の実測幅を引いた残り」で決めているが、実際のレイアウトでは Run ごとの丸めやゲージの枠の測り方で**わずかに広くなる**ことがあり、その数 px が末尾を食って `(あと5d8h)` が `(あとSd8…` のように化けていた。ゲージ 1 本あたりに余裕を先に見込むようにし、さらに**描いた実物の幅を測ってあふれた分だけマス数を削る**ようにした（同じ幅・同じ内容につき 1 回だけ測るので描画は重くならない）。100 マスを超えるゲージに対して 1〜2 マスの差なので、見た目の長さは変わらない

- **ターミナルの画面ログに、Claude Code の起動コマンドだけが延々と積まれ続ける問題を修正:** 直前の修正で「どこまで書いたかを覚える目印は、表側の画面領域にいるときだけ張り替える」ようにしたが、`cd ... && claude` のように**起動してすぐ裏側の画面領域（全画面表示）へ入るセッションでは、目印が一度も張られない**ままだった。目印が無いときの代わりの位置（渡し済みの行数）は記録していたのに、**目印がある場合しか参照していなかった**ため、15 秒ごとの追記が毎回先頭から取り直しになっていた。結果として**起動コマンドの 1 行だけが延々と積まれ続けていた**（実機のログでは 24 分のセッションで同じ行が 97 回。ほかに記録されている内容は皆無だった）。目印が無い間はその行数をそのまま起点に使うようにした。これにより、Claude Code だけを動かしたセッションでは**起動コマンドが 1 回だけ**残り、Claude Code を抜けたあとのシェル操作はその続きから記録される

- **ターミナルのタブを閉じると、1 回のセッションのログが 2 つのファイルに割れる問題を修正:** 末尾のひと塊だけが**新しい時刻名・ヘッダー付きの別ファイル**として落ちていた（実機では 1 セッションが 160 バイトと 95 バイトの 2 ファイルに分かれていた）。タブを閉じるときは、画面の内容を書き出すよう**画面側へ依頼してから返事を待つ**作りなのに、依頼を出した直後に「どのファイルへ追記するか」の対応付けを捨てていたため、返事が届いた時点で**初めて記録するタブと判断され、新しいファイルが作られていた**。対応付けを捨てるのは**最後の追記を書き終えた後**に変更した。あわせて、15 秒ごとの追記が飛んでいる最中にタブを閉じると依頼が 2 件同時に走る点、および追記自体が並行して走ると書き込み順が入れ替わり得る点にも対処し、**未返信の依頼が残っている間は対応付けを捨てない**・**同じタブへの追記は必ず前の 1 件を待ってから始める**ようにした。これにより 1 セッション = 1 ファイルが保たれる

- **貼り付けの瞬間に他のアプリがクリップボードを握っていると、強制終了することがある問題を修正:** 前回の更新でコピー側（書き込み）は保護したが、**貼り付け側（読み取り）だけが無防備なまま残っていた**。クリップボードの読み取りは内部で「クリップボードを開く」操作を伴うため、ブラウザ・IME・他社のクリップボード管理アプリ・監視ソフト（EDR/DLP）が握っている一瞬に貼り付けると失敗し、**そのままアプリが落ちる**経路になっていた。読み取りを専用のスレッドへ逃がし、失敗しても 50 → 100 → 200 ミリ秒と間隔を空けて自動で待ち直すようにした。それでも読めなかった場合は落とさず、**「クリップボードが使用中のため、貼り付けできませんでした」と通知**して終わる。あわせて、Outlook からの貼り付け（メール本文に添付されたファイルを直接貼り付ける機能）が従来どおり動くよう、添付の取り出しを同じスレッド内で完結させている

- **テーマカードにマウスを乗せたときの反応を、なめらかな遷移にした:** これまでは枠の色と太さが**一瞬で切り替わる**だけで、素っ気ない印象だった。**枠がふわりと浮かび上がり、カードがわずかに持ち上がる**遷移（乗せて 0.18 秒、離れて 0.28 秒）に変えた。動かしているのは**透明度と位置だけ**で、これらは描画装置側で処理されるため、カードが 50 枚あっても速度に影響しない。あわせて**枠の太さを変えるのをやめた** ── 太さが変わるとその都度レイアウトの計算が走り、せっかく軽くしたスクロールが重くなるため。演出を切っている場合は、同じ見た目が瞬時に出る（反応そのものは消さない）。**テーマストアのカードにも同じ反応を入れた** ── これまでストアのカードだけは枠が光らず、持ち上がり方も他と違っていた。あわせて、ストアのカードでも**いま使っているテーマに枠が付く**ようにした（従来はストア側だけ、どれを使っているか見分けが付かなかった）。**実績・報酬のカードにも同じ速さの反応を入れた**が、こちらは**持ち上がるだけ**にとどめている ── カードが約 300 枚あるため、1 枚ごとに光の層を重ねると描画の負担が増え、以前スクロールを軽くした対策を打ち消してしまう。金枠や達成済みの強調表示は従来のまま変わらない

- **テーマ一覧のスクロールを軽くした:** カード内のアイコンは**図形として毎回描き直す**部品で置かれており、スクロールのたびに画面全体の図形の輪郭を計算し直していた。テーマは 50 枚あり、1 枚あたり最大 6 個のアイコンが載るため、この計算だけでスクロール中の処理の大半を占めていた。**あらかじめ描いて凍結した画像に置き換え**、輪郭の計算を単純な四角形で済むようにした（アイコンの見た目は変わらない）。実測では、なめらかに描けなかったコマの割合が **47% → 4%**、描画が間に合わなかった時間が **1 秒あたり 322ms → 37ms** になり、9 割のコマが画面の更新間隔に間に合うようになった。**テーマストアも同じ作りを共有している**ため一緒に軽くなる。あわせて**報酬コレクション**のカードにも同じ対策を入れた（こちらはカードが約 300 枚ある）。実績ページには前回の更新で同じ対策を入れており、その第 2 弾にあたる

- **画面が固まった記録に「何をしていて固まったか」が残らない問題を修正:** 画面の反応が途切れた場合、その時間と一緒に「そのとき何をしていたか」を記録する仕組みが入っていたが、**記録するのが復帰した後**だったため、そのころには操作が終わっていて**ほぼ毎回「何もしていない」と記録されて**いた（実測: Outlook からのドロップで 0.78 秒固まった記録が「何もしていない」として残っていた）。固まっていた時間帯に動いていた操作を拾うようにしたので、次に固まったときは原因を名指しで追えるようになる

- **AI の API キーを読めない環境で、同じ警告がログを埋め尽くす問題を修正:** API キーは Windows の暗号化機能で保存しており、**暗号化した PC・ユーザーでしか復号できない**。そのため設定を別の PC から引き継ぐと復号は何度試しても失敗するが、**起動のたび・設定を変えるたびに同じ警告を記録し続けて**いた。フィードバック送信に添付される「直近のエラーログ」は件数が限られているため、**この 1 行が本当に見たいエラーを押し出してしまう**状態だった。同じ内容についての警告は 1 回だけ記録するようにした。**保存されているキーは消さない** — 元の PC に戻れば復号できるため、消すと再入力が必要になってしまう

- **設定画面のページを開き直すたびに引っ掛かる問題を修正した（スクロール軽量化の第 3 弾）:** 前回の更新でカード内のアイコンを「一度描いて凍結した画像」に置き換えたが、**この画像をしまっておく棚の上限（500 個）が実際に必要な数に足りていなかった**。アイコンは絵柄と色の組み合わせごとに 1 個必要で、色はテーマごとに違うため、**テーマだけで 50 枚 × 5 個 = 250 個**、これにストア・実績・報酬ぶんが乗り、さらにテーマを切り替えるたびに色が増えるため、上限に届きうる状態だった。上限を超えた分は棚に載らないので、**ページを開き直すたびに描き直しになる**。上限を引き上げて必要な分がすべて載るようにし、さらに**テーマ一覧ぶんのアイコンは設定画面を開いた時点でバックグラウンドで先回りして用意する**ようにした（設定画面を開かない限り一切動かないので、アプリの起動は速いまま）。あわせて、**カード 1 枚ごとに画面の親を延々とたどって設定値を読みに行っていた**のをやめ、一覧の単位で 1 回だけたどった結果を全カードで共有するようにした（テーマ・ストアで 50 回 → 1 回、実績・報酬で約 300 回 → 15 回程度）。見た目は変わらない
- **Box API の認証情報が未入力のときの警告を、他の入力エラーと同じ通知に揃えた:** Client ID・Client Secret・リダイレクト URI のいずれかが空のまま「保存して続行」を押すと、この画面だけ**モーダルダイアログ**が出て、閉じるまで他の操作ができなかった。AI のテーマ生成やスティックマン生成では同じ「入力必須」の警告が**ステータスバーの通知**で出ており、扱いが揃っていなかった。通知に統一したので、操作を止められずに内容を確認できる
