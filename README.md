## Latest Changes — [1.14.8] - 2026-09-04 : Macros from a sentence, plus clearer new files, network locations, and Explorer handoff

### Added

- **Macro Studio can now build a macro from a sentence:** Until now every macro had to be assembled by hand — drag each part off the palette, fill in its arguments, wire them together. **Write something like "file the PDFs into monthly folders and notify me", press "Generate", and those parts appear on the canvas already wired up.** What comes out is **an ordinary macro, no different from one you built yourself**, so you can keep adding parts and editing arguments. **Generating does not run it** — you look it over, and press ▶ when you are happy with it. If it isn't what you meant, reword the request and press Generate again. The name of the folder you have open and what is in it (the first 40 items) are sent along, so phrases like "the selected files" or "the images in here" make sense to it — **the folder's actual location is never sent**. Requires an AI provider to be configured.

- **Part settings moved into the right pane, where there is room for them:** Each part's settings used to live **inside its card**. A card is only 248px wide, yet it had to hold a label, an input field, and the 📁 Browse, ▾ Presets and { } Tokens buttons — leaving **roughly 100px for the input itself**, too narrow to read or fix a folder name or message of any length. **Clicking a card now opens "Part settings" in the right pane**: the input takes the full width, and Browse, Presets and Tokens sit below it as full text labels. What the part does, and the JavaScript it produces, are shown there too. **The card is now just a place to read the part's name and its current value**, so it is about half as tall — which makes **the whole macro readable at a glance**. The selected card gets a thicker accent-coloured border so you can see what the right pane is editing. The right pane is wider now and scrolls when there is more to show.

- **New "≡ Tidy" button re-arranges scattered cards:** Dragging cards around, adding parts, deleting others — the canvas drifts out of shape, and until now the only fix was **moving every card back by hand**. "≡ Tidy" at the top-left of the canvas **lays the cards out to follow their connections**: a straight run becomes a single column, and a branch sends "yes" downwards and "no" into the column to its right. It is **exactly the layout the AI generator uses**, so a macro you built by hand and one that was generated end up looking the same. **The cards are not rebuilt** — connections and the values you typed stay untouched, only the positions move (they animate, so you can follow where each card went). Spacing is worked out from each card's real height, so a mix of long and short values does not end up cramped. Cards that are not connected to anything, or that form a loop, are gathered in a column at the right — **nothing ever disappears**.

- **New "Script" part for anything the other parts cannot express:** Sorting by extension, moving only the files above 1 MB — anything that means **walking a list and branching on a condition** — could not be expressed with the existing parts. There is now a part on the palette that **takes JavaScript directly**. Its card holds a multi-line editor, and what you write becomes part of the macro as-is. Generated macros use it too, but only where the real parts fall short.

- **New files and network locations are now visible at a glance (#287):** Added after a report of putting an unprocessed file into the folder meant for processed ones. What made that mistake possible was that **whether the file at hand is current** and **where you are about to put it** were both invisible while working. **Recently modified files now show their date in bold**, and anything touched in **the last 10 minutes gets a ✨ mark** that **clears itself** once the time passes. Alongside that, **having a network folder open now tints the tab and the address bar**, and the tab icon becomes a globe — so a shared server is never mistaken for your own machine. It recognises more than `\` paths: **mapped drives like `Z:` are identified too**. The colours are derived from each theme's accent, so nothing clashes across the 50 bundled themes. Under **Settings → Display**, "Spotting what's new" lets you pick the range — off, today, 24 hours, 3 days or 7 days — and the ✨ mark and the network tint can each be turned off on their own.

### Changed

- **Drag and drop now follows the same rule as Explorer (#288):** Until now, **anything you dropped was moved unless you held `Ctrl`**. Explorer's rule is **move within the same drive, copy when crossing to another drive, a network share, or a server**, and Zenith Filer now does the same. You can still be explicit: hold `Ctrl` to copy, or `Shift` to move even across that boundary (`Shift` is newly honoured). **Within a single drive nothing changes at all** — what changes is that dropping onto another drive or a server now **leaves the original where it was**.

### Fixed

- **Fixed "Copy Share Link" for Box at the root cause (#273):** 1.14.7 stopped hiding the share window, but **the link still never arrived**. The problem was not how it was hidden — it was **hiding it at all**. Box writes the link to the clipboard from inside the share window the moment it has been created, and that write is **refused outright unless the window is in the foreground**: even sitting in plain view, a window without focus always fails. Zenith Filer moved the share window off-screen and never brought it forward, so **no amount of waiting would produce a link** — and every way of hiding it we had tried (hiding, moving off-screen, making it transparent) ends the same way. The share window is now **shown normally and brought to the front**. As soon as Box has written the link, it is **closed automatically and focus returns to Zenith Filer**. The window is visible for one to three seconds in practice, and **you still only press one thing**: the menu entry. If the link still hasn't arrived after 8 seconds, the window is left with you and the prompt to copy it there appears, as before — and anything you copy by hand is still formatted into the usual path / URL / file name block.

- **Fixed files cut in Explorer being pasted as copies (#288):** Pressing `Ctrl+X` in Explorer and `Ctrl+V` in Zenith Filer left **the original file in place**. Whether a cut or a copy was intended is carried by a marker Windows puts on the clipboard, and that marker is **a set of flags that can be combined** — Explorer's cut raises "move" alongside another flag. Zenith Filer treated **only the exact value for "move"** as a cut, so the combined marker fell through and was handled as a copy. It now reads the "move" flag out of whatever else is set. **Cutting inside Zenith Filer always worked**, because it writes the exact value — which is why this only ever failed when the files came from Explorer.

- **Fixed files dragged to a server being copied while the originals disappeared (#288):** Dropping onto a pane connected to a server (FTP/SFTP), Zenith Filer **sent the files as a copy** but reported back to the drag source that it had **moved** them. Deleting the original is **the drag source's job**, so you could end up with the copy on the server and **nothing left on your machine**. It now reports the operation it actually performs. On top of that, cutting and pasting to a server now tells you that **it was carried out as a copy and the originals were kept** — moving to or from a server is not supported yet.

## 最新の変更履歴 — [1.14.8] - 2026-09-04 : マクロを言葉から組み立てられるようにし、新着とネットワークの見分け・エクスプローラーとの受け渡しを直した

### Added

- **マクロスタジオに、やりたいことを言葉で書くとマクロを組み立ててくれる欄を付けた:** これまでマクロは、部品を一つずつパレットから引っ張ってきて、引数を埋めて、線で繋ぐ必要がありました。**「PDF を月別フォルダへ整理して通知」のように書いて「AI生成」を押すと、その通りの部品が線で繋がった状態でキャンバスに並びます**。生成されたものは**普通に組んだマクロとまったく同じ**なので、そのまま部品を足したり引数を書き換えたりできます。**生成しただけでは実行しません** — 中身を見て、納得してから ▶ 実行を押す流れです。思っていたものと違うときは、指示を書き直してもう一度押してください。いま開いているフォルダの名前と中身（先頭 40 件）も一緒に渡すので、「選択中のファイルを」「この中の画像を」といった書き方が通じます（**フォルダの場所そのもの（フルパス）は渡していません**）。生成 AI の設定が必要です。

- **マクロスタジオの部品の設定を、右ペインでゆったり行えるようにした:** これまで各部品の設定は**カードの中**にありました。カードは幅 248px しかないのに「ラベル・入力欄・📁参照・▾プリセット・{ }トークン」を詰め込んでいたため、**入力欄に残る幅は 100px 程度**しかなく、少し長いフォルダ名やメッセージを入れると読めない・直せない状態でした。**カードをクリックすると、右ペインに「部品の設定」が開く**ようにしています。入力欄は横幅いっぱいを使い、参照・プリセット・トークンの各ボタンも省略なしの文字ラベルで並びます。その部品が何をするものかの説明と、生成される JavaScript もここで確認できます。**カード側は「何をする部品か」と「今の値」を読ませるだけ**になり、高さが約半分に縮んだので、**マクロ全体の流れが一目で追える**ようになりました。選択中のカードは枠がアクセント色で太くなり、右ペインがどれを編集しているか分かります。右ペインは幅を広げ、内容が増えてもスクロールで追えるようにしています。

- **散らばったカードを並べ直す「≡ 整列」ボタンを追加した:** カードを手で動かしたり、部品を足したり消したりを繰り返すと、キャンバス上の配置は少しずつ崩れます。これまでは**一枚ずつ手で並べ直す**しかありませんでした。キャンバス左上の「≡ 整列」を押すと、**つながりの順にカードを並べ直します** — 直列の流れは縦一列に、条件分岐は「はい」を下へ、「いいえ」を右隣の列へ流します。**AI 生成が使うのとまったく同じ並べ方**なので、手で組んだマクロも生成したマクロも同じ見た目に落ち着きます。**カードを作り直すわけではない**ので、接続も入力した値もそのまま残り、位置だけが動きます（アニメーションで移動するので、どのカードがどこへ行ったか追えます）。カードの実際の高さを測って間隔を決めるため、値が長いカードと短いカードが混ざっていても詰まりすぎません。つながっていないカードや、輪になってしまったカードも右端にまとめて置かれるので、**消えたように見えることはありません**。

- **部品で表せない処理を書ける「スクリプト」部品を追加した:** 「拡張子ごとに仕分ける」「1MB を超えるものだけ移す」のように、**一覧を回して条件で分ける処理**は、これまでの部品では表せませんでした。**JavaScript を直接書ける部品**をパレットに追加しています。カードの中が複数行の入力欄になっていて、書いた内容がそのままマクロの一部として動きます。AI 生成でも、部品で足りないところにだけこの部品が使われます。

- **新しいファイルと、ネットワーク上の場所が、ひと目で分かるようにした (#287):** 「加工前のファイルを、加工後を置く場所へ入れてしまった」というご報告から追加した機能です。事故のもとは**手元のものが新しいかどうか**と**今どこへ置こうとしているか**が、作業中に目に入らないことでした。**最近更新されたファイルは更新日時が太字になり**、**たった今（10 分以内）更新されたものには ✨ のしるし**が付きます。しるしは時間が経つと**自分で消えます**。あわせて、**ネットワーク上のフォルダを開いている間はタブとアドレスバーに色が付き**、タブのアイコンが地球のかたちに変わります。共有サーバーを自分のパソコンと取り違えたまま操作する状態を無くすためです。ネットワークかどうかは、`\` で始まるパスだけでなく、**`Z:` のように割り当てたドライブも見分けます**。色はテーマのアクセント色から作るので、50 種類のどのテーマでも浮きません。**設定 → 表示**の「新着の目印」で強調する範囲を「強調しない／今日／24 時間／3 日／7 日」から選べ、しるしとネットワークの色分けはそれぞれ個別に切れます。

### Changed

- **ドラッグ＆ドロップの既定動作を、エクスプローラーと同じ規則に揃えた (#288):** これまでは **`Ctrl` を押していない限り、どこへ落としても「移動」**でした。Windows のエクスプローラーは**同じドライブの中なら移動、別のドライブやネットワーク共有・サーバーを跨ぐならコピー**という規則で動きます。Zenith Filer もこれに合わせました。`Ctrl` を押しながらならコピー、`Shift` を押しながらなら跨いでいても移動、と明示することもできます（`Shift` は新しく効くようになりました）。**同じドライブの中で使っている限り、これまでとまったく同じ動きです。**変わるのは、別のドライブやサーバーへ落としたときに**原本が残るようになる**点です。

### Fixed

- **Box の「リンク連携コピー」でリンクが取れない問題を、原因から直した (#273):** 1.14.7 で共有ウィンドウを伏せるのをやめましたが、**それでもリンクは取れないまま**でした。原因は隠し方ではなく、**隠そうとしていたこと自体**です。Box はリンクを作った直後に、共有ウィンドウの中からクリップボードへ書き込みます。ところがこの書き込みは、**そのウィンドウが前面にないというだけで拒否されます** — 画面の中に置いてあっても、フォーカスが無ければ必ず失敗します。Zenith Filer は共有ウィンドウを画面の外へ動かし、前面にも出していなかったため、**何秒待ってもリンクが入らない**状態でした（伏せる・画面外へ出す・透明にする、これまで試したどの隠し方も同じ結果になります）。共有ウィンドウを**普通に表示して前面に出す**ようにしました。Box がクリップボードへ書き終えた時点で**自動的に閉じ、フォーカスを Zenith Filer へ戻します**。共有ウィンドウが見えているのは実測で 1〜3 秒ほどで、**押す操作はこれまでどおりメニューの 1 回だけ**です。8 秒経っても自動で取れなかった場合は、これまでどおりウィンドウをそのまま残して「共有ウィンドウでリンクをコピーしてください」と案内します（手でコピーした分も、パス・URL・ファイル名の形に整形されます）。

- **エクスプローラーで切り取ったファイルを貼り付けると、コピーになる問題を修正 (#288):** エクスプローラーで `Ctrl+X` してから Zenith Filer で `Ctrl+V` すると、**元のファイルが残ったまま**でした。切り取りかコピーかは、Windows がクリップボードに添える印で伝わります。この印は**複数の意味を重ねて持てる**形をしていて、エクスプローラーの切り取りは「移動」に加えて別の意味も一緒に立てて渡してきます。Zenith Filer は**「移動」ちょうどの値だけを切り取りと見なして**いたため、重なった印を取りこぼしてコピー扱いにしていました。重なっていても「移動」を読み取るようにしています。**Zenith Filer 内での切り取りは印がちょうど一致するので、これまでも動いていました** — 「エクスプローラーからだけ効かない」という分かりにくい症状の原因はここです。

- **サーバーへドラッグしたファイルが、コピーなのに元だけ消える問題を修正 (#288):** サーバー（FTP/SFTP）へ接続したペインへドラッグすると、Zenith Filer は**コピーとして送っていた**のに、ドラッグ元へは**「移動しました」と返していました**。原本を消すのは**ドラッグ元の役目**なので、送った先には複製があるのに**手元からは消える**という状態になり得ました。実際に行う操作をそのまま返すようにしています。あわせて、**切り取り→貼り付けでサーバーへ送ったとき**は「コピーとして実行し、元は残した」と通知します（サーバーとの移動そのものは未対応のためです）。
