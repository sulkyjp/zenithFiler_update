## Latest Changes — [1.14.0] - 2026-08-23 : A keyboard-complete shortcut system, plus a rethink of the store gates and the free tier

### Added

- **An "AFXW style" key scheme is now available:** `C` to copy, `M` to move, `D` to delete, `K` to make a folder, `R` to rename — **single keystrokes with no modifier**, the finger habits of AFXW, a long-standing Japanese file manager. `V` previews, `E` opens the editor, `L` shows drives, `H` history, `J` frequent folders, `N` copies the path. Pick it under Settings → Shortcuts. The point is that **hands trained on AFXW keep working** without relearning anything.

- **Macro shortcuts now live alongside every other key:** Macros had **their own separate mechanism** — you typed the key in as text ("Ctrl+Shift+M"), and **nothing told you when it clashed with something else**. They now appear under a "Macros" group in Settings → Shortcuts and are recorded like any other binding. Clashes are flagged, and if you bind one to the start of a two-key shortcut such as `Ctrl+K`, **you are told it will never fire** instead of it silently doing nothing. Macros can also be run by name from the command palette (`Ctrl+Shift+P`), and can take **two-key shortcuts** themselves (`Ctrl+K` then `M`).

- **Clicking something that has a shortcut now tells you about it:** Shortcut keys were **only discoverable by opening the settings and looking**, so it was easy to keep working without ever learning them. Press a status bar or toolbar button with the mouse and, if that operation has a key, a notification says so: "'Dual pane' also runs with `Ctrl+Shift+W`". **Three times per operation**, then it goes quiet — and the count carries across restarts, so it will not greet you three times every session. Nothing appears when you use the keyboard; you already know. Turn it off at the top of Settings → Shortcuts.

- **Operations that could only be reached with the mouse are now in the command palette:** The manual, the changelog, challenges, feedback, macro recording, the search filters (date / size / scope), search presets, clearing a search, copying the current folder's path, and the window snaps (left / right / bottom…) — **19 operations** — lived only on toolbar and status bar buttons, **out of reach while working from the keyboard**. They now appear by name under `Ctrl+Shift+P`, and you can bind a key to any of them from the settings. **Not one new shortcut key was added** — the set of keys to learn is unchanged; only the reach grew. The shortcut list also gained a "Search" group, holding the seven entries that only apply while searching.

- **A two-key shortcut scheme, "Zenith 2", is now available:** `Ctrl+K` followed by one key opens any nav pane view, and `Ctrl+B` drives the panes and the layout — `Ctrl+K F` for favorites, `Ctrl+B 2` for the side-by-side split, and so on. **Hold the prefix for a moment and the keys you can press next appear**, so there is nothing to memorise; type straight through and the list never shows. The list is clickable too. **You can keep `Ctrl` held down** — `Ctrl+K` followed by `F` works whether or not you let go of `Ctrl` in between. Pick it from "how the keyboard should feel" on first launch, or switch at any time under Settings → Shortcuts. Under Zenith 2, `Tab` is released from pane switching and **goes back to stepping through the elements on screen** (moving between panes is what `←` `→` are for). **Nothing changes for existing users** — one key, one action, `Tab` for pane switching, exactly as before.

- **The nav pane views now all answer to the same keys:** Working sets were **the only view you could drive from the keyboard**; everywhere else you opened a view with `F6` or `Ctrl+Shift+1` and then had to reach for the mouse anyway. History, frequent folders, recent files, drives, search presets, search history, the tree, favorites, the index search settings, the tab list, remote sites and Box — **twelve views** — now take `↑` `↓` to pick a row, `Enter` to use it and `Esc` to hand focus back to the file list. `F2` (rename), `Delete`, `Insert` (add) and `Ctrl+F` (filter) work too, but **only where that view actually has such an operation** — elsewhere they do nothing at all, and never quietly mean something else. **Favorites answers the same keys in all three of its layouts** (tree, A-Z and search results); renaming and deleting used to be reachable only from the tree's context menu. **In the tab list, `Delete` closes a tab and `Insert` adds one** — which pane it acts on follows from which of the two lists you are in. Views without a list at all — preview, properties, macros and the AI panels — **still answer `Esc`**, so the same key gets you back to the file list from anywhere.

- **The nav pane layout window now explains what each view can do:** Hovering a row showed **only its name**, so an unfamiliar name gave no clue what you were about to put in that quadrant. Alongside the name and a one-line summary, the tooltip now carries a **"What it does" section covering the actual capabilities** and **the shortcut key assigned to that view** — your own key, if you have rebound it. Rows that would move a view out of another quadrant still end with that warning.
- **`Ctrl+3` now switches to the top/bottom split:** `Ctrl+1` (single pane) and `Ctrl+2` (side-by-side) have always been there, but **the top/bottom split had no key of its own** — it could only be reached from the status bar button or the menu. The row is filled in, so all three splits are one keystroke away.
- **`F6` now moves between the nav pane areas and the file list:** Opening a view with `Ctrl+Shift+1` and friends **left focus sitting in the file list**, so anything beyond that meant reaching for the mouse. `F6` now steps through **left nav top → left nav bottom → pane A → pane B → right nav top → right nav bottom**, and `Shift+F6` walks back. Areas that are closed, and pane B in single-pane mode, are skipped. **`F6` also gets you out of the terminal** — inside it the app takes no keys at all, so this is the only way out. **The area you are in is now shown by its header changing colour** — the A/B panes have always done this, but the four nav pane areas were indistinguishable. Clicking into an area with the mouse lights it the same way. Note that the Total Commander preset uses `F6` for "Move to other pane", so there the ring is on `Ctrl+F6` / `Ctrl+Shift+F6` instead.

- **After you save a customized theme, Zenith now offers to publish it:** The upload entry point lived inside the store tab of the settings window, and **almost nobody found their way there.** The moment you finish a theme is the moment you most want to show it to someone, so saving a customized theme now asks "Share this theme?" right there, and answering yes publishes it. **You are only asked once per theme**, so saving repeatedly while adjusting colors will not nag you (a fresh session asks again, but by then you have reworked the theme). Nothing appears if uploading is not unlocked yet or you have reached the daily limit.
- **Zenith can now start when you sign in to Windows:** Until now, closing the window ended the process, so **using it again meant walking back to the folder you unzipped and double-clicking the executable**. The global hotkey (Ctrl+Shift+E and friends) only works while the app is running, which left you **opening Explorer in order to open your file manager**. Settings > General now has "Start when I sign in to Windows". It is **off by default** and only takes effect if you choose it. It works by placing a shortcut in your Startup folder and **writes nothing to the registry**, so portable use stays portable. You can turn it off from the checkbox, or from **Settings > Apps > Startup in Windows**. Enabling it also turns on tray residency, because without it closing the window kills the process and the hotkey stops working. Zenith starts minimized, so it will not jump in front of you every time you sign in.
### Changed

- **The key that summons the app from outside is back to `Ctrl+Shift+E`:** It was moved to `Ctrl+Shift+H` last time to clear a clash with "Open in Explorer", but **some window-management utilities claim `Ctrl+Shift+H` through `L` as a block, and on those machines the summon key did nothing whatsoever.** Summoning registers a key with Windows itself, so whichever app gets there first keeps it. `Ctrl+Shift+E` — which has never been seen taken — goes back to summoning, and "Open in Explorer" moves to `Ctrl+Shift+X`. If you have rebound either one yourself, your own setting wins and the swap passes you by.
- **You can now tell when another app has taken the summon key:** A failed registration left **nothing on screen and nothing in the log**, so there was no way to find out why pressing the key did nothing at all. The row under Control Deck → "Shortcuts" now carries a warning, and **picking a key that is already taken tells you so on the spot**. It goes into the log as well, so it can be checked later. When the warning appears, move the key to one that is still free.
- **Moving between panes with `←` `→` can now be rebound:** Pressing `←` in pane B, or `→` in pane A, has always jumped to the other side, but **the keys were written into the code and could not be changed**. They now appear under the "Window" group in the shortcut settings as "Focus Left Pane" and "Focus Right Pane". The behaviour itself is unchanged.

- **The theme and Stickman stores are now open from the start:** Both stores used to be **rewards unlocked through achievements**. Browsing the theme store took 10 theme switches, uploading took 50, and downloading a Stickman pattern required **challenge level 90**, which was designated end-game content. Worse, for Stickman the **download gate (90) sat above the upload gate (70)**, so anyone between level 70 and 89 could publish their own work but could not see anyone else's. **Nobody publishes into a room with no audience**, so the stores stayed structurally empty — and since the free tier caps theme switching at 3 per day, simply reaching the old upload gate of 50 took at least 17 days. **Browsing, downloading and uploading are now all available from the start.** Publishing a theme only requires that you have saved one customized theme, and Stickman uploads unlock at challenge level 50, the same point as AI generation. **AI theme generation and AI Stickman generation remain achievement-unlocked rewards** — those are capabilities for you personally, and gating them does not keep anyone out of the store.
- **The free tier now draws its line at creating, exporting and delegating rather than at using:** Opening a terminal, switching themes, indexed search and grep search each used to be capped at 3 uses per day. But **the terminal and the 50 themes are the things this app is known for** — inviting people in and then rationing them to three a day never made sense, and with themes people were running out without noticing and spending the rest of the day in something they could not comfortably read. **Those four caps are gone**, and all four are now unlimited on the free version. Themes switch the instant you tap a tile, with no confirmation bar, because nothing is being consumed. What remains metered is **creating** (theme customization, macros), **exporting** (Excel / CSV / PDF, store uploads) and **delegating** (the AI features) — the operations that produce something. There is deliberately no time-limited trial: the app is portable by design, so a calendar-based expiry would have nothing solid to stand on.
### Fixed

- **Fixed the quick preview closing with `Space` even after its open key was changed:** The open key was configurable while the close key sat hard-coded in the source. **The Total Commander preset binds `F3`**, so anyone using it got the mismatched "open with `F3`, close with `Space`" behaviour. Pressing the same key you opened it with now closes it (`Esc` still works too).

- **Fixed macro shortcuts not working until the macro view had been opened:** The key table was built when that view opened, so until then none of the macro keys responded at all. It is now loaded at startup.
- **Fixed macro shortcuts without a modifier never firing:** A key like `F9`, without `Ctrl` or `Shift`, could be set and saved but **never did anything when pressed**. Keys that type a character — letters, digits, punctuation — **now require `Ctrl` or `Alt` alongside them**, since otherwise they would swallow your typing in text fields (`Shift+M` counts as typing too).

- **Fixed the log filling with nested copies of itself after repeated abnormal exits:** When the previous session did not shut down cleanly, the last 50 lines of its log are copied into the new one so the cause can be traced. **Those copied lines were then eligible to be copied again**, so a run of abnormal exits stacked the same text in ever-deeper nests and **pushed out the part that actually mattered — what the app was doing just before it went down.** Copied lines are now skipped.

- **Fixed unassigned entries warning that they conflicted with each other:** Changing any single shortcut made the **four entries that have no key assigned** — "Top/bottom split", "Copy to other pane", "Move to other pane" and "Open in editor" — point at one another and claim a conflict. Nothing without a key can conflict with anything, so they are now left out of the check. The same goes for entries you have set to "unassigned" yourself.
- **Fixed some keys appearing under their internal names in the shortcut list:** Entries that read `Ctrl+Shift+OemTilde` now show the character you actually type, as in `` Ctrl+Shift+` ``. Brackets, slashes, other punctuation and the digits from 6 up are handled the same way.

## 最新の変更履歴 — [1.14.0] - 2026-08-23 : キーボードだけで完結する操作体系へ刷新し、ストアと無料版の線引きを見直した

### Added

- **「あふw 風」のキー体系を追加した:** `C` でコピー、`M` で移動、`D` で削除、`K` でフォルダ作成、`R` で名前の変更。**修飾キーを押さず 1 打鍵で操作する**、日本製ファイラー「あふw」の指の運びをそのまま持ち込めます。`V` でプレビュー、`E` でエディタ、`L` でドライブ、`H` で履歴、`J` でよく使うフォルダ、`N` でパスのコピー。設定 →「ショートカットキー」から選べます。**長年あふw を使ってきた手が、そのまま動く**ことを狙ったものです

- **マクロのショートカットキーを、ほかのキーと同じ場所で扱えるようにした:** マクロのキーだけ**別の仕組みで動いていて**、設定は文字を手で打ち込む方式（「Ctrl+Shift+M」と入力）、**ほかのキーと重なっていても誰も教えてくれませんでした。** 設定 →「ショートカットキー」の一覧に「マクロ」グループとして並び、ほかと同じようにキーを記録して割り当てられます。重複していれば警告が出ますし、`Ctrl+K` のような **2 打鍵ショートカットの起点に割り当ててしまった場合も、「このままでは実行されません」と教えます**（これまでは黙って効かないだけでした）。コマンドパレット（`Ctrl+Shift+P`）からマクロ名で呼び出せるようにもなり、**2 打鍵のキー**（`Ctrl+K` → `M` など）も割り当てられます

- **マウスで押した操作にキーがあるとき、その場で教えるようにした:** ショートカットキーは**設定画面を開いて探さないと分からず、知らないまま使い続けることになりがち**でした。ステータスバーやツールバーのボタンをマウスで押したとき、その操作にキーが割り当てられていれば「「2画面に切替」は `Ctrl+Shift+W` でも実行できます」と通知でお知らせします。**同じ操作につき 3 回まで**で、以降は黙ります（数えた回数は次に起動しても引き継ぐので、毎回 3 回出ることはありません）。キーボードで実行したときは出ません — 既に知っている方に見せても仕方がないからです。設定 →「ショートカットキー」の一番上で止められます

- **これまでマウスでしか押せなかった操作を、コマンドパレットから呼べるようにした:** マニュアル・更新履歴・チャレンジ・フィードバック・マクロの記録・検索の絞り込み（日付／サイズ／範囲）・検索プリセット・検索のクリア・今いるフォルダのパスのコピー・ウィンドウの配置（左／右／下…）といった **19 の操作**は、**ツールバーやステータスバーのボタンからしか実行できず、キーボードだけで操作している間は手が届きませんでした。** `Ctrl+Shift+P` のコマンドパレットに名前で並ぶようになり、必要なら設定画面から好きなキーを割り当てられます。**新しいショートカットキーは 1 つも増やしていません** — 覚えるキーを増やさずに、届く範囲だけを広げました。あわせてショートカットキーの一覧に「検索」グループを設け、検索中しか使わない 7 項目をそちらへ移しています

- **2 打鍵のショートカット体系「Zenith 2」を選べるようにした:** `Ctrl+K` に続けて 1 打鍵でナビペインの各ビューを開き、`Ctrl+B` でペインと配置を操ります（`Ctrl+K F` でお気に入り、`Ctrl+B 2` で左右 2 画面、というふうに）。**プレフィックスを押したまま少し待つと、次に押せるキーの一覧が出ます** — 覚えていなくても使えますし、覚えている方が続けて打てば一覧は出ません。一覧はクリックでも実行できます。**`Ctrl` は押したままで構いません** — `Ctrl+K` のあと指を離さずに `F` を打っても、離してから打っても同じように効きます。初回起動の「キーの使い心地」で選べるほか、あとから設定 →「ショートカットキー」でいつでも切り替えられます。Zenith 2 では `Tab` がペイン切替から解放され、**画面の中の要素を順に辿る本来の働きに戻ります**（ペインの移動は `←` `→` が担います）。**これまでお使いの方の割り当ては変わりません** — 1 つのキーに 1 つの機能、`Tab` はペイン切替、という従来のままです

- **ナビペインのビューを、どれも同じキーで操作できるようにした:** キーで操作できるのは**ワーキングセットだけ**で、ほかのビューは `F6` や `Ctrl+Shift+1` で開いても**結局マウスに持ち替える必要がありました。** 履歴・よく使うフォルダ・最近開いたファイル・ドライブ・検索プリセット・検索履歴・ツリー・お気に入り・インデックス検索設定・タブ管理・接続先・Box の **12 のビュー**で、`↑` `↓` で選び、`Enter` で使い、`Esc` でファイル一覧へ戻れます。あわせて `F2`（名前の変更）・`Delete`（削除）・`Insert`（追加）・`Ctrl+F`（絞り込み）が使えますが、**そのビューに該当する操作があるときだけ**効きます — 無いビューでは何も起きず、別の意味に化けることはありません。**お気に入りは、ツリー・ABC 順・検索結果のどの表示でも同じキーが効きます**（これまで名前の変更と削除は、ツリー表示の右クリックからしかできませんでした）。**タブ管理では `Delete` でタブを閉じ、`Insert` で追加**できます — A/B どちらの一覧にいるかで対象のペインが決まります。一覧を持たないビュー（プレビュー・プロパティ・マクロ・AI 系）でも、**`Esc` を押せばファイル一覧へ戻れます** — どこにいても同じキーで帰れる形にしました

- **「ナビペインの配置」で、それぞれのビューに何ができるか分かるようにした:** 行にマウスを乗せたときに出るのは**名前だけ**で、**初めて見る名前だと、その枠に何を置こうとしているのか分かりませんでした。** ビュー名・一言の説明に加えて、**「できること」として機能まで踏み込んだ説明**と、**割り当てられているショートカットキー**を出すようにしています。ショートカットはご自身で変更していればその内容が出ます。別の枠から移動することになる行では、これまでどおりその予告も末尾に続きます
- **`Ctrl+3` で上下 2 画面に切り替えられるようにした:** `Ctrl+1`（1 画面）・`Ctrl+2`（左右 2 画面）は前からありましたが、**上下 2 画面だけキーが空いたまま**で、ステータスバーのボタンかメニューから切り替えるしかありませんでした。並びを埋めて、3 つとも同じ手つきで切り替えられます
- **`F6` でナビペインの枠とファイル一覧を行き来できるようにした:** これまで `Ctrl+Shift+1` などでビューを出しても、**フォーカスはファイル一覧に残ったまま**で、そこから先はマウスに持ち替える必要がありました。`F6` を押すと **左ナビの上 → 左ナビの下 → A ペイン → B ペイン → 右ナビの上 → 右ナビの下**の順に移り、`Shift+F6` で逆順に戻ります。閉じている枠・1 画面モードで隠れている B ペインは飛ばします。**ターミナルからも `F6` で抜けられます** — ターミナルの中ではアプリ側がキーを一切奪わないので、これが唯一の出口です。**今どの枠にいるかは、その枠の見出しが色づいて分かります**（A/B ペインは前から色が変わっていましたが、ナビペインの 4 枠は見分けがつきませんでした）。マウスでクリックして移ったときも同じように色づきます。なお Total Commander 風プリセットでは `F6` が「反対ペインへ移動」に使われているため、枠の巡回は `Ctrl+F6` / `Ctrl+Shift+F6` になります

- **カスタマイズしたテーマを保存した直後に、ストアへ出すか聞くようにした:** 投稿の入口は設定画面のストアタブの中にあり、**自分でそこまで辿り着ける方はほとんどいませんでした。** 作った瞬間がもっとも人に見せたい瞬間なので、カスタマイズしたテーマを保存したその場で「ストアに出しますか？」とお聞きします。出すと答えれば、そのまま投稿されます。**同じテーマでは二度お聞きしません**ので、色を調整しながら何度も保存しても邪魔になりません（アプリを開き直したときは改めてお聞きしますが、そのときは作り直しているはずです）。まだ投稿が解放されていないときや、その日の上限に達しているときは、何も出しません。
- **Windows のサインイン時に起動できるようにした:** これまで、アプリを閉じるとプロセスが終了するため、**次に使うときは展開したフォルダまで行って実行ファイルをダブルクリックする**必要がありました。呼び出しキー（Ctrl+Shift+E など）も、アプリが起動している間しか効きません。**ファイラーを開くために、まずエクスプローラーを開く**という状態でした。設定 →「一般」に「Windows のサインイン時に起動する」を追加しました。**既定はオフ**で、選んだときだけ有効になります。仕組みはスタートアップフォルダにショートカットを置くだけで、**レジストリは変更しません**（ポータブル運用を崩さないためです）。解除はチェックを外すほか、**Windows の「設定 > アプリ > スタートアップ」からも切れます**。有効にすると常駐モードも一緒に入ります — 常駐していないとウィンドウを閉じた時点でプロセスが消え、呼び出しキーが効かなくなるためです。起動は最小化状態で行うので、サインインのたびにウィンドウが前に出てくることはありません。
### Changed

- **アプリを外から呼び出すキーの既定を `Ctrl+Shift+E` に戻した:** 前回、「エクスプローラーで開く」との重複を解消するために `Ctrl+Shift+H` へ移していましたが、**ウィンドウ操作系の常駐ツールが `Ctrl+Shift+H`〜`L` をまとめて押さえている環境があり、そうした環境では呼び出しキーがまったく効きませんでした。** アプリ外からの呼び出しは Windows 全体にキーを登録する仕組みで、先に使っているアプリがあればそちらに横取りされるためです。取られた例のない `Ctrl+Shift+E` を呼び出し側へ戻し、重複する「エクスプローラーで開く」を `Ctrl+Shift+X` へ移しました。どちらもご自身で変更している場合はその設定が優先されるので、この入れ替えの影響は受けません
- **呼び出しキーが他のアプリに取られているとき、それが分かるようにした:** これまでは登録に失敗しても**画面にも記録にも何も残らず**、押しても反応しない理由にたどり着けませんでした。Control Deck →「ショートカットキー」の該当行に警告を出し、**設定でキーを変えた直後に取られていたときは、その場で通知**します。ログにも残るので後から確認できます。警告が出たら、空いているキーへ変更してください
- **`←` `→` でのペイン移動を、設定画面から変更できるようにした:** B ペインで `←`、A ペインで `→` を押すと反対側へ移る動きは前からありましたが、**キーがコードに直接書かれていて変更できませんでした。** ショートカットキーの「ウィンドウ」グループに「左のペインへ」「右のペインへ」として並びます。動き自体は今までと同じです

- **テーマストアと Stickman ストアを、最初から使えるようにした:** ストアはこれまで**実績で解除する報酬**でした。テーマストアを覗くにはテーマを 10 回切り替える必要があり、投稿するには 50 回、Stickman のダウンロードにいたっては**チャレンジレベル 90**（エンドコンテンツ）が必要でした。しかも Stickman は**ダウンロード（90）のほうが投稿（70）より重く**、レベル 70〜89 の方は「自分は投稿できるのに、他の方の作品は見られない」状態でした。**見る人が居ない場所に投稿する動機は生まれません**ので、ストアは構造的に空のままでした。無料版ではテーマの切り替えが 1 日 3 回までのため、投稿の解除条件だった 50 回に届くまで最短でも 17 日かかっていた、という事情もあります。**見る・ダウンロードする・投稿する、のすべてを最初から使えるように**しました。テーマの投稿は「カスタマイズしたテーマを 1 回保存していること」だけが条件です。Stickman の投稿は AI 生成と同じチャレンジレベル 50 で解放されます。なお **AI によるテーマ生成と Stickman 生成は、これまでどおり実績で解放される報酬のまま**です（こちらはご自身の機能であって、ストアの賑わいとは関係がないためです）
- **無料版の線引きを「使う」から「作る・出す・任せる」へ移した:** これまで**ターミナルを開く・テーマを着替える・インデックス検索・Grep 検索**にも 1 日 3 回の上限がありました。しかし**ターミナルも 50 種のテーマも、このアプリが看板にしている機能**です。呼んでおいて 1 日 3 回と伝えるのは筋が通りませんし、テーマについては上限に気づかず使い切って読みにくいテーマのまま一日を過ごしてしまう、という報告もいただいていました。**この 4 つの上限を撤廃**し、無料版でも無制限に使えるようにしました。テーマはタイルを押した瞬間に切り替わります（回数を消費しないので、確認バーは出ません）。上限が残るのは、**作る**（テーマのカスタマイズ・マクロ）・**出す**（Excel / CSV / PDF・ストア投稿）・**任せる**（AI 各種）といった、実行すると成果物が生まれる操作です。なお期限つきの試用にはしていません — フォルダを持ち運べるポータブル運用なので、日付で区切っても意味を持たせられないためです。
### Fixed

- **クイックプレビューを開くキーを変えても、閉じるキーが `Space` のままだった問題を修正:** 開くキーは設定で変えられるのに、閉じる側がコードに直接書かれていました。**Total Commander 風プリセットは `F3` を割り当てる**ので、そのプリセットを使うと必ず「`F3` で開いて `Space` で閉じる」というちぐはぐな操作になっていました。開いたキーをもう一度押せば閉じます（`Esc` でも閉じられるのは今までどおりです）

- **マクロのビューを一度も開かずに起動すると、マクロのショートカットが効かない問題を修正:** キーの一覧を作るのが**マクロのビューを開いたとき**だったため、開かずに使っている限りどのキーも反応しませんでした。起動時に読み込むようにしています
- **修飾キーを使わないマクロのショートカットが動かない問題を修正:** `F9` のように `Ctrl` や `Shift` を伴わないキーは、設定して保存はできるのに**押しても永久に無反応**でした。ただし英字・数字・記号のように**文字を打つためのキーは、`Ctrl` や `Alt` と組み合わせないと割り当てられません** — そのままだと入力欄で文字が打てなくなるためです（`Shift+M` も文字入力なので同じ扱いです）

- **異常終了が続いたとき、ログに同じ内容が何重にも書き込まれる問題を修正:** 前回が正常に終了しなかった場合、原因を追えるように**直前のログの末尾 50 行を新しいログへ写す**仕組みがあります。ところが**写した行そのものが次回の写し取りにも含まれていた**ため、異常終了が続くと同じ内容が入れ子で積み重なり、**肝心の「落ちる直前に何をしていたか」が押し出されて読めなくなっていました。**写した行は次からは対象外にしています

- **キーを割り当てていない項目どうしが「競合しています」と警告し合う問題を修正:** ショートカットキーを 1 つでも変更すると、**まだキーを割り当てていない 4 項目**（「上下2画面モード」「反対ペインへコピー」「反対ペインへ移動」「テキストエディタで開く」）が互いを指して警告を出していました。割り当てが無いものはそもそも競合しようがないので、警告の対象から外しています。ご自身で「割り当てなし」にした項目も同じです
- **ショートカットキーの一覧で、一部のキーが内部の名前のまま表示されていた問題を修正:** `Ctrl+Shift+OemTilde` のように内部名が出ていたものを、`` Ctrl+Shift+` `` のように**実際に打つ字**で表示します。角かっこ・スラッシュ・記号・6 以降の数字も同様です
