### Added

- **Times can now be shown in 12-hour format with AM/PM (#495)** [Preview 2.1.1.1] — Settings → Language has a new **Time format** option with three choices: **24-hour** (the default, as before: "2026/11/14 15:05"), **12-hour** ("2026/11/14 3:05 PM"; on Japanese Windows, "午後 3:05"), and **Match Windows settings** (uses the date and time formats from the Region settings in Windows, so with US settings the date order also changes, as in "11/14/2026 3:05 PM"). Times shown on screen switch together: Date modified, Date created and date property columns in the file list, row tooltips, Properties, Recent files, Frequent folders, Working sets, preview information, the overwrite confirmation, the backup list and more. The file list updates right away when you change it (no restart needed). Dates in logs and in exported CSV and Excel files are data and do not change. Requested by a user overseas

- **New nav pane view "Recently updated" lists only the files marked as new (#497)** [Preview 2.1.1.2] — See the files that were just updated anywhere, without opening folders one by one. It lists, newest first and up to 200, the files updated within the highlight range (Control Deck → Display → Markers → Spotting what's new; 24 hours by default) from your indexed folders and the folders you have open, with the name, location (the folder it is in) and date modified. Files still within the ✨ time get the same ✨ as in the file list. The index is read without scanning the disk, so it stays light, and a file you save inside an open folder shows up within seconds without waiting for the index to update (local drives only; network and cloud folders appear when the index updates). Deleted files disappear right away, and files that fall out of the range remove themselves. Double-click or press `Enter` to open the location in the active pane with the file selected. Right-click for Open file, Show location in pane A / pane B and Show in Explorer, or middle-click to open the location in a new tab. The search box at the top filters by name and location. If you already use the app, it is added at the end of the left icon bar with a ✨ icon (on a new installation, place it from `∨` at the right end of the icon bar → "Edit All Pane Slots")

- **You're now notified when the developer replies to your feedback, even with settings closed (#514)** [Preview 2.1.1.2] — Replies were only checked when you opened the Feedback page in settings, so you couldn't tell when an answer had arrived. The app now checks in the background 1 minute after startup and every 4 hours, and shows "The developer replied — #number subject" when a new reply has come in. When an update brings you to the version with the fix, it asks you to check whether it's fixed. Open in the notification takes you to that report under Conversations, and a small dot appears on the Feedback button in the title bar while there's an unread reply or a fix to check. You're never notified twice about the same reply. Only reports in progress and those closed within the last 30 days are checked, and unchanged reports are asked about in a way that doesn't count against the request limit. You can turn this off with "Check for replies in the background" below the conversations (on by default). If the key used to read replies has expired, you're asked to update the app instead of seeing a generic connection error

- **Added "Zenith Link" for the Zenith Deck custom keyboard (stage 1: telling it whether ZenithFiler is in front) (#395)** — Turn on "Zenith Link (custom keyboard)" under Control Deck → General → External devices to send ZenithFiler's state to a Zenith Deck connected over USB (off by default). This stage sends only whether ZenithFiler is in front: when any ZenithFiler window (including Settings and dialogs) comes to the front, the keyboard switches to its ZenithFiler key layer, and switches back when you move to another app. While ZenithFiler is in front it repeats this every second, so if ZenithFiler closes or stops responding, the keyboard returns to normal within a few seconds. It reconnects after you unplug the keyboard or switch it between its two PCs. Data goes only to the keyboard on USB, never to the network. While off, the link isn't loaded at all and adds nothing to startup or everyday use. Panes, folders, tabs, theme colors and progress come in the next stages

### Changed

- **Folders now get the "new" marker when something deep inside them changes (#496)** [Preview 2.1.1.2] — The "new" marker (bold Date modified and ✨) used to be decided only by each item's own Date modified. Windows updates a folder's Date modified only when an item directly inside it is added, removed or renamed, so editing a file several levels down left the folders above it unmarked. Zenith Filer now looks through a folder down to the deepest level for its newest change and uses that too. For example, saving `Project\Docs\2026\Quote.xlsx` marks `Docs` in the list of `Project`, and `Project` in the list above it, so you can see at a glance which way to go to find the new file. Hover over ✨ to see when the newest change inside happened. This is checked while folder sizes are counted (on by default for local drives), so the file list is no slower. Changes deep inside a folder you have open mark it right away. In places where folder sizes are not counted (network and cloud-synced folders and servers, unless turned on in settings), or when automatic folder size counting is off, folders are marked by their own Date modified as before. Files dated in the future (such as photos from a camera with a wrong clock) are ignored

- **Deleting many selected items in a large folder no longer freezes before the deletion starts (#509)** [Preview 2.1.1.2] — To decide where to put the focus after deleting, the list was searched from the top once for every selected item. Selecting everything in a 100,000-item folder meant around 5 billion comparisons, and the window stopped for seconds before the deletion confirmation appeared. The list is now scanned only once

- **Cancelling a rename or confirming it unchanged no longer reloads the whole folder (#510)** [Preview 2.1.1.2] — Pressing Esc during F2 rename, pressing Enter without changing the name, or answering No to the change-extension prompt changed nothing, yet the whole folder was reloaded just to reselect the item. In large folders or on file servers that meant waiting seconds each time. The item is now reselected without reloading

- **Reselecting many files no longer freezes the window (#508)** [Preview 2.1.1.2] — After pasting or moving thousands of items, and when inverting the selection, selecting by wildcard, clicking a group header, re-sorting or drag-selecting, items were selected one at a time. Each one copied the whole selection and refreshed the properties and preview, so 5,000 items froze the window for seconds. Items are now selected in one go

- **Preview builds now log what the app was doing when the window froze (#502)** [Preview 2.1.1.2] — The log only said how long the UI froze, not which work caused it (almost all of 118 freezes in three months on the development PC had no known cause). When the window freezes for 2 seconds or more, the app now records where the UI work is stuck while it is still stuck. This happens at most once every 10 minutes and 5 times per run, so it stays light. It will come to regular releases once preview builds confirm it does not clash with security software on company PCs

- **The Feedback page is rebuilt around your conversations with the developer (#515)** [Preview 2.1.1.2] — The send form used to sit at the top, so reading a reply meant scrolling past it every time; the text was small and faint, and the developer's replies used the same background as the card. Now **Conversations** and **New feedback** switch at the top of the page. The page opens on Conversations when there is an unread reply or a fix waiting for you to confirm, with a count next to it. Each report is a card showing its status (in progress, done, not planned), reference number, subject and the first line of the developer's latest reply, and opens like a chat: the developer's replies are on the left in a bubble lightly tinted with the accent color, your messages on the right. Unread replies are marked "New" with a brief glow on their edge, and reports that are done or not planned end with a divider such as "Done — fixed in v2.1.1". Links in replies can be clicked only when they point to the developer's own pages (the developer's GitHub and the manual site); other URLs are shown as text instead of disappearing. Also: dates older than 7 days are shown as dates (instead of growing to "120 days ago"), the time of the last check is shown ("Checked 3 min ago"), check failures appear in red, an empty page explains what to do, the reply box shows a hint, new replies no longer rebuild the bubbles you are reading (so selected text stays), and Tab now reaches the type and attachment controls

- **"It's fixed", "Still happening" and replies in Feedback now respond the moment you press them (#516)** [Preview 2.1.1.2] — Pressing them used to show nothing for a few seconds, then rebuild the whole conversation, with no way to undo. "Still happening" also quietly sent whatever was in the reply box below. Now "It's fixed" immediately turns into "Telling the developer it's fixed" with a brief glow, and a thin line shrinks over 5 seconds; Undo puts things back without sending anything, and the answer is sent when the line runs out. "Still happening" opens a "When does it happen?" box right there (the note is optional), and once sent the report goes straight back to in progress (it used to stay "Done" until GitHub reopened it). If sending fails, "Couldn't send" and "Try again" appear in place. A reply now appears as your bubble, faded and marked "Sending…", the moment you send it; if it fails, your text goes back into the box with the reason in red. The wait before you can reply again is counted down next to the button, and "Seen by the developer" appears under your message once the developer has read it

- **Sending feedback now feels more responsive (#517)** [Preview 2.1.1.2] — After sending, a notification says "Received as #number — replies will appear under Conversations", the page switches to Conversations with your report opened, and its status is read right away (the message just stayed under the send button and the history showed "Unknown"). When you can't send yet, the reason appears before you press the button ("Add a subject to send", "You can send again in 4:32"); the button used to be silently disabled, or the rate limit only showed up after pressing. The subject box shows a character count. Attachment switches you changed yourself are no longer reset when you pick another category. Your user folder name (after C:\Users\) in the subject and description is replaced with `<user>` before sending, and the notice that said "no personal information is collected" now explains that what you write arrives as written and what gets hidden

- **Removed the › at the right end of the rows in the search conditions panel (#519)** — The rows in the panel opened by the button at the right end of the search bar (Open search conditions: Size, Date modified, Scope, presets) had a › at the right end. It is the same mark a right-click menu uses for a submenu that opens to the side, so it looked as if clicking would open one, which was confusing. Clicking a row actually closes this panel and opens the panel for entering that condition. The right side of each row already shows the current value (such as "Any"), which is enough to tell the row can be clicked. This now matches the Windows Settings layout, and the value sits at the right edge of the row

- **The "before" and "after" columns in Batch Rename can now be resized and fill the width of the window (#522)** — The two columns used to have fixed widths that did not grow when you made the window larger. When only the end of a long name changed, the difference was hidden behind "…", and the only way to compare was the "e.g." line under the rename mask. You can now drag the border between the column headers to change a column's width, or double-click it to fit the contents. The two columns fill the width of the window, and the ratio you set between them is kept when you resize the window

### Fixed

- **Pressing Space with Japanese input turned on now opens Quick Preview (#492)** [Preview 2.1.1.1] — With Japanese input (kana) on, Space went to the IME and only typed a full-width space, so Quick Preview did not open and nothing appeared on screen. In the file list (and the preview window), Space is now taken as the shortcut unless you are in the middle of converting text, so you can open and close the preview without switching the input off. While you are converting (for example after typing "か"), Space still converts as before. Letter keys assigned to actions (such as F or L in a keymap preset) are still taken as text while Japanese input is on, because they cannot be told apart from typing Japanese to jump to a file by its first letters. Instead, when an assigned key is taken as text, the status bar now says "Japanese input is on, so F was typed as text. Switch it off (Hankaku/Zenkaku key) to use the shortcut" (at most once every 30 seconds). Shortcuts with Ctrl or Alt keep working with Japanese input on, as before

- **Clicking a scrollbar track twice in quick succession no longer opens the selected file or folder (#490)** [Preview 2.1.1.1] — The file list opened the selected item on any double-click, without checking where the double-click happened. Since v2.1.1 made scrollbar tracks clickable, two quick clicks on the track reached the list as a double-click and opened the item. Items now open only when you double-click a row. Clicking the track, the thumb or the arrow buttons quickly only scrolls, as in File Explorer

- **With wrapped tabs, the tab bar no longer looks broken by a "+" sitting alone on the second row (#493)** [Preview 2.1.1.1] — When the first row of tabs was just full and only the new tab "+" did not fit, the "+" was put on a row of its own. The tab bar became two rows tall with only one row of tabs, and with the option to match the A and B heights, the other pane grew too. Now, when the "+" does not fit, the rightmost tab moves down to the next row together with it (the same look as before v2.1.1). The number of rows does not change

- **Text in the status bar no longer occasionally overlaps (#494)** [Preview 2.1.1.1] — Status bar text could overlap and become unreadable in four cases: (1) the progress text of a copy or similar operation and a completion message showed in the same place (the mechanism added earlier to hold messages back during progress was being undone at startup); (2) starting a copy while a message was showing put the progress text on top of it; (3) the progress text overlapped the item count and selection shown on the left (the mechanism that hides them during progress was also undone at startup); (4) with a narrow window or a long message, the text in the middle ran over the buttons and information on the left and right. Now these mechanisms stay in place after startup, a message that is showing is taken down as soon as progress starts, and the text in the middle is placed where it does not overlap the left and right sides, shortened with "…" when it does not fit. Short messages in a full-screen window still appear in the center as before

- **Index search results no longer show Date modified 9 hours early in Japan (#497)** [Preview 2.1.1.2] — The index stores dates in UTC but did not convert them back to local time when reading them, so the Date modified column of search results was off by your time zone offset (9 hours in Japan: a file saved at 3 PM showed 6 AM). Filtering by date and the sort order were already correct. Found while building the Recently updated view above

- **Overwriting a file by copying no longer loses the original when the copy fails or is cancelled (#499)** [Preview 2.1.1.2] — When copying onto a file with the same name and choosing Overwrite, cancelling, a full disk, a dropped network connection or a source file locked by another app all deleted the original destination file (without going to the Recycle Bin). The destination was emptied when the copy started and removed on failure. Copies now write to a hidden temporary file in the same folder and swap it in only once it is complete. If the copy stops partway, only the temporary file is removed and the original stays as it was. The same applies to each file overwritten while copying a folder into an existing one

- **Stopping a copy or move partway no longer loses Ctrl+Z for what was already transferred (#500)** [Preview 2.1.1.2] — The undo entry was only registered when the whole transfer finished. After cancelling, an automatic stop after repeated failures, or an unexpected error, the files already transferred could not be put back. Now whatever was transferred can be undone with one Ctrl+Z however the transfer stopped. Also: (1) files that failed before the stop are still reported ("N items could not be transferred"); (2) the reason for an automatic stop (no permission, the same failure repeating) is no longer replaced by "Cancelled"; (3) when a merging folder move stops at a file in use, what was already moved can be undone; (4) a single shell error no longer stops the whole transfer — it is counted as one failure and the rest continues

- **Closing the app during a copy or move no longer leaves half-written files behind (#501)** [Preview 2.1.1.2] — Exiting did not check for running file operations, so the process ended partway and the destination was left with partial files under the right names (with their dates not restored), looking like complete files. Now the app asks "N file operation(s) are still running. Stop them and exit?". Yes stops them, waits a few seconds at most for half-written files to be cleaned up, then closes (files already transferred stay). No keeps the app open. When Windows is shutting down or signing out, the operations are stopped without asking. Closing to the tray (resident mode) lets the operations carry on

- **Undo no longer says "Undone" when there is nothing left to undo, and a folder moved to another drive can now be moved back with Ctrl+Z (#505)** [Preview 2.1.1.2] — If a moved or renamed file or folder was moved or deleted elsewhere before pressing Ctrl+Z, the app said "Undone" without doing anything. It now says the item to undo was not found. Undoing a folder moved to another drive always failed after freezing for about 1.4 seconds, because Windows cannot rename across drives. It is now moved back with the Windows move, just like the original move (and the same for Ctrl+Y)

- **Deleting from the nav pane tree no longer says "Deleted" and hides the folder when the deletion was stopped (#503)** [Preview 2.1.1.2] — Answering No to Windows' "permanently delete?" prompt (in places without a Recycle Bin), or a deletion that stopped at a file in use, still showed "Folder deleted" and removed the folder from the tree, so it disappeared from the tree until reopened even though it was still there. The app now checks the folder is really gone before saying so, and leaves the tree alone if it is not

- **Ctrl+V paste and key-bound copy/move to the other pane now tell you when they fail (#506)** [Preview 2.1.1.2] — The same failure showed an error for drag and drop, but with Ctrl+V or keys such as F5/F6 (when assigned to copy or move to the other pane) it only went to the log, so pressing the key seemed to do nothing. Now you see a message such as "Paste failed" with the reason. Nothing is shown when you cancel

- **After many files change at once, the list no longer stays stale with a false "Reconnecting to network" message (#504)** [Preview 2.1.1.2] — Switching branches in git, extracting an archive or a build writing its output can change so much at once that Windows' change notifications overflow. This was treated like a network disconnect: the app showed "Reconnecting to network" and re-attached the watcher, but never reloaded the list, so the changes did not appear until F5. Now the list is reloaded once, without the message. After a real disconnect and reconnect, the list is also reloaded once to pick up what changed in between

- **Feedback conversations no longer disappear after a network or save failure (#513)** [Preview 2.1.1.2] — Replies you had received, or the whole feedback list, could vanish from the screen: (1) if GitHub briefly failed to respond while checking for replies, the saved replies were overwritten with nothing, and the next successful check marked old replies as unread again; (2) if the records file could not be written, the whole feedback list disappeared; (3) if antivirus or sync software briefly held the records file, it was read as empty and saved that way. Now an item that could not be checked keeps its previous replies, and if the records cannot be read or written the screen stays as it is and tells you. A damaged records file is kept under another name instead of being discarded. Also: (4) after sending "Fixed", "Not fixed yet" or a reply, a failed refresh made the app ask "is it fixed?" again next time (so it could be sent twice); the answer is now recorded as soon as it is sent; (5) when sending timed out but actually reached GitHub, the app now checks and says it was sent; (6) unread replies are tracked one by one, so a new reply counts as unread even if the developer deleted another; (7) replies are checked again when you reopen the settings window

- **ナビペインのツリーから削除するとき、途中でやめても「削除しました」と出てフォルダが見えなくなっていたのを直しました (#503)** 〔先行版 2.1.1.2〕 — ごみ箱に入らない場所で Windows が「完全に削除しますか」と尋ねたときに「いいえ」を選んだ場合や、使用中のファイルで削除が止まった場合でも、「フォルダを削除しました」と出し、ツリーからそのフォルダの枝を消していました（フォルダは残っているのに、開き直すまでツリーに出ない）。今は消えたことを確かめてから知らせ、消えていなければツリーもそのままにします

- **Ctrl+V の貼り付けと、キーでの反対ペインへのコピー・移動が失敗したときに、何も知らせなかったのを直しました (#506)** 〔先行版 2.1.1.2〕 — 同じ失敗でも、ドラッグ＆ドロップならエラーが出るのに、Ctrl+V や F5／F6 などのキー（反対ペインへのコピー・移動を割り当てたとき）ではログにしか残らず、押したのに何も起きないように見えていました。今は「貼り付けに失敗しました」のように理由と一緒に知らせます。途中でやめたときは知らせません

- **一度にたくさんのファイルが変わったあと、一覧が古いままになり「ネットワーク再接続中」と誤って出ていたのを直しました (#504)** 〔先行版 2.1.1.2〕 — git の切り替え・圧縮ファイルの展開・ビルドの出力などで、開いているフォルダの中身が一度に大量に変わると、Windows の変更の知らせが溢れることがあります。以前はこれをネットワークの切断と同じに扱い、「ネットワーク再接続中」と出して見張りを張り直すだけで、一覧は読み直していませんでした（F5 を押すまで変化が出ない）。今は知らせを出さずに一覧を 1 回読み直します。本当に切断して張り直したときも、切れている間の変化を拾うために 1 回読み直します

- **フィードバックのやり取りが、通信や保存の失敗で消えることがあったのを直しました (#513)** 〔先行版 2.1.1.2〕 — 次のような場合に、届いていた回答やフィードバックの一覧が画面から消えていました。① 回答の確認の途中で GitHub が一時的に応えなかったとき、保存してあった回答を空で上書きし、次に確認できたときは古い回答まで「未読」に戻っていた ② 控えのファイルに書けなかったとき、フィードバックの一覧が丸ごと消えた ③ ウイルス対策や同期のアプリが控えのファイルを一瞬掴んでいたとき、空として読んで上書き保存していた。今は、確認できなかった件は前の回答をそのまま残し、控えを読めない・書けないときは画面をそのままにして知らせます。控えのファイルが壊れていたら、捨てずに別の名前で取っておいてから始め直します。あわせて、④「直った」「まだ直っていない」や返信を送ったあとに確認が失敗すると、次に開いたときにまた「直ったか」を尋ねていた（二度送れた）のを、送れた時点で手元に記録するようにし、⑤ 時間切れで「送れませんでした」と出ても実は届いていたときは、確かめて「送りました」と出すようにしました。⑥ 回答の未読は、読んだ回答を 1 件ずつ覚えるようにし、作者が回答を消して別の回答を足したときも新しい回答を未読にします。⑦ 設定の窓を閉じて開き直したときも、回答を確認し直します

> 過去の変更履歴は [Releases](https://github.com/sulkyjp/zenithFiler_update/releases) を参照してください。
