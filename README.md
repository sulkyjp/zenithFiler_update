## Latest changes

<details>
<summary><b>Show the notes for the latest release</b></summary>

<!-- latest-changes-en:begin -->
**[2.1.1] - 2026-11-13 : The search bar is rebuilt as a single command bar with easier-to-read results, the address bar (breadcrumb) now behaves like File Explorer, and the new tab "+" sits next to the last tab; fixes include type filters turning themselves off, column widths resetting, copies with missing files doing nothing and scrollbar tracks that could not be clicked**

### Changed

- **The new tab "+" button now sits right after the last tab (#481)** [Preview 2.1.0.1 → 2.1.0.4] — The same layout as web browsers and File Explorer in Windows 11. "+" used to sit at the right end of the tab bar, away from the tabs when there were only a few. Now it moves along as you add tabs, and once the tabs no longer fit in the tab bar it stays at the right end so it never scrolls out of sight. With tabs wrapped onto several rows, it appears after the last tab (or at the start of a new row if the last row is full). To keep it at the right end as before, turn off **Tab → Show the new tab button next to the last tab** in Settings. In previews 2.1.0.1 to 2.1.0.3, the tab just left of "+" (the last tab) was sometimes not drawn at startup, leaving an empty gap (#485). At display scales such as 125%, rounding made the width of the tab row slightly too small, so only the last tab was moved to a hidden second row. Now a single-row tab strip always keeps every tab on the same row

- **Search result type chips now show how many results match, and chips that are on are bold (#486)** [Preview 2.1.0.4] — Each chip above the search results ("Folder", "Excel", "PDF"…) now has a count badge in the accent color at its top-right. It appears on chips that are on and chips that are off, so you can see how many results of each type there are before you narrow them down (100 or more shows as "99+"; a type with no results has no badge and its chip is dimmed). The count includes only results that pass the size and date conditions. Chips that are on are now bold as well as filled, and "Select all" / "Deselect all" on the left turn bold in the accent color when every type is on or every type is off. When some results are hidden by type, the count reads "12 / 340 items". When there are results but the type filters hide all of them, the list now says "All 340 results are hidden by the type filters" instead of "No results", with "Show all types" to bring them back. Counts are added up as results arrive, so showing them does not slow the search down (the count used to recount the whole list every time a batch of results arrived). The index search scope can no longer drop to zero folders. Before, you could deselect every folder, and the search then covered all folders while the badge said "0/10" as if it were narrowed. "Deselect all" in the scope now keeps the first selected folder and tells you which one it kept

- **The search bar is now a single input field (a command bar) that shows the conditions in effect as chips, and search results highlight the matching characters in each name (#487)** [Preview 2.1.0.4] — The search bar used to line up four mode buttons, scope, size, date and ★ buttons, and ".*" / "Aa", and the only sign that a condition was set was a filled button. Now the **mode chip** at the left end (for example "Search ▾") lists the four ways of searching with a description and key for each, and the conditions are gathered into one panel opened from the **⚙** at the right end. The panel lists Size, Date modified, Scope (index search only) and Presets with their current values; click a row to open its editor. While a size, date or scope condition is in effect, chips such as "≥ 10 MB", "11/1 – 11/12" and "3/10" appear inside the search field; click a chip to open its editor or its × to remove just that condition. The ⚙ turns the accent color and gets a dot when any condition is set. The "reset" that used to hide behind right-clicking the buttons is replaced by the chip × and "Clear all conditions" in the panel (the search text stays). In a narrow pane the mode chip shows only its icon and the condition chips fold into one, such as "Conditions 2". In the results, the characters of each name that match the words you typed are shown in the accent color, underlined on the selected row. Excluded words (`-word`) and condition words such as `ext:` are not highlighted, and content search (Grep) does not highlight names. Keyboard shortcuts and how Esc works are unchanged. The results list is easier to read too. With column widths set to "Fit to window", the name column used to be fixed at 240px while the path took all the remaining space, so long names were cut off. The name column now widens to fit 90% of the names in the results (up to 40% of the list or 640px, always leaving 35% of the list and at least 200px for the path; the width is set the moment the first results arrive, before any row is drawn, and does not move afterwards). A few very long names no longer squeeze the path; they end with "…" and show in full on hover. Names now use the normal text color instead of the file type color, so the only color in a name is the matching part, and extensions are dimmed. Hovering over a row shows small "Open file location" and "Copy path" buttons at the right end of its path. When search results appear, the visible rows fall into place one after another from the top, each easing down from slightly above its spot (about a second; the progress glow at the bottom of the window no longer runs during searches, the rows settling in show that results arrived; rows can be clicked right away, the effect can be turned off on the Effects page, and it is toned down for back-to-back searches). Also, the search history list that opens from the search box no longer stays open until you press Esc: clicking anywhere outside it and the search box closes it

- **Scrollbars now have arrow buttons at both ends (#490)** [Preview 2.1.0.4] — App scrollbars used to give no visible way to move other than dragging the thumb. Now, when you hover over a scrollbar, arrow buttons appear at its ends; click one to move a line, or hold it to keep moving. When you are not hovering, the scrollbar keeps its slim look. Clicking the empty part of the track above or below the thumb moves a page at a time

- **Suggestion lists for search and the address bar are now rounded floating cards, and the search bar and address bar now match in height and width (#487)** — The search history list that opens from the search box and the suggestions that appear as you type in the address bar used to be plain square boxes stuck to the field, only as wide as its text area. They now open as rounded cards with a shadow, like the search mode menu, a little below the field and exactly as wide as it. Their rows have rounded corners too, and the row under the pointer uses the same hover color as other lists. The address bar strip was also 6px shorter than the search bar and its left and right ends were slightly off; it now has the same height, the same ends and the same rounded corners as the search bar. The filter strip that replaces the address bar while searching has the same size too, so the file list no longer moves up or down when a search starts or ends. When the search bar sits on the same row as the toolbar, its height and right end also line up with the address bar

- **The address bar (breadcrumb) now behaves like File Explorer in Windows 11 (#491)** — Clicking the file list or the other pane while you are typing a path takes the bar back to the breadcrumb without moving (what you typed is dropped, and the next time you switch to the text box it holds the current path). Before, the text box stayed until you clicked the icon on the left or pressed Esc. Just switching to another app keeps the text box. Pressing Enter on a typed path now goes there, switches back to the breadcrumb and moves the keyboard to the file list (before, the text box stayed). Going up a level with the breadcrumb, the "«" list or a typed address opens the folder with the one you came from selected, just like Up. The last level (the folder you are in) now has a "›" too, listing the folders inside it. A new "›" just right of the location icon lists your folders (Downloads, Desktop, Documents and so on), your user folder, This PC and your drives, two clicks from anywhere (the same order as File Explorer; Home, Gallery, Libraries, Network, Control Panel and the Recycle Bin are left out because the file list cannot open them). The "›" lists are now the same rounded floating cards as the search suggestions. Because clicking the file list now leaves the text box, you can no longer keep the text box open while you go and copy a file name from the list (File Explorer works the same way)

### Fixed

- **"Open file location" on a shortcut whose target was moved or deleted now opens the nearest parent folder that still exists (#482)** [Preview 2.1.0.2] — Previously it only showed "Link target not found" and opened nothing. Now it opens the closest folder above the shortcut's recorded target that still exists, and tells you "Link target not found. Opened the nearest folder that still exists". It does not search for where the target was moved to, as File Explorer sometimes does. If the whole drive or shared folder cannot be found, it still shows "Link target not found" as before

- **Fixed an error, "Drag-and-drop operation already in progress", that could appear when you started dragging files (#483)** [Preview 2.1.0.2] — The error fixed once in v2.0.0 (#474) could still appear. The earlier fix recognized "another drag is already in progress" by the error number Windows returns, but the same error sometimes arrived in a different form and slipped past that check. Now, whenever the Windows drag returns an error, whatever the number, it is treated as "the drag did not start": no error window appears and you can carry on. What the error was is still written to the log

- **Column widths you changed went back to their old sizes when you restarted the app; fixed (#484)** [Preview 2.1.0.3] — Dragging a column border was meant to switch the column width setting to "Set by hand" and remember that width. But the code that should notice the drag was never called, so the setting stayed at "Fit to window" and the widths were recalculated from the pane width at every startup. Now dragging a column border switches to "Set by hand" (a notice appears the first time), and the next startup opens with the same widths. The widths are remembered once for the whole app, not per tab, with separate widths for normal lists and search results. For the same reason, the guard that keeps a hidden column from widening when you drag its border was not working either; that is fixed too

- **Fixed the search file type filters (Folder, Excel, PDF…) sometimes being turned off on their own (#486)** [Preview 2.1.0.4] — Each tab kept its own copy of the type filter state, but only one copy was saved for the whole app. Changing a chip in a tab that had been open for a while saved that tab's old state over everything, undoing changes made in other tabs. New search tabs start from the saved state, so the filters looked like they had been turned off when you searched. The type filters are now one shared state for the whole app, like the size and date conditions: a change in any tab applies to every tab's results and is kept across restarts. Two other places that changed conditions without saying so are fixed too. Picking a search history entry cleared the current size and date conditions even when that search had none; now conditions are restored only for entries that had them. Esc in an empty search box (the second press) and right-clicking the preset button were meant to reset the index scope to all folders but kept the previous selection; they now reset it and tell you so

- **Fixed the "index may be out of date" notice above index search results being unreadable in light themes (#487)** [Preview 2.1.0.4] — The notice used the light text color meant for the dark address bar, so on light themes it was almost the same color as its background. The text color is now picked from the notice's own background (black or white, whichever reads)

- **Fixed a line appearing under the first result row when a notice was shown above index search results (#487)** [Preview 2.1.0.4] — The shadow at the top of the list was placed lower by the height of the notice above it instead of at the bottom of the column headers. The notice itself now matches the type chip bar above it, as a rounded box with side margins

- **Fixed copying or moving with files that no longer exist doing nothing or skipping them silently (#489)** [Preview 2.1.0.4] — When the selection included files that another app had renamed, moved or deleted, a right-drag showed no drop menu and nothing happened, and a normal drag or paste skipped the missing files without a word (and did nothing at all if none were found). Now, like File Explorer, the files that exist are copied or moved, and the missing ones are skipped with a notice such as "Skipped 2 item(s) that could not be found (a.txt, b.txt)". When none are found, a notice says so. The right-drag drop menu now appears even when some files are missing

- **Fixed clicking the empty part of a scrollbar (above or below the thumb) doing nothing (#490)** — App scrollbars were meant to move a page when you click the empty track above or below the thumb, but nothing happened. The track pieces picked up the default look from the UI component library, which has no background, so they never received the click. ### Fixed

- **リンク先が移動・削除されたショートカットで「ファイルの場所を開く」を押すと、残っている上位のフォルダを開くようにしました (#482)** 〔先行版 2.1.0.2〕 — これまでは「リンク先が見つかりません」と知らせるだけで、どこも開きませんでした。いまは、ショートカットが覚えている行き先の場所のうち、まだ残っているいちばん近い上位のフォルダを開き、「リンク先が見つからないので、残っている上位のフォルダを開きました」と知らせます。エクスプローラーのように移動先を探し当てることはしません。ドライブや共有フォルダごと見つからないときは、今までどおり「リンク先が見つかりません」と知らせます

- **ファイルをドラッグしようとしたときに「ドラッグ操作は既に実行中です」のエラーが出ることがあったのを直しました (#483)** 〔先行版 2.1.0.2〕 — v2.0.0 で一度直した（#474）エラーが、まだ出ていました。前の直し方は、Windows が返すエラーの番号で「別のドラッグと重なった」ことを見分けていました。ところが同じ文面のエラーが別の形で届き、見分けを素通りしていました。いまは、Windows のドラッグがエラーで返ったときは番号によらず「ドラッグは始まらなかった」として扱い、エラーの窓を出さずにそのまま操作を続けられます。何のエラーだったかは、ログに残します

- **列の幅を変えても、アプリを再起動すると元の幅に戻っていたのを直しました (#484)** 〔先行版 2.1.0.3〕 — 列の境目をドラッグすると、列の幅の決め方が「自分で決める」に切り替わり、その幅を覚えるはずでした。ところが、このドラッグを拾う処理が一度も呼ばれておらず、決め方は「画面の幅に合わせる」のまま、起動のたびに画面の幅から計算し直していました。いまは境目をドラッグすると「自分で決める」に切り替わり（初めての時は知らせが出ます）、次に起動しても同じ幅で開きます。覚える幅はタブごとではなくアプリ全体で 1 つで、ふつうの一覧と検索結果は別々に覚えます。あわせて、隠した列の境目をドラッグしても幅が広がらないようにする処理も、同じ理由で効いていなかったので直りました

- **検索すると、種類のフィルタ（フォルダ・Excel・PDF…）が勝手に外れていることがあったのを直しました (#486)** 〔先行版 2.1.0.4〕 — 種類のフィルタの状態はタブごとに持っていたのに、保存はアプリ全体で 1 つでした。そのため、前から開いていたタブで 1 つ切り替えると、そのタブが開いたときの古い状態で全体を上書きし、別のタブで変えた分が消えていました。その後に開く検索タブはこの状態を引き継ぐので、「検索したらフィルタが外れている」ように見えました。いまは種類のフィルタをサイズ・日付の条件と同じくアプリ全体で 1 つにし、どのタブで変えても全部のタブの結果に効き、再起動しても残ります。あわせて、条件が黙って変わる所を 2 つ直しました。検索履歴を選ぶと、条件を付けずに探した履歴でも、いま付けているサイズ・日付の条件が消えていました。いまは条件を付けて探した履歴だけ条件を戻します。検索欄が空のときの Esc（2 回目）とプリセットのボタンの右クリックは、「索引の範囲を全部に戻す」はずが前の選び方のまま残していました。いまは全部に戻し、戻したことを知らせます

- **インデックス検索の結果の上に出る「インデックスが古いかもしれない」の注意の文字が、明るいテーマで読めなかったのを直しました (#487)** 〔先行版 2.1.0.4〕 — 注意の帯の文字に、アドレスバー（暗い帯）用の明るい文字色を使っていたため、明るい地のテーマでは地とほぼ同じ色になっていました。いまは帯の地の色から、読める文字色（黒か白）を選びます

- **インデックス検索の結果の上に注意の帯が出ると、一覧の 1 行目の下に線が出ていたのを直しました (#487)** 〔先行版 2.1.0.4〕 — 一覧の上端に落とす影の位置を、ヘッダーの下端ではなく、上の行（注意の帯）の高さの分だけ下で計算していました。注意の帯も、上の種類のチップの帯と同じく、左右に余白を取った角の丸い枠にしました

- **見つからないファイルを含めてコピー・移動すると、何も起きなかったり黙って飛ばされたりしていたのを直しました (#489)** 〔先行版 2.1.0.4〕 — ほかのアプリで名前が変わった・移動された・消されたファイルを含めて運ぶと、右ボタンのドラッグでは落とした先のメニューが出ずに何も起きず、ふつうのドラッグや貼り付けでは見つからないファイルを黙って飛ばしていました（全部見つからないときは黙って何もしませんでした）。いまはエクスプローラーと同じく、見つかるファイルは運び、見つからないファイルは飛ばして「見つからない 2 件（a.txt, b.txt）は飛ばし、残りをコピーします」と知らせます。全部見つからないときは「コピーする項目が見つかりませんでした」と知らせます。右ボタンのドラッグのメニューは、見つからないファイルがあっても出ます

- **スクロールバーの空いた所（つまみの上下）を押しても動かなかったのを直しました (#490)** — アプリの中のスクロールバーは、つまみの上下の空いた所を押すと 1 ページずつ動くはずでしたが、押しても何も起きませんでした。空いた所の部品の見た目に、画面の部品集の既定の見た目が当たっていて、その見た目は地の色を持たないため、押下を受け取れていませんでした。いまは空いた所を押すと 1 ページずつ動き、押し続けると続けて動きます。ファイル一覧の縦・横のスクロールバーのほか、右クリックのメニューの中や、ナビペインのフォルダのツリーなどの細いスクロールバーでも、空いた所を押せるようにしました（これらには元々空いた所の部品がありませんでした）

> 過去の変更履歴は [Releases](https://github.com/sulkyjp/zenithFiler_update/releases) を参照してください。
