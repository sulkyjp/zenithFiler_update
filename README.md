## Latest Changes — [1.15.0] - 2026-09-18 : Six new themes, automatic favorites for folders you open often, and unreadable text fixed by measuring what is actually drawn on screen

### Added
- **Added four themes (54 in total)** — **Midnight Espresso** (Professional, the cool glow of a screen in a late-night café), **Rainfall Blue** (Professional, rain-washed blues and greys), **Ember Fury** (Premium, ember red and burning orange on starlit black) and **Magenta Aviatrix** (Premium, vivid magenta on a softly blushing ground) were previously store downloads and are now bundled, so they can be picked without downloading anything. Each was rebuilt to the standard of the bundled themes: the number of specified colours went from around 100 to over 154 (unspecified colours are inherited from others, which can let text sink into its background on some screens), and every text-and-background pairing was measured by rendering all 54 themes across 25 screens until **no unreadable pairing remained**. Their descriptions are now available in all 10 languages
- **Frequently used folders can now be added to favorites automatically (#329)** — Turning on "Add frequently used folders automatically" in the favorites view settings (the gear icon) registers a folder once it has been opened exactly the configured number of times. Entries are collected in a "Frequently Used" folder, so the order you arranged by hand stays intact. The addition happens **once, at the moment the count is reached**, so deleting an automatically added entry will not bring it back the next time you open that folder. The threshold can be set to 2 or more and defaults to 20. Because favorites are something you curate yourself, the feature is **off by default**. Nothing is added while favorites are locked
- **The theme store now asks whether to switch to a theme right after it is downloaded** — Downloading did not apply the theme, so you had to find it again in the list and select it. The moment it arrives is the moment you want to try it, so the question is asked there. It is skipped when the theme is already in use, since answering yes would change nothing
- **Publishing a theme to the store now asks for confirmation first** — Publishing makes a theme available for anyone to download and cannot be undone, so a misplaced click should not be enough. The question is skipped when it follows on from the prompt shown right after saving a theme, which already asked
- **A thank-you message is now shown after a theme is published** — Previously there was only a toast that disappears after a few seconds, which meant the thing most worth saying — that your palette may change someone's day — went by unnoticed
- **Added two more themes (56 in total)** — **Rust Lance** (RetroTech, rust and steel lit by running-flame orange) and **Crimson Gamma** (Premium, battle-worn crimson and steel) were previously store downloads and are now bundled. Each was rebuilt to the standard of the bundled themes, going from 100 specified colours to 154, with descriptions in all 10 languages

### Changed
- **Theme store ratings now require an explicit Submit (#327)** — Tapping a star sent the rating to the server immediately, so a single mis-aimed click while reaching for a card left a rating behind with no way to undo it. Stars now only select; the rating is sent when you press "Submit rating". The stars show your own score (previously they always showed the community average, so re-rating barely moved the display and looked like it could not be changed), and the community average is shown as a number beside them. A failed submission is rolled back, and the stars have a larger click area
- **Generated and imported themes are now checked for readability on settings cards as well** — Body text, secondary text and button labels were only checked against the app's base surface. Settings cards are painted in a different colour, so a theme could pass the checks and still be hard to read on a card. Card surfaces are now covered by the same checks and automatic correction
- **The automatic correction that keeps theme text from blending into its background now covers far more of the screen (#328)** — It previously looked only at buttons and the settings sidebar. All 50 themes were rendered across 25 screens to find which text and surfaces actually sit together, and the title bar, sidebar, status bar, header icons, address bar, badges, settings cards, the hint text inside the search box, the focused pane header and the AI badge were added. When one text colour sits on several surfaces (for example the normal pane header and the focused one), correcting each surface in turn used to undo the previous correction and leave one side unreadable; a single lightness that satisfies every surface at once is now chosen instead. A colour scheme that cannot satisfy all of its surfaces at any lightness is left untouched and logged, rather than breaking one side to fix the other. This correction is the last line of defence that also reaches store themes, hand-edited themes and AI-generated themes. It now also covers **surfaces that do not appear in the theme's colour table at all** — the stripe on every other row of the file list is derived by the app from the base colour, so it was previously invisible to the correction. A row sits on a different surface depending on whether its pane has focus, so a lightness that stays readable across all four combinations (both surfaces, with and without the stripe) is now chosen, which fixes the date of recently changed items being unreadable on striped rows in 12 themes
- **A bare IP address typed into the address bar now opens in your default browser (#316)** — Router and NAS admin pages are usually reached by typing something like `192.168.1.1`. People type it the way they would in a browser, but Zenith Filer could not read it as an absolute URL and could not find it as a folder either, so nothing happened and no error appeared. Four-part IP addresses now get an `http://` prefix and are handed to the default browser. A port (`192.168.1.1:8080`) or a path (`192.168.1.1/admin`) works the same way. Bare host names such as `example.com` are still left alone, because they cannot be told apart from a folder of the same name — type the `https://` prefix for those. Shared folders such as `\\192.168.1.1\share` keep opening as folders.
### Fixed
- **Fixed the "What's new" window showing an old release when opened from the options (#326)** — Depending on how the app was deployed, the lookup for the changelog could find leftovers from an earlier installation first, and whatever version stood at the top of that file was shown as the latest. The app now verifies that the file actually describes the running version, and says so instead of silently showing stale content. The startup notice swallowed the same failure by showing nothing, which is why only the options route looked broken
- **Fixed the selected "Manual / Changelog" tab being unreadable in Graphite, Monochrome, PaperWhite and others (#328)** — Only the selected tab lost its label, because the text colour that matches the button fill never reached it. This affected more than half of the bundled themes. The same cause made the "All" filter chip on the theme screen unreadable while selected, which is fixed too
- **Fixed labels and icons becoming unreadable once selected in the settings screen** — The descriptions under the option choices (context menu type, search and index behaviour) and the item names and icons in the left menu kept their old colour when the row was selected, so only the background flipped. This affected 40 themes for the descriptions and 29 for the menu icons. All of them now switch to the selected colour
- **Fixed toolbar and search-mode buttons losing their icon while selected in some themes** — The icon used a colour that was not paired with the selected fill. In themes that use the same value for the selection and accent colours (such as Retro95) the icon ended up exactly the same colour as its background
- **Fixed the "Search in subfolders" hint in the search box being too faint to read in every theme** — An already-muted text colour had a further dimming applied on top of it
- **Fixed the drop-down arrows on the terminal buttons being too faint to see in every theme** — Same cause as above: dimming stacked on an already-muted colour
- **Fixed category buttons such as "Standard (10)" on the theme screen not scrolling to that section (#327)** — The inner list absorbed the scroll request, so it never reached the outer area that actually scrolls. "My themes" and "Store" sit outside the list and had always worked, which is why only the curated categories were affected
- **Fixed the size column becoming unreadable when a folder row is selected (#328)** — Folder rows show their size cell in a faint italic, and that instruction outranks the colour a row takes when selected, so only the background flipped and the faint text stayed behind. This affected 34 of the bundled themes. Hovering and selecting now return the cell to the colour that pairs with the fill
- **Fixed the "Lv" and title badges in the title bar being hard to read (#328)** — The whole badge was drawn at 85% opacity, which undid the contrast the theme had reserved between the label and the fill by the time it reached the screen; purple themes suffered most. The neighbouring "PRO" badge never had that dimming, so it was removed to match
- **Fixed the terminal options button and the indexing spinner being invisible in pale themes (#328)** — Both were drawn in the accent colour, which in pale themes is light enough to blend into the bar the icon sits on (the terminal action bar and the status bar). The terminal icon now uses the dedicated colour that marks an option as currently on, and the spinner matches the progress message beside it
- **Fixed the file list using mismatched colours when panes have their own themes** — Applying a theme to a single pane also overwrote the place where the app records which theme is currently in use. The list stripes, the per-file-type colours and the favourite colour tags each adjust their lightness against the base colour and then remember the result, so this mix-up left them built from the *pane* theme's base colour. The symptom was fixed the moment the list was first drawn and stayed until the app-wide theme was changed — in practice, until a restart. Applying a theme to a single pane no longer touches the app-wide state, and no longer counts as changing the theme
- **Fixed the close-tab button losing its icon on hover in some themes (#328)** — The red surface and the discard icon ended up almost the same colour, so the button was visible but the icon on it was not. This affected Retro95, SlateBlue, Graphite, RoseDust, CrimsonPeak, IronSteel and Nordic. **Colours that only appear while the cursor is over something cannot be measured by the full render sweep** (the result would depend on where the cursor happens to be, so hovered elements are excluded), so a new automated check covers this pairing across all 54 themes
- **Fixed the favorites settings window being cut off at the bottom, leaving the OK button unreachable** — Its height was fixed, so anything past that was simply clipped, and because the window could not be resized there was no way to get to the button. The contents now scroll, the OK button is pinned to the bottom, and the window can be resized. Dialogs are also **fitted to the screen's work area when they open**, so they no longer extend past the edge on shorter displays
- **Fixed coloured labels being hard to read in the achievement history and the version information (#328)** — Small coloured labels such as category names, titles and the "Changed" tag had a further dimming applied on top of their colour, which pulled the text and its background towards the surface behind them and closed the gap between them (2.43:1 in CloudGray). Themes guarantee readability as a text-and-background pair, but the dimming sat outside that pair, so neither the theme checks nor the full render sweep could see it. The dimming is gone and the background now uses the colour paired with the text. **An automated check now finds this shape wherever it appears**, so the same mistake on another screen will not go unnoticed
- **Fixed text and icons sinking into the background in themes you made or downloaded** — When a theme is created, some colours were left out on the assumption that inheriting them from other colours would keep everything in harmony. But inheritance only decides **which colour to borrow**; nobody checks whether the borrowed colour is readable where it actually lands. Bundled themes hid the problem because their base and sidebar are close in lightness, so it **only showed up in themes you made yourself**. Every colour is now settled when a theme is saved, and put through the readability correction as well. This covers both AI-generated themes and themes downloaded from the store. The correction also now covers text sitting on the navigation band and pane headers, and the "back to work" icon in the settings sidebar no longer sinks into the band
- **Fixed a load error appearing on every launch after typing a web address into the address bar** — The address box writes what you type back to the current location after a short delay, so a web address could be recorded as the current location before it was handed to the browser, and then saved as a path. Every later launch would try to open it and fail. Values that are not locations are now rejected both when saving and when restoring, and a value already saved is quietly returned to a real location on the next launch

## 最新の変更履歴 — [1.15.0] - 2026-09-18 : テーマを 6 本増やし、よく使うフォルダの自動お気に入りを足し、文字と背景の同化を描画の実測で解消した

### Added
- **テーマを 4 本追加した（全 54 本）** — ストアで配布していた **Midnight Espresso**（Professional・深夜のカフェの青白い画面）、**Rainfall Blue**（Professional・雨に洗われた青とグレー）、**Ember Fury**（Premium・星空の黒地に燃える赤とオレンジ）、**Magenta Aviatrix**（Premium・淡い桃色の地に弾ける鮮やかなマゼンタ）を、パッケージに組み込んだ。ダウンロードしなくても最初から選べる。取り込みにあたっては同梱テーマの水準に合わせて作り直してあり、色の指定を 100 前後から 154 以上へ増やし（指定の無い色は別の色から引き継ぐため、画面によっては文字が背景に沈むことがある）、文字と背景の組み合わせを全 54 テーマ × 25 画面の描画実測で確認して**読めない組み合わせを 0 件**にした。説明文も 10 言語に揃えている
- **よく使うフォルダを自動でお気に入りに追加できるようにした (#329)** — お気に入りビューの設定（歯車）にある「よく使うフォルダを自動で追加」を入れると、指定した回数ちょうど開いたフォルダを一度だけお気に入りへ登録する。追加先は「よく使う」フォルダにまとまるので、手で作った並びは崩れない。**規定回数に達した瞬間の一度きり**にしてあるので、自動で入ったものを削除しても、次に開いたときに復活することはない。規定回数は 2 以上で指定でき、既定は 20 回。お気に入りは自分で育てるものなので、この機能は**既定ではオフ**にしてある。お気に入りに鍵を掛けている間は自動追加も行わない
- **テーマストアで、取り込んだ直後に「今すぐ切り替えるか」を聞くようにした** — これまでは取り込んでも当たらないため、一覧からそのテーマをもう一度探し出して選び直す必要があった。取り込めた瞬間が、いちばん試したい瞬間なので、その場で聞く。すでにそのテーマを使っているときは聞かない（「はい」と答えても何も変わらないため）
- **テーマをストアへ公開する前に、確認のウィンドウを出すようにした** — 公開はほかの人がダウンロードできるようになる操作で、取り消しが利かない。押し間違いから守る。ただし、テーマを保存した直後に「ストアへ出しますか」と尋ねた流れから続けたときは、二度は聞かない
- **公開できたときに、感謝のメッセージを表示するようにした** — これまでは数秒で消えるトーストだけだったため、「あなたの配色が誰かの毎日を変えるかもしれない」という、いちばん伝えたいことが流れてしまっていた
- **テーマを 2 本追加した（全 56 本）** — ストアで配布していた **Rust Lance**（レトロテック・錆と鋼に走行炎のオレンジ）と **Crimson Gamma**（プレミアム・戦い抜いた深紅と鋼）を、パッケージに組み込んだ。取り込みにあたっては同梱テーマの水準に合わせて作り直し、色の指定を 100 から 154 へ増やし、説明文も 10 言語に揃えている

### Changed
- **テーマストアの星評価を「選んでから送信」に変えた (#327)** — 星に触れた瞬間にサーバーへ送っていたため、カードを押そうとして狙いが逸れた一度のクリックで評価が付いてしまい、取り消す手段もなかった。星は選ぶだけにして、「評価を送信」を押したときに初めて送るようにした。星は自分が付けた点を表し（これまでは常にみんなの平均だったので、付け直しても表示がほとんど動かず変更できないように見えていた）、みんなの平均は隣に数字で出す。送信に失敗したときは元に戻す。星の押せる範囲も広げた
- **AI で生成したテーマや取り込んだテーマが、設定画面のカードの上でも読める配色になるようにした** — 本文・補助文・ボタンの文字は、これまで「アプリの地の色の上で読めるか」だけを見ていた。設定画面のカードは地の色とは別の色を敷いているため、検査を通っていてもカードの上では読みにくい配色があり得た。カードの上での読みやすさも検査と自動補正の対象にした
- **テーマを適用するときの「文字が背景と同化しないようにする補正」の守備範囲を広げた (#328)** — これまではボタンと設定画面の左メニューまわりだけを見ていた。全 50 テーマ × 25 画面を実際に描いて調べ、タイトルバー・サイドバー・ステータスバー・ヘッダーのアイコン・アドレスバー・各種バッジ・設定画面のカード・検索欄の中の案内文・フォーカス中のペインの見出し・AI のバッジなど、画面で実際に隣り合っている組も対象に加えた。あわせて、同じ文字色が複数の面（たとえば通常のヘッダーとフォーカス中のヘッダー）に乗る場合、面ごとに順番に直すと後の面の補正が前の面の補正を壊して片側しか読めなくなっていたのを、すべての面で同時に読める明るさを一度に選ぶように変えた。どの明るさでも両立できない配色は、片側を壊さないよう補正せず記録だけ残す。この補正は配信テーマ・手で編集したテーマ・AI が作ったテーマまで届く最後の砦にあたる。あわせて、**テーマの色表に載っていない面**も対象に含めた —— 一覧の 1 行おきに敷く縞はアプリが地の色から作っているため、これまで補正の対象外だった。行の下地はフォーカスしているペインかどうかで変わるので、2 種類の下地とその上に縞が重なった状態の4 通りすべてで読める明るさを選ぶようにし、「最近更新した項目」の日時が縞の行で読めなくなる問題（12 テーマ）を解消した
- **アドレスバーに IP アドレスだけを打っても、既定のブラウザで開くようにした (#316)** — ルーターや NAS の管理画面は `192.168.1.1` と打たれることが多い。ブラウザのアドレスバーと同じ感覚で入力されるが、これまでは絶対 URL として解釈できず、フォルダとしても見つからないため、何も起きずエラーも出なかった。4 つ組の IP アドレスに限って `http://` を補い、既定のブラウザへ渡す。`192.168.1.1:8080` のようにポートを付けても、`192.168.1.1/admin` のように続きを書いても同じ。`example.com` のようなホスト名は、同じ名前のフォルダと区別できないため従来どおり開かない（`https://` を付けてください）。`\\192.168.1.1\share` のような共有フォルダも、これまでどおりフォルダとして開く。
### Fixed
- **オプションから「更新のお知らせ」を開くと、古い版のお知らせが出ることがある問題を修正 (#326)** — 更新履歴のファイルを探す手順が、配置によっては以前のインストールの残骸を先に見つけることがあり、そのファイルの先頭にある版を無条件に「最新」として表示していた。いま動いている版の記載があるファイルかどうかを確かめるようにし、確かめられないときは黙って古い内容を出さずに、その旨を知らせるようにした。起動時に出るお知らせは同じ故障を無表示で握り潰していたため、設定から開いたときだけ症状が見えていた
- **Graphite・Monochrome・PaperWhite などで「マニュアル／更新履歴」の選択中のタブが読めない問題を修正 (#328)** — 選択中のタブだけ、文字がボタンの色とほぼ同じになって消えていた。ボタンの色に合う文字色が選択中のタブへ届いていなかったのが原因で、同梱テーマの半数以上で起きていた。あわせて、同じ原因でテーマの絞り込みチップ「All」も選択中に読めなくなっていたのを直した
- **設定画面で、選んだ項目の文字やアイコンが読めなくなる問題を修正** — 選択肢（コンテキストメニューの種類・検索やインデックスの動作）の説明文、および左メニューの項目名とアイコンが、選ぶと背景だけ反転して文字色が取り残されていた。説明文は 40 テーマ、左メニューのアイコンは 29 テーマで起きていた。いずれも選択中の色に切り替わるようにした
- **ツールバーや検索モードのボタンが、選択中にアイコンごと消えるテーマがある問題を修正** — 選択中の面に対して、対になっていない色をアイコンに当てていたのが原因。選択色とアクセント色に同じ値を使っているテーマ（Retro95 など）では、アイコンが背景と完全に同じ色になって見えなくなっていた
- **検索欄の「フォルダ以下を検索」という案内文が、どのテーマでも薄すぎて読めない問題を修正** — 元から控えめな文字色に、さらに薄く見せる指定が重なっていた
- **ターミナルのボタンに付いている下向き矢印が、どのテーマでも薄すぎて見えない問題を修正** — 上と同じく、控えめな文字色に薄さが重ねられていた
- **テーマ画面で「スタンダード(10)」などのカテゴリを押しても、その位置まで移動しない問題を修正 (#327)** — 一覧の内側が移動の要求を受け止めてしまい、実際にスクロールする外側まで伝わっていなかった。「テーマ作成」「ストア」は一覧の外にあるため以前から動いており、キュレーションのカテゴリだけが効かない状態だった
- **フォルダーを選んだとき、サイズ欄の文字が読めなくなる問題を修正 (#328)** — フォルダーの行はサイズ欄を薄い斜体で出しているが、この指定が「行を選んだときの文字色」より優先されるため、面だけが反転して薄い文字が取り残されていた。同梱テーマの 34 本で起きていた。カーソルを乗せたとき・選んだときは、面と対になる色へ戻すようにした
- **タイトルバーの「Lv」と称号のバッジで、文字が読みにくい問題を修正 (#328)** — バッジ全体を 85% の薄さで描いていたため、テーマ側で確保していた文字と面のコントラストが描画の段階で崩れていた（紫系のテーマで顕著）。すぐ隣の「PRO」バッジは元から薄さを掛けておらず、そちらに揃えて撤去した
- **淡いテーマで、ターミナルのオプションボタンとインデックス作成中のアイコンが見えない問題を修正 (#328)** — どちらもアクセント色で描いていたが、淡いテーマではアクセント色自体が明るいため、アイコンが乗っている帯（ターミナルの操作バー・ステータスバー）と同化していた。ターミナル側は「その操作が今 ON」を表す専用の色へ、インデックス側は隣に出ている進捗メッセージと同じ色へ変えた
- **ペインごとにテーマを分けているとき、一覧の配色がちぐはぐになる問題を修正** — ペイン 1 枚だけにテーマを着せる処理が、アプリ全体が「いまどのテーマか」を持っている場所まで書き換えていた。一覧の縞模様・ファイル種別ごとの色分け・お気に入りのカラータグは、地の色に合わせて明るさを自動調整してから覚えておく仕組みなので、この取り違えが起きると**ペインのテーマの地の色を基準に作られた色**がそのまま残る。症状は一覧を初めて描いた時点で決まり、全体のテーマを切り替えるまで（実質、再起動するまで）直らなかった。ペイン 1 枚への適用では全体の状態に触れないようにし、あわせて「テーマを変えた回数」にも数えないようにした
- **タブを閉じるボタンにカーソルを乗せたとき、アイコンが見えないテーマがあったのを修正 (#328)** — 赤い面と破棄アイコンがほぼ同じ色になり、押せる場所は分かるのにアイコンが消えていた。Retro95・SlateBlue・Graphite・RoseDust・CrimsonPeak・IronSteel・Nordic の 7 テーマで起きていた。**カーソルを乗せている間の色は、全テーマ × 全画面の描画実測でも測れない**（カーソルの居場所で結果が変わるため走査の対象外）ので、この組み合わせを検査する自動テストを新しく足し、全 54 テーマで確認するようにした
- **お気に入りの設定画面で、下の方が切れて OK ボタンが押せなくなっていたのを修正** — 高さが固定で、中身がそれを超えると下がそのまま切れる作りだった（大きさも変えられなかったため、閉じることもできなかった）。中身をスクロールできるようにし、OK ボタンは常に下端へ固定し、ウィンドウの大きさも変えられるようにした。あわせて、**ダイアログを開くときに画面の作業領域へ収める**ようにしたので、縦の狭いディスプレイでも画面からはみ出さない
- **実績の履歴とバージョン情報で、色付きのラベルの文字が読みにくいのを修正 (#328)** — カテゴリ名・称号・「Changed」といった色付きの小さなラベルに、色の上からさらに薄くする指定が重なっており、文字と背景がそろって下地へ寄って差が縮んでいた（CloudGray で 2.43:1）。テーマ側は「文字と背景の組」で読みやすさを確保しているのに、その外側で薄めていたため、テーマの検査にも全画面の描画実測にも映らなかった。薄くする指定をやめ、背景を文字と対になっている色で塗るようにした。**同じ書き方をした箇所を洗い出す自動テストも足した**ので、次に別の画面で同じことをしても気づける
- **自分で作ったテーマや取り込んだテーマで、文字やアイコンが背景に沈む問題を修正** — テーマを作るとき、一部の色は「指定しなくても他の色から引き継げば調和する」として省略していた。ところが引き継ぎは**どの色から借りるかを決めるだけ**で、借りた色が実際に乗る場所で読めるかは誰も見ていなかった。同梱テーマでは地とサイドバーの明るさが近いため表に出ず、**自分で作ったテーマだけで起きて**いた。テーマを保存する時点ですべての色を確定させ、読みやすさの補正まで通すようにした。AI で作ったテーマとストアから取り込んだテーマの両方に効く。あわせて、ナビの帯・見出しの上に乗る文字の補正範囲も広げ、設定画面の「作業に戻る」ボタンのアイコンが帯に沈んでいたのも直した
- **アドレスバーに Web アドレスを打った後、起動のたびに読み込みエラーが出ることがあったのを修正** — アドレス欄は打ち込みを少し遅れて現在地へ書き戻すため、ブラウザへ渡す前に Web アドレスが現在地として残り、パスとして保存されてしまうことがあった。次の起動でその場所を開こうとして失敗し続ける。保存と復元の両方で、場所ではない値を受け付けないようにした。すでに保存されてしまっている場合も、次の起動で自動的に元の場所へ戻る
