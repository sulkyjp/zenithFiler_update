## Zenith Filer in 4 Lines / 4 行でわかる Zenith Filer

- ⚡ **Fast** — starts in about 1 second, every operation runs asynchronously. Optimized on real measurements to stay snappy even on antivirus-laden corporate PCs<br>**速い** — 起動約 1 秒・全操作を非同期化。ウイルス対策ソフトで重い社用 PC でも軽快に動くよう実測ベースで最適化

## Latest Changes — [1.16.0] - 2026-09-19 : A progress window for copying and moving, per-element font and icon sizes, and no more freezing when handling large numbers of files

### Added
- **List and tab text and icon sizes can now be set individually (#331)** — Until now the only way to change any of this was the row height, and the text size itself could not be chosen (it only shrank automatically at a row height of 20px — a two-step link, nothing more). **List text, list icons and tab text** can now each be picked in Settings → Display. All three default to **Auto (follow row height)**, so **if you leave them alone nothing changes**. Choose a size yourself and it stays put even when the row height changes. The tab text setting applies both to the A/B pane tabs and to the tab list in the navigation pane. Sizes stay within readable bounds: 8–32 for text, 8–48 for icons.
- **Transfers that keep being denied now stop early, and say why (#334)** — When Windows ransomware protection (Controlled folder access) is in the way, **every single file fails**. Zenith Filer used to try each one to the end: 5000 files meant 5000 pointless attempts, and **nothing explained the failure**. It now stops after 10 failures in a row for the same reason and tells you that **ransomware protection may be blocking it, and that adding Zenith Filer to the allowed apps in Windows Security often resolves it**. A success in between resets the count, so a single file being open does not stop the whole transfer.
- **The window froze right after copying or moving a lot of files (#336)** — Dropping around 1200 files into the other pane made the app stop responding for one to three seconds. The folder watcher was **notifying the UI once per file**, so 1200 files meant thousands of queued updates. They are now handled as one batch, and when there are many changes the list is simply reloaded once. Small numbers of changes are still applied one by one, so renaming a file does not lose your selection or scroll position. We also removed the cost of **re-reading every dragged file name from the OS on each cursor move** while dragging (a drag that starts inside the app already knows what it carries). On top of that, a **right-button drag** asked the OS about every file one by one so that dropping outside the app would offer the standard menu; inside a cloud-synced folder this stalled for 1.5 to 1.9 seconds with 1200 files. We now skip that when there are many files (the menu you get where you drop still appears).
- **Clicking one file while several are selected now selects just that file (#335)** — The multi-selection used to stay, so you had to click an empty area first to start over. This now matches File Explorer. Dragging a multi-selection still works as before: the selection is kept when you actually drag.
- **The overwrite prompt could hide behind the copy progress window (#335)** — The prompt could end up behind the progress window, leaving the transfer stuck with no way to answer. The prompt now always sits in front, and the progress window no longer takes the input focus.
- **A progress window for copying and moving (#334)** — While copying a lot of files, all you had was a thin bar at the bottom left and a single line of text. There is now a window listing **speed, time remaining, file count, size and the file being processed**. You can **pause and resume**, and **stop each operation individually**. Several copies appear as rows in one window (previously, starting a second copy silently stopped the first — that is fixed too). **Progress also appears on the taskbar icon**, so you can follow it from another application. **Closing the window does not stop the transfer** — the bar at the bottom left takes over, and it stays hidden while the window is up so the same numbers never move in two places. The window closes itself once everything succeeds and stays open when something was stopped or failed. Choose when it appears in Settings → Display → Copy progress window: **always**, **only for large transfers**, or **never**.
- **Usage statistics now count macros, AI, archiving and remote connections (#266)** — The statistics page lists things like "Open folder" and "Close tab", but **macros and AI were never counted at all**, so there was no way to tell whether they went unused or simply unmeasured — and no basis for deciding what to polish next. Zenith Filer now counts macros (running one, recording actions, opening the Studio), AI (manual, folder cleanup, tab cleanup, rename, theme generation, macro generation, favorites cleanup, usage analysis, folder creation, Stickman generation), compressing and extracting, and remote connections. **Anything the app calls by itself — the greeting on startup, challenge titles — is not counted**: those are not actions you took, and counting them would distort the ranking of what you actually use. A remote connection counts only the **first time you connect to that site**.
- **You can now rate themes from the cards in the theme list (#327)** — Until now the stars on the **Theme** tab were decoration showing the average, and clicking them did nothing. They now work the same way as the store cards: pick a star, then confirm with **Submit rating**. **Bundled themes can be rated too.** The stars show your own score, with the community average as a number next to them. Every bundled theme is by the same author, so that line was given over to the rating instead.

### Fixed
- **The Application key `[≡]` did not open the menu (#332)** — There was no way to open the menu without taking your hands off the keyboard: the file list had **no keyboard route to the menu at all**, and `Shift+F10` fell through to the Windows window menu, which did something else entirely (maximising, for instance). Both the Application key and `Shift+F10` now open the menu for the selected files, **just below the selected row** so the row stays visible. With nothing selected you get the same menu as right-clicking the background. The Application key can be reassigned in settings (Shortcuts → File list → Context menu); `Shift+F10` is fixed, because Windows sends it everywhere. **Shift-right-click still opens the standard Windows menu as before** — only for `Shift+F10` is that `Shift` not counted.
- **Shortcuts (.lnk) pointing into a network location could not be opened (#330)** — A shortcut whose target lives on a mapped network drive, such as `X:\networkpath\file.abc`, was reported as unrecognised and impossible to open. Zenith Filer checked whether the target existed and, when it could not confirm it, **gave up without handing the shortcut to Windows**. File Explorer never makes that check — it passes the shortcut straight to Windows, which takes care of connecting and signing in. Zenith Filer now does the same. When the place the target lives in (the drive or the share) is reachable and the target simply is not there, you still get the quick "link target not found" message as before, which also keeps confirmation windows from piling up when you open many items at once.

- **Category buttons on the Theme page did not jump to the category (#327)** — This was reported as fixed in v1.15.0, but it was not. The request to scroll was being **swallowed by a non-scrolling layer on its way up**, so it never reached the part that actually scrolls (measured: nine clicks across four categories left the scroll position unchanged, to the pixel). Zenith Filer now measures where the target sits and scrolls there directly, instead of relying on that request being passed along. The category you pressed also **lights up briefly**, using the same frame as random selection: the list lays the five categories out as columns side by side, so every category starts at the same height and the scroll position alone cannot tell you which one you picked. **Theme creation** and **Store** light up the same way.

## 最新の変更履歴 — [1.16.0] - 2026-09-19 : コピー・移動の進捗ウィンドウを作り、一覧とタブの文字の大きさを選べるようにし、大量ファイルの取り回しで固まる問題を解消した

### Added
- **一覧とタブの文字・アイコンの大きさを個別に決められるようにした (#331)** — これまで大きさを変える手立ては「行の高さ」だけで、文字そのものの大きさは選べませんでした（行の高さが 20px のときだけ自動で小さくなる、という2 段階の連動があるだけでした）。**一覧の文字・一覧のアイコン・タブの文字**の 3 つを、設定の「表示」からそれぞれ選べるようにしました。既定はどれも **「自動（行の高さに合わせる）」** なので、**設定を触らなければ見た目は今までどおり**です。自分で選ぶと、行の高さを変えても文字の大きさは保たれます。タブの文字はA/B ペインのタブとナビペインのタブ一覧の両方に効きます。読めない大きさにならないよう、文字は 8〜32、アイコンは 8〜48 に収めます。
- **移動やコピーが拒否され続けるとき、理由を添えて早めに止めるようにした (#334)** — Windows の「ランサムウェア防止（コントロールされたフォルダー アクセス）」に阻まれていると、**すべてのファイルで確実に失敗します**。これまでは 1 件ずつ最後まで試し続けたため、5000 件なら 5000 回ムダに試したうえ、**なぜ失敗したのかも伝わりませんでした**。同じ理由で 10 件続けて失敗したら止め、**「ランサムウェア防止に阻まれている可能性があります。Windows セキュリティの許可されたアプリに追加すると通ることがあります」と案内します**。途中に成功が挟まれば数え直すので、開いているファイルが 1 つある、といった場合には止まりません。
- **大量のファイルをコピー・移動した直後に画面が固まる問題を修正 (#336)** — 1200 件ほどを別のペインへドロップすると、その瞬間に 1〜3 秒ほど操作を受け付けなくなっていました。**フォルダの見張りがファイル 1 件ごとに画面へ知らせていた**のが原因で、1200 件なら数千回ぶんの処理が画面側に積み上がっていました。まとめて 1 回で処理するようにし、**件数が多いときは一覧を 1 回読み直すだけ**にしました。少数の変更はこれまでどおり 1 件ずつ反映するので、名前を変えたときに選択やスクロール位置が飛ぶことはありません。 さらに、**ドラッグ中はカーソルが動くたびに運搬中の全ファイル名を OS から取り出し直していた**ぶんも取り除きました（アプリ内のドラッグは中身が分かっているので問い合わせません）。 さらに、**右ボタンでのドラッグ**は、アプリ外へ落としたときのメニューのためにファイルを 1 件ずつ OS に問い合わせており、クラウド同期フォルダでは 1200 件で 1.5〜1.9 秒止まっていました。件数が多いときは問い合わせないようにしています（落とした先のメニューはこれまでどおり出ます）。
- **複数選択したまま 1 件をクリックすると、その 1 件だけの選択になるようにした (#335)** — これまでは複数選択が解除されず、選び直すのに一度何もない場所をクリックする必要がありました。**エクスプローラーと同じ動き**になります。複数選択したままドラッグして運ぶ操作はこれまでどおりです（運んだときは選択を保ちます）。
- **上書きの確認がコピー中のウィンドウに隠れて答えられないことがあった問題を修正 (#335)** — 確認の窓が進捗ウィンドウの裏に回ってしまい、操作が進まなくなることがありました。確認の窓を必ず前に出し、進捗ウィンドウは**入力の焦点を奪わない**ようにしました。
- **コピー・移動の進み具合を出すウィンドウを作った (#334)** — 大量のファイルをコピーしているとき、これまでは画面左下の細いバーと 1 行の文字だけで、何がどこまで進んでいるのか分かりませんでした。**速度・残り時間・件数・サイズ・いま処理しているファイル**を並べたウィンドウを出します。**一時停止と再開**ができ、**操作ごとに止められます**。複数のコピーは 1 つのウィンドウに行として並びます（以前は 2 つ目のコピーを始めると 1 つ目が黙って止まっていました。これも直しました）。**タスクバーのアイコンにも進み具合が出ます**ので、ほかのアプリで作業していても分かります。**閉じても転送は続きます** — 左下のバーが引き継ぎ、ウィンドウが出ている間はバーを出しません（同じ数字が 2 か所で動かないように）。すべて成功すると自動で閉じ、中止や失敗があった回は残ります。出し方は設定（表示 → コピー中のウィンドウ）で**常に出す／大きいときだけ／出さない**から選べます。
- **使用統計にマクロ・AI・圧縮・リモートの記録を足した (#266)** — 統計画面には「フォルダを開く」「タブを閉じる」などが並びますが、**マクロと AI はそもそも数えていませんでした**。使われていないのか数えていないのかが区別できず、どこを磨くかの判断材料になっていませんでした。マクロ（実行・操作の記録・スタジオを開く）、AI（マニュアル・フォルダ整理・タブ整理・リネーム・テーマ生成・マクロ生成・お気に入り整理・統計分析・フォルダ作成・Stickman 生成）、圧縮と解凍、リモート接続を数えるようにしました。**アプリが勝手に呼ぶもの（起動時のあいさつ文、チャレンジの二つ名など）は数えません** — 押した操作ではないので、混ぜると「よく使っている機能」の順番が歪みます。リモートは**その接続先に初めて繋いだときだけ**数えます。
- **テーマ一覧のカードからも★評価を送れるようにした (#327)** — これまで「テーマ」タブの★は平均を示す飾りで、押しても何も起きなかった。ストアのカードと同じ作りに揃え、星を選んでから「評価を送信」で確定する形にした。**同梱テーマも評価できる**。星は自分が付けた点を表し、みんなの平均は隣に数字で出る。作者の表記はすべて同一だったため、その行をまるごと評価に充てている。

### Fixed
- **アプリケーションキー `[≡]` でメニューが開かない問題を修正 (#332)** — キーボードから手を離さずにメニューを開けませんでした。ファイル一覧には**キーからメニューを開く道がそもそも無く**、`Shift+F10` は Windows のウィンドウメニューへ素通りして別の動作（最大化など）になっていました。アプリケーションキーと `Shift+F10` のどちらでも、選んでいるファイルのメニューが**その行の左下**に開きます。行が隠れない位置です。何も選んでいなければ、背景を右クリックしたときと同じメニューが出ます。アプリケーションキーは設定画面（ショートカットキー → ファイル一覧 → コンテキストメニュー）で変更できます。`Shift+F10` は Windows 共通の操作なので固定です。**`Shift` を押しながらの右クリックで OS 標準のメニューを出す機能は、そのまま残っています**（`Shift+F10` のときだけ、この `Shift` は数えません）。
- **ネットワーク上のショートカット（.lnk）が開けないことがある問題を修正 (#330)** — `X:\networkpath\file.abc` のように、ネットワークドライブに割り当てた場所を指すショートカットが認識されず開けない、という報告。リンク先が実際にあるかをアプリ側で確かめ、**確かめられなかった時点でWindows に渡さず打ち切っていた**のが原因。エクスプローラーはこの確認をせず、ショートカットをそのまま Windows に渡して、接続やサインインの処理まで任せている。同じようにした。リンク先の置き場（ドライブや共有）には届いているのに目的のものが無い場合は、これまでどおりその場で「リンク先が見つかりません」と伝える（そのほうが速く、まとめて開いたときに確認のウィンドウが積み上がらない）。

- **テーマ画面でカテゴリのボタンを押しても移動しない問題を修正 (#327)** — v1.15.0 で直したとお伝えしていましたが、直っていませんでした。**移動の要求を上へ伝える仕組みが、途中にあるスクロールしない部分で止められていた**のが原因です（4 つのカテゴリを 9 回押しても表示位置が1 ピクセルも動いていないことを実測で確認しました）。伝言に頼らず、飛び先の位置を測って直接移動するようにしました。あわせて、**押したカテゴリの枠をしばらく光らせます**。テーマ一覧はカテゴリを横に 5 列並べていて先頭の高さが揃っているため、移動先だけではどのカテゴリを指したのか分かりません。ランダム選択で使っている枠と同じ見た目です。「テーマ作成」「ストア」も同じように光ります。

## Feedback & bug reports / フィードバック・不具合報告

Please send requests and bug reports from **inside the app**: **Settings → Feedback**.

要望・不具合は、**アプリ内の「設定 → フィードバック」**からお送りください。

| Why from inside the app / アプリから送っていただきたい理由 |
|---|
| Replies come back to you in the app's **Feedback history**, so you actually get an answer<br>作者からの回答が**アプリ内の「フィードバック履歴」に届きます** |
| When a fix ships, the app asks whether it is fixed — a report is followed through to the end<br>修正版が出ると「直った／まだ直っていない」を知らせるボタンが出るので、**最後まで追えます** |
| It reaches me directly. This repository only hosts the release files and is not a support channel<br>確実に届きます。このリポジトリは配布物を置くためだけのもので、問い合わせ窓口ではありません |
