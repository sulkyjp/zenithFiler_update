<!-- latest-changes-en:begin -->
**[2.0.0] - 2026-10-27 : Zenith Filer now does what File Explorer does (opening archives by double-click, grouping, view modes, columns, editing file properties, the address bar, search using the Windows index, Quick access and Network in the nav tree), the settings screen was rebuilt so you can search it by name, effects across the app share one "single streak of light" language, and you can talk to the Stickman in the status bar**

### Added

- **The settings window now has a search box for finding settings by name (#408)** [Preview 1.17.4.1] — As settings grew, finding one when you didn't know its page meant opening the pages one by one. Now, when you type a name in the search box at the top right of the settings window, matching settings appear in two lines, the name and "page › heading", and choosing one jumps to that setting on its page. The setting is outlined for 1.5 seconds so you can see where you landed (even when effects are turned off). `Ctrl+F` (or `Ctrl+E`) moves to the search box; choose with `↑` `↓` and jump with `Enter`. Full-width and half-width characters, katakana and hiragana, and upper and lower case are treated the same, and when you type several words separated by spaces, only settings containing all of them remain. English names work too (for example, "font" or "theme"). Shortcut names appear as well; choosing one opens the Shortcuts page filtered by that name. In the search box, the first `Esc` closes the results and the second clears the text (when the box is empty, `Esc` closes the settings window as before). For now you can jump to page names and to settings on the General, Display, File type colors, Effects, Tab, Search, and Index pages.

- **File name search, index search, and Filter in place can now search with regular expressions (#409)** [Preview 1.17.4.1] — Until now only file content search (grep) accepted regular expressions. The ".*" button in the search bar now appears in every mode; with it on, everything you type is one regular expression matched against the name including its extension. All .NET regular expression syntax works, including lookahead, lookbehind, backreferences, named groups, and `(?-i)` to match case (for example `^IMG_\d{4}\.jpe?g$`, or `^(?!.*old).*\.xlsx$` for Excel files without `old`). It works in index search without rebuilding the index, and it sees the original case of names. If the expression has an error, the search box border turns red as you type, "Invalid regular expression (near character N)" appears with the reason, and pressing Enter does not search. In Filter in place, the list stays as it was last filtered while the expression has an error. If an expression is so complex that matching takes too long, it stops after 0.1 seconds per name and tells you, so the app does not freeze (batch rename regular expressions now have the same limit). grep also switches to PCRE2 automatically for expressions with backreferences, lookahead, or lookbehind. There is one ".*" switch per pane, and search presets save it.

- **Switching working sets now keeps the work you had before switching in a history you can go back to (#411)** [Preview 1.17.4.2] — Until now, switching to another set simply discarded the tabs you had open, and the only way back was to have saved them yourself. Now every switch automatically keeps the state before switching (tabs, sort, selection, scroll position, how the screen is split), and you can go back with one click from "Before switching" under the working sets in the nav pane (up to 30 entries). Each switch shows a toast at the top with an **Undo** button that goes straight back to the state before switching. Restoring from the history also keeps the state before restoring, so you can go back and forth. Nothing is added if the state exactly matches the set you switch to (down to selection and scroll position), and a toast says so. Nothing is added either if it matches the entry kept just before. Leaving a preview with "Revert" keeps nothing, and closing the app while previewing keeps the work from before the preview. Right-click to save an entry as a set or remove it. Keeping history and restoring from it do not count toward the free version's limits.

- **Terminals in a working set now come back with their previous screen text and Claude Code conversation (#411)** [Preview 1.17.4.2] — Until now, switching away and back opened the terminal on a blank new screen. Now saving, overwriting, and switching sets also keep the terminal's screen text (up to the last 3,000 lines). When the set comes back, that text is written back in gray at the top of the new terminal, followed by a divider such as "Screen up to 10/18 09:00 (working set "Work")", with a fresh prompt below it; scroll up to read where you left off. For a terminal that was running Claude Code, `claude --resume <conversation ID>` is placed in the input line at the first prompt (it is not run; press Enter to resume the conversation). The conversation ID is known when the Claude Code status line integration is registered; otherwise `claude --continue` (the latest conversation in that folder) is placed instead. After the app is reopened, programs that were running do not continue where they were (the terminal opens a new shell; while the app keeps running, "kept running in the background" below brings them back as they were). Screen text is stored in `data\working_sets\screens` in the app folder and removed once no set or history entry uses it.

- **Terminals taken out by switching working sets now keep running in the background until the app closes, and come back as they were, process and all (#411)** [Preview 1.17.4.2] — Until now, switching sets closed the terminals, stopping any running build or Claude Code. Now terminals taken out keep running in the background instead, and recalling a set or history entry that includes one, or leaving a preview with "Revert", brings back that same terminal as it was. Output produced while it was in the background is on its screen, and a Claude Code conversation keeps going. How many to keep is set by "Terminals to keep running in the background" in the working sets gear settings (3 by default, 0 keeps none, up to 8). Beyond that number, idle ones are closed oldest first; ones running a command are not closed. Ones that no set or history entry includes (so there is no way back to them) are closed right away. Below the table of the working sets on the status bar, a count such as "2 terminal(s) running in the background (Claude Code 1)" appears, with a **Close all** button. The same settings also gain "Also keep terminal screen text", so screen text can be kept off the disk.

- **Items in the file list can now be selected by clicking check boxes (#413)** [Preview 1.17.4.4] — It works like File Explorer's "Use check boxes to select items". Until now, picking several items took `Ctrl` + click or dragging a box, and clicking one item afterwards went back to selecting just that one. Turn on "Use check boxes to select items" under Display in the settings (off by default), and every item gets a check box, to the left of the name in detail view and at the top left of the card in icon view, with a tick on the selected ones. Clicking it adds or removes just that item, and the rest of the selection stays. The check box in the Name header in detail view selects or clears everything. Clicking a name or icon works as before.

- **The Ring Launcher can now show names as horizontal labels, icons only, or curved text (#414)** [Preview 1.17.4.4] — Choose under Settings → "Ring Launcher" → "Design", in "How names are shown" above the designs (horizontal labels stay the default). "Icons only" shows just slightly larger icons on the ring and puts the name of whatever you point at large in the centre, for a clean look. "Curved text" bends smaller text along the outer edge of the ring, like a watch face, so every name stays in view; text on the lower half still reads left to right. The name in the centre shrinks to fit the circle, and longer names wrap to two or three lines.

- **You can now send feedback and replies to feedback from the keyboard (#422)** [Preview 1.17.4.7] — Until now you had to move the mouse to the send button when you finished writing, because Enter in the input boxes inserts a new line. Now **`Shift+Enter` (or `Ctrl+Enter`) sends** from the reply box, the title box, and the description box. **Enter still starts a new line**, so a multi-line reply is never sent half-written by accident. Even if you press the keys right after typing, everything up to the last character is sent. Hover over a send button to see the key

- **You can now give terminal tabs a name, a note and a color (#419)** [Preview 1.17.4.7] — With many terminals open, the tab title (the folder name or the shell's title) was not enough to tell which one was doing what. Now, on a terminal tab in Pane A/B or in the nav pane, **right-click the tab → "Name, note and color…"** to open a small box under the tab. The **name** becomes the tab title, and the **note** appears with the working folder when you hover over the tab (tabs with a note get a small mark). The **color** is one of the same seven colors used for favorites: the tab gets a light tint and a colored bar on its left edge. Press Enter in the name box, or `Shift+Enter` (or `Ctrl+Enter`) anywhere, to save, and `Esc` to cancel. **None of this is stored** — it goes away when you close the tab

- **The menu shown when you drop with a right drag now gives you items from apps such as 7-Zip and EXPLZH (#417)** [Preview 1.17.4.7] — Until now, dropping with a right drag offered only "Copy here", "Move here" and "Create shortcut here", so app items that File Explorer shows there (such as EXPLZH's "Create archive here") were not available. Now, when Settings → General → "Context Menu" is set to **Explorer-compatible menu**, a right-drag drop onto the file list, the breadcrumb or the nav pane tree brings up **the same Windows menu as File Explorer**. The three items at the top are still carried out by the app itself, so the same-name check, the progress window and undo with `Ctrl+Z` work as before. App items are carried out by that app and cannot be undone with `Ctrl+Z`. With the default "App custom menu", the usual menu gains an **"Apps ▶"** row that opens a Windows menu with just the app items beside it (the three items still appear at once, and apps are loaded only when you press that row). Nothing changes when you drop with a right drag from File Explorer

- **Added "See the effects" to the Effects page so you can try the app's effects on a sample (#423)** [Preview 1.17.4.7] — Press Play at the top of Settings → Effects to watch, on a small sample, the underline light when switching tabs, the row light after pasting, the ring of light when pressing ★, and the light running around a notice with its name rippling, one after another. They run on the same parts as the real screens, so you can also check how things look after changing effect categories. When all effects are off or Windows' "Show animations" is off, the sample does not move and a line tells you why

- **Select several tabs with Ctrl- or Shift-click and move them together (#426)** [Preview 1.17.4.8] — As in a browser, `Ctrl`-click adds tabs to the selection one at a time, and `Shift`-click selects every tab from the open tab to the clicked one. Drag any selected tab and they all move together, in order, to the other pane (or to a new position in the same pane). "Move to other pane" on the right-click menu also moves all the selected tabs. Previously tabs could only be moved one at a time.

- **7z, rar, tar.xz and other archives can now be extracted with the same Windows support that File Explorer uses (#438)** [Preview 1.17.4.9 → 1.17.4.10] — Built-in extraction covered only ZIP, TAR and TAR.GZ; 7z and rar were left to `Shift` + right-click → OS menu, or to 7-Zip. Now 7z, rar, tar.bz2 / tar.xz / tar.zst (tbz2 / txz / tzst) and single gz / bz2 / xz / zst files extract from the **same entries under "Archive ▶"** on the right-click menu (Extract..., Extract here, Extract to "name\\", Extract to the other pane). The reading and writing is done by **Windows' own archive component** (the one behind File Explorer's "Extract All"), so nothing is bundled with the app and Windows Update keeps it current. Windows decides which formats work (7z and rar arrived with the autumn 2023 update to Windows 11; on Windows 10 only ZIP and TAR entries appear). It works even if your default app for these files is 7-Zip or another tool. ZIP and TAR are still extracted by the built-in code (which has safety checks and is faster). Name clashes use the same dialog as copying, and `Ctrl+Z` undoes the extraction. - **Fixed sizes of indexed folders sometimes differing from Explorer's Properties (#404)** [Preview 1.17.4.8] — The total from the index was shown as is, so it was off by whatever the index excluded or had not caught up with yet. Now the index value is shown dimmed first and replaced with the same value as Properties once counting finishes.

- **Fixed junctions inside cloud folders (such as OneDrive) being counted twice (#404)** [Preview 1.17.4.8] — In cloud locations, which folders to follow was decided without looking at their type. Now junctions and symbolic links are never followed, wherever they are, and only cloud placeholder folders are followed. When a row in the list is itself a junction, its target is counted, as in Properties (it used to be blank).

- **Fixed the Down key never selecting a file after switching panes by clicking an empty area of the other pane (#424)** [Preview 1.17.4.8] — Clicking an empty area puts keyboard focus on the list itself rather than on a row. In that state, Up and Down searched for the next row starting from the row that last had focus, which the list never forgets, and did nothing when none was found (pressing Up once moved focus into a row, after which keys worked). Now, when the list itself has focus, Up and Down select the first row if nothing is selected (End selects the last), and move from the selected row otherwise, just like switching panes with ← →.

- **Fixed typing in the terminal tab name, note and color editor going into the terminal instead (#427)** [Preview 1.17.4.8] — The editor was a bubble floating inside the app, and over a terminal it could not take keyboard input back from the terminal. The terminal is a window drawn by a separate program, so keys go straight to it. The mouse was also contested with the terminal: the pointer stayed thin and hard to see, and the color swatches were hard to click. The editor is now its own window that opens below the tab. It receives keys as soon as it opens, so you can type in it even over a terminal. The pointer and the color swatches work the same as on folder tabs. Typing right after it appears now composes Japanese input inside the box instead of at the top-left of the main window (a freshly created window is not yet ready for the input method, so the editor window is now reused rather than recreated). Clicking outside closes it and keeps what you wrote. Opened from a tab at the edge of the screen, it stays on screen.

- **Fixed shortcuts created by dragging a page from a browser being named after the address instead of the page title (#429)** [Preview 1.17.4.8] — Browsers pass the page title along with the drag, but it was read 4 bytes too early, from a different field just before the name. The name came out empty, so the address (a host name such as `www.example.com`) was used instead. Now the page title becomes the shortcut name, as in File Explorer.

- **Fixed Enter sending the message after switching away from a terminal tab running Claude Code and back, even with "Enter for newline" on (#431)** [Preview 1.17.4.8] — The A/B panes rebuild the terminal view each time you switch tabs. Whether Enter becomes a newline depends on the view remembering that Claude Code was started in that tab, and on a setting Claude Code sends only once at startup (the mode that wraps pastes), and the rebuilt view had forgotten both. The same happened when bringing back a terminal kept running in the background by a working set. The app itself now remembers both and restores them whenever the view is rebuilt. Multi-line pastes are no longer sent one line at a time either.

- **Fixed no File Explorer-style menu appearing when right-clicking a drive in "PC" (#432)** [Preview 1.17.4.8] — File Explorer's context menu is obtained from the parent folder by pointing at the item inside it. The parent was taken from the path, and a drive (`C:\`) has no parent in its path, so nothing was shown. The same cause left "Show the File Explorer context menu" empty in the app's own menu. Drives and share roots now get their menu from "PC" (or the network location), as in File Explorer. Right-clicking an empty area of "PC" also uses "PC" itself.

- **Fixed being unable to click an upper level in the address bar (such as "Users") while a long path was open (#430)** [Preview 1.17.4.8] — When the breadcrumb does not fit, it keeps the current folder (the right end) in view and hides the leading levels to the left. Its scrollbar was hidden, so there was no way to bring them back with the mouse (a menu for the hidden levels existed in the code but was never connected). Now a "«" button appears at the left end when levels are hidden; press it to pick a hidden level and go there, as in File Explorer. Turning the mouse wheel over the breadcrumb also slides it sideways, and hovering over a folder name shows its path, so a translated display name can be matched to `C:\Users`.

- **Fixed the end of a long name being hidden under the next column while renaming in the list, even when moving the cursor (#428)** [Preview 1.17.4.8] — When renaming in the Name column of the Details view, the edit box grew to the full length of the name, and the part beyond the column was cut off at the next column (such as Date modified). Since the box thought it was fully visible, moving the cursor right did not scroll its contents. The edit box now stays inside the Name column, so moving the cursor scrolls the hidden part into view. It also adjusts if you resize the column while renaming.

- **Fixed flickering around Pane A's terminal when Panes A and B had a different number of tab rows (#435)** [Preview 1.17.4.9] — With wrapped tabs and the option to match the tab-row heights of A and B turned on, when one pane had one row of tabs and the other had two, the height-matching routine ran again about 16 times a second, nonstop, from right after startup. It was picking up the size change it had just made itself. Each time, the tab row shrank and grew back, and a terminal in Pane A shrank and grew along with it, which showed up as flicker (with only folder tabs, it still kept running out of sight). Now the heights are matched once, when they actually change.

- **Fixed sorting by extension, which actually sorted by name (#437)** [Preview 1.17.4.9] — "Extension" was offered in the right-click sort menu and in the default-sort setting, but the sorter had no branch for it and fell back to name order. It now sorts by extension (natural name order within the same extension); files without an extension come first, as in File Explorer, and folders are sorted by name regardless of any dot in their name.

- **Fixed the app's own "OS context menu ▶" being empty when you right-click a drive in "PC" (#437)** [Preview 1.17.4.9] — The previous release (#432) fixed the Explorer-compatible menu, but the "OS context menu ▶" entry inside the app's own menu took a different path: a drive has no parent folder, so it built nothing. It now takes the menu from "PC" as File Explorer does, so items such as Eject and Format appear. Empty space in "PC" works the same way.

- **Pressing `Alt+Enter` (or Properties on the right-click menu) with nothing selected now opens the current folder's properties instead of doing nothing (#437)** [Preview 1.17.4.9] — The same as File Explorer. At a drive root (`C:\`) you get the drive's properties. In places with no real folder behind them, such as "PC" or a device, nothing happens, as before.

- **Fixed undoing a copy or an extraction deleting files permanently without warning when they could not be recycled (#437)** [Preview 1.17.4.9] — `Ctrl+Z` after a copy or extraction sends what was created to the Recycle Bin. When that failed (on a network location, for example), the files were deleted permanently with no warning. There is no longer any fallback to a non-recycling delete: where the Recycle Bin is unavailable, Windows asks for confirmation as File Explorer does, and anything that could not be removed is reported by count.

- **Fixed files and folders with only the system attribute, or the temporary attribute, never appearing in the list under any setting (#437)** [Preview 1.17.4.9] — Enumeration skipped the system and temporary attributes outright, so system-attribute folders inside `C:\Windows` and temporary files created by apps stayed invisible even with hidden files shown. File Explorer hides only items that carry **both** the hidden and system attributes (`$RECYCLE.BIN`, `pagefile.sys` and so on) as "protected operating system files", and shows system-only and temporary items normally. The app now follows the same rule, with a new **"Hide protected operating system files"** option (on by default) under Settings → Display. Turn it off, together with showing hidden files, and items such as `$RECYCLE.BIN` become visible. This applies to the file list, the breadcrumb folder lists, search, the nav pane tree and CSV / Excel export (index search is unchanged).

- **Corrected out-of-date statements in the manual (#437)** [Preview 1.17.4.9] — Four places: the address bar article (environment variables such as `%APPDATA%` do open), the search article (only index search excludes files without an extension), the context menu article ("Compress..." offers ZIP only) and the archives article (Windows' own 7z / rar extraction arrived with the autumn 2023 update).

- **Fixed dropping files dragged from inside a ZIP opened in File Explorer losing their folder structure (#438)** [Preview 1.17.4.9] — Dropping `dir\f.txt` from inside a ZIP produced a single file named `dir_f.txt`, because the receiving side replaced path separators with `_` along with other characters. Separators are now kept and the folders are created, so `dir\f.txt` lands as `dir\f.txt`. Folder descriptors (which carry no content) are no longer written as files. This is the same entry point as Outlook attachments, so characters that are not allowed in names, such as `:` in a subject, are still replaced with `_`. Names that try to escape with `..` or an absolute path, and reserved names such as `CON`, are rejected with the same checks as archive extraction.

- **Fixed the app sometimes closing while trying to show the error dialog after an unexpected error (#454)** [Preview 1.17.4.10] — When an error happened in the middle of something like opening a menu, the error dialog was shown right there, the screen layout ran nested, and the app exited. The error dialog now appears once the current work has finished, and a failure to show it no longer closes the app. Further errors in a row are logged without stacking more dialogs.

- **Fixed undoing Extract to "(name)\" with `Ctrl+Z` leaving an empty folder behind (#455)** [Preview 1.17.4.10] — The extracted contents were removed, but the folder created for them stayed. Now the folder goes too. If you have put anything of your own into it since, the folder is kept

- **Fixed typing "PC" in the address bar and pressing `Enter` not going to the PC view (#399)** [Preview 1.17.4.11] — When typed text started being resolved relative to the current folder (v1.17.4), "PC" was also treated as a folder named PC inside the current folder, and you got "not found". It now goes to the PC view as before

- **Fixed "Attach system information" and "Attach recent error log" in Feedback being on at first whatever the category (#458)** [Preview 1.17.4.11] — The manual said both start off, but they were always on. Only bug reports need them, so they are now on at first only when the category is "Bug report", and off at first for "Feature request" and "Other". Changing the category puts them back to that category's starting state. Reports from the error dialog are bug reports, so they stay on as before. The manual has been updated to match. Thanks for the report
- **The "Report a problem" button on the error screen now hides your user name in the error details (#460)** — The error message and stack trace were put into the feedback subject and body as they were. When they contained a path such as `C:\Users\(name)\…`, your name was sent if you did not notice it. The name part is now replaced with `<user>`, the same as in attached logs
- **Fixed features whose free daily limits were not applied as intended (#460)** — AI rename suggestions, AI folder creation and the AI backup summary did not check the limit. AI Stickman generation and publishing a theme to the store checked it but did not count each use. AI theme diagnosis did not check the limit when opened from the theme page, and was not counted from either entry. All of them now stop at their limits. AI rename suggestions and the backup summary quietly fall back to working without AI once the limit is reached. AI theme diagnosis shares the AI theme generation quota from either entry and counts once when a result is shown
- **Search presets saved in grep (content search) mode came back as normal searches (#460)** — Presets only remembered whether they were index searches. They now return in the mode they were saved in (normal, grep or index). Presets saved earlier come back as before
- **Stickman reward behaviors did not appear until the next launch after completing a challenge (#460)** — The completed list was saved but the value the app reads was not updated, so other unlocks based on the number of completed challenges were delayed too. Reward behaviors and unlocks now take effect as soon as the challenge is completed
- **Fixed 9 places that showed a key name (such as `tab.copy_path`) instead of text in tooltips and labels (#460)** — The AI diagnosis button in the theme store, six items in the index search right-click menu, "Converting" in the preview, and the copy path button in the address bar. Their text was missing from the language files, so the key name was shown as is. Text has been added in all 10 languages
- **Fixed 4 descriptions in the settings screen and elsewhere that did not match the actual behavior (#460)** — "Same pane, instant search in current tab" under how search results open said it searched as you type, but it now searches when you press Enter (the option is now called "Same pane, current tab"). The index search description said it could search contents, but the index holds names and similar details, not file contents. The archive extraction setting now says that on Windows 10, 7z, tar.xz and tar.bz2 that tar.exe cannot read are extracted with a component built into the app. The recovery description now says when backups are made automatically (about 5 minutes after a change, on exit and when hidden to the tray) and when the AI summary is written. Fixed in all 10 languages
- **Fixed property editing, where the fields stayed grayed out and nothing could be written, even for JPEG images and Office documents (#460)** — The app asked Windows whether the file was writable while it was still open read-only, so every file type came back as not writable. File types that the Details tab in File Explorer can edit (JPEG, Office documents and so on) can now be written. Types that cannot be edited, such as text files, stay grayed out as before
- **Extracting a tar.xz or tar.bz2 made with 7-Zip or similar tools on Windows 10 put each file in its own folder with a numeric name (#433)** — GNU-format tar files, which 7-Zip and others create, store timestamps where the first part of the name normally goes. The component built into the app read them as part of the name and put files one by one into folders such as "15267350254 00000001000". The contents of tar files are now read with the tar reader built into .NET, so GNU, PAX and ustar archives all extract with their original folder structure. The archive-wide metadata that git archive adds is no longer counted as an entry that was not extracted

### Removed

- **Removed the feature list at the bottom of About in the settings window (#408)** [Preview 1.17.4.1] — It showed the app's features as cards, and some of them took you to the matching screen. Now that the settings navigation has headings and the search box at the top right finds a setting by name and jumps to it, the list is no longer needed. It also had to be updated by hand each time a feature was added, so it easily drifted from the actual features.

## 最新の変更履歴

<details>
<summary><b>最新リリースの内容を表示</b></summary>

<!-- latest-changes-ja:begin -->
**[2.0.0] - 2026-10-27 : エクスプローラーでできることをそろえ（書庫をダブルクリックで開く・グループ表示・表示形式・列・ファイルのプロパティの編集・アドレスバー・索引を使う検索・ナビのクイック アクセスとネットワーク）、設定画面を名前で探せる形に作り直し、アプリ全体の演出を「一筋の光」にそろえ、ステータスバーの Stickman と話せるようにした**

### Added

- **ファイル名の検索・インデックス検索・その場の絞り込みでも、正規表現で探せるようにしました (#409)** 〔先行版 1.17.4.1〕 — これまで正規表現が使えたのはファイル内容の検索（grep）だけでした。検索バーの「.*」をどのモードでも出し、オンにすると、打った文字全体を 1 つの正規表現として、拡張子込みの名前に当てます。先読み・後読み・後方参照・名前付きグループ・`(?-i)` による大文字と小文字の区別など、.NET の正規表現の構文をすべて使えます（例: `^IMG_\d{4}\.jpe?g$`、`old` を含まない Excel なら `^(?!.*old).*\.xlsx$`）。インデックス検索でもインデックスを作り直さずに使え、名前の大文字と小文字もそのまま見ます。式に誤りがあると、打っている途中から検索欄の枠が赤くなり、「正規表現の誤り（○ 文字目付近）」と理由が出て、Enter を押しても検索しません。その場の絞り込みでは、式が誤っている間は直前の絞り込みのまま一覧が動きません。式が複雑すぎて照合に時間がかかるときは、名前ごとに 0.1 秒で打ち切って知らせるので、アプリが固まりません（一括リネームの正規表現にも同じ上限を付けました）。grep も、後方参照・先読み・後読みを含む式を自動で PCRE2 に切り替えて探すようにしました。「.*」のオン／オフはペインごとに 1 つで、検索プリセットにも保存されます。

- **長いパスを開いていると、アドレスバーの上の階層（「ユーザー」など）をクリックして移れなかったのを直しました (#430)** 〔先行版 1.17.4.8〕 — アドレスバーのパンくずは、収まらないときに今いるフォルダの側（右端）へ寄せ、先頭の階層を左へ隠します。スクロールバーは隠していて、マウスで左へ戻す手段がありませんでした（隠れた階層を出すメニューも、作りかけのまま画面につながっていませんでした）。いまは隠れた階層があるとバーの左端に「«」が出て、押すと隠れた階層を一覧から選んで移れます（エクスプローラーと同じ）。パンくずの上でホイールを回しても横にずらせます。フォルダ名にマウスを乗せるとパスが出るので、「ユーザー」が `C:\Users` だと分かります。

- **一覧で名前を書き換えるとき、長い名前の後ろが隣の列の下に隠れ、カーソルを動かしても見えなかったのを直しました (#428)** 〔先行版 1.17.4.8〕 — 詳細表示の名前の欄で書き換えるとき、入力欄が名前の長さまで広がり、はみ出した部分が隣の列（更新日時など）との境で切られていました。入力欄は自分が全部見えていると思っているので、カーソルを右へ動かしても中身をずらしませんでした。いまは入力欄を名前の列の中に収めるので、カーソルを動かすと隠れていた部分までずれて見えます。書き換えている間に列の幅を変えても合わせ直します。

- **A と B でタブ行の段数が違うと、A のターミナルのあたりがチカチカしていたのを直しました (#435)** 〔先行版 1.17.4.9〕 — タブを折り返して表示し、A と B のタブ行の高さをそろえる設定にしていると、片方が 1 段・もう片方が 2 段のときに、高さをそろえる処理が起動直後から 1 秒に約 16 回、止まらずにやり直されていました。高さを入れ直したときの大きさの変化を、自分自身で拾ってしまっていたためです。そのたびにタブ行が縮んでは伸び、A にターミナルがあるとターミナルの画面も一緒に伸び縮みするので、チカチカして見えていました（フォルダのタブだけのときも、見えないところで回り続けていました）。いまは高さが変わったときに 1 回だけそろえます。

- **拡張子で並べ替えると、名前の順になっていたのを直しました (#437)** 〔先行版 1.17.4.9〕 — 右クリックの並べ替えと設定の既定の並べ替えに「拡張子」はあったのに、並べる側に拡張子の分岐が無く、名前の順に落ちていました。いまは拡張子の順（同じ拡張子の中は名前の自然順）に並び、拡張子の無いファイルはエクスプローラーと同じく先頭、フォルダは拡張子を見ずに名前順です。

- **「PC」でドライブを右クリックしたとき、アプリ独自メニューの「OS標準メニュー ▶」が空だったのを直しました (#437)** 〔先行版 1.17.4.9〕 — 前の版（#432）でエクスプローラー互換メニューは直しましたが、独自メニューの中の「OS標準メニュー ▶」は別の経路で、ドライブには上のフォルダが無いので何も作らずに終わっていました。いまはエクスプローラーと同じく「PC」から取り出すので、取り出しやフォーマットなどの項目が並びます。「PC」の空いたところも同じです。

- **何も選ばずに `Alt+Enter`（または右クリックの「プロパティ」）を押しても何も起きなかったのを、開いているフォルダのプロパティが出るようにしました (#437)** 〔先行版 1.17.4.9〕 — エクスプローラーと同じ動きです。ドライブの根（`C:\`）ではドライブのプロパティが出ます。「PC」や機器のような実体の無い場所では、これまでどおり何もしません。

- **コピー・展開の取り消しで、ごみ箱に入れられないと黙って完全に削除していたのを直しました (#437)** 〔先行版 1.17.4.9〕 — `Ctrl+Z` でコピーや展開を取り消すと、作られたものをごみ箱へ送ります。ところがごみ箱へ送れなかったとき（ネットワークの場所など）は、警告なしに完全に削除する作りでした。いまはごみ箱を通さない削除には落ちず、ごみ箱に入らない場所ではエクスプローラーと同じく Windows が警告を出して確認し、消せなかったものは件数でお知らせします。

- **システム属性だけ・一時属性のファイルやフォルダが、どの設定でも一覧に出なかったのを直しました (#437)** 〔先行版 1.17.4.9〕 — 列挙のときにシステム属性と一時属性をまとめて飛ばしていたので、`C:\Windows` の中のシステム属性のフォルダや、アプリが作った一時属性のファイルが、隠しファイルを表示する設定にしても見えませんでした。エクスプローラーは**隠し属性とシステム属性の両方が付いたもの**（`$RECYCLE.BIN`・`pagefile.sys` など）だけを「保護されたオペレーティング システム ファイル」として隠し、システム属性だけ・一時属性の項目はふつうに出します。いまは同じ決まりにし、設定 →「表示」に**「保護されたオペレーティング システム ファイルを隠す」**（既定オン）を足しました。オフにすると、隠しファイルを表示する設定と合わせて、`$RECYCLE.BIN` のような項目も見えます。一覧・パンくずのフォルダの一覧・検索・ナビペインのツリー・CSV / Excel の出力に効きます（インデックス検索はこれまでどおりです）。

- **マニュアルの古い記述を直しました (#437)** 〔先行版 1.17.4.9〕 — アドレスバーの記事（環境変数 `%APPDATA%` は開けます）、検索の記事（拡張子の無いファイルを含めないのはインデックス検索だけ）、右クリックメニューの記事（「圧縮...」で選べる形式は ZIP だけ）、アーカイブの記事（Windows の 7z・rar の展開は 2023 年秋の更新から）の 4 か所です。

- **エクスプローラーで開いた ZIP の中からファイルをドラッグして落とすと、フォルダの階層がなくなっていたのを直しました (#438)** 〔先行版 1.17.4.9〕 — ZIP の中の `dir\f.txt` をこのアプリへ落とすと、受け取る側が区切りまで `_` に直していたので `dir_f.txt` という 1 つのファイルになっていました。いまは区切りを保ってフォルダを作り、`dir\f.txt` のまま置きます。フォルダの記述子（中身の無いもの）はファイルとして作りません。Outlook の添付と同じ入口なので、件名の `:` などの使えない文字はこれまでどおり `_` に直します。`..` や絶対パスで外へ出ようとする名前と `CON` のような予約名は、書庫の展開と同じ判定で捨てます。

- **思わぬエラーが起きたとき、エラーの画面を出そうとしてアプリが落ちることがあったのを直しました (#454)** 〔先行版 1.17.4.10〕 — メニューを開く途中などでエラーが起きると、その場でエラーの画面を出そうとして画面の組み立てが入れ子になり、アプリが終了していました。エラーの画面は今の処理を抜けてから出すようにし、出すこと自体に失敗しても落ちないようにしました。続けてエラーが起きても、画面は重ねて出さずに記録だけ残します。

- **アーカイブを「「（名前）\」に展開」したあと `Ctrl+Z` で取り消すと、空のフォルダが残っていたのを直しました (#455)** 〔先行版 1.17.4.10〕 — 中身は消えても、展開のために作ったフォルダだけが残っていました。いまは作ったフォルダごと消えます。展開したあとにご自分で置いたものがあれば、そのフォルダは消さずに残します

- **アドレスバーに「PC」と打って `Enter` を押しても、PC の一覧へ移らなかったのを直しました (#399)** 〔先行版 1.17.4.11〕 — 打った文字を今のフォルダからの相対パスとして解くようにしたとき（v1.17.4）、「PC」も「今のフォルダの中の PC という名前のフォルダ」として扱われ、「見つかりません」になっていました。いまは以前のように PC の一覧へ移ります

- **フィードバックの「システム情報を添付」「直近のエラーログを添付」が、種類によらずはじめからオンになっていたのを直しました (#458)** 〔先行版 1.17.4.11〕 — マニュアルには「どちらもはじめはオフ」と書いていたのに、実際はいつもオンでした。不具合を調べるのに要るのはバグ報告だけなので、種類が「バグ報告」のときだけはじめからオンにし、「機能リクエスト」と「その他」でははじめはオフにしました。種類を切り替えると、その種類のはじめの状態に戻ります。エラー画面からの報告はバグ報告なので、これまでどおりオンです。マニュアルの説明もこれに合わせました。ご報告ありがとうございます
- **エラー画面の「問題を報告」で、エラーの内容に入ったユーザー名を伏せるようにしました (#460)** — エラーの文とスタックトレースは、フィードバックの件名と本文にそのまま入っていました。そこに `C:\Users\(名前)\…` のパスがあると、気づかずに送ったときに名前が届いていました。添付のログと同じく、名前の部分を `<user>` に置き換えてから入れます
- **無料版の 1 日の回数が、決めたとおりにかからなかった機能を直しました (#460)** — AI のリネームの提案・AI のフォルダ作成・バックアップの AI 要約は回数を確かめていませんでした。Stickman の AI 生成とストアへのテーマの公開は、確かめていても使った回数を数えていませんでした。AI テーマ診断は、テーマのページから開くと回数を見ず、どちらから開いても数えていませんでした。いまはどれも決めた回数で止まります。AI のリネームとバックアップの要約は、上限に達すると知らせずに AI を使わない形に戻ります。AI テーマ診断は、どちらから開いても AI テーマ生成と同じ枠を使い、診断の結果が出たときに 1 回と数えます
- **grep（中身の検索）で保存した検索のプリセットが、通常検索として戻っていたのを直しました (#460)** — プリセットはインデックス検索かどうかだけを覚えていました。いまは保存したときのモード（通常・grep・インデックス）で戻ります。前に保存したプリセットは、これまでどおりに戻ります
- **チャレンジを達成しても、Stickman の報酬の動きが次に起動するまで出てこなかったのを直しました (#460)** — 達成した一覧を保存するだけで、アプリの中で読む値を替えていなかったため、ほかの解放（チャレンジの達成数で開くもの）も同じく遅れていました。いまは達成したその場で、報酬の動きが出るようになり、解放も反映されます
- **ツールチップや表示に、訳の代わりにキーの名前（`tab.copy_path` など）が出ていた 9 か所を直しました (#460)** — テーマストアの AI 診断のボタン、インデックス検索の右クリックの 6 項目、プレビューの「変換中」、アドレスバーのパスのコピーのボタンです。訳が言語ファイルに無く、見つからないキーの名前がそのまま出ていました。10 言語とも訳を足しました
- **設定画面などの説明が、実際の動きと違っていた 4 か所を直しました (#460)** — 検索結果の開き方の「同一ペイン・現在タブで即時検索」は、入力したそばから探すと書いていましたが、いまは Enter を押したときに探します（項目名も「同一ペイン・現在タブ」にしました）。インデックス検索の説明は「中身まで探せる」としていましたが、索引に入れるのは名前などで、中身は入れません。書庫の展開の設定に、Windows 10 で tar.exe も読めない 7z・tar.xz・tar.bz2 をアプリに内蔵した部品で展開することを足しました。リカバリの説明に、自動でバックアップを作る時機（設定を変えてから約 5 分後・終了時・トレイへ格納したとき）と、AI の要約を作る時機を書きました。10 言語とも直しました
- **ファイルのプロパティの編集で、JPEG や Office の文書でも入力欄が灰色のままで、何も書き込めなかったのを直しました (#460)** — 書き込めるかを、読み取り専用で開いた状態のまま Windows に尋ねていたため、どの種類のファイルでも「書けない」と返っていました。いまは、エクスプローラーの「詳細」タブで編集できる種類（JPEG・Office の文書など）なら書き込めます。テキストファイルのように編集できない種類は、これまでどおり灰色です
- **7-Zip などで作った tar.xz・tar.bz2 を Windows 10 で展開すると、ファイル 1 つごとに数字の名前のフォルダができていたのを直しました (#433)** — 7-Zip などが作る GNU 形式の tar は、名前の前半を置く場所に時刻を書きます。アプリに内蔵した部品がそれを名前の一部として読み、「15267350254 00000001000」のようなフォルダの中にファイルを 1 つずつ出していました。tar の中身は .NET に組み込みの読み取りで読むようにし、GNU・PAX・ustar のどの形式でも元のフォルダ構成で出ます。git archive で作った tar に入る書庫全体の付帯情報も、展開しなかった項目として数えません

### Removed

- **設定画面の「このアプリについて」の下にあった機能の一覧をなくしました (#408)** 〔先行版 1.17.4.1〕 — アプリの機能をカードで並べた一覧で、押すとその画面へ移れるものもありました。いまは設定画面の左のナビに見出しが付き、右上の検索で設定を名前から探して飛べるので、役目を終えました。一覧は機能が増えるたびに手で書き足す作りで、実際の機能とずれやすくもありました。
