## Latest Changes — [1.10.0] - 2026-07-25 : Introduced role-based depth throughout the UI (three shared elevation tiers for floating surfaces, lit edges and Lit Chrome on control surfaces, contact shadows between menu and list), centralized how motion respects the OS animation setting and lightweight mode, and fixed the navigation pane split divider and the list scrollbar range

### Added
- **(Internal groundwork, no visible change) Added shared design tokens for role-based depth layering (Issue #194).** Three shadow tiers for floating surfaces (Elevation.Raised / Flyout / Overlay) and four corner-radius tokens (Radius.Small / Control / Surface / Float) are now defined in the app-wide resource dictionary. Nothing references them yet, so appearance, behavior, and startup time are completely unchanged.

### Changed
- **All in-app motion and shadows now consistently respect Windows' "Show animations" accessibility setting and the automatic lightweight mode (Issue #194 depth layering, part 3).** Entrance animations for popups, toasts, dialogs, and the hover thumbnail now all fall back to instant display when either the OS accessibility setting (animations disabled) or the low-spec automatic lightweight mode is active, using a single centralized check. Previously several effects (the action toast, tab list popup, hover thumbnail, and others) ignored these settings, so behavior varied by environment. In lightweight mode the shared floating-surface shadows are also turned off, further reducing rendering load on slow machines. The popup entrance animation, previously duplicated in five places, was consolidated into one implementation so the motion spec can no longer drift during maintenance.
- **Added a "lit from above" depth treatment to the title bar, toolbars, and status bar (Issue #194 depth layering, part 2).** The control surfaces (title bar, each pane's toolbar row, and the status bar) now carry a 1-pixel light edge along their top plus an ultra-subtle top-down highlight, both derived automatically from the theme's surface color, carving them out as sitting one level "above" the data surface (the file list). No shadows are involved — just a 1px line and a faint gradient — so rendering cost does not increase. Because the strength is computed from each surface's lightness, dark themes get a delicate rim of light while light themes get a soft sheen, blending naturally across all themes and per-pane theme combinations. In addition, a "contact shadow" — a short gradient laid along the top edge of the surface below — is now cast by each A/B pane's toolbar row onto the file list beneath it, and by the header of each navigation-pane section — both the top and the bottom one — onto the content directly beneath it, making the height difference between the menu area and the list area more pronounced; its darkness auto-adjusts to the receiving surface's lightness, and like the rest it uses a single gradient rather than any shadow effect. In lists that show a column-header row, the header row counts as part of the menu surface, so the contact shadow falls directly beneath it.
- **Unified the shadows of every "floating" surface into three elevation tiers (Issue #194 depth layering, part 1).** Context menus, tooltips, popups, toasts, and dialogs previously defined their shadows individually in 46 places, each with its own darkness, blur, and light direction (opacity 0.1–0.35, three different light angles), so the depth language varied from screen to screen. They now share three tier definitions — slightly raised (tooltips, toasts), floating (menus, popups, dialogs), and top-most (full-pane overlays such as Quick Preview) — with a consistent overhead light source and a softer, subtler look overall. Since per-instance shadow objects became shared resource references, rendering cost also trends slightly lower. Decorative glows (GlowBar, search-focus glow, achievement badge light) are unchanged.

### Fixed
- **The vertical scrollbar of a list no longer extends up through the column-header row; it now matches the actual item area.** In the A/B panes and the navigation pane, the vertical scrollbar spanned the column-header row as well, making the scrollable range appear to start at the header. The column header is the fixed top edge of the list, so the scrollbar now covers only the area below it — the rows themselves. Header horizontal-scroll tracking and column reordering are unchanged.
- **Fixed the navigation pane's top/bottom split divider being invisible and impossible to drag.** The horizontal splitter had no style applied, so it fell back to the default splitter style meant for left/right splits (a 1px vertical line with a "Columns" resize direction) — the divider was practically invisible and dragging it did not change the top/bottom ratio. It now uses the horizontal splitter style (1px horizontal line, 7px hit area, accent glow on hover), so the boundary is clearly visible and grabbable. Additionally, when the bottom section is "docked" (sized to its content), the divider line used to disappear entirely, leaving no indication of where the top section ended — the line is now shown in that state as well (dragging still cannot change the ratio there, since the height follows the content).

## 最新の変更履歴 — [1.10.0] - 2026-07-25 : UI全体に役割ベースの立体表現を導入（浮遊面の影を3段ティアに統一・操作面の光の稜線とLit Chrome・メニュー↔一覧の接触影）、OSのアニメーション設定と軽量モードの尊重を一元化、ナビペインの上下境界線と一覧スクロールバー範囲の不具合を修正

### Added
- **（内部基盤・表示への影響なし）役割ベースの立体レイヤリング（Issue #194）に向けた共有デザイントークンを追加:** 浮遊面用の影ティア3種（Elevation.Raised／Flyout／Overlay）と角丸トークン4種（Radius.Small／Control／Surface／Float）をアプリ共通リソースに定義した。現時点ではどの画面からも参照していないため、見た目・動作・起動時間は一切変わらない

### Changed
- **Windows の「アニメーションを表示しない」設定と自動軽量モードを、アプリ内のモーション・影が一貫して尊重するようにした（Issue #194 立体レイヤリング第3弾）:** ポップアップ・トースト・ダイアログ・ホバーサムネイルの出現アニメーションが、OS のアクセシビリティ設定（視覚効果のアニメーションを無効にする設定）と低速環境向け自動軽量モードの両方で即時表示に切り替わるよう、判定を一元化した。これまでは一部の演出（操作完了トースト・タブ一覧・ホバーサムネイル等）がこれらの設定を見ておらず、環境によって挙動が不揃いだった。あわせて自動軽量モードでは浮遊面の共有影も消灯し、低速環境での描画負荷をさらに下げる。5箇所に重複していたポップアップ出現アニメーションの実装も1つに統一し、今後の保守で動きの規格がズレないようにした
- **タイトルバー・ツールバー・ステータスバーに「上からの光」を感じる立体表現を追加した（Issue #194 立体レイヤリング第2弾）:** 操作面（タイトルバー・各ペインのツールバー行・ステータスバー）の上辺に、テーマの面色から自動計算した1pxの光の稜線と、上から下へ極薄く消えていくハイライトを重ね、データ面（ファイル一覧）より一段「高い」面として彫り込んだ。影は一切使わず1pxの線と薄いグラデーションだけで表現しているため描画負荷は増えない。色はテーマごとに面の明るさから導出する（暗いテーマでは繊細な光の縁、明るいテーマでは淡い艶になる）ので、全テーマ・ペイン別テーマの組み合わせでも自然に馴染む。あわせて、A/Bペインのツールバー行が下のファイル一覧に、ナビペインの上段・下段それぞれのヘッダーが直下のコンテンツに、それぞれ落とす「接触影」（面上端に敷く短いグラデーション）を追加し、メニュー部分と一覧部分の高低差をよりはっきりさせた（受け面の明るさに応じて濃さを自動調整。こちらも影エフェクトは使わずグラデーション1枚のみ）。列名を表示する表ヘッダーがある一覧では、表ヘッダーもメニュー側の面として扱い、その直下に接触影が落ちる
- **アプリ全体の「浮いている面」の影を3段の高度ティアに統一した（Issue #194 立体レイヤリング第1弾）:** これまでコンテキストメニュー・ツールチップ・各種ポップアップ・トースト・ダイアログの影は46箇所がそれぞれ個別の濃さ・ぼかし・方向で定義されており、画面ごとに影の「言語」がバラバラだった（不透明度0.1〜0.35、光の方向も3種混在）。これらを「小さく浮く（ツールチップ・トースト等）／しっかり浮く（メニュー・ポップアップ・ダイアログ）／最前面に浮く（プレビュー等の全面オーバーレイ）」の3ティアの共有定義に集約し、光源を真上方向に統一、全体をより柔らかく淡い影に揃えた。個々の影インスタンス生成が共有リソース参照になるため、描画負荷もわずかに軽くなる方向。GlowBar・検索フォーカスの発光・実績バッジの光などの「演出系の光」は従来どおり

### Fixed
- **一覧の縦スクロールバーが列名の行（表ヘッダー）まで伸びていたのを、実際のアイテム範囲だけに合わせた:** A/Bペインおよびナビペインの一覧で、縦スクロールバーが列ヘッダー行の高さぶんも占めており、スクロールできる範囲がヘッダーから始まるように見えていた。表ヘッダーは一覧の上端（動かない壁）なので、スクロールバーはその下＝実際に並ぶアイテムの範囲だけを対象にするよう変更した。列ヘッダーの横スクロール追随や列の並べ替えは従来どおり
- **ナビペインの上下分割の境界線が見えず、ドラッグで上下比率を変えられなかった問題を修正:** 上下分割用のスプリッターにスタイルが指定されておらず、左右分割用の既定スタイル（1pxの縦線・リサイズ方向が「列」）が当たっていたため、境界線がほぼ見えないうえドラッグしても上下の比率が変わらなかった。上下分割用のスタイル（1pxの横線・ヒット領域7px・ホバーでアクセント発光）を適用し、境界がはっきり見えて掴めるようにした。あわせて、下段を「固定」（高さを内容にあわせる）にしているときに境界線そのものが消えてどこまでが上段か分からなくなっていたのも改め、固定中も境界線を表示するようにした（この状態では高さが内容依存のためドラッグでの比率変更はできない）
