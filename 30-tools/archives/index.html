    Archives (Extract and Compress)¶

    Open and create archives such as ZIP without leaving the app. Everything lives under Archive ▶, at the top level of the right-click menu.

    Its contents swap depending on what you selected. With only archives selected you get the extraction commands; with anything else you get the compression commands. Showing both at all times would mean reading the list every time to work out which half currently applies. If even one non-archive is mixed into the selection, you get the compression side.

    Where the destination is already decided, the resulting folder or file name appears in the command itself, so you can read what will happen before pressing. Folders carry a trailing \, so they are distinguishable from files.

    • With archives selected — extraction
    • Extract... — opens a folder picker. Since you chose the destination yourself, the contents go straight into it
    • Extract here — puts the contents straight into the folder you are viewing
    • Extract to "(name)\" — creates a folder named after the archive and extracts into it (release.tar.gz gives you a release folder). If a folder of that name already exists, a new name is used, so contents never get mixed together. With several archives selected this becomes Extract each to its own folder
    • Extract to pane (A / B) — extracts into the folder open in the other pane, inside a folder named after the archive. No extracting and then copying. It is not shown when the other pane has no folder open

    • Test archive — reads the archive through to the end without writing a single byte, to tell you whether it is damaged. Use it when you want to know a download was truncated before extracting and littering your disk (see Detecting damage below). It appears only when ZIP or TAR files are selected (the Windows archive component offers no way to verify)

    • With anything else selected — compression

    • Compress... — opens a dialog for the destination folder and file name. The format can be ZIP, TAR, TAR.GZ or 7z (typing a name ending in .tar, .tar.gz or .7z picks that format too)
    • Compress to "(name).zip" — bundles the selection into one ZIP. The name comes from the single selected item, or from the current folder when several are selected
    • Compress to "(name).7z" — bundles it into a 7z with the same name. The 7z is made by the tar.exe that ships with Windows (present since the spring 2018 update to Windows 10). On Windows 11 it uses 7z's standard LZMA; on Windows 10, whose tar.exe has no LZMA, it uses the same method as ZIP (deflate). Either way 7-Zip and similar tools can open it. The strength follows the "ZIP compression level" setting below (Auto behaves like Standard for 7z). If a name contains characters that cannot be represented in the Windows code page (for example Korean or emoji on Japanese Windows), tar.exe cannot handle it, so no 7z is made and you are told which name it was. Compress as ZIP in that case
    • Compress each to its own ZIP — produces one ZIP per selected item (shown only with two or more selected)
    • Create ZIP in pane (A / B) — puts the resulting ZIP in the other pane's folder
    • Compress with level ▶ — makes the same ZIP as Compress to "(name).zip" (same place, same name), but with a different compression strength for this one time. The current default is checked
      • No compression (store only) — packs the files without shrinking them. The fastest choice; the size stays about the same as the originals. Suited to bundling photos and videos
      • Fastest / Standard / Smallest size — how much effort goes into shrinking. You choose a strength, not a target size (files that are already compressed barely shrink whichever you choose)
      • Auto (store photos, videos and the like as is) — stores formats that are already compressed (photos, videos, music, archives, Office documents and so on) as they are and shrinks the rest at Standard, so no time is spent on files that will not get smaller

    The default strength for ZIPs made by Compress is set with "ZIP compression level" under Settings → General → File operations (it starts at Standard). All four compression entries above follow this default. It does not apply to TAR.GZ

    • Supported formats
    Operation Formats How
    Extract ZIP / TAR / TAR.GZ (.tgz) Built in (with safety checks; fast)
    Extract 7z / rar / TAR.BZ2 (.tbz2) / TAR.XZ (.txz) / TAR.ZST (.tzst) / single gz, bz2, xz, zst files Windows' archive folder (the same component behind File Explorer's "Extract All")
    Compress ZIP / TAR / TAR.GZ (chosen in "Compress..."; the other entries make ZIP; ZIP also lets you choose the strength) Built in
    Compress 7z ("Compress..." or Compress to "(name).7z") The tar.exe that ships with Windows
    Extract rar (plus 7z, TAR.XZ, TAR.BZ2 and TAR.ZST when tar.exe has the components) On Windows without the archive folder support (such as Windows 10), the tar.exe that ships with Windows
    Extract 7z / TAR.XZ (.txz) / TAR.BZ2 (.tbz2) Only when neither the Windows archive folder nor tar.exe can read them (such as on Windows 10), a component built into the app (SharpCompress)

    Reading 7z and rar is left to Windows wherever possible. The components that read them are large and complex, and serious vulnerabilities are found in them nearly every year; bundling one would make its vulnerabilities Zenith Filer's vulnerabilities. Instead, 7z, rar and the other formats are read by Windows' own archive component (the one File Explorer uses for "Extract All"), and the app handles only the destination, name clashes and undo. Windows Update keeps that component current. Windows decides which formats work (7z and rar arrived with the autumn 2023 update to Windows 11; on Windows 10 and other versions without that support, rar and others are extracted with the tar.exe that ships with Windows instead. The Windows 10 tar.exe cannot read 7z's standard compression (LZMA), tar.xz or tar.bz2, so those three alone are extracted with a component built into the app [SharpCompress]. It is written in .NET, which makes the memory-corruption kind of vulnerability found nearly every year in C and C++ components unlikely. It is used only when the Windows components cannot read the archive). It works even if your default app for those files is 7-Zip or another tool. CAB is excluded because Windows does not support extracting from it this way. Password-protected or damaged archives are reported as "Windows could not open this archive" with no dialog. Speed matches File Explorer's "Extract All" (around 30 seconds for 10,000 files; the built-in ZIP and TAR take a few seconds). Turning off "Use Windows to extract 7z, rar and other archives" under Settings → General → File operations returns to the built-in ZIP and TAR only. The built-in ZIP and TAR extraction uses only components that ship with Windows.

    • Safety rules: extracting means opening contents you did not write. These protections are always in effect.

    • Nothing is written outside the destination. The trick of slipping ..\ into a file name to write into a parent or system folder is blocked by resolving the real path and confirming it stays inside.

    • Shortcut (symbolic link) entries are discarded. Harmless-looking in themselves, they become the foothold that lets later files be written outside the destination.
    • An archive that expands abnormally is cut off part-way, so a small file cannot keep expanding until it fills the disk; extraction stops the moment more data arrives than the archive declared.
    • Windows reserved names such as CON and NUL, and alternate data streams hidden in a file name (readme.txt:other content), are not extracted.
    • The total extracted size is checked against the free space before anything is written.
    • For formats extracted by the Windows archive folder (7z, rar and so on), Windows itself drops entries that point outside the destination, and links fail. Windows will still create files with reserved names such as CON, so those are removed after extraction and reported by count. Stored checksums (CRC) cannot be verified
    • For formats extracted with tar.exe, tar.exe itself refuses entries that point outside the destination with .. or an absolute path (the refusals are reported by count). Files with reserved names and links are removed after extraction. When extracting into an existing folder, the archive is first extracted into a hidden staging folder inside it, then moved into place following your choices for name clashes (the staging folder is removed afterwards). Items whose names cannot be represented in the Windows code page cannot be read by tar.exe; they are skipped and reported
    • For formats extracted with the component built into the app (7z, tar.xz and tar.bz2 on Windows 10), entries are taken out one at a time under the same rules as ZIP and TAR: entries that point outside the destination, reserved names, alternate data streams and links are not written (and are reported by count). An archive that expands beyond 16 GB for one entry or 64 GB in total is cut off. Password-protected archives cannot be extracted. Extracting into an existing folder uses the same staging folder as tar.exe

    Rejected entries are not discarded silently — the summary at the end reports "N unsafe entries were skipped".

    • Detecting damage: being readable and being intact are not the same thing. If the archive's structure survives, extraction goes through even when the data inside is corrupted, and a damaged file is left behind wearing a perfectly healthy name — the worst possible outcome. For ZIP, the contents are therefore checked during extraction against the checksum (CRC-32) recorded in the archive, and files that fail are removed rather than left behind, with the summary saying what went wrong. Test archive runs the same check without writing anything. Note that TAR and TAR.GZ carry no per-file checksum at all, so there the check can only confirm the archive's structure and, for gzip, that decompression succeeds.

    • When a name already exists: nothing is overwritten by default (the file is saved under a new name). If there are collisions you get the same confirmation used for copying, offering Replace, Skip or Keep both. Clear "Do the same for the remaining N" to decide one file at a time, and edit the name for Keep both.

    • Garbled names in older ZIPs: ZIPs created on Japanese Windows and similar systems may not store names in UTF-8. A ZIP without the UTF-8 marker is read using your system's code page, so names come out intact — the same behaviour as Explorer and 7-Zip.

    • Ctrl+Z puts it back. Undo removes only what this operation created. Files that were already there, and anything you placed in the folder yourself after extracting, are left alone.

    • Pricing: extracting is free. Compressing (creating ZIP, TAR, TAR.GZ or 7z) is limited to 3 times a day in the free version.

    Looking inside an archive¶

    As when you open a zip in File Explorer, double-clicking an archive (or pressing Enter) opens it in the pane. This works for zip, 7z, rar, tar, tar.gz and other formats the app or Windows can extract (except CAB and the second and later parts of split archives).

    • Moving around inside: double-click a folder to go in; Backspace or a double-click on empty space goes up. Going up from the top of the archive returns to the folder that holds it, with the archive selected. The breadcrumb reads "… › archive name › folder inside".
    • Opening a file inside: double-clicking extracts it to a temporary folder and opens it in its default app (temporary folders are cleaned up after a day).
    • Getting files out: use the right-click "Extract..." (pick a destination) or "Extract to the (other) pane", or "Extract all..." on empty space. Ctrl+C puts the extracted files on the clipboard for another pane or File Explorer. Name conflicts get the same prompt as copying, and Ctrl+Z undoes it. You can also drag items out: they are first extracted to a temporary folder and, if you are still holding the button, carried as a copy (large files take a moment to extract; letting go while you wait does nothing; right-dragging cannot carry them).
    • Inside is read-only: delete, rename, paste, new items and drop are not available (you get a notice). Extract first if you want to change the contents.
    • Opening in the default app instead: hold Shift while double-clicking. To always use the default app, turn off "Open archives as folders on double-click" under Control Deck → "General" → "File operations" (on by default).
    • Password-protected archives either show nothing inside or say they could not be opened when you open a file. Use 7-Zip or similar for those.
